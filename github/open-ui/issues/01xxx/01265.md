Creating an issue to discuss open questions on CSS Overflow in the Open UI tracker, since I think this group may make more sense to kick off that discussion (probably should've just logged the issues here, in hindsight).

- Backwards vs. forwards tab order mismatch caused by tab triggering scrolling when reaching partially-visible slides: https://github.com/w3c/csswg-drafts/issues/12270 
- Mechanism for customizing ARIA props on overflow markers: https://github.com/w3c/csswg-drafts/issues/12269
- Browser feedback on feasibility of localizing the `content: 'string-not-to-be-translated' / 'string that should be translated'` format: https://github.com/w3c/csswg-drafts/issues/12268
- How to handle programmatic `.focus()` calls: https://github.com/w3c/csswg-drafts/issues/12240
- Handling `document.activeElement` and focus event targets: https://github.com/w3c/csswg-drafts/issues/12239

## @smhigley — 2025-10-22

Adding this as an additional thing to consider based on the discussion in September:

If we have a `<scrollmarkergroup>`-type container element that is focusable by default with CSS pseudo-elements for each generated marker, that could resolve a lot of the focus-management-related issues. There would be a few remaining (defining custom accNames of individual markers, user-side translation of those custom accNames being the two that come to mind first).

It would also make it easier for authors to customize where in the DOM the scroll markers are displayed.
