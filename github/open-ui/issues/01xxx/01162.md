Currently the [openable explainer](https://open-ui.org/components/openable.explainer/#find-in-page-support) plans to use hidden=until-found attribute value pair with some special handling such that openables can be searchable.

Is this the correct choice?

The [proposed UA styles](https://open-ui.org/components/openable.explainer/#rendering) were potentially naive based on how complex the hidden=until-found styling is in chrome.

1. Hidden attribute isn't implemented purely in UA stylesheet, as such the styles have a higher specificity than if they were, this means that my proposed styles won't actually work. In my prototype I had to use !important which is undesirable.

2. I used revert but that probably isn't the correct value for a UA style.

Given this complexity is it better off being a different mechanism such as openable=searchable? Would this have essentially the same issues given we'd probably share code between the two mechanisms?

<!-- comment id=2701197563 author=brechtDR created=2025-03-05T15:01:52Z url=https://github.com/openui/open-ui/issues/1162#issuecomment-2701197563 -->
## @brechtDR — 2025-03-05

Just a note, I have two thoughts on this:
- Opening items when a user search could result into unwanted change on the screen which might not be nice for users
- Blocking it on the other hand, can have a negative accessible impact.

Providing an option would leave this choice in a developer's hands, but then the question would remain: which is the default?

<!-- comment id=2704117975 author=sorvell created=2025-03-06T15:07:12Z url=https://github.com/openui/open-ui/issues/1162#issuecomment-2704117975 -->
## @sorvell — 2025-03-06

Relying on `content-visiblity` means generating boxes which seems potentially cumbersome since `openable` may be applied to elements that have unwanted default box styling (e.g. padding / margin / border).

I guess this is [potentially contentious](https://www.scottohara.me/blog/2023/03/21/visually-hidden-hack.html), but independent of a11y concerns, it seems really useful for UIs like tabs or chrome://settings.

> which is the default?

IMO, the default should be findable.
