It's not uncommon that Home + End can be used to quickly go to the first and last items within certain focusgroup patterns. For example, toolbars often have this, MDN (and APG) describe these as optional but:

1. If it's useful should it be included by default?

2. If it is included is it only for certain behaviour tokens?

## @dsenneff — 2026-03-06

Came here to file the same issue after playing with 'focusgroup' today, but thankfully saw this first. 

When I implement custom widgets like Tabs currently, I do include Home/End key functionality. I've seen in user testing folks using those keys because they're accustomed to it working in Excel or whatever also try them within a component to jump to the start/end of a group.

If a goal of 'focusgroup' is to help devs by not needing to roll out their own focus handling then I feel like this feature should be included. Or at the least, optional but able to be included via a modifier or something.

Also semi-related side note: in some custom components like interactive lists and such where users can rank and reorder items, I also implement Page Up/Down keys functionality. I use the Page Up/Down in these instances to jump the focus up/down the list by X items. This is probably less-used than Home/End, but wanted to throw it out there since the discussion is somewhat related.

## @lukewarlow — 2026-03-09

According to MDN various roles can use Home and End:

- [menubar](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/menubar_role#home) should if wrapping *isn't* enabled.
- [menu](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/menu_role#home) should support them too.
- [tablist](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/tablist_role#home) can optionally support them.
- [toolbar](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/toolbar_role#home) can optionally support them.
- [listbox](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/listbox_role#:~:text=move%20with%20focus.-,Home,-(Optional)%3A%20Moves%20focus) can optionally support them.

Notably radiogroup does not mention home or end key support.

Based on the above I think it's fine to support everywhere unless someone can tell us why it absolutely shouldn't be supported for radiogroups.

Having said the above the behaviour in browsers is as follows (test on macOS):

listbox (`<select size=3>` or the picker part of `<select>`): Home + End works and Page Up + Page Down works.[1]

radio buttons: Neither Home/End or PageUp/PageDown do anything besides scrolling.

[1] except in chromium with base appearance select where Home/End randomly don't work [crbug.com/491140854](https://issues.chromium.org/u/1/issues/491140854)
