This was raised in the [CSSWG's discussion](https://github.com/w3c/csswg-drafts/issues/12437#issuecomment-3382444205) of the `::interest-button` pseudo element. Currently, it's not possible to polyfill that pseudo element because there's no imperative way to show interest in an interest invoker. Perhaps there should be one?

The most straightforward approach would seem to be something like:

```html
<a href=# interestfor=foo>Link</a> <span id=fake_pseudo>(i)</span>
<div popover id=foo>Hovercard</div>

<script>
fake_pseudo.addEventListener('click', () => {
  document.querySelector('a').showInterest();
});
</script>
```

Are there parameters that should be passed? Nothing comes to mind, but maybe?

Would firing an `interest` event be more in-line with command invokers https://developer.mozilla.org/en-US/docs/Web/API/CommandEvent ? That also allows you to wire up the `source` as well; a bit easier in a polyfill situation I think. 

<!-- comment id=3383336784 author=mfreed7 created=2025-10-08T21:42:41Z url=https://github.com/openui/open-ui/issues/1303#issuecomment-3383336784 -->
## @mfreed7 — 2025-10-08

There's a general principal in HTML though, which is that events are the result of an action, not the cause. The historical precedent that `click` events do things is an anti-pattern. So I think there will be resistance to e.g. making the default popover actions (open on `interest`, close on `loseinterest`) happen via a manually-fired interest event. This is equivalent to the `commandfor` API, which doesn't do anything in response to manually-fired `command` events.

Edit: also, this wouldn't provide the other things that interest invoker does, like the invoker matching `:interest-source` and the target matching `:interest-target`, when it has interest.
