## Context
The Chromium prototype has a built-in value bubble above each thumb. It can't be styled, moved, formatted or hidden per thumb.
The same result is easy with existing features:
```css
rangegroup::slider-thumb(1) { anchor-name: --t1; }
.pill { position: absolute; position-anchor: --t1; position-area: block-start; }
```
```js
group.addEventListener("input", () => pill.textContent = format(group.values[0]));
```
Fully stylable, any formatting, can be an `<output>`. The cost is a few lines of JS plus hand-wired anchor names.

## Questions
1. Should a value bubble exist at all? Opt-in or on by default?
2. If yes, does it need a pseudo-element (`::slider-thumb-value`)? How is its content formatted? I think authors will want to style this (colors, arrow/no-arrow) which makes me believe a one liner of JS and some CSS might actually open more dynamic styling.
3. Or is script + anchor positioning enough, provided we add:
   - an **implicit anchor** (`<output for>` or `<label>` resolves `position-anchor: auto` to its thumb, as in the label issue), and
   - a spec'd contract that thumb pseudo-elements are valid anchors?
4. When is it shown (always, hover, drag, focus)? Is it announced, given it duplicates `aria-valuetext`?
