If you're focused on a menuitem inside a menubar or menulist, should the tab key move focus to the next focusable thing after the end of the menubar/menulist and close the menulist like we did for customizable select, or should it just move focus to the next menuitem? Should we also account for the author incorrectly putting other interactive content inside the menu and turn off this behavior like we did for customizable select?

## @josepharhar — 2026-04-28

I don't think this behavior will be standardized, just like it wasn't for customizable select. I'm interested in hearing a suggestion from OpenUI to choose the behavior in chromium.

In chromium we also choose not to follow the platform conventions/settings on MacOS which suggest which elements are keyboard focusable.

The Open UI Community Group just discussed `What should the tab key do in menu elements?`, and agreed to the following:

* `RESOLVED: pressing tab on a menuitem moves focus to the next focusable item after the entire tree of menubar/menulist menus`
