Hello,

First of all, congrats for the invoker spec; it helps clean up many things.

One thing that is frustrating though is the restriction to button only. We have a use case where we have a `carousel-scroll-button` component. This allows to go to the next/prev slide. The reason why we have to use a custom component here instead of just using a button is that this component also have extra features that also requires the reference to the controlled carousel specified in the commandfor.

Ideally, we wanted to use it like this:

```
<carousel-scroll-button commandfor="my-carousel" command="--prev">
  <button type="button">Prev</button>
</carousel-scroll-button>
```

Unfortunately, this does not work. I'm aware of the `is`, but as WebKit decided to never implement it, using `is` is not possible for us. The solution we've found so far is to reflect all the attributes to the button, but we're afraid that this might cause a breaking change if the standard changes in the future to also support commandfor for web components (in which case we would have the command triggered twice).

## @alexkeng — 2025-10-01

> I'm confused why that shadow root has a button inserted into it?

technically, with our proposal, the button in the shadow is NOT needed for command/commndfor to work, i.e., you can direclty do `shadowRoot.appendChild(slot)` and the [example](https://jsfiddle.net/26j1d7ta/) will still work. The button was added only because the original post mentioned they wanted the example below to work (my interpretation was that the native button was in the shadow, not the light dom), and I wasn't sure if they have logic other than command/commandfor that requires the native button so I kept it in the example

```
<carousel-scroll-button commandfor="my-carousel" command="--prev">
  <button type="button">Prev</button>
</carousel-scroll-button>
```
