## Introduction

This proposal introduces a new feature for HTML range inputs: the ability to select two values within a given range using a single input element. This enhancement aims to provide a more intuitive and space-efficient way to select a range of values, commonly used in scenarios such as price filters, age ranges, or time spans.


## Use Cases



* Price range selectors in e-commerce filters
* Age range inputs in demographic forms
* Time range selectors for scheduling applications
* Data range selectors in analytics tools

## Proposed Solution

We propose extending the existing `<input type="range">` element with a new dual attribute and modifying the value attribute to accept two values.

HTML Syntax


```
<input type="range" dual min="0" max="100" value="25 75">
```



## Attributes

* `dual`: A boolean attribute that enables the dual-handle behavior.
* `value`: When dual is present, this attribute accepts two values containing two numbers representing the lower and upper selected values.
* `min`, `max`, and `step` still behave as with a non-dual range input. The handles should not have the ability to be crossed (missing real word data where this makes sense)
* If the value for example is lower than the min value, the lower handle part of the value is set to the min value (As currently with `input[type=range]`)


## JavaScript API


```
const rangeInput = document.querySelector('input[type="range"][dual]');

// Getting the value
console.log(rangeInput.value); // "25 75"

// Setting the value
rangeInput.value = "[30 70]";

// Convenience properties
console.log(rangeInput.lowerValue); // 30
console.log(rangeInput.upperValue); // 70

rangeInput.lowerValue = 35;
console.log(rangeInput.value); // "35 70"
```



## Events

The input and change events will fire when either handle is moved, with the `event.target.value` reflecting the new state of both handles.


## Accessibility



* The element will have an ARIA role of range.
* Two separate ARIA labels will be provided for the lower and upper handles.
* Keyboard navigation will allow focusing and adjusting each handle separately by using the arrow-keys, or pgDown/pgUp to jump bigger values.
* The input will fall back to a standard range input for browsers that don't support the dual attribute. For polyfilling, the value will be set to the average of the two values or the first value in the array. Another suggestion could be that the fallback handle becomes the lower value.

In the case of average, it could be something like this:


```
if (!('dual' in HTMLInputElement.prototype)) {
  const [lower, upper] = JSON.parse(rangeInput.value);
  rangeInput.value = Math.round((lower + upper) / 2);
}
```



## Open questions


* Should we introduce separate events for changes to lower and upper values?
* How should we handle cases where the lower value exceeds the upper value?
* Are we happy with the fallback strategy?
* How to handle fallbacks when authors add JS events on dual range change?
* How should it be handled in combination with `<datalist>`?
* What should happen when handles are too close together? Does this open the window for crossing handles to be a benefit?
* Accessibility: on a single range input, clicking the track moves the handle. How should it behave when multiple are available? Could be click handle and then track?

## @mvl22 — 2025-03-09

Thanks; native support for this is much-needed.

I would have expected use of a comma rather than space as the result value separator, because:

- It is a list of things. Commas are the standard way in written text to separate a list of items.
- Graceful degradation is likely to appear more sensible - a user is intuitively more likely to manipulate correctly a default comma-separated list rather than a space which reads like two words.
- Commas are unambiguous, compared to a space. Is the space a single space or can it be multiple? Is the space a tab? Does my data processor have to use a regexp to split by all kinds of space-like things rather than just a simple string split?
