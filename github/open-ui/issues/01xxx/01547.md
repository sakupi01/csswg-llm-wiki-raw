## Terminology
- **Real focus**: DOM focus, i.e. `document.activeElement`, `:focus`, `:focus-visible`.
- **Virtual focus**: DOM focus stays in the text field and the browser marks an option as "active" for AT (like `aria-activedescendant`). The option matches `:active-option`.

## Questions
1. When focus is in the text field, should arrow keys move virtual focus through the options, or should ArrowDown move real focus into the listbox?
2. Should the listbox/options also be reachable with Tab, separately from the text field?
3. Should you be able to select/toggle an option while real focus is in the text field? (This would have to be Enter, because Space types a space.)

At TPAC, [the ARIA WG discussed this](https://github.com/w3c/aria/issues/2841#issuecomment-6443074990) and Jamie Teh asked whether it makes sense for options to be reachable both through virtual focus from the text field and through real focus by tabbing  into the listbox (Matt King called this a "dual focus" problem). [My summary of that feedback](https://github.com/w3c/aria/issues/2841#issuecomment-6476617456).

Already agreed in ARIA (applies to Options 1 and 2): the text field is mapped as a plain text field (not a combobox) that controls the listbox. Virtual focus (`aria-activedescendant`) is only set after the user presses an arrow key, and it is cleared    when the user edits the text or moves the caret (typing, Backspace, Left/Right, Home/End).

## Options

### Option 1: Virtual focus from the text field AND options can get real focus
- This is what the Chromium prototype does.
- Based on the ARIA feedback, this may be confusing for AT users.
- Authors need to style an option for both `:active-option` and `:focus-visible`, e.g. `option:is(:active-option, :focus-visible)`.

### Option 2: Virtual focus from the text field only; options can't get real focus
- This is how the GitHub labels picker works.
- ARIA feedback said it's hard to get back to the text field when using AT. 
- Options can be `:active-option`, but never `:focus-visible`.
- Clicking an option keeps focus in the text field.

### Option 3: Text field only filters; ArrowDown moves real focus to the first option
- Based on the ARIA feedback this seems like the best path, but I'm not sure that non-AT users or developers would like it. 
- `:active-option` goes away completely, so authors have less to think about.
- Once focus is in the listbox, typed characters no longer go to the text field. Instead they do typeahead within the listbox. We could redirect typed characters (and Backspace) back to the text field instead, but that might be unexpected.
- Moving focus with the arrow keys does not change the selection (selection doesn't follow focus); Space/Enter selects.
- ArrowUp on the first option moves focus back to the text field.

## Keyboard summary

| Key | Option 1 | Option 2 | Option 3 | 
|---|---|---|---|
| ArrowDown in text field | Virtual focus to next option | Virtual focus to next option | Real focus to first option |
| Enter in text field | Select/toggle active option | Select/toggle active option | Nothing (form submission?) |
| Tab from text field | Into listbox | Past listbox | Into listbox |
| Printable chars in listbox | Typeahead | n/a | Typeahead or redirect to text field (TBD) |
| Click an option | Focus moves to option | Focus stays in text field | Focus moves to option |
