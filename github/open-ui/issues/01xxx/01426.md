I have a use case where disabling segments for a focusgroup could be useful.
(Tell me if it's a bad pattern)

For example, with the HTML below, `.item-actions` is visible when the item is selected, focused or hovered:
```html
<div id="js" class="menu" focusgroup="menu nomemory nosegment">
	...

	<div class="item-wrapper">
		<button class="item" focusgroupstart>
			# item2
		</button>
		<div class="item-actions" focusgroup="none">
			<button class="item-action">☍</button>
			<button class="item-action">✖</button>
		</div>
	</div>

	...
</div>
```
If segments were disabled, navigation would behave like this:
(red arrows = sequential navigation, green arrows = directional navigation)

<img width="359" height="288" alt="Image" src="https://github.com/user-attachments/assets/0d2c5da1-db5b-4308-91e3-156a3b524b95" />

---

One way I thought to achieve this is by adding a `nosegment` modifier that makes all the focusgroup items part of the same segment.

An additional or alternative approach could be to indicate that a subgroup that normally splits a segment should not do so, using an attribute like `nosegmentcut`. I don't have a use case for this, but it could always be added later if one comes up, though I doubt it.

---

Currently, similar (or more complex) patterns can be achieved using `tabindex="-1"` (which does not create segments) along with JS, but this is not always straightforward.

For example:
```html
<div id="js" class="menu" focusgroup="menu nomemory">
	...

	<div class="item-wrapper">
		<button class="item" focusgroupstart>
			# item2
		</button>
		<div class="item-actions">
			<button class="item-action" tabindex="-1">☍</button>
			<button class="item-action" tabindex="-1">✖</button>
		</div>
	</div>

	...
</div>
```
In this case, most navigation can rely on sequential and directional navigation, with only the "purple" navigation needing custom logic:
