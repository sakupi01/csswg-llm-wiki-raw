Following recent discussions and resolutions (https://github.com/openui/open-ui/issues/939#issuecomment-1910837275) around the `combobox` [anatomy](https://open-ui.org/components/combobox.explainer/#anatomy), this issue aims to explore the potential benefits and implications of integrating an `<input>` element as a child of the `<select>` element, which could potentially enable us to achieve all the functionalities of a `combobox`.

<!-- comment id=2127125544 author=zcorpan created=2024-05-23T13:34:45Z url=https://github.com/openui/open-ui/issues/1055#issuecomment-2127125544 -->
## @zcorpan — 2024-05-23

`<input>` in `<select>` is not web compatible, it needs to close the `select`. See https://github.com/whatwg/html/issues/10310

HTML has `input`+`datalist` for combobox. While there are many issues with it, they might be solvable.

<!-- comment id=2127148026 author=lukewarlow created=2024-05-23T13:44:55Z url=https://github.com/openui/open-ui/issues/1055#issuecomment-2127148026 -->

Having said that if it's not web compatible we'll need a different idea. Maybe a texarea (bit odd ergonomically but if it's web compatible?)

## @css-meeting-bot — 2024-05-23

The Open UI Community Group just discussed ``Explore `<input>` Element as a child within `<select>` for Combobox``, and agreed to the following:

* `RESOLVED: the input should not be allowed within the select. The combobox should be implemented as a new element or as part of e.g. input/datalist.`
