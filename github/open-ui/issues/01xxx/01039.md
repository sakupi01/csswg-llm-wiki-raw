This issue is for collecting use cases for a button with a pressed state. Sometimes referred to as toggle buttons (but that's an overloaded term), or aria-pressed buttons (but that's an implementation detail).

I'm not looking for ideas on how this could be implemented (e.g. checkbox, switch, select), just for examples of how it would be used.

The usecase shouldn't need more than 2 states (for now lets ignore the aria-pressed mixed case unless you've a strong example)

## @o-t-w — 2024-04-24

The use case example I see most often is bold/italic/underline. 
- [Material Design](https://m2.material.io/components/buttons#toggle-button) uses bold/italic/underline as the examples (they also classify text-alignment as "toggle" but that's actually tabs not toggle as you can only select one at a time). They also have a favourite ❤️ button example.
- [Shadcn](https://ui.shadcn.com/docs/components/toggle) uses bold/unbold as the example
- [Fluent UI](https://react.fluentui.dev/?path=/docs/components-button-togglebutton--default) includes a toggle button but the docs site doesn't have any real-world example use cases
- [Salesforce](https://developer.salesforce.com/docs/component-library/bundle/lightning:buttonStateful/example) have a follow/unfollow button example. Twitter is also another obvious example of that use case. Also bookmark/unbookmark button on Twitter. 
- [Prime Vue](https://primevue.org/togglebutton/) uses a locked/unlocked example. Their docs site is using a toggle button to select between light/dark mode
- This article from [Inclusive Components](https://inclusive-components.design/toggle-button/) uses a play/pause button as an example. That's also something Jeremy Keith talks about in [an article of his](https://adactio.com/journal/tags/aria) referring to a play/pause button used on [The Session website](https://thesession.org/tunes/7451#setting50278).


- Many examples of show/hide eyeball button for password fields and other sensitive fields
- [Goldman Sachs](https://design.gs.com/components/tag#toggle-tag) has a "toggle tag" example for filtering. This is relatively common. See also Google Fonts filter below:
<img width="319" alt="Screenshot 2024-04-24 at 11 08 45" src="https://github.com/openui/open-ui/assets/29547922/93c02d42-192b-4498-b5b4-b489e6fad43d">

- Google Meet/Zoom and other video conferencing apps: raise hand/lower hand toggle. webcam on/off. mute/unmute your microphone. Mute/unmute audio. captions on/off
<img width="232" alt="Screenshot 2024-04-24 at 16 17 32" src="https://github.com/openui/open-ui/assets/29547922/85bc824b-9753-494c-a6d2-4b2e9f2cfe16">

- Trello: enable/disable colorblind mode
<img width="356" alt="Screenshot 2024-04-24 at 18 26 01" src="https://github.com/openui/open-ui/assets/29547922/59a172ac-547c-4306-bce3-a368e2b189f7">

A pretty common pattern is that a button, after being pressed, can be unpressed, but pressing _another_ button will also automatically unpress it, so only zero or one options can be pressed at a time. Styling the background of a Trello board is one of many examples of this.

A common pattern for this is button groups where either each button acts as an independent toggle:

<img width="109" height="54" alt="Image" src="https://github.com/user-attachments/assets/b46f49f0-e162-4aca-b3d7-87371bf43c79" />

or they represent an exclusive choice:


<img width="343" height="487" alt="Image" src="https://github.com/user-attachments/assets/d1f558a9-5182-4e92-9b0d-2bb688f338b7" />

Ideally, both would be supported with this. Some ideas:
- a grouping element
- grouping via `name`, like `<details>`
- `<button type="checkbox | radio">`
- `<input type="checkbox | radio" appearance="button">` (can also be used for switches, instead of a boolean `switch` attribute)
