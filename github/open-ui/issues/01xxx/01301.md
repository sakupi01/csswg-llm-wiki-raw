How does the focusgroup interact with custom elements that delegate focus to an element inside the shadow root?

```html
<div focusgroup>
  <host-element>
    <template shadowrootmode="open" shadowrootdelegatesfocus>
      <button>Inside button</button>
    </template>
  </host-element>
  <button>Outside button</button>
</div>
```

Will this "just" work? Or will focus be trapped on the inside button?

## @gfellerph — 2025-10-08

I think the idea for it is to "just work". The second point in the [focusgroup explainers use case section](https://open-ui.org/components/scoped-focusgroup.explainer/#use-cases) states that `focusgroup` can be declared on a shadow host or an ancestor and it should still work. I explored a bit how this could work in an experimental polyfill implementation (based on the old explainer but will update to the new one soon): https://gfellerph.github.io/focusgroup-polyfill/#shadow-dom-focusgroup in case you want to try it.

## @janewman — 2025-10-08

+1 this will "just work". `focusgroup` will consider all focusable elements within the focusgroup's scope as a focusgroup item, including shadow trees. If you as the developer didn't want this, you can use focusgroup="none" to opt out.

<!-- comment id=3386367488 author=gfellerph created=2025-10-09T15:40:59Z url=https://github.com/openui/open-ui/issues/1301#issuecomment-3386367488 -->
## @gfellerph — 2025-10-09

Tabbing would work like this (taking your example): 

1. User tabs into focusgroup, "Primary inside button" gets focus because it's the first element in DOM order
2. Pressing the right arrow key moves focus to the "Outside button" because "Secondary inside button" is opted out of focusgroup behaviour
3. Pressing <kbd>shift</kbd> + <kbd>tab</kbd> focuses the "Secondary inside button" because this button is opted out of focusgroup and does not participate in the roving tabindex. Arrow keys are not moving focus at this step because this button is considered to be ouside of the focusgroup
4. Pressing <kbd>shift</kbd> + <kbd>tab</kbd> again moves focus back to "Primary inside button" due to the [segmentation when opting out](https://open-ui.org/components/scoped-focusgroup.explainer/#impact-on-sequential-focus-navigation). An opted out item will split the focusgroup in two, adding one guaranteed tab stop per segment. Arrow keys are enabled again at this step
