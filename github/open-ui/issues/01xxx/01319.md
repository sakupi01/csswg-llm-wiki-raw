I was reading the [aria practices guide for combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), and if we want to support all of the "four forms of autocomplete" in there then I think we need some more behaviors which can be controlled:

1. A way to disable filtering, which could be done if we add a new filter attribute with values to support basic filtering use cases which also has a value like "none". This enables the "**No autocomplete**" case from APG.
2. Inline autocomplete, where the text in the input element gets completed to match the text of the currently focused option. This enables the "**List with inline autocomplete**" case from APG.

I don't fully understand the difference between the "List autocomplete with manual selection" and "List autocomplete with automatic selection" cases in the APG. It seems like in the automatic case, an option becomes focused when the picker gets opened vs not in the manual case. It almost sounds like the automatic case forces only valid options to be typed into the input, but I'm not sure... @scottaohara could you clarify?
