There are various ways that authors can handle the sequential focusability of nested content, the fluent "card" does a good job of showing some of the patterns that can be used https://storybooks.fluentui.dev/react/iframe.html?id=components-card-card--focus-mode&viewMode=story

* 'off' the card itself isn't focusable
* 'no-tab' changes to use the enter and esc keys for entry/exit, and provides a loop for sequential focus navigation.
* 'tab-exit', like 'no-tab' but doesn't trap the user in a focus loop, upon reaching the end of the content, tab breaks out.
* 'tab-only' probably the closest analogue to the current proposal of itemcontrols, tab can enter and exit the card's nested content.

In addition to these examples, I've head of the desire for arrow keys in the cross-axis direction to facilitate entry/exit, this would be particularly useful for creating a menu with submenus.

With all of this variety, should we consider making itemcontrols its own attribute, with its own set of allowed tokens? If so, should we also consider allowing this to be used on elements that aren't participating in a focusgroup? I can imagine something like a standalone "profile card" being useful to some developers, but haven't done the research to see if this is popular or needed.

## @janewman — 2026-08-17

I'll personally agree that tab is the most intuitive way to handle nested content in general, and that's what's in the current focusgroupV2 proposal.

That said, other paradigms exist on the web, and the enter/esc pattern to enter nested content is relatively popular, especially in the grid case, here are some examples of where this behavior can be seen:
### Generic (less strong need IMO):
- [Fluent UI Card focus modes](https://storybooks.fluentui.dev/react/?path=/story/components-card-card--focus-mode) are the closest match. They demonstrate `no-tab`, `tab-exit`, and `tab-only`; Enter moves into the card's controls and Escape returns to the card.
- [Tabster Groupper](https://tabster.io/docs/groupper/) ([interactive examples](https://tabster.io/storybook/?path=/story/groupper)) is the underlying production implementation. A chat message containing reaction and reply controls where "enter" is used to move focus to the reation/reply controls is an example of this pattern in the wild. 
### Grid-specific:
- [MUI Data Grid editing](https://mui.com/x/react-data-grid/editing/) could be implemented with this proposal by making the editable region a descendant of the grid cell.
- [Handsontable](https://handsontable.com/docs/javascript-data-grid/keyboard-shortcuts/) (similar to above)
- The [W3C APG data-grid examples](https://www.w3.org/WAI/ARIA/apg/patterns/grid/examples/data-grids/) include an editable grid operated via enter/esc, where an input is nested within the cell, and enter moves focus to the nested content.

I think the nested interactive content in a grid is probably the strongest argument for enter/esc to drill into/escape out of the nested content.
