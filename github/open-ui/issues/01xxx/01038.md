It's great that we've got [`stepUp`/`stepDown` for number inputs](https://github.com/openui/open-ui/issues/968), but in addition to this I'd like to propose a `set` and possibly `reset` or `clear` for form inputs (`set` with an empty value could work for `clear` and `set` with an 'original' value could work for `reset` so all 3 may not be necessary)

My use-case is having a bunch of filters on an ecommerce website. Outside the filter form (that might be buried in a closed `<dialog>`), there's a list of active filters, providing quick-access for the user to remove them and widen the search.

For the checkbox filters, I can use `<label for="[checkbox-id]">` to uncheck the filters, however with the price filter (two number inputs), there's no way to clear their values without manual JavaScript (afaik), `<button commandfor="[input-id]" command="set" value="">` would work wonders for this and provide an extensible mechanism to reset/clear individual inputs and no doubt apply to a bunch of other use-cases given that any `value` could be set.

(sorry if this has already been proposed, I couldn't find anything in the Github issue search!)

## @PaulKiddle — 2025-08-28

I didn't see a specific rejection of the `set` command in the meeting notes and I think it could be quite useful for setting a field to one or more popular/likely values. For example:

```html
<label>Pick a date: <input id=date name=date type=date value='2025-01-01'></label>
<button type=button command=set commandfor=date value='2025-08-28'>Today</button>
<button type=button command=set commandfor=date value='2025-08-29'>Tomorrow</button>
```

Here the buttons use the `set` command to populate the date field with today's and tomorrows date, respectively.

## @PaulKiddle — 2025-08-29

It could also be useful to be able to set multiple fields' values, that could be done by targetting a form or fieldset and using a url-encoded parameter string as the `value`.

For the paper size example:
```html
<fieldset id=size>
<input type=number name=width> x <input type=number name=height>
</fieldset>
<button type=button command=set commandfor=size value="width=210&height=297">A4</button>
```

That would also be useful for the date-select form I'm working on right now, which allows a user to select a day or a month:

```html
<form id=search>
<label>From<input type=date name=start></label>
<label>Until<input type=date name=end></label>
<button type=button command=set commandfor=search value="start=2025-08-29&end=2025-08-29">Today</button>
<button type=button command=set commandfor=search value="start=2025-09-01&end=2025-09-30">All of September</button>
<button type=button command=set commandfor=search value="start=2025-10-01&end=2025-10-31">All of October</button>
<button>Search</button>
</form>
```

This use case is potentially more useful than setting a single value, but the algorithm for doing so is less well defined - there isn't a simple native way to do this in Javascript for example, and populating fields from a query string requires making some decisions about how exactly to associate which parameter with which field in certain edge cases where it's not obvious.

Multiple fields with the same name comes to mind as one less-straight-forward example:

```html
<form id=flag>
Pick your flag colours:
<input type=color name=colour>
<input type=color name=colour>
<input type=color name=colour>
<input type=color name=colour>
<input type=color name=colour>
<input type=color name=colour>
<button type=button command=set commandfor=flag value="colour=#d62800&colour=#ff9b56&colour=#ffffff&colour=#d56sa6&colour=#a40062">Lesbian Pride</button>
<button>Save</button>
</form>
```

Here I would expect the first five fields to be filled in with the five colours from the command button's query parameters, but the exact algorithm would need to be defined and consider what happens when fields are out of order, missing, what to do about radio inputs & check boxes, etc.

Obviously this adds a lot more complexity to the proposal -- perhaps it should use a separate command name like `setfields`


Update: FYI I've [created a ticket](https://github.com/whatwg/html/issues/11643) to add a JS-method-equivalent to the DOM
