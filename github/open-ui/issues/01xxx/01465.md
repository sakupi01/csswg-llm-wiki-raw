In Safari all the arrow keys work to move focus. In Chrome only the up and down buttons work. 

The layout of the options of a custom select may be horizontal, vertical, or in a grid. When the layout is not vertical, the behaviour in Chrome is problematic because the up/down keys have to be used to move left and right. When the options have a grid layout, neither the Chrome nor Safari behaviour is ideal.

## @josepharhar — 2026-07-09

Here's a demo which shows the different keyboard behavior we implemented:
```html
<style>
select, ::picker(select) {
  appearance: base-select;
}
</style>

<select>
  <option>one</option>
  <option>two</option>
  <option>three</option>
</select>

<select style="writing-mode:vertical-lr">
  <option>one</option>
  <option>two</option>
  <option>three</option>
</select>

<select style="writing-mode:vertical-rl">
  <option>one</option>
  <option>two</option>
  <option>three</option>
</select>
```

Putting the behaviors in a table feels hard so I'll just say it:
- For vertical-lr, chrome and safari do the same thing: left and up arrow keys go backwards, right and down arrow keys go forwards.
- For vertical-rl, chrome and safari do the same thing: right and up arrow keys go backwards, left and down arrow keys go forwards.
- For horizontal-tb, chrome and safari are different:
  - chrome: up arrow goes backwards, down arrow goes forwards. left and right keys do nothing.
  - safari: left and up arrows go backwards, right and down arrows go forwards. same as vertical-lr.

I implemented the chrome behavior to simply match the safari behavior which they put in a wpt here, which must have not tested right/left in horizontal-tb: https://github.com/web-platform-tests/wpt/commit/d2ad58e1ff0ac60de95ebeb937bb9a70b4e08852
