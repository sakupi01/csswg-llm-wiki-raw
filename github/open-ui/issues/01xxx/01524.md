The prototype uses `::slider-thumb(n)`, `::slider-thumb(*)` and `::slider-segment(n)`. Segments are numbered by position; thumbs are undefined.

## Questions

- **Stability:** inserting a thumb renumbers the ones after it, so styles jump to another input. Acceptable?
- **State:** styling a disabled thumb today needs `rangegroup:has(input[name=x]:disabled)::slider-thumb(1)`. Should thumbs match their input's state directly (`::slider-thumb(*):disabled`, `:focus-visible`)?
- **Syntax:** is `(*)` needed, or does bare `::slider-thumb` mean all thumbs? Allow `An+B`?

## Suggestion
`n` = DOM order, segments stay positional, and thumbs match their input's pseudo-classes.

Some example CSS
```css
rangegroup ::slider-thumb {}
rangegroup input[type=range i]::slider-thumb {}
rangegroup input[name=fish]::slider-thumb {}
rangegroup :disabled::slider-thumb {}
rangegroup ::slider-thumb:active {}
rangegroup ::slider-thumb:hover {}
rangegroup label:nth-of-type(1) ::slider-thumb {}
```
