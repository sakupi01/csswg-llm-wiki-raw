As part of the standards process for command/commandfor we've ended up dropping `<input type="button">` support, requiring users to have an actual `<button>`.

Should we do the same for interesttarget?

cc @keithamus  and @mfreed7 

<!-- comment id=2596790843 author=lukewarlow created=2025-01-16T20:04:16Z url=https://github.com/openui/open-ui/issues/1138#issuecomment-2596790843 -->
## @lukewarlow — 2025-01-16

I vote yes because `<input type="button">`, type="reset" and type="submit" are mistakes and it'd be good to be consistent.

<!-- comment id=2610387604 author=mfreed7 created=2025-01-23T16:43:54Z url=https://github.com/openui/open-ui/issues/1138#issuecomment-2610387604 -->
## @mfreed7 — 2025-01-23

This wouldn't bother me too much. We should definitely be as consistent with `commandfor` as possible. Having said that, there *is* a difference. E.g. it's possible a site already has some HTML that uses/requires `<input type=button>` for reasons, and just wants to add a helpful hovercard for the existing button. Additionally, the (new) explainer also mentions wanting to expand support for `interesttarget` to more elements, potentially anything that is already interactive, which would include `<input>`.

What was the explicit rationale for removing support for `<input>` from `commandfor`?

<!-- comment id=2610399934 author=lukewarlow created=2025-01-23T16:48:40Z url=https://github.com/openui/open-ui/issues/1138#issuecomment-2610399934 -->
## @lukewarlow — 2025-01-23

Input buttons are legacy and they already lead to interop bugs with popover so during whatnot we were discussing it and decided it was better to encourage users to use the button elements. Hence, we stopped supporting them. I believe it also simplifies the spec and implementations.

<!-- comment id=2611243990 author=mfreed7 created=2025-01-23T23:47:57Z url=https://github.com/openui/open-ui/issues/1138#issuecomment-2611243990 -->
## @mfreed7 — 2025-01-23

Ok, fair enough. I think the chance of actually removing `<input type=button>` from the platform is exceedingly small. But I guess there's no harm in trying not to encourage more usage.

<!-- comment id=2611252794 author=lukewarlow created=2025-01-23T23:56:22Z url=https://github.com/openui/open-ui/issues/1138#issuecomment-2611252794 -->
## @lukewarlow — 2025-01-23

For command especially it's even more of an issue because the value attribute has usages with some commands (close and request-close for dialog for example). Whereas for input buttons this is the text contents of the button.
