Apologies if this has already been addressed somewhere; couldn't find an open issue or anything in the [demos](https://microsoftedge.github.io/Demos/focusgroup/).

The current behaviour of `focusgroup` is (IIUC) for the down/right arrow keys to focus the next focusable item, and for the up/left arrow keys to go backwards. In many grid-based UIs, especially on TVs, arrow keys will instead focus the focusable element in the direction of the arrow, which feels somewhat more intuitive. I think it would be cool if `focusgroup` supported this mode, perhaps with a new behavior token such as `focusgroup="menu multidirectional"`. (I realise that 'in the direction of the arrow' is a gross oversimplification!)

Demo to show what I mean: https://svelte.dev/playground/dfb6b000d7414721ab575d45c636654a?version=latest

## @g12n — 2026-03-11

[manual-grid](https://open-ui.org/components/scoped-focusgroup.explainer/#manual-grids-row-and-cell-connections) and [focusgroup="grid"](https://open-ui.org/components/scoped-focusgroup.explainer/#setting-up-a-grid-focusgroup) work well for elements like tables with a structure of columns and rows already determined at authoring of the html code. 

But it lags the ability to adapt to responsive changes in layout caused by device and container size. 

## Example: image picker: 

Lets as an example take an [image picker component](https://codepen.io/editor/g12n/pen/019cdc98-9c32-74e7-8440-1a88f1395eed)

<img width="237" height="307" alt="screenshot of a grid of three by four cells with image placeholders" src="https://github.com/user-attachments/assets/d3fcb543-7555-4c53-868a-c8b5ae4fec4d" />

<img width="392" height="232" alt="screenshot of a grid of five by three cells with image placeholders" src="https://github.com/user-attachments/assets/7f3b86f3-3b90-43ef-a80e-0a332ecd37d9" />

```
<div class="image-grid-section" focusgroup="radiogroup" data-label="September">
  <button>
    <img src="https://placehold.co/60x60/png">
  </button>
  <button>
    <img src="https://placehold.co/60x60/png">
  </button>
...
</div>
```

In its simplest incarnation this is just container with focusable items. 
The number of columns in this example is determined by the CSS depending of the size of the container itself.
Even the fact that these are displayed as a grid can be dependent on the overall layout. 


So I think we will either have to add an "auto" behaviour to the focus group, that determines after rendering the next items in the bock and inline direction.

```
<div focusgroup="grid auto">
  <button>
    <img src="https://placehold.co/60x60/png">
  </button>
  <button>
    <img src="https://placehold.co/60x60/png">
  </button>
</div>
```

Or introduce css attributes to inform the focus behaviour: 

```css
.image-picker[focusgroup]{
    grid-template-columns: repeat(3, 1fr);
    focus-direction: grid; 
    focus-grid-columns: 3;
}

@media (max-width: 320px) {
    .image-picker[focusgroup]{
        display: flex; 
        flex-direction: column;
        focus-direction: block;
   }
}
```
