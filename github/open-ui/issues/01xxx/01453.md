Single-select can have an option that is considered a placeholder for validation purposes,
to be a placeholder that option must be the first option and the select select the first option when no option are selected.
Select-multiple historically never had a placeholder option.

Some time ago was added to the spec the possibility to have a placeholder for `select multiple size=1`, without making the the placeholder option handling any different from other options.
I think this creates some undesirable behaviours:
- js api returns the placeholder option with other options selected.
- selecting another option plus the placeholder result in the UA text saying "2 Selected".
- the placeholder is copied to the selectedcontent element with other selected options.
- if no options are selected, the placeholder remains not selected.

This behaviour looks a *bit* more like `min=2` than placeholder.

I noticed the spec change from this html issue:
https://github.com/whatwg/html/issues/12246
Something I commented there:
> - Is a placeholder option for size=1 web compatible?
> - for single-select the placeholder option or any other option is deselected when selecting a new option, this logic I think is not present for select-multiple, so currently the placeholder options would remain selected when selecting other options.
Maybe additional logic can be added to deselect the placeholder when selecting options and reselect the placeholder when none are selected.
> - with the hypothetical logic above, clicking the placeholder would deselect all the options?
> - UAs that render a listbox for size=1,  is another thing to consider.

Some previous discussions:
https://github.com/openui/open-ui/issues/1355

TL;DR: I don't like the current specced placeholder behaviour for `select multiple size=1` (that luckily nobody implemented), I suggested an alternative behaviour, or to just use css and drop the placeholder concept for select-multiple.
