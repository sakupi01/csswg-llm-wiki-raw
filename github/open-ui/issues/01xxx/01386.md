This issue was lifted almost verbatim from [this comment](https://github.com/openui/open-ui/issues/1372#issuecomment-3929530624) by @smhigley:

We need to solve for the following two cases:

- If the overscroll area is modal (see [#1384](https://github.com/openui/open-ui/issues/1384)), so the original button isn't in the a11y tree. This would affect screen reader and voice control software. (Desktop screen reader users could potentially use escape, but not touch SR users or VC users)
- Whether or not it's not modal, if the scroll causes the orignal button to be outside the visible area. This would not affect screen readers, but would affect some switch users, voice control users, and some people not using any AT but with mobility disabilities that affect their ability to scroll.
