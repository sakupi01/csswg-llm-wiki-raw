## Problem
Every `<rangegroup>` example hides its labels with a `visually-hidden` class, then needs extra CSS to un-hide them in browsers without `<rangegroup>`. Without the class, the Chromium prototype renders labels as plain text under the track, and the collapsed inputs leave gaps.
The markup itself is right: `<label>Minimum <input type="range"></label>` names the thumb and falls back correctly. Only the visual default is might be something to concider.

## Proposal
- The `<legend>` stays visible, like in `<fieldset>`. If authors would wrap `<rangegroup>` in a `<fieldset>` you could create a form of progressive enhancement
- Each `<label>` is visible by default, as a caption centered under its own thumb, and moves with it.
- The thumb is the label's **implicit anchor**, like an invoker is for a popover, so authors never write `anchor-name`:
```css
/* UA stylesheet sketch */
rangegroup > label {
  position: absolute;
  position-anchor: auto;
  position-area: block-end;
  position-try-fallbacks: flip-block;
}
```
- Collisions (track edges, close thumbs) are handled by `position-try` fallbacks rather than new features, overlapping might still happen.
- Hiding is plain CSS. A hidden label (even `display: none`) still names its thumb (if technical feasable, i know similar mechanics were used for `<selectecontent>` in select elements.

## Open questions
- `display: none` on a label also hides the fallback input in browsers without `<rangegroup>`. Is there a feature detection method that could help with this, or do we need a hook that only exists when the element is supported?
- Should other associated elements (e.g. `<output for>`) also get the thumb as their implicit anchor?
- Can a UA thumb pseudo-element act as an implicit anchor across the shadow boundary?
- Single-thumb groups: the caption repeats the legend. Hide it by default?

## @brechtDR — 2026-10-15

For easily continuing where we left off. Maybe an intro to upcoming telecon:
The main open question was whether UA defaults should ship an opinionated floating/tooltip layout pinned to each thumb (and if so, how collision/overlap between thumbs should be handled), or whether the default should remain a simpler in-flow readout that relies on CSS anchoring/pseudo-elements for author positioning.

We also touched on ensuring that visual labels remain cleanly synchronized with the accessibility tree's value announcements without imposing layout restrictions on authors.
