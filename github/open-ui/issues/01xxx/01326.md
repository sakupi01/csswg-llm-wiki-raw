When working on #1324, I noticed that lots of code examples had repetitive `command="show-menu"` attributes:

<img width="685" height="193" alt="Image" src="https://github.com/user-attachments/assets/516b46ba-74fc-434a-8027-9fdebdb971b0" />

It's annoying to have to write this, and it feels unnecessarily repetitive and verbose. In reality, when you're using a `<menuitem>` with a `commandfor` attribute, you're probably using it to open another sub-menu. And when you're not, you'll need to specify the command anyways. So can we just make `show-menu` the "default command" for these elements? You can manually set `command` when you want to override this, but otherwise you won't have to provide it to get the normal sub-menu-invoking behavior, which seems pretty sensible to me.

Thoughts?

## @lukewarlow — 2025-11-05

Would we want the default to be show-menu or toggle-menu is one question?

We did specifically decide against implicit commands for buttons. But I think this is a case where the context might be scoped enough that it's clear.

I worry that people will wonder why a button pointed at a menulist still needs an explicit command tho.

<!-- comment id=3791299571 author=dbaron created=2026-01-23T17:06:02Z url=https://github.com/openui/open-ui/issues/1326#issuecomment-3791299571 -->
## @dbaron — 2026-01-23

I think it should be `toggle-menu`.

I'm also considering the possibility that maybe only `toggle-menu` should establish what we consider a "submenu" relationship.  (`show-menu` and `hide-menu` could continue to exist, they just wouldn't be special for `<menuitem>` elements and thus wouldn't establish submenu relationships that are handled by keyboard navigation, builtin mouse/pointer behavior, UI that shows a marker, etc.... and would really be useful for buttons rather than for menuitems.)
