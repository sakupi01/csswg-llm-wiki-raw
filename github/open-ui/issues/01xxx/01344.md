## @alsanan — 2025-12-18

> Some others I'm less sure on, could you explain for example the focus command use case and how it would be used?

focus isn’t about calling .focus().
It’s about declaring where the user’s point of interaction should move next — for accessibility, guided flows, and keyboard-first UX — without imperative JavaScript.

Uses:
1. Forms: Take the user to the next field (allowing multi-step long forms with automatic scroll).
2. Search: return focus to the field when you are browsing results.
3. Skip to content.
4. Guided flows: onboarding wizards
5. Improving UX on touch screens : <button command="focus" commandfor="qty">Enter quantity</button> [...] <input id="qty" type="number">

In essence, we are giving more power to HTML over JS, so I think that the typical small uses of JS that can be declarative should be covered. In the same motivation, I've asked for emit(event) and load-content(url), even when I know that it's difficult to be accepted this way. 

You are right on the better way to address toggle-reduced-motion and toggle-dark-mode.

About toggle-hidden, please consider using toggle(attribute), so it would be command="toggle(hidden)" in this case. I think that  it can be used in more ways : hidden, open, popover, inert, disabled, contenteditable, readonly, required, spellcheck... or even customized-attributes for web components. I think the proposal is interest enough to consider because of its power.
