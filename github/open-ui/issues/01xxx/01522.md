## Context
Wavy and circular tracks work today without any engine-exposed position:
- **Wavy** (~10 lines of JS): copy `values` into custom properties; `offset-path` does the rest.
- **Circular** (~80 lines of JS): the same, plus a pointer adapter, because linear hit-testing is meaningless on a ring (angle math, a clamp at the seam, `setRangeValue()`).

[Wavy & circle example can be found here](https://brechtdr.github.io/enhanced-range-slider-poc/#wavy-track)

```js
group.addEventListener("input", () =>
  group.values.forEach((v, i) =>
    group.style.setProperty(`--thumb-${i + 1}-pos`, `${v}%`)));
```
```css
rangegroup::slider-thumb(*) {
  offset-path: path("…");
  offset-distance: var(--pos);
}
rangegroup::slider-thumb(1) { --pos: var(--thumb-1-pos); }
```
Keyboard, accessibility and form behavior stay native. The gaps are exposing the value to CSS, and hit-testing.

## Questions
1. Is "mirror values + your own pointer mapping" acceptable for v1, as a documented pattern?
2. Arrow keys follow the value, not the shape (Arrow Right moves counterclockwise on our ring on the first thumb). Fine?
