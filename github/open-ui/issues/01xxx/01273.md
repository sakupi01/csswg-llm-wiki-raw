I have some thoughts about how to move forward with combobox and some questions about the explainer: https://open-ui.org/components/combobox.explainer/

### New element

Due to feedback from Apple, I don't think that we should try to make a new `<combobox>` element:
- https://github.com/whatwg/html/issues/9799#issuecomment-1770254871
- https://github.com/whatwg/html/issues/11288#issuecomment-2857464795

Instead, I think that we could try to just reuse `<input type=text list=datalist>` and put base appearance on it (and its datalist), like we did with customizable select.

### filter attribute

Without the proposed filter attribute, are all the options in the datalist supposed to be rendered all the time? Why not just always let filtering happen without the need for another attribute?

### button and selectedcontent elements

The explainer has an example that has a button and selectedcontent element:

```html
<combobox>
  <input type="text"/>
  <button><selectedoption></selectedoption></button>
  <datalist>
    ...
```
I'm guessing that this is supposed to clone the DOM contents of the currently selected option into something inside the text input, in addition to the text that the user is actually typing? I think that the select element with some filtering upgrades could work better for this.

### filtering for select elements

[This HTML issue](https://github.com/whatwg/html/issues/11288) made me think more about how we could try to add a text filter to the select element in some way, which I think would accomplish a lot of use cases related to the combobox proposal. I posted more about that here: https://github.com/openui/open-ui/issues/847#issuecomment-2876984892

I think there could be some overlap with the proposed `search` attribute and how we could make filtering work for select elements like @lukewarlow mentioned here: https://github.com/openui/open-ui/issues/847#issuecomment-2877017007

## @josepharhar — 2025-10-14

Proposed resolutions:
1. Use input and datalist elements instead of creating a new combobox element.
2. Replace the filter attribute with a "manual" value for the search attribute which can disable automatic filtering.

I'd also like to better understand the button and selectedcontent elements usage in the combobox explainer, perhaps that can be in a separate issue.
