```html
<button commandfor=menulist command=toggle-menu>command=toggle-menu</button>
<menubar>
  <menuitem commandfor=menulist command=toggle-menu>command=toggle-menu</menuitem>
</menubar>

<menulist id="menulist">
  <menuitem>menuitem 1</menuitem>
  <menuitem>menuitem 2</menuitem>
  <menuitem>menuitem 3</menuitem>
  <menuitem>menuitem 4</menuitem>
  <menuitem>menuitem 5</menuitem>
</menulist>
```
https://davidsgrogan.github.io/menu-keyboard.html (Try on Chrome Dev/Canary with experimental-web-platform-features enabled)

When activating the `menulist` via the keyboard (focus then &lt;ENTER> or &lt;SPACE>), should focus move into the submenu so that you can use the up/down arrow keys to focus the `menuitem`s? Or should moving focus into the submenu require an extra &lt;TAB> keypress?

Should the answers be the same no matter if the source of the activation is the `button` vs the `menuitem`?

/cc @josepharhar

## @css-meeting-bot — 2026-04-30

The Open UI Community Group just discussed `[menu] moving keyboard focus into submenus`, and agreed to the following:

* `RESOLVED: when activating a menuitem or button which opens a submenu with with space or enter or arrow down or arrow right, focus should move to the first focusable menuitem in the submenu. with arrow up, focus moves to the last menuitem in the submenu`

## @tom-sherman — 2026-05-13

I'd recommend reading https://github.com/w3c/aria-practices/issues/2206 which is a very similar discussion to this one, relating specifically to the UX for mouse/pointer users.

From a subjective UX POV and also my interpretation of the ARIA consensus in that discussion it seems perfectly valid to _not_ focus the first menu item when the menu is opened with a mouse/pointer.
