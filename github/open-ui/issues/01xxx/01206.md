Currently, the Popover API doesn't allow for a way to cancel a popover closing event, so it can lead to issues if the user has an unsaved state inside the popover. This pen demonstrates this:

https://codepen.io/thdoan/pen/jEELBXm

It would be nice to have a cancelable `cancel` event similar to standard dialogs.

## @thdoan — 2025-04-29

@scottaohara a growing number of CSS frameworks are using the Popover API for dialogs ([example](https://github.com/beercss/beercss/blob/main/docs/DIALOG.md)). One can argue that a dialog is a type of popover, or that a popover is simply a non-modal dialog; in either case, the distinction is nuanced enough that IMHO it's a positive developer experience to have a more consistent events interface for both dialogs and popovers, and leave it up to the UX designer to determine whether they should preserve dirty state in forms using a modal vs. non-modal component.
