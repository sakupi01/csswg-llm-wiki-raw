The enhanced range explainer recommends a first `<legend>`, wrapped `<label><input type="range"></label>` handles, and author-created `<output>` elements, but it does not define the `<rangegroup>` content model or what happens to unrelated descendants.

Examples:

```html
<rangegroup>
  <legend>Budget</legend>
  <p id="help">Choose a minimum and maximum.</p> <!-- is this allowed? -->
  <iframe src="help.html"></iframe> <!-- is this allowed? -->
  <input type="number" name="exact-budget"> <!-- is this allowed? -->
  <label>Minimum <input type="range" name="minimum"></label>
  <label>Maximum <input type="range" name="maximum"></label>
</rangegroup>
```

### Options to consider

1. Allow an optional first `<legend>` followed by flow content. This would support labels, descriptions, outputs, layout wrappers, and custom elements. It may be too permissive because unrelated interactive descendants would become valid content even though they have no role in the shared track.
2. Permit only a legend, participating range inputs, their labels, and a defined set of supporting elements (wrappers, custom elements).
3. Allow general wrappers while constraining the content that supplies handles (only `<input type=range>` I assume).

### Questions to resolve

- Are nested rangegroups conforming?
- Should the conforming content model be flow content, or a narrower subset?
- If narrower, which wrappers and supporting elements are allowed?
- Should non-participant content be rendered before/after the shared track in a default UA layout?
