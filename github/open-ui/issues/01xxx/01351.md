While the new base appearance listboxes are massively better than the old ones (can be tested in Chrome canary via https://demo.lukewarlow.dev/css-forms.html) we do lose some (mainly one) keyboard functionality that does feel like a downgrade.

1. Ablity to check all options:

With auto appearance listboxes we can ctrl+a when the listbox is focused and that will select all options (not sure if it's all or just all visible ones this would need testing). With the new model we'd have to manually select them all. I know checkedness doesn't follow selection now but some way to select all would be nice, be that ctrl+a or ctrl+a + space to actually toggle.

The latter feels slightly better because then you can use this to uncheck all too.

----

2. Ability to submit form from the listbox:

We also lose the ability to submit a form while the listbox is focused, previously pressing enter would trigger submit but now it just toggles the currently focused option. (This is a less important loss but it's worth noting)

## @lukewarlow — 2026-01-06

>What do you think about the shift+arrow behavior there?

As an immediate reaction, It's slightly odd that if I shift + down from Aardvark it selects everything below but not aardvark, It's also slightly confusing with non-continguous selections. Perhaps this or a variant of this would be nice to have though, to keep some of the existing keyboard behaviours without the most annoying selection follows focus one?

Then again shift + arrow on auto multi listboxes while they do behave as I would expect for shift + down from aardvark, also have wonky behaviour for non contiguous lists (inconsistent between firefox and chromium even), so that's not a perfect model to follow either.

Some form of shift select allowing multiple to be selected (Even if then requiring space to toggle the values) seems reasonable alongside ctrl+a.

I agree enter to submit a form is probably fine to lose. Just was a difference I noticed so thought I'd mention.
