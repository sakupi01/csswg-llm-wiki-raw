Based on this explainer: https://open-ui.org/components/enhanced-range-input.explainer/ 

I can't help but thinking that a progressive enhancement idea is going to be tough. I'd love to get some input on this by people with more experience in this field. For me it feels as something polyfillable though.

<!-- comment id=2776459257 author=myakura created=2025-04-03T17:17:42Z url=https://github.com/openui/open-ui/issues/1186#issuecomment-2776459257 -->
## @myakura — 2025-04-03

The tricky part is that `<input type="range">` is used _to pick a single value_ constrained by the `min`, `max` and `step` attributes, whereas the newly proposed input is meant _to return a range_ defined by those same attributes. While it’s possible to reuse the `min`, `max`, and `step` attributes, I wonder whether extending the "range" keyword to describe this new input type is the best idea.
