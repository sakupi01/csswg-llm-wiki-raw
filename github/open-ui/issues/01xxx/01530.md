What should the full DOM structure for a `<rangegroup>` look like?
including shadow/light DOM, slotting, pseudo-elements.

This is the current markup from the [explainer](https://open-ui.org/components/enhanced-range-input.explainer):
```html
<rangegroup name="price-range" min="0" max="1000">
    <legend>Price Range</legend>
    <label>
        Minimum Price
        <input type="range" name="price-min" min="0" max="500" value="250" step="10" />
    </label>
    <label>
        Maximum Price
        <input type="range" name="price-max" min="500" max="1000" value="750" step="10" />
    </label>
</rangegroup>
```

For reference the current css-forms-1 `<input type="range">` structure is:
```
<input type="range">
├─ ::slider-track
│  ├─ ::slider-fill-under/::slider-fill (alias)
│  └─ ::slider-fill-over
└─ ::slider-thumb
```
https://github.com/w3c/csswg-drafts/issues/11330
> RESOLVED: The originating element of ::slider-fill is the input element, not the ::slider-track.
RESOLVED: The slider-fill is a child of the slider-track in the pseudo-element tree

https://github.com/w3c/csswg-drafts/issues/12419
> RESOLVED: two pseudos called slider-fill-over and slider-fill-under
RESOLVED: keep slider fill as an alias for slider fill under

## @sb3nder — 2026-10-07

> yes. and rangegroup is the parent

Assuming the thumbs are siblings of the track, we need a common parent that is not `<rangegroup>`, to position them.
Otherwise the width of `<legend>` is also counted.
I guess that common parent would be `::slider-track` or a new pseudo.

Another question is: do we want to allow the author to place the `<legend>` after the slider?
If yes we need a simple logic to determine the order, **for example**:
`if <legend> is positioned after all the <input>, slot <legend> last`,
or `if <legend> is positioned after the first <input>, slot <legend> last`.

> currently not. do you see a benefit in this? examples?

Not at the moment, I was asking just to know.
