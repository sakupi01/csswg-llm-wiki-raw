Currently, textareas can't be used with datalist and it was raised during the call that actually this seems like a valid pattern. It was also raised that there's a lot of possible complexity depending on how many use cases we wanted to solve (GitHub rich textareas have lots of datalist esque UIs that can be anchored to the caret and codnitional based on entered text).

Raising this issue so it doesn't get lost.

## @sanketbhuite — 2026-04-10

This seems like a very useful pattern, especially for multi-line authoring experiences such as comments, markdown editors, and chat inputs.

Many modern UIs already implement textarea-based suggestions:

* @mentions
* #tags
* emoji autocomplete
* slash commands (/command)
* AI prompt helpers
Currently this requires custom JS logic for caret position, filtering, and popup rendering. Allowing `<textarea>` to work with `<datalist>` (or a combobox-like primitive) would standardize a very common pattern.

One concern is anchoring — unlike `<input>`, suggestions may need to appear at the caret position instead of the textarea edge. So the model may need:

* caret-anchored popup positioning
* conditional triggering based on prefix (@, #, /, :)
* multi-token support inside same textarea

Even a minimal version (same behavior as input + datalist) would still be useful and progressively enhanceable.
