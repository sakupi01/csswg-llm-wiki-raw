The current behavior requires JS otherwise radio buttons don't work correctly, for example in this demo: https://microsoftedge.github.io/Demos/focusgroup/radiogroup.html

It's unfortunate that a declarative mechanism would require script to work properly. Is there a reason that radio doesn't have the native behavior built in if that's always the correct behavior?

## @lukewarlow — 2026-11-01

focusgroup isn't designed to fully implement all of the associated patterns. It's designed to specifically handle the collapsing into a single tab stop and adding arrow key navigation within the group.

For a radiogroup you often (though not always) do want selection to follow focus and that is something you currently require JS to achieve. The same way you probably also need JS to implement activation behaviour etc.

For radios inside of a toolbar for example you *don't* want selection to follow focus.
