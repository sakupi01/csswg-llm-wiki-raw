currently i don't believe it's possible to have a button that opens a modal smaller viewports and a popover on larger viewports without having 2 seperate buttons and show/hiding them at the desired breakpoints.

my example use case would be for an `<input type=date>`esque component that has an input with a calendar button next to it which opens a date picker dialog. on smaller viewports it would open the dialog as a modal and on larger viewports it would open the dialog as an anchored popover.

with the work around using 2 seperate buttons shown and hidden based on viewport size, i could see an edge case where the user, to get a better view, has changed their viewport size by say zooming in, after opening the date picker and thus it is in "popover mode" while the button has switched to "modal mode" so it is unable to close the popover (_if it were a manual popover_) and it's anchor positioning would break (_tho that could be fixed with css ofc_).

## @EllyLoel — 2026-03-05

it could potentially use a syntax similar to the [sizes attribute](https://html.spec.whatwg.org/multipage/images.html#sizes-attribute), something like this maybe:
```css-formal-syntax
<command-list> = <command>#? , <command-keyword>
<command> = <media-condition> <command-keyword>
<command-keyword> =
  toggle-popover            |
  show-popover              |
  hide-popover              |
  close                     |
  request-close             |
  show-modal                |
  <custom-command-keyword>
<custom-command-keyword> = <dashed-ident>
```
in practice the example would look something like this:
```html
<button
  type=button
  command="(width < 576px) show-modal, toggle-popover"
  commandfor=date-picker>
  Calendar
</button>
<dialog id=date-picker>...</dialog>
```
