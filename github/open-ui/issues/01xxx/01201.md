In the case of menubars the default will be horizontal but it's possible people will want vertical ones. This orientation attribute should control which arrow keys are used for navigation as well as setting the aria-orientation value. It should probably also apply some default styles to actually make the menubar render vertical.

MDN suggests you'd also want this for menulist with a default of vertical, I'm not sure if this is actually useful for menulist and what the rendering would look like but for the sake of completeness it seems reasonable to support both.

## @lukewarlow — 2025-05-08

Rough Proposal

A new orientation attribute and associated IDL reflector. Where supported this should set `aria-orientation`, it should also impact the arrow key navigation behaviour, aswell as updating the default UA styles (I suspect anyway). 

Per aria spec aria-orientation applies to a subset of aria roles:

- `slider` aka `<input type="range">`
- `listbox` aka `<select>` (sometimes whole element, sometimes a subpart), and also `<datalist>` (I think?)
- `toolbar` (nothing in HTML yet)
- `menubar` (nothing in HTML yet ;) )
- `tree` (nothing in HTML yet)
- `scrollbar` (going to ignore this)
- `menu` (nothing in HTML yet ;) )
- `tablist` (nothing in HTML yet)
- `separator` (hr maybe?)

This would exist on a subset of HTML elements:

- `<select>`: Applies to the listbox aspect of the select control, defaults to vertical.
- `<menubar>`: Applies to the new menubar proposed here, defaults to horizontal.
- `<menulist>`: Applies to the new menulist proposed here, defaults to vertical.
- `<datalist>`: Applies to listbox aspect, defaults to vertical.
- `<input>`: Applies to the range input type?
- `<hr>`: Maybe?

Potentially also to some form of `<radiogroup>` element, or potentially to `<fieldset>` if we gave it some special behaviour for radigroups?

## @lukewarlow — 2026-01-08

Based on the discussion today here's another discussion about slider-orientation as a CSS concept: https://github.com/w3c/csswg-drafts/issues/9832

Here's another issue Mason raised about that: https://github.com/w3c/csswg-drafts/issues/11891

I'm not saying our resolution here is wrong (I in part advocated for this). I just think we need to be careful about introducing it and ensuring we cover all bases, rather than it maybe getting lost in wider menu element discussions.

The main tension with CSS changing the layout (something that could be common on mobile depending on the exact element in question) and thus breaking keyboard navigation or aria-orientation value is my main concern here. Also there's many different ways to make something visually vertical, what is the correct styles to apply.

I think that orientation is perhaps a topic for the joint taskforce meetings all by itself, though I do think aria should be part of those discussions too (they're potentially rather unfortunately not a default part of the joint meeting)
