## @aardrian — 2020-08-28

I cannot figure out where to edit the inline CSS, and I am not a Gatsby/etc. user, but if you want a stop-gap fix sans a PR, here is a suggestion...

For this wrapper div:
```
<div style="display:flex;padding:0 1rem;margin:0 auto;max-width:1200px;">
```

Add `flex-wrap:wrap`:
```
<div style="display:flex;padding:0 1rem;margin:0 auto;max-width:1200px;flex-wrap: wrap;">
```

For its child nav:
```
<nav style="margin-right:2em;">
```

Add `flex: 1 1 15em` (or whatever you want its default width to be, which you may want in pixels given you are using pixels on the `max-width`):
```
<nav style="margin-right:2em;flex: 1 1 15em;">
```

For the wrapper's child div / sibling to the nav:
```
<div style="flex:1;">
```

Give it the ability to shrink and grow and give it a maximum width:
```
<div style="flex: 1 1 auto;max-width: calc(100vw - 2em);">
```

And the thing that keeps it from wanting to shrink appears to be the code blocks:
```
<pre class="prism-code language-" style="color:#9CDCFE;background-color:#1E1E1E;padding:0.25rem 0.5rem">
```

So make them overflow and set a maximum width:
```
pre.prism-code {
    overflow: auto;
    max-width: calc(100% - 1em);
}
```

And because those code blocks need to support a keyboard-only user to scroll, they will need a `tabindex`, which necessitates and region and accName so a screen reader user understands what this tab-stop is:
```
<pre class="prism-code language-" style="[...]" tabindex="0" role="region" aria-label="Code block">
```

This is tough because the CSS is inline, which means I cannot quickly debug on mobile. So yeah, it's a hack and you should never attribute it to me, but it can at least make it usable on mobile right now.
