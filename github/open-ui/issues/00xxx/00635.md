I wonder how would one aproach stacked top layer approach when we have for example modal and toasts.

Let’s say toast are supposed to be topmost, 
and even modals should not cover them. 

In stacked approach this is not possible to achieve as let’s say we have
1. Toasts wrapper that is on top layer wchich holds all toasts. And then we have 
-toasts wrapper
-modal 
And now modal wants to show toasts and it end up being under it.
Solution (trick) hide and show again toasts layer to move it to top again - but that would introduce flicker , animation states problems etc.
2. Toasts shown individually then again we can and up with Toasts and modals one over another like
-toast
-modal
-toast
3. keeping toasts away from top layer but then again modal over them always.

so maybe instead it would be good to introduce something like top-layer-priority property that would hint on wchich level popover/modal (are modals popovers as well - is there a term that would incorporate all top-layer elements) should appear, and if two elements would have the same priority then stack order would apply. If a new popover would appear from within such element with such priority set it should be possible to inherit this priority or igonre it puting it on top most layer.

Then we can do something like this:
-toast wrapper popover (priority: 1)
-modal (priority : 2)
-hint popover - now we can decide if it should appear over toast or not as well.


There is also second problem with inert attribute when opening modals as modals. Again I would like to leave toasts active when modal is open but there is no way to prevent it - maybe something like preventinert attribute would be possible to achive - possible only applicable to popovers and other top layer elements and only if it’s priority would be higher than current inert applying modal - or maybe all such elements should be spared from jnert behaviour.

## @mfreed7 — 2022-12-14

Sorry for the delay - I hadn't noticed this issue in the tracker. I've labeled it with popover so I keep track of it.

My general belief is that this line of reasoning starts a z-index arms race again, which inevitably leads to the need for a new "even higher top layer" that is over the top of the rest.

Instead, the design of the popover feature was such that it uses the existing mechanics of the [top layer](https://fullscreen.spec.whatwg.org/#top-layer), full stop. That does mean that the latest popover is topmost, and that can mean that a modal `<dialog>` can be shown on top of a `popover=manual` toast. However, in most typical use cases, that's the right thing for the developer/user: the latest thing to show up is shown top-most. It's generally always odd when a new thing shows up (e.g. a modal dialog) and it's displayed partially obscured underneath something that was already there (e.g. an existing toast).

Other thoughts? I'll add this to the agenda to discuss next year.

b) on save and copy you will show "toast with successful creation information and link" but you will keep the dialog open
