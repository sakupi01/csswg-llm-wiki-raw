https://open-ui.org/components/select#structure bans a set of interactive elements from existing under `<select>`.  We should define more precisely how this is enforced and what it looks like when this rule is broken.  Parser rules can prevent these elements from being placed under `<select>` at parse time, but they can still be injected there dynamically.  So we have to handle this case.

There are a number of things we could do here:
1. Refuse to slot the banned content into the `<select>`'s shadow DOM.  It's not clear how this would be specified, especially given that banned elements could be present in the subtree of a slotted node even if the root of the slotted content was not a banned element.
1. Refuse to render the control if a banned element has been slotted anywhere into the control.
1. Refuse to render any banned content slotted into the control (treat it as `display:none`?), but allow everything else to work.
1. Show the banned elements but don't allow clicks/user interaction.
1. Other approaches?

Thanks to @mfreed7 for originally raising this question.

> > Refuse to render any banned content slotted into the control (treat it as display:none?), but allow everything else to work.

For option (3) I mean that an `<iframe>`, `<input>` etc would be slotted into the `<select>`'s shadow and be reachable through the DOM in the normal ways, but always forced to be `display:none`.  The other content would not be affected (except by having the `dispay:none` element in the tree order).  It feels like some `display:none` interactive elements could still cause problems somehow but I don't have an example at hand.

Thanks for raising this issue. I think either option 2 or 3 might be the best. As you pointed out, just disallowing this in the parser isn’t enough, since you can modify the DOM imperatively and we need to guard against that also. It seems like the display:none solution would likely be the most straightforward, but I agree that it feels like there might be a few corner cases left to outlaw here. I also don’t have any specific examples.

Not rendering the disallowed elements is a bit confusing, but it is also pretty close to what happens today when almost anything is nested inside a `<select>`. So I’m not sure it would be so confusing in practice.
