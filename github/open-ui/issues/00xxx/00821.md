In the new architecture, we are using `<button type=selectlist>` to open the listbox. What happens if you have multiple of them, like this?
```html
<selectlist>
  <button type=selectlist>button one</button>
  <button type=selectlist>button two</button>
  <listbox>
    <option>one</option>
    <option>two</option>
  </listbox>
</selectlist>
```
In the old architecture, I believe that specifying `behavior=button` on multiple buttons would only make one of them get behavior.
This doesn't have to be a use case that actually makes any sense, but we have to implement it one way or the other. I am implementing the prototype of the new architecture in chromium, and I went with all `type=selectlist` buttons getting the behavior because it was easier to implement.

Another question that came up during my implementation is whether we need `type=selectlist` at all. What if all `<button>` descendants of the `<selectlist>` open the listbox automatically?
The reason I chose to create `type=selectlist` was to make it easy to have multiple buttons in a [split button](https://web.dev/building-a-split-button-component/) selectlist, but you could also create a split button if you add some script which calls preventDefault on one of the button's click events. This does require more script though, but maybe you'd want to add a click event listener to one of the buttons anyway...?

This is related to https://github.com/openui/open-ui/issues/809

## @mfreed7 — 2023-08-29

I really like the two ideas presented:
- All `<button>`'s within `<selectlist>` (and outside of `<option>` or `<optgroup>`) get the behavior added: they all open the popover with the listbox.
- If you want to build a split button, you'll need to add code to `preventDefault` for the action button. That can look like:

```html
<selectlist>

  <button onclick=preventdefault()>Run the action</button>
  <button>Pick your action (this triggers the listbox popover)</button>

  <option>one</option>
  <option>two</option>

</selectlist>
```

So yes there's code involved, but it can be inline in the HTML, so perhaps not terrible? The upside of this approach is:
1. No need for `<button type=selectlist>` or `<selectlistbutton>`.
2. Perhaps more interesting use cases with multiple buttons that trigger the listbox.
