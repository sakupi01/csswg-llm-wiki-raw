RE: #180 

I'd like to discuss about naming conventions for these elements. Take file as an example:

- current HTML: `<input type="file">`
- open-UI proposal: `<file>`

Another option would be `<file-input>` or `<input-file>` as a naming convention. These feel more clear to me and nod to the underlying web components (which we hope to become native). You can also replace "file" with anything and you still have a naming pattern, i.e.:

- `<input-color>`
- `<input-date>`
- `<input-dropdown>`

etc.

## @chrisdholt — 2020-10-19

I think there's a couple of considerations here to be made.

As some of these may not end up in the platform (or it may take awhile), how do we refer to the control - what do we call it?  As other libraries are creating this and looking to align on naming, anatomy, parts, do we have a common way to refer to this control?. For those seeking alignment with open-ui and for whatever elements are proposed here I'd assume that name is part of it.

If this is going into the platform, I think we would need to go without prefixing. Thus I'd expect a proposed name of `file`. If we are speaking to an element which would live within this repo, then I think `wicg-file` or `oui-file` would be acceptable. For custom element names looking to align to Open UI, I'd suggest leaving the prefix open as most implementors will already be prefixing their controls for their library.

Given the different contexts to consider around naming, perhaps something like the following:

**Control name**: File
**Proposed platform name**: `<file/>`
**Proposed element**: `<____-file>`

Resolved in 01/07/2021 Open UI telcon meeting: 

> Use `openui-` naming for prototyping and web components, and the file name after the prefix alone for native implementation of the components.

i.e. `<openui-superselect>` and `<superselect>`
