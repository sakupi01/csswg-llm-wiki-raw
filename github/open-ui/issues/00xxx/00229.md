## @dandclark — 2020-12-04

This was discussed during today's Telecon: https://www.w3.org/2020/12/03-openui-minutes.html#resolution01.
There was agreement that this is a capability worth supporting.  However rather than introducing an additional property, we resolved that the existing [open state](https://open-ui.org/components/select#open-state) should be exposed as a JS property and reflected HTML content attribute.  In addition to toggling the `<select>` open/closed programmatically, these can be used to achieve the `startOpen` behavior by e.g. writing the initial HTML like this:

```html
<select open>
  <option>Thing 1</option>
  <option>Thing 2</option>
</select>
```

See: https://github.com/WICG/open-ui/pull/236
