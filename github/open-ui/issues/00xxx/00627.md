In the WHATWG [issue](https://github.com/whatwg/html/issues/7785), the are some valid concerns raised by @domenic and @annevk around cosistency in naming due to the web platform already having a paradigm that uses the term popup but it means to open a new window. @domenic outlines the potential dev confusion clearly here:

> So indeed, it seems unfortunate if, e.g., sandbox without allow-popups set, still allows popup="" attributes in the sandboxed iframe, due to the fact that popup="" is reusing the term "pop(-)up" for something different than what it's meant in web APIs so far.

So the question to the Open UI CG is whether we want to change the name, if so, to what? I'll readily admit that I'm torn on this as so many component libraries and design systems use this terminology so I don't think that we're necessarily incorrect in the current name, but the potential confusion outline by @domenic and @annevk are valid and should be weighed accordingly.

## @mfreed7 — 2022-10-21

Thanks @gregwhitworth for opening this issue. It's unfortunate that at such a late stage, and more than a year after we had our original brainstorming on a name, we need to do it again.

Here's the list of alternative names we brainstormed in the past (from https://github.com/MicrosoftEdge/MSEdgeExplainers/issues/438 and https://github.com/openui/open-ui/issues/296):

- float
- floatable
- popover
- positioned
- overlay
- popout
- popper

My personal favorite is `popover`. It's close to `popup`, it still indicates what "happens" when a pop-up/popover/whatever opens, and it'll be semi-easily found for developers looking for a "pop-up" because it starts with "pop".

Thoughts? I'd like to get this resolved ASAP, as it'll break just about everything (pop-up prototype, selectmenu prototype, blog posts, examples, origin trial code, etc.).
