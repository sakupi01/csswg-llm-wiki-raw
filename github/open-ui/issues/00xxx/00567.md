Following the resolution to [incubate a solution to semantic measurements](https://github.com/openui/open-ui/issues/499#issuecomment-1084962904).

If such a solution is found (whether through the `<data>` element or a new one) a proper API to convert its client-side visible value will be necessary.

Some possible options I could think of:

1. wait for the creation of an `Intl` constructor such as `.ConvertUnit()` or `.ConvertMeasurement()` that takes an object and can convert its data
2. think of a `HTMLMediaElement`-like interface that works with the HTML element, probably something like `HTMLMeasureElement`, where user agents will be able to provide an interface for the users

I wanted to hear the opinions of the community on the best approach for this issue - option 1, 2, both, or something else?

## @bkardell — 2022-07-14

I think advocating for and participating in efforts in Intl/Temporal kinds of spaces are the best path here.  This is such a hard set of problems and getting everyone to agree to the mechanisms runtimes need and commitment to do them is going to be hard to get done and prioritized once - two efforts that wind up with very different answers is probably not something with great odds of success or ultimate developer satisfaction either.  I'm not suggesting it need literally _use_ the JS APIs, but the same work will be necessary to empower both and they should agree on use cases/needs etc... So, to be clear - at a certain point you could probably parallelize, but I don't think that we're ready for that myself.
