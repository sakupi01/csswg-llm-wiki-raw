This has been discussed in https://github.com/openui/open-ui/issues/311, particularly around [this comment](https://github.com/openui/open-ui/issues/311#issuecomment-820655960). Given the [new approach for popup](https://github.com/openui/open-ui/issues/455), and the associated [resolutions](https://github.com/openui/open-ui/issues/311#issuecomment-1050192589) not to have a "live" `open` content attribute, we need to revisit this issue. The questions:

 1. Should there be a CSS pseudo class that indicates when the popup is "open"?
 2. What should "open" mean here - in the top layer? Visible at all?
 3. What should the pseudo-class be called?
 4. Should this pseudo class apply to other top layer elements, like modal `<dialog>` and fullscreen elements?

-----

**In my view:**
  1. We **should** have a CSS pseudo class, to allow developers to style "open" vs. "closed" popups differently, and allow animations between these states. Note https://github.com/mfreed7/popup/issues/3, which is relevant here, since I believe a conclusion we're coming to is that both states (open and closed) should be developer-stylable. The only difference really being whether the popup is in the top layer.
 2. Given the above, I think the pseudo class should simply indicate **top layer status**. Visibility is controlled by the developer, so this pseudo class shouldn't be concerned with visibility. It should just indicate whether the given element is in the top layer.
 3. And given that, I think the new class should be called `:toplayer` or something similar, rather than `:open` which can be confusing for a popup that is "closed" but "visible" in the page.
 4. For consistency, I think we should push for this pseudo class to apply to any element that currently resides in the top layer, no matter how it got there. So include modal `<dialog>` and fullscreen elements.

Thoughts appreciated.

## @mfreed7 — 2022-04-14

So the resolution above checks one of the questions off the list: the pseudo class can only apply when the popup is in the top layer, and **cannot be related to actual visibility**. Good. That leaves two open questions from the prior list, plus another nuance was added to the last point. So here's the current set of open questions to discuss:

- What should the pseudo-class be called? (This heavily depends on the answers to the questions below.)
- Should this pseudo class apply to other **top layer** elements, like modal `<dialog>`, the `::backdrop` pseudo element, fullscreen elements, shared element transition pseudos, etc.? If so, a name like `:top-layer` would seem to make sense.
- **Or** should this pseudo class apply to other **open things**, like modal `<dialog>`, open `<summary>`/`<details>`, (maybe?) fullscreen elements, etc.? (The difference here is that maybe `::backdrop` isn't "open", and `<summary>`/`<details>` has been added.) If so, a name like `:open` would seem to make sense.

So essentially, the open question becomes: "top layer" or "open"? Remember, in both cases, the pseudo class cannot be related to **actual visibility**, but only to the UA's concept of either being in the top layer, or being "open".

## @mfreed7 — 2022-04-18

Looks like the CSSWG is [moving towards resolving](https://github.com/w3c/csswg-drafts/issues/6965#issuecomment-1101792245) that each top layer "concept" needs its own pseudo class. I.e. no "general purpose" name for a pseudo class that means "any element in the top layer".

Assuming that resolution happens as expected, that effectively resolves the last two bullet points in my comment above, and **this** issue becomes a bikeshed on just the name we should use for when a **popup** is in the top layer.

I propose `:popup-open`. Another choice is just `:open` but I fear it'd be confusing that it only applies (for now) to popups.

Other ideas?

## @mfreed7 — 2022-04-29

So per the resolution, we've decided to pick a generic (non-popup-specific) name that means "this element is in the top layer" (exactly as [defined right here](https://fullscreen.spec.whatwg.org/#top-layer)). One thing to remember about that definition: there can be multiple elements in the top layer, meaning that an element in the top layer isn't guaranteed to be "on top" of everything. Just guaranteed to be "on top" of everything that **isn't** in the top layer. Another thing to remember is that because this pseudo class will apply to anything in the top layer, it should match modal `<dialog>`s, fullscreen elements, and even `::backdrop` pseudo elements.

**Suggestions welcome!** The ones I've heard so far:
- `:top-layer`
- `:overlay`
- `:topmost` (or `:top-most`?)
- `:popup` (this would define anything in the top layer to be a "popup", which might be confusing)
