With [this](https://open-ui.org/components/selectlist/#slotting-your-own-content) and [this example](https://open-ui.org/components/selectlist/#extending-the-markup), in the explainer, they both have an authoring error. That text inside the `span class="label"` should clearly be a `label` element instead.

Which makes me think:
Should `<label>`s without a `for` attribute as a child of `selectlist` act as a label for the button?

Or maybe to fix authoring errors like this, that the text content of `<selectlist>` could be used as an accessible name by default, even without it being a `<label>` element. - it also seems like this behaviour was assumed in these two examples

## @josepharhar — 2024-04-25

In the examples I can currently see in the explainer, all of the class=label text is inside buttons:
```html
  <button type=select>
    <span class="label">Choose a plant</span>
    <selectedoption></selectedoption>
  </button>
```
```html
  <button type=select>
    <span class="open">Open</span>
    <span class="label">Choose an option</span>
  </button>
```
Rather than adding new machinery for label elements, I think it would be better to either say that these examples are OK or provide some guidance that you should have this text in a label element which is outside the `<select>`.
