I believe it would be a great addition if we were able to detect the availibility of the refreshed control styles via [@supports](https://developer.mozilla.org/docs/Web/CSS/@supports).

This way CSS can be adapted to work for browsers that do or do not use/support the new styles, or at a point of time before broader support it would signal if the feature flag was enabled or not.

Otherwise making use of new styling rules may impact the look on older browsers or those who do not have the feature flag enabled.

# Problem and workaround
Let's take this meter element for example:
```html
<meter value="50" max="100"></meter>
```
![image](https://user-images.githubusercontent.com/5056880/79053607-fa74da00-7c3e-11ea-8a36-b99f7efcbb9f.png)

Right now I would need this piece of CSS to make it red:

```css
meter::-webkit-meter-optimum-value {
    background: red;
}
```

It would then be red, but lose the gradient on the colored section:
![image](https://user-images.githubusercontent.com/5056880/79053632-21331080-7c3f-11ea-93c5-08e6f693c698.png)

Now for additional styling, I might have to add an HTML container to apply more styles like a `::before` block that covers the meter or something just to make it look right.

```html
<div class="meter-styler">
    <meter value="50" max="100"></meter>
</div>
```
```css
.meter-styler {
    position: relative;
    display: inline-block;

.meter-styler meter::-webkit-meter-optimum-value {
    background: red;
}
.meter-styler::after {
    content: '';

    top: 0;
```

# A possible solution
Since styling of the control elements might be easier after the refresher, I would not have to do additional stuff like overlaying elements or applying filters etc.

For this case one could use something like a simple `@media` block.

```html
<meter value="50" max="100"></meter>
```
```css
/* new */
@media (--webkit-uses-refreshed-2020-controls) {
    .meter-styler meter {
        color: red
    }
}

/* old */
@media not (--webkit-uses-refreshed-2020-controls) {
    .meter-styler {
        position: relative;
        display: inline-block;
    }
    .meter-styler meter::-webkit-meter-optimum-value {
        background: red;
    }
    .meter-styler::after {
        content: '';
        
        position: absolute;
        top: 0;
        left: 0;
        
        width: 50%;
        height: 100%;
        
        background: linear-gradient(to bottom, white, transparent 70%);
    }
}
```

## @gregwhitworth — 2020-04-17

Thanks @metaa - there's quite a bit there to unpack. A few things here, the goal of Open UI is to try and standardize the anatomy, behaviors and states of the controls/components. So specific to your meter example, the goal would be to make it so that there isn't the need for `-webkit` specific parts or `-moz` based parts. One aspect we're avoiding is the actual appearance of them and also we'll try, both here and in other WGs to try and avoid partial styling. The reason for this is because user agents often change these over time and you end up needing to go to a clean slate. Because you may want to solely change the color of the meter but we then add additional items to it that you weren't over-riding which may break your design. As such, we'll want to have a solution that resets the parts of the component to a base state, such as `appearance: none`. What this will enable is you to have interop across all browsers, frameworks, etc will have the same parts to allow you to style them exactly as you need even though in one implementation they may have gradients by default while another may not.

Hopefully that makes sense. While I don't think we're at a point to have the discussion you've brought up, I'm going to keep this open until we have a proposal for how we plan to address the issue you've brought up so that you can provide your feedback on it (I'm actively digging into <select> so hopefully will have a proposal for this in the near future).
