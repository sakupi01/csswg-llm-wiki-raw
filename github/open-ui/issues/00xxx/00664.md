The chromium prototype for selectmenu [uses option.innerText](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/html/forms/html_select_menu_element.cc;l=337;drc=b9006923e2e749c01c16f05fdef6ed4dda997091) to find a matching option when assigning to selectmenu.value.

This is odd because the regular select element [uses option.value](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/html/forms/html_select_element.cc;l=305;drc=f27e6ea87ecf211c8b8644813422a9e7f19cd1cc) and getting the selected value in a selectmenu [uses option.value](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/html/forms/html_select_menu_element.cc;l=315;drc=b9006923e2e749c01c16f05fdef6ed4dda997091).

The difference between these can be observed [like this](https://jsfiddle.net/jarhar/ch8o205u/):
```html
<select id=select>
  <option>hello world</option>
  <option value=valueattribute>innertext</option>
</select>
<selectmenu id=selectmenu>
  <option>hello world</option>
  <option value=valueattribute>innertext</option>
</selectmenu>
<script>
select.value = 'valueattribute'; // successfully changes the option
selectmenu.value = 'valueattribute'; // doesn't change the option!
selectmenu.value = 'innertext'; // successfully changes the option

select.value; // returns "valueattribute"
selectmenu.value; // returns "valueattribute"
</script>
```

For consistency, can we make selectmenu value assignment use option.value instead of option.innerText? Was there any reason that innerText was used in the first place? @dandclark

## @josepharhar — 2023-03-09

After discussing with @dandclark, it may have been initially implemented this way because there was an idea to support elements other than option elements, which would not have the option.value IDL since they are not option elements. As it stands we are only supporting option elements, so we should be able to do the same thing as the existing select element as I proposed.

There is some concern about the fact that option.value has [custom logic to collect text nodes](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/html/forms/html_option_element.cc;l=249-256;drc=e984b029c5093245073dddc9fa64bbd5af755e7b), but since that can be circumvented by setting the value attribute on the option I think this is fine.
