# Issue

The only way to display a label with an `optgroup` element is with the `label` attribute.

But this would not allow for very much customisability. Since no other HTML elements would be shown, if induced with the attribute.

Also that there is currently [no way to style an `optgroup`'s label](https://open-ui.org/components/selectlist/#styling-parts-of-the-control).

Both of these issues would cause authors to create their own custom groups, which is what `selectlist` is supposed to fix.

# Possible Solution

Add a `::group-label` pseudo-element selector that targets the group's label.

Allow a `label` element to be the first child of an `optgroup` element. This would allow for authors to include their own elements.

Use cases for the latter:
Would allow authors to include more semantic meaning in a group's name. For example, an `abbr` element.
Would allow for better styling. For example, `span` elements to style individual words.

## @scottaohara — 2023-08-30

it was previously resolved that `legend` would be used to label optgroups https://github.com/openui/open-ui/issues/558

originally it was suggested that `caption` could be that element, but `legend` ended up being a better choice due to the baggage of the `caption` element being expected as a child of a `table`.

`legend` is more consistent with how labeling/captioning a container of interactive elements work anyway (re: providing a 'label' / accessible name to a `fieldset`), as a `label` is currently only meant to provide a label for a single form control.
