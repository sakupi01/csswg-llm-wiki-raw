This issue comes from this comment: https://github.com/WICG/open-ui/pull/140#discussion_r468265146

A common convention for RTL languages is to reverse the label and button position - where the label is now first, and the button second.

Feature | Chrome | Firefox | Safari
-- | -- | -- | --
RTL reversed | ✔  | ✔  | ✔ 

The table below assesses the libraries and websites discussed in #114. Where libraries are marked as N/A, they didn't use the standard button-label layout.

Feature | [MOJ](https://moj-design-system.herokuapp.com/components/multi-file-upload) | GitHub | [Ant Design](https://ant.design/components/upload/) | [Carbon](https://www.carbondesignsystem.com/components/file-uploader/usage/) | [Evergreen](https://evergreen.segment.com/components/filepicker/) | [Materialise](https://materializecss.com/text-inputs.html) | [Bootstrap](https://getbootstrap.com/docs/4.0/components/forms/#form-controls)
-- | -- | -- | -- | -- | -- | -- | --
RTL reversed | ❌ | N/A | N/A | N/A | ✔  | ❌ | ❌

Based on this research, I propose that we move forward with the recommendation that when the label is positioned to the right of the button, this is reversed for RTL languages.
