Research pages are structured like: [Base Component] > Concepts > individual example components from various libraries.

The base component (page-level) can have a description, and the individual examples can have descriptions. AFAICT it is currently not possible in the research project infrastructure to express a description for the middle layer, e.g. a Concept. This might be useful for discussion, as anatomies or behaviors may change on a per-concept basis.

Should we add this capability? What would be the best way to extend the current project schemas?

## @melanierichards — 2020-09-30

The motivating use case behind this issue is the "Popup" research PR I'm putting together. "Popup" is the top-level research page, whereas "concepts" in this case would be things like button menus, teaching bubbles, toasts. I expect us to have a conversation on whether all these concepts are actually popups or deserve to be broken out into a completely separate paradigm, but it would be good to be able to say "here is what a teaching bubble is and what kind of behaviors are common to teaching bubbles as a subset of popups".

## @kant2002 — 2020-10-02

IMO this is important thing to consider. I have slightly different use-case for description of concepts. My experience with Bootstrap (but probably this can be extrapolated) is that there some concepts which orthogonal to all components.
Example usually sizes and states:
- Size: large, small
- States: Focused, disabled/enabled, readonly(?)

As developer and customer facing person, it is easier to teach other developers how to use design system if there some standard modifications to all components. Customer especially important, since they usually want to make something more prominent, or less visible, so they definitely use sizes a part of their vocabulary. 

Maybe all of that should belongs to some CSS modification to existing components, but why then these concepts listed separately?
