This issue comes from this comment: https://github.com/WICG/open-ui/pull/140#discussion_r468266133

When testing browser implementations, only Firefox had the container set as the drop target.

Feature | Chrome | Firefox | Safari
-- | -- | -- | --
Drag and drop | ✔  | ✔  | ✔ 
Drop target | Button | Input | Button

The table below assesses the libraries and websites discussed in #114 (where input refers to the containing element).

Feature | [MOJ](https://moj-design-system.herokuapp.com/components/multi-file-upload) | GitHub | [Ant Design](https://ant.design/components/upload/) | [Carbon](https://www.carbondesignsystem.com/components/file-uploader/usage/) | [Evergreen](https://evergreen.segment.com/components/filepicker/) | [Materialise](https://materializecss.com/text-inputs.html) | [Bootstrap](https://getbootstrap.com/docs/4.0/components/forms/#form-controls)
-- | -- | -- | -- | -- | -- | -- | --
Drag and drop | ✔  | ✔  | Optional | Optional | ✔  | ✔  | ❌
Drop target  | Input | Input | Input | Button | ❌ | Input | Input

Based on this research, I propose that we move forward with the recommendation that the drop target is set to the containing element.
