##### (not sure this meets popup criterion or it may have been addressed elsewhere. will transfer if need)

lately I've been facing more than a few issues regarding web components needing to popup an element to the document (e.g. **snackbar**, **select**, **dialog**, **textfield** triggering **date-picker** etc').

in such scenarios, these components act as services, proxying configuration to be reflected in the popup.
their order of appearance / position in the DOM is irrelevant to their [stacking context](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Positioning/Understanding_z_index/The_stacking_context) and commonly required to nest in specific html scopes. 

This causes issues with layout and containment and more...

a suggested solution can be having a common singleton element (typically placed at the end of the document to have high stacking value) that listens and receives requests from an event-based protocol. put that requires weaving a complete modular system together to cause a **popup** to be displayed.

not sure how well this scales as with integrated components, much can be changed in the document and there's no control over the styling and extra dynamic overlapping elements authors can introduce.
