I think it would make sense, as a recommendation, if we "reserved" a namespace for project-specific, private things.

But this would also be useful for Custom Elements, Custom Variables and HTML classes, events and so on.

Using the namespace "p" would look like this:

```css
--p-color:green
```
```html
<p-box>
```
```html
<div class="p-large">
```
```js
addEventListener('p-close')
```

If I understand it correctly, the "data attribute" is somehow designed like this.
https://html.spec.whatwg.org/multipage/dom.html#attr-data-*.

## Naming
"p" is my favorite namespace because it is small and can be associated with "project" and "private"

## Advantages
No one would use this namespace for their own framework.  
This would help when looking at foreign code to see what is project specific or framework dependent.  
You would have a defacto standard that does not need to be further discussed in a team. 

## Background
I got this idea because I am engaged in the topic of web-namespaces.
https://github.com/nuxodin/web-namespace-registry
