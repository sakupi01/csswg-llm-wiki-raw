The invokers proposal adds `toggle` and `toggleModal` actions, which aim to toggle the dialogs openness:

 - `toggleModal` should open the dialog as modal when closed.
 - `toggle` should open the dialog as _non modal_ when closed.

There's some questioning what it should do when it's open. The options are:

 1. `toggleModal` closes a dialog if it is open as modal, if it is open _non modal_ then it is a noop. Likewise, `toggle` closes an open _non modal_ dialog, and on a _modal_ is a noop.
 2. Both `toggleModal` and `toggle` will close a dialog regardless of whether it is _modal_ or not.

### Advantages of 1

It is clearer the intent for `toggleModal` and `toggle`; one always does the modal operation, and one always does the non-modal operation.

### Advantages of 2

As the default action for an invokertarget pointing to a `<dialog>` is `toggleModal`, it would mean that just having an invoker button with no action inside of a `<dialog>` is always going to do the right thing.
