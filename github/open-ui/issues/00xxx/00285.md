## @melanierichards — 2021-03-31

A couple weeks ago, a small group brainstormed some approaches to the information architecture (IA). We thought about various jobs to be done, and what structure of IA might be needed to meet those various JTBD. [The scratchpad document is here](https://docs.google.com/document/d/1Nao8Lvy7CoGn-yKrhueAIiJSB7R4tLycJ7GvUJV5Ml4/edit). Note, this doc is currently readonly. Members of that brainstorm, please comment here if I missed anything pertinent in this distillation or if any new ideas come to mind. :)

## Summary of the brainstorm

### Navigation

Distilling various ideas together, the IA ends up something like the following:

* Home
* Get Involved (was "Contribute")
* Work Items: high-level view of all the proposals / research we're working on
   * Sub-page / landing page for each work item
* About (sub-pages could instead be folded into the top-level "About" page)
  * Sub-page: Charter
  * Sub page: Participants
  * Sub page: FAQ

We weren't sure yet whether there should be a top-level nav item along the lines of "Component Library" or "Catalog". Here we are thinking about some way for an author to stop on the site and say, "ok, I don't really care about all the research and what stage a proposal is at for a given component. All I want to do here is consume the Open UI suite of Web Components in my project." We could elevate this to the top level, or one could get to the consumable WC from a work item's landing page. This could be deferred until it becomes more relevant, though?

### "Home" page contents

Clearly address:

* What is Open UI?
* Why is it important?
* What are we actually providing through this CG? What are our deliverables? What's in scope? (Wasn't clear to a participant that new components are in scope)
* How can someone get involved?
* What should I go and do next?
* How can I find the status on existing proposals?

### Get involved contents

* Elevate the status of basic mechanical information (joining the CG, the importance of the Discord, getting invites to meetings, the fact that we don't really use mailing lists the way other groups do)
* Add a design system
* Contribute to research
* Process/stages
* Information for UAs who want to implement some of the proposals we're generating, or influence their direction

### Work Items contents (index)

* Short description of the various different deliverables/stages we will generate for various work items
* Filterable dashboard of all the components/controls the group is looking into. Each work item row should have:
  * Title and link to landing page
  * Status label, e.g. “Platform proposal incubation”
  * Direct links to / indication of availability for:
     * Research
     * Initial proposal (explainer)
     * Open UI Web Component
     * Platform proposal(s) / draft specs

### Each work item's landing page

* Short description
* Status label for the "stage" the work item is at
* Direct links to / indication of availability for:
  * Research
  * Initial proposal (explainer)
  * Open UI Web Component
  * Link to labeled GH issues
  * Browser support, if it's a platform API/control (pull in Can I Use?)

@bkardell I don't think there's too much interdependency, to be honest. Mostly:

* Home page changes should probably come after we move pieces around, since we'd be deep-linking into various parts of the site.
* We'll want to figure out URL structure for work item landing pages in tandem with the creation of the Work Items index page. And then we'd either need to create/convert landing pages for all the work items before swapping over the navigation to that index, OR, perhaps easier, have fallback logic ("if no landing page, link in the Work Items dashboard for the individual work item falls back to the work item's main research page ").
