In the Open UI + CSSWG joint meeting during TPAC we agreed that there is indeed a spectrum of native control/component customization. We'd like to have a standardized definition of these buckets. Here are the initial buckets that @melanierichards and I proposed. I'd like to get feedback on this and ultimately land this as normative text (location TBD). 

<img width="2046" alt="Screen Shot 2020-10-20 at 3 34 34 PM" src="https://user-images.githubusercontent.com/865244/96651477-c6632b80-12e9-11eb-9dfb-08412296b17f.png" aria-hidden="true">

- **None:** Does not allow any style-ability or extensibility to the control or its parts
- **Hint:** Allows the author to provide a value that the UA applies to a component or control that aligns with the spirit of the property​
- **Limited:** A defined set of parts or attributes that provide customizability but have some form of limitations.
- **Fully Style-able:** Elements that allow developers to opt-in to a standardized ​anatomy, DOM structure, and base styles that user-agents apply their styles upon​.
- **Fully Extensible:** Standardization of a control's anatomy, states, behaviors, with the capability of reusing behavior provided by the hosting element

## @JanMiksovsky — 2020-12-16

To make a concrete proposal:

First, rename the fifth box from

> Fully Extensible
> Standardization of a control's anatomy...

to

> Parameterized Extensibility
> Standardized anatomy, states, and behaviors permit a wide range of possibilities while reusing controller code

Second, add a sixth box to the right:

> Custom Controller [or Full Control]
> A fundamentally new control that reuses standard elements so the developer can efficiently meet user expectations

If the platform defines mixins, those are relevant in that sixth box as well.
