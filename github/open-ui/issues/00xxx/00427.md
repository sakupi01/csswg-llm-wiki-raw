Popup anchor positioning seems to be set up to anchor the popup relative to the element it is referring to, however typically context menus are anchored to the pointing device used to summon them. How should developers anchor context menus to the pointing device (e.g. contextmenu event) that summoned it? Should we consider a method of handling this automatically for the developer?

I think ideally a developer should be able to write a custom context menu as simply as setting an attribute on an element, e.g.

```html
<div contextmenu="popupid"></div>
```

And then the popup would be summoned as the default action of a contextmenu event and the anchor position would be relative to the triggering event point.

How about adding an ident to the CSS property of `anchor-position: pointer`? This would enable you to technically have a context menu without needing a new content attribute. You'd still tie them together via the anchor content attribute but adjust the invocation method.
