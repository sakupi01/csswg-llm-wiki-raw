Based on the [research comparing various design systems](https://open-ui.org/components/checkbox.research.concepts), it's common practice for the control to be placed to the left hand-side, and the corresponding text label to be placed on the right hand side.

![image](https://user-images.githubusercontent.com/17087167/123315559-c32cd900-d523-11eb-913e-6f289dd7950f.png)

The proposed DOM structure  found on the [checkbox research page](https://open-ui.org/components/checkbox/) shows the label placed on the left-hand side by default:

```html
<oui-checkbox>
  <label part="label">
    <slot name="label"></slot>
  </label>
  <div part="indicator">
    <slot name="indicator"></slot>
  </div>
</oui-checkbox>
```

This is what a basic implementation of a checkbox looks like with the structure defined in the proposal:

https://user-images.githubusercontent.com/17087167/123315764-fbccb280-d523-11eb-9345-cec2e2371fee.mov


Note: These are the styles on set on the checkbox `:host` . 

```css
:host {
    display: flex;
    contain: content;
    cursor: pointer;
    width: fit-content;
}
```
All other styles are defined on the client side for some visual flair.

Here's an example of the same checkbox component but with an altered DOM structure. The label is placed after the control.

```html
<div part="control">
    <div part="indicator">
        <slot></slot>
    </div>
</div>

<label id="label" part="label">
    <slot name="label"></slot>
</label>
```

https://user-images.githubusercontent.com/17087167/123315808-09823800-d524-11eb-95d7-39e6591ee137.mov

I tried having a look for rationale in some previous issues, like [here](https://github.com/openui/open-ui/pull/54) but couldn't find an answer.

My main questions are:

- According to the [out of scope](https://github.com/openui/open-ui/pull/54) section, the styling is up to the browser. So does that make this a non-issue? Or do we still need to be mindful about the placement of the markup?
- Are there a11y considerations I'm completely missing with having the label placed after the control? Or would using properties like `aria-labelledby` make the structure of the DOM trivial?

## @gregwhitworth — 2021-07-21

Yes, the important aspect here is that there IS a label in association by default with the checkbox. `aria-label` can also ensure that the exact name computation can be defined. That said, we can easily add a slot that wraps both the indicator and the label and this will enable an author to change the ordering.
