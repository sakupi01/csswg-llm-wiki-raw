I can see this one working either way or people having a preference on a case-by-case basis.

How could a user define that they don't want the popover to close when selecting an option in a SelectMenu? For example, a custom multi-select where the user is likely to select multiple options would require the user to keep opening and closing the listbox. We can't cancel the `popuphide` event to get around this as far as I'm aware either.

The `react-select` version: https://react-select.com/home#custom-styles

## @josepharhar — 2023-02-16

You can prevent the default behavior of clicking an option causing the listbox to close by calling preventDefault on the click event, I tested it out [here](https://jsfiddle.net/jarhar/3d89pkhx/):
```html
<selectmenu>
  <div popover=auto slot=listbox behavior=listbox>
    listbox
    <option>one</option>
    <option>two</option>
  </div>
</selectmenu>
<script>
const selectmenu = document.querySelector('selectmenu');
document.querySelectorAll('option').forEach(option => {
  option.addEventListener('click', event => {
    event.preventDefault();
    selectmenu.value = option.textContent;
  }, true);
});
</script>
```

You have to use the capture phase because the browser's bubbling phase event listener is registered first, but I could see this not being required if during the HTML spec review they ask us to integrate it into the event dispatching system instead of actually using addEventListener like they asked for popover.

Since I don't see any usecases for non-multiselect, and as Mason mentioned we have moved that to v2, I'm going to change the label from select to select-v2
