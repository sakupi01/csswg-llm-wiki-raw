From what I saw, most developers prefer third-party color pickers ([`react-color`](https://casesandberg.github.io/react-color/), [`colorPicker`](http://www.dematte.at/colorPicker/) etc.) over native `<input type="color">` for many reasons.

Off the top of my head:

* switching between various color spaces: HEX, RGB, HSV, HSL, etc.
* switching between various UIs: wheel, palettes, etc.

It would be also really nice to:

* enable/disable color components (e.g. enable A for RGB)
* limit `min` and `max` values for color components (e.g. limit L in HSL) (BTW, what about also `step` attribute?)

Something like:

![color-picker](https://user-images.githubusercontent.com/7892779/142891576-59ef6759-f2cb-4eb0-b730-2c6ae9dd170b.png)

I've also found that `pattern`, `required`, `readonly` attributes don't work for `<input type="color">` in Chromium, but `disabled` works. @domenic cc.

## @gregwhitworth — 2021-12-01

These are great suggestions, currently there is no one championing a customizable color input which would aid in developers being able to adjust how switching modes occur irregardless of the default that ships with the browser. As it relates to the min/max capabilities possibly being in the native variants I think it's worth possibly getting new content attributes added to the WHATWG specification for `<input type="color">` or added support of `min` or `max`. We could possibly incubate these recommendations in Open UI initially to get further support for the idea and help upstream them if there is enough interest. Let me know and I'll add it to the agenda.

## @sm-Fifteen — 2022-02-24

Using 8-bit sRGB hex codes as the "universal" color format for color value is also something that probably deserves being revised. For starters, 8-bit hex codes aren't [that much more meaningful than percentages](https://hg2dc.com/2019/03/24/question-2/), they're mainly just obfuscating a fraction over 255. Also, sRGB has been the ASCII of color formats for decades now, and done a decent enough job at serving most people's needs, but [a surprising amount of colors land outside of that colorspace](https://css.land/lch/), which can cause issues when trying to match [the color of an image with a CSS background](https://twitter.com/panic/status/1106633444157607936). While browser's color support outside of images [is still pretty much just sRGB](https://caniuse.com/css-color-function) (which is why you probably won't see UI toolkit color pickers have support for it) and will continue to be for a while, at least, Safari has already begun implementing support for CSS colors beyond sRGB and [their color picker also displays the limits of the color space](https://webkit.org/blog/10042/wide-gamut-color-in-css-with-display-p3/).

![The Safari color picker](https://webkit.org/wp-content/uploads/p3-color-picker.png)
