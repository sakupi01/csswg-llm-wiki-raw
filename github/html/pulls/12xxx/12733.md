This event.button check was added to make sure that right clicking a select doesn't open its picker, but since the same algorithm handles keyboard events it should be specific about looking at event.button only on mouse events.

This PR also corrects the number being looked at from 1 to 0 for event.button

## @josepharhar — 2026-08-21

> I'm somewhat surprised we're not using pointer events here.

We're using mousedown because appearance:auto selects use mousedown to open the picker, and I think that is the case in all browsers. This way we are consistent regardless of appearance value. I'd be hesitant to switch to pointer events for some other reasons, like pointer events getting skipped in some engines/platforms (like the webkit ios popover light dismiss bug) and because the disabled attribute should prevent mousedown from getting fired but not pointer events.

Edit: or did you mean checking for a PointerEvent type instead of a MouseEvent type and continuing to actually listen for the mousedown event?
