This PR adds support for using the selectedcontent element in a select
element with the multiple attribute by cloning each of the option
elements into the selectedcontent element.
    
Each cloned option will be wrapped by a generated div element inside the
selectedcontent element, so the resulting DOM would look like this:
    
```html
<select multiple size=1>
  <selectedcontent>
    <div>one</div>
    <div>two</div>
  </selectedcontent>
  <option selected>one</option>
  <option selected>two</option>
  <option>three</option>
</select>
```
    
Fixes https://github.com/whatwg/html/issues/12342

## @josepharhar — 2026-07-24

> Is it intentional that #selectedness-setting-algorithm [bails](https://whatpr.org/html/12430/56ec622...4bb6f73/form-elements.html#selectedness-setting-algorithm:~:text=If%20element%20%27s%20has%20the%20multiple%20attribute%20is%20absent%2C%20and%20attribute%2C%20then%20return%2E) for select multiple?

Yes, because we don't want to deselect other options in response to an option's selectedness being changed in a `<select multiple>`, because its fine for zero or many options to be selected.

> Wouldn't this imply that selecting an <option> by script (which goes through [#ask-for-a-reset](https://whatpr.org/html/12430/56ec622...4bb6f73/form-elements.html#:~:text=ask%20for%20a%20reset,-given%20this)) is broken?

Good catch, yeah I agree that is broken. Sounds like we should make "ask for a reset" update selectedcontent elements if the select has the multiple attribute? Do you think this would work?
