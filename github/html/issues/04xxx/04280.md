We already have an `invalid` event for form fields, but no `valid` event. (In contrast, in CSS, we have **both** an `:invalid` and a `:valid` pseudo-class, which is very helpful.) Can we add a `valid` event for form fields?

Use case: I have a warning paragraph that shows when a field is invalid, which is easy to trigger with the `invalid` event. However, it's much harder to hide the paragraph when the field becomes valid again.

It seems like this idea must have come up before, though I couldn't find anything about it.

(Note: I already posted this issue here -- https://github.com/w3c/html/issues/1665 -- but now I'm wondering if this is the better place? Sorry for any confusion!)

Heya, whatwg/html is the place for HTML feature requests. I transferred the issue for you. https://whatwg.org/faq#adding-new-features and https://whatwg.org/working-mode might help you get a feel for how the WHATWG operates.

As for this particular feature, it doesn't seem that hard to implement yourself?
```js
someControl.oninput = _ => {
  if(someControl.validity.valid) { // or use someControl.checkValidity() if you want another invalid event
    hideParagraphFor(someControl);
  }
}
```

Thanks for the response, @annevk. Your snippet indeed works, and without that much extra code. That said, IMHO having parallel `valid` and `invalid` events would be more elegant in some cases. (I'm not sure why, if we have one event, we wouldn't have the other?)

I've mocked up a CodePen to show what I'd like to do: https://codepen.io/mark-fluehr/pen/dwqPqW?editors=1010. The important part is these lines:
```JavaScript
fields.forEach((field) => {
  // This works
  field.addEventListener('invalid', showWarning);

  // This doesn't work, as it's not in the DOM API
  field.addEventListener('valid', hideWarning);
});
```

## @annevk — 2019-01-10

Because it doesn't really make sense to dispatch a `valid` event whenever we dispatch an `invalid` event today. The processing model would be quite a bit different, meaning there's no real symmetry to speak of, at which point it's not clear to me that it's a good thing to have both.
