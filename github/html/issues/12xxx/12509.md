### What is the issue with the HTML Standard?

Consider this example:

```html
<!doctype html>
<select id=s style="appearance: base-select">
  <button>
    <selectedcontent></selectedcontent>
  </button>
  <option id=o selected>ABC</option>
</select>
<script>
onload = () => {
  document.querySelector("#o").textContent = "DEF";
};
</script>
```

I would expect the selectedcontent's content to be "DEF", it's "ABC" though.

## @annevk — 2026-06-02

Why would that depend on `appearance: auto`? You'd also need that when the `button` element is not used, presumably. We should not make tree mutations depend on the `appearance` value.

I also think the question posed above is wrong, as whether the `select` element button text reacts to mutations is not a function of its `appearance` value, its a function of its structure in the node tree. If you use a `button` element it's only synchronized at select points in time. If you don't use a `button` element it's live. And yes, if you want to mimic liveness with the `button` element you'd have to listen to mutations yourself (or ensure you drive all mutations and can make them in multiple places).
