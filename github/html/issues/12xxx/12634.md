### What is the issue with the HTML Standard?

The default styles are currently:

```css
::picker(select) {
  position-area: self-block-end span-self-inline-end;
  position-try-fallbacks:
    self-block-start span-self-inline-end,
    self-block-end span-self-inline-start,
    self-block-start span-self-inline-start;
}
```

But should it be:

```css
::picker(select) {
  position-area: self-block-end span-self-inline-end;
  position-try-fallbacks: 
    flip-block,
    flip-inline,
    flip-block flip-inline;
}
```

I think this reacts better to developer changes. For example, if the developer does:

```css
.custom-select::picker(select) {
  position-area: self-block-start span-self-inline-start;
  position-try-order: normal;
}
```

In the current system, the picker will never appear `self-block-end span-self-inline-end`, because that's no longer in the set. With my proposal, it would.

Also:

```css
.custom-select::picker(select) {
  margin-block-end: 1em;
}
```

This margin will always be at the block end, which likely isn't what the developer wants when the picker flips position. With my proposal, the margin would also be flipped.
