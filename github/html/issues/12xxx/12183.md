### What is the issue with the HTML Standard?

`html/semantics/forms/the-select-element/customizable-select/select-picker-hover-active-pseudo.html` has some expectations around how `:hover` and `:active` match, but I don't see this reflected in the specification. They do seem like reasonable changes however.

## @lukewarlow — 2026-02-20

I believe this is specified in https://drafts.csswg.org/selectors/#useraction-pseudos 

> [:hover](https://drafts.csswg.org/selectors/#hover-pseudo), [:active](https://drafts.csswg.org/selectors/#active-pseudo), [:focus-within](https://drafts.csswg.org/selectors/#focus-within-pseudo). Specifically, if these match on a given element, they also match on the element’s [flat tree](https://drafts.csswg.org/css-shadow-1/#flat-tree) ancestors, up to and including the first [top layer](https://drafts.csswg.org/css-position-4/#document-top-layer) element or the [root](https://dom.spec.whatwg.org/#concept-tree-root) element, whichever is encountered first.

I think the top layer bit here specifically accounts for the behaviour in that test.

This came from https://github.com/w3c/csswg-drafts/issues/11185
