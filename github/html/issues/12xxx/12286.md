### What is the issue with the HTML Standard?

I'm not quite sure how outline is supposed to work with `::picker(select)`. As far as I can tell the `option` element takes up the entire width so the outline will be clipped by the `::picker(select)` box (which has `overflow: auto`). It seems that in Chrome however the `option` element still has 1px wiggle room somehow. It still looks bad as Chrome's outline is 1.5px.

WebKit's macOS outline is much bigger and I'd need to apply a negative `outline-offset` to compensate, but that does not seem ideal.

## @sb3nder — 2026-03-19

On my WebKit build (MiniBrowser), I can control the initial offset with outline-width.
As I understand it, it works like this:

The outline is drawn before the outer outline area defined by `outline-width`. The outline line itself has a width of 2px, which ignores zoom.
Example: `outline-width: 5px`
(The blue solid outline is there for reference; it is 5px and is affected by zoom.)

<img height="100" alt="Image" src="https://github.com/user-attachments/assets/755c5b63-e721-49e6-ae1c-1c146d635e95" />

If `outline-width` is smaller than the line width, the line is drawn just outside the inner area defined by `outline-width`:
Example: `outline-width: 0px`

<img height="100" alt="Image" src="https://github.com/user-attachments/assets/df6089fc-c54c-4eb8-97e1-053c470f4201" />

So if I want to place the outline just inside a box, I set `outline-width` to a value, and the `outline-offset` to its negative,
for example: `outline-width: 2px; outline-offset: -2px`, (which is different from `outline-width: 0px; outline-offset: -2px`).

<img height="100" alt="Image" src="https://github.com/user-attachments/assets/eeae94a8-0872-4e53-a24f-dbff3a0b3a0f" />

A little while ago, I opened an issue in CSSWG about this:
https://github.com/w3c/csswg-drafts/issues/13587

Another question regarding WebKit's auto outline:
> Is it intended that the width does not scale with zoom?

---

When one uses a negative `outline-offset`, it indirectly implies that a **specified** portion of the focused element can be obscured without compromising the visibility of the content.
This allows the style and width of the outline to be changed safely without affecting the visibility of both the content and the outline.

`inset` alone doesn't do that.

`outline-offset: inset {min-offset};`

getComputedValue returns max(- outline-width, min-offset)
