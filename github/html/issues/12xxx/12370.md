## @cwilso — 2026-04-16

Minutes:

- Stage Three Request for Patching Issue 11542: The discussion centered on requesting Stage Three for patching issue 11542, which involves three separate pull requests (PRs) that have complete spec tests and support from two implementers, along with existing implementation experience. Although Henry wanted to review the patches, it was clarified that moving to Stage Three does not require the PRs to be fully approved, and the complete solution, including an explainer, examples, and a polyfill, is up to date. An origin trial for processing instructions has begun in Chrome beta to identify any web compatibility breakage.
- Testing and Organization for Issue 11542: The testing for issue 11542 includes a large number of web platform tests, though they are currently located in the partial updates folder and are scheduled to be moved to the template folder for better organization. Additionally, the tests cover complex scenarios involving DOM modification during processing, described as "mindbending tests," and the team is working on upstreaming the processing instructions (PI) into the sanitizer. The team is waiting for Henry's final input before proceeding.
- Shadow Root Adopted Stylesheet Discussion: Kurt Catti-Schmidt presented an issue regarding the shadow root adopted stylesheet, where the proposed implementation involves fetching stylesheets as specified in the attribute using a placeholder that is swapped when the fetch completes. This change splits the existing single-step stylesheet fetch into two steps, which cleans up the placeholder swap mechanism but raises questions about its impact on the existing fetch process. It was determined that this change does not affect observability via CSSOM, as an empty stylesheet would not be visible before being populated. Kurt Catti-Schmidt was tasked with pinging Noam Rosenthal once the changes are fully reflected in the relevant PR.
- Content Security Policy for Style Type Module: The conversation moved to a separate PR concerning the `style type=module` tag, specifically addressing its Content Security Policy (CSP) implementation. An issue was raised that since this impacts the module map, it should respect both the `style-src` and `script-src` policies, as import maps respect `script-src`. Kurt Catti-Schmidt has changed the implementation to respect the stricter subset of both CSPs to prevent modification of the import map if `script-src` is blocked.
- Clarity on CSP and Module Map Interaction: There was confusion regarding why `script-src` would apply to CSS in the module map, as the type is enforced to be CSS upon fetching. The concern was articulated that a style tag could potentially "clobber" a script entry in the import map by having the same name but a different type, which could prevent the intended script from executing. Anne van Kesteren stated that the module map is keyed by a tuple that includes the module type (e.g., JavaScript), suggesting that clobbering should not occur. The group determined that if no clobbering of scripts is possible, then using `script-src` is unnecessary.
- Resolution on Style Type Module CSP: Kurt Catti-Schmidt will CC Anne van Kesteren on the relevant bug to investigate further, acknowledging that the concern about clobbering may not be valid. Additionally, Frederik Braun requested that a test case be written for this issue.
- Media Element Muted Attribute Standardization: The discussion shifted to issue 5013 concerning the `muted` attribute's getter, which currently references the element's creation time, a concept not standardized in DOM or HTML. This behavior is non-standard, as WebKit implemented the getter to return the attribute value, causing some test failures but no reported issues. Anne van Kesteren suggested aligning on the more straightforward Safari behavior to simplify and remove the "magic" associated with the creation time.
- Next Steps for Muted Attribute Simplification: The participants reviewed the history of the `muted` attribute, noting its original intent was likely to reflect the default setting rather than user changes, but with an awkward "creation time" component. Anne van Kesteren proposed that they will create a PR with test changes to implement the default value approach, which WebKit currently uses, as it aligns with the attribute's default state. Despite some concerns from Olli Pettay about potential web compatibility risks from changing the existing behavior, the group agreed to proceed with the changes and reevaluate if compatibility issues arise.
- HTML Setting and Streaming Methods Update: Noam Rosenthal provided an update on the draft PR for HTML setting and streaming methods, which includes a full implementation and tests. An open question is how to handle calls to streaming methods on elements without a parent, as current DOM methods silently do nothing in this case. The current proposal is to throw a hierarchy error when calling stream methods without a parent, which was viewed as a cleaner solution, though throwing an exception can always be removed later if needed. The streaming implementation keeps the fragment parser processing model intact but redirects insertions to the target element, and work is currently underway to upstream the sanitizer that these methods rely on.
- Fieldset Anonymous Inner Box CSS Properties: Kurt Catti-Schmidt presented issue 11095 concerning the anonymous inner box inherited by `fieldset`, which currently lists certain CSS properties, including `column-rule`. Because the CSS Gap spec introduced `row-rule` property, the list needs to be updated to include the new property and clean up shorthands, aligning the HTML specification with the evolving CSS standards. The properties to update were provided by Kevin, and there were no immediate objections, though Simon Pieters and Anne van Kesteren agreed that this list of properties should ideally be maintained in a CSS specification rather than HTML.
- Decision on Fieldset CSS Properties and Future Maintenance: The consensus was to update the list of CSS properties, specifically adding the row-rule and removing the redundant `grid-gap` (which is covered by `gap`) for the anonymous inner element in the short term. Kurt Catti-Schmidt was assigned the task of filing a new issue to discuss moving the maintenance of these CSS properties out of the HTML specification and into a CSS-related specification.
- SVG Natural Width and Height Discussion: The topic of issue 11287, concerning `naturalWidth` and `naturalHeight` in SVG, was raised, noting that for fallback cases (when intrinsic width, height, or aspect ratio is missing), density is considered for the properties but not for layout. This inconsistency can lead to a difference between reported height and layout height. Anne van Kesteren's proposal in the issue is to use the CSS defaults (300x150) as static constants when no intrinsic dimensions are available and an aspect ratio cannot be computed. The suggestion to return `null` or `0` for an aspect ratio was briefly considered, though returning `0` for natural width/height is web compatibility risky.
- Proposal for Natural Dimensions and Density: Anne van Kesteren maintained their proposal to make a slight semantic change so that density does not impact these unknown dimensions, as they do not believe density should affect unknown dimensions, particularly for imported SVG. Although there is a recognized web compatibility risk with any change in this area, the proposed change addresses an inconsistency between implementation and layout. The remaining discussion was postponed, and Anne van Kesteren will try to work on a PR for the proposed semantic change.
