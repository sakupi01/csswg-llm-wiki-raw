These two things rendering differently in Chrome makes zero sense to me, but WPT kind of expects it:

```html
<!doctype html>
<select multiple>abc</select>
<select multiple><span>abc</span></select>
```

## @josepharhar — 2026-07-24

The reason that we are slotting span elements is so that this works:
```html
<select multiple>
  <span>
    <option>option</option>
  </span>
</select>
```
Before customizable select, there was a conservative slotting algorithm which would only slot options, optgroups, and hr elements, and leave anything else unslotted. With customizable select, I added spans and divs to this.

I guess I'd be fine slotting anything (such as text nodes) as long as it doesn't break any websites, which it probably wouldn't.

<!-- comment id=5072984515 author=josepharhar created=2026-07-24T18:06:57Z url=https://github.com/whatwg/html/issues/12717#issuecomment-5072984515 -->
## @josepharhar — 2026-07-24

Also, it was very important for me to slot spans and divs in this case because there were websites which had html like that, with options inside divs and spans, and they were relying on the old HTML parser which would remove the divs and spans in order to make the slotting work. When changing the parser, we also had to allow these elements to be slotted in order to not break those websites.

I agree that we could specify slotting. There is slotting specified for base appearance in the rendering section, but I don't think that we are specifying what gets slotted for appearance:auto?

## @emilio — 2026-07-24

I guess slotting for base appearance right now says text should be slotted, right?

> A select popover slot, which is a [slot](https://html.spec.whatwg.org/#the-slot-element) element. It is appended to the [select popover](https://html.spec.whatwg.org/#select-popover). It is [expected](https://html.spec.whatwg.org/#expected) to take all child nodes of the [select](https://html.spec.whatwg.org/#the-select-element) except for the first child [button](https://html.spec.whatwg.org/#the-button-element), which is taken by the [select button slot](https://html.spec.whatwg.org/#select-button-slot).

I think slotting decisions shouldn't depend on style, so that should also apply to `appearance: auto`.

## @tabatkins — 2026-07-30

Discussion in the WHATWG meeting agreed with @emilio's request - we should make text behave the same as spans here. (In general, CSS tries to ensure that inserting an unstyled span or div shouldn't meaningfully change your page, and HTML should probably lean in that direction as much as it reasonably can as well.)
