Is there a particular reason why `select fallback button text` is a div element?
It feels a bit strange that it has `display: block` while `<button>` has `display: content` and `<selectedcontent>`  has `display: inline`.
I would have expected maybe a span?

<!-- comment id=4674929576 author=josepharhar created=2026-06-10T21:50:47Z url=https://github.com/whatwg/html/issues/12558#issuecomment-4674929576 -->
## @josepharhar — 2026-06-10

The reason that its a div is because I reused the element from appearance:auto, which [happens to be a div](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/html/forms/menu_list_inner_element.h;l=12;drc=c9ded7f18331563286e950c8867d670eb677e225).

Changing it to be inline for base appearance would be very easy and is probably fine. Removing the element entirely by just making it a text node child of the button slot would be more challenging to implement, and I wonder if it would break the `gap:0.5em` we put on the select element to separate this text element from `::picker-icon`.
