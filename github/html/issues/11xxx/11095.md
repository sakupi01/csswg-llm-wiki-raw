### What is the issue with the HTML Standard?

The `<fieldset>` element is specified to generate an [anonymous fieldset content box](https://html.spec.whatwg.org/multipage/rendering.html#anonymous-fieldset-content-box) which inherits a set of properties from the `<fieldset>` element. Among that list of properties is `column-rule` which will then apply if the content box is a grid, flexbox, or multicol container.

[CSS Gap Decorations](https://drafts.csswg.org/css-gaps-1/) introduces `row-rule` and subproperties `row-rule-width`, `row-rule-style`, and `row-rule-color` which function exactly the same as the corresponding `column-rule-*` properties, but in the row direction. As such, I suggest adding `row-rule` to the list of properties that inherit from a `<fieldset>` to its anonymous fieldset content box.

## @kbabbitt — 2026-04-13

We've made some further progress on CSS Gaps 1, and I think there are some additional properties that should be included in the list alongside `row-rule-*`.

One thing I noticed about the list is that some of them are longhands and some are shorthands. For all of the gap and gap decoration related properties, we have parallel sets of properties that work in each direction (column and row), and shorthands that work in both directions simultaneously. For brevity and consistency I'd suggest we list the bi-directional shorthands only, and propose the following changes:

Add the following properties:
* [gap](https://www.w3.org/TR/css-align-3/#gap-shorthand)
* [grid-gap](https://www.w3.org/TR/css-align-3/#gap-legacy)
* [rule](https://www.w3.org/TR/css-gaps-1/#gap-decoration-shorthands)
* [rule-break](https://www.w3.org/TR/css-gaps-1/#break)
* [rule-inset](https://www.w3.org/TR/css-gaps-1/#inset)
* [rule-overlap](https://www.w3.org/TR/css-gaps-1/#overlap)
* [rule-visibility-items](https://www.w3.org/TR/css-gaps-1/#visibility)

And strike the following properties since they're covered by the above:
* column-gap
* column-rule
* grid-column-gap
* grid-row-gap
