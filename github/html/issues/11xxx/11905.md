### What is the issue with the HTML Standard?

https://html.spec.whatwg.org/multipage/common-dom-interfaces.html#dom-htmloptionscollection-setter

> 2. Let length be the number of nodes [represented by the collection](https://dom.spec.whatwg.org/#represented-by-the-collection).
> 
> 3. Let n be index minus length.
> 
> 4. If n is greater than zero, then [append](https://dom.spec.whatwg.org/#concept-node-append) a [DocumentFragment](https://dom.spec.whatwg.org/#interface-documentfragment) consisting of n-1 new [option](https://html.spec.whatwg.org/multipage/form-elements.html#the-option-element) elements with no attributes and no child nodes to the [select](https://html.spec.whatwg.org/multipage/form-elements.html#the-select-element) element on which the [HTMLOptionsCollection](https://html.spec.whatwg.org/multipage/common-dom-interfaces.html#htmloptionscollection) is rooted.

The calculation for n correctly identifies the gap size between the current end of the collection (length) and the target insertion point (index). However, the subsequent step incorrectly calculates the number of padding elements required to fill that gap.

Examples: 
length = 0; index = 2 => n = 2;  n-1 = 1; We would only add one padding element but we need 2
length = 5; index = 8 => n = 3; n -1 = 2; We would only add two padding elements but we need 3

The padding logic is consistently off by one

Proposed change to the 4 point:

If n is greater than zero, then [append](https://dom.spec.whatwg.org/#concept-node-append) a [DocumentFragment](https://dom.spec.whatwg.org/#interface-documentfragment) consisting of n new [option](https://html.spec.whatwg.org/multipage/form-elements.html#the-option-element) elements with no attributes and no child nodes to the [select](https://html.spec.whatwg.org/multipage/form-elements.html#the-select-element) element on which the [HTMLOptionsCollection](https://html.spec.whatwg.org/multipage/common-dom-interfaces.html#htmloptionscollection) is rooted.
