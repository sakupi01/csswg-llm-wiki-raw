## @F3n67u — 2025-12-20

https://github.com/web-platform-tests/wpt/blob/master/html/semantics/forms/the-select-element/customizable-select/selectedcontent-mutations.html

Given:

```html
<div id=test3>
  <select>
    <button>
      <selectedcontent>outer1
        <selectedcontent>inner1</selectedcontent>
      </selectedcontent>
      <selectedcontent>outer2
        <selectedcontent>inner2</selectedcontent>
      </selectedcontent>
    </button>
    <option>option</option>
  </select>
</div>
```

The latest selectedcontent-mutations.html expects test3's `innerHTML` to be:

```html
<select>
    <button>
      <selectedcontent>option</selectedcontent>
      <selectedcontent>outer2
        <selectedcontent>inner2</selectedcontent>
      </selectedcontent>
    </button>
    <option>option</option>
  </select>
```

I think it should be:

```html
 <select>
    <button>
      <selectedcontent>option</selectedcontent>
      <selectedcontent></selectedcontent>
    </button>
    <option>option</option>
  </select>
```

outer2 is a non-primary selectedcontent, so it should be cleared?

## @josepharhar — 2026-01-02

The "outer2" text node and the inner2 selectedcontent element are included in the test expectations because:
1. The insertion of outer2 triggers an update of all selectedcontent elements which copies "option" into outer1 because outer1 is the active/enabled selectedcontent element, and it also clears the contents of outer2. However, the parser hasn't appended any children to outer2 yet, so the "outer2" text node and the inner2 selectedcontent aren't removed because they haven't been appended yet.
2. The insertion of inner2 does not trigger an update of any selectedcontent elements because it is nested inside of another selectedcontent element, which makes it disabled. This is to prevent infinite loops.
