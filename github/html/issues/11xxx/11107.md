### What is the issue with the HTML Standard?

@josepharhar @mfreed7 I just realized a pretty big part of the rendering story is still missing. I don't see any PR for the native/primitive appearance, as well as an allowance for user agents to render `img` elements in those modes as part of the `option` element's label (which I guess will have to be redefined to allow for some kind of structure). Is there test coverage for all the new markup features with `appearance: auto / none`?

(Bit surprising this is overlooked given it is insisted upon for `<input type=checkbox switch>` to be able to land.)

## @mfreed7 — 2025-03-07

> @josepharhar @mfreed7 I just realized a pretty big part of the rendering story is still missing. I don't see any PR for the native/primitive appearance, as well as an allowance for user agents to render img elements in those modes as part of the option element's label (which I guess will have to be redefined to allow for some kind of structure). Is there test coverage for all the new markup features with appearance: auto / none?

Right - there aren’t any PRs for that, because the rendering of `<select>` in `appearance:auto` mode isn’t really specified at all. The only mention in the [rendering section](https://html.spec.whatwg.org/multipage/rendering.html#the-select-element-2) is this sentence:

> An [option](https://html.spec.whatwg.org/multipage/form-elements.html#the-option-element) element is expected to be rendered by displaying the element's [label](https://html.spec.whatwg.org/multipage/form-elements.html#concept-option-label), indented under its [optgroup](https://html.spec.whatwg.org/multipage/form-elements.html#the-optgroup-element) element if it has one.

If that were desired in `appearance:auto` mode, we could potentially add a sentence that makes it “ok” to also render images with labels.

>  Is there test coverage for all the new markup features with appearance: auto / none?

That's tough/impossible to do, given the undefined nature of the spec and the lack of interop on the appearance of `<select>` in `appearance:auto/none` mode.

> (Bit surprising this is overlooked given it is insisted upon for `<input type=checkbox switch>` to be able to land.)

I think this is different, given that `<input type=checkbox switch>` is a significant new control mode. As I mentioned [on that spec PR](https://github.com/whatwg/html/pull/9546#issuecomment-1660741288), we don’t believe new controls – or significant new control modes – should be added to the platform that aren’t customizable out of the gate, with `appearance:base`, etc. We [also had other concerns](https://github.com/whatwg/html/pull/9546#issuecomment-1989739381) about the state of the discussion for that control mode specifically.

In the case of what we did so far for customizable select, we added customizability to the existing `<select>` form control. Here you are proposing to modify `appearance:auto`, which we’re open to as mentioned above, but that is a separable discussion.
