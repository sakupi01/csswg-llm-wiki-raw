## @frivoal — 2026-10-08

I think this PR is a reasonable representation of what we resolved in https://github.com/w3c/csswg-drafts/issues/13669, but I wonder if the complexity if worth it.

If the resolution had been
> RESOLVED: we do clip floats even if we hadn't hit the clamp point yet

instead of
> RESOLVED: we do clip floats even if we hadn't hit the clamp point yet, based on simulated lines or height

things would be simpler, as we simply wouldn't need this PR.

The key argument came from @mirisuzanne in https://github.com/w3c/csswg-drafts/issues/13669#issuecomment-4179668609:
> miriam: I think I'm okay. think it's wrong to clamp at 3 lines when you ask for 15
> miriam: the behavior I asked for is to clamp at 15

So, in this example, we're counting up to 15 virtual lines before clamping the float, when we only have 3 real lines.

If we really want to do this, I don't have an objection, but this seems overkill, and to introduce complexity we might not care for.

@andreubotella , what do you think?
