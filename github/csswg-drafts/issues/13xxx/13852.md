How/when does the [`inset`](https://drafts.csswg.org/scroll-animations/#dom-viewtimelineoptions-inset) property on [ViewTimelineOptions](https://drafts.csswg.org/scroll-animations/#dictdef-viewtimelineoptions), and processed in the [ViewTimeline constructor](https://drafts.csswg.org/scroll-animations/#dom-viewtimeline-viewtimeline), get resolved.

Specifically, the spec says "If a [DOMString](https://webidl.spec.whatwg.org/#idl-DOMString) value is provided as an inset, parse it as a [<'view-timeline-inset'>](https://drafts.csswg.org/scroll-animations/#propdef-view-timeline-inset) value". But it doesn't say how that [<'view-timeline-inset'>](https://drafts.csswg.org/scroll-animations/#propdef-view-timeline-inset) value is then resolved. (This applies to the sequence of [CSSNumericValue](https://drafts.css-houdini.org/css-typed-om-1/#cssnumericvalue) form as well). 

For example, how/when should an inset value like `{ inset: "1em 2em" }` be resolved? In the CSS form, using `view-timeline-inset: 1em 2em;`, it is resolved at computed value time, which is well defined. This extends beyond just font sizes, for example, consider the use of something like sibling-index(), `{ inset: "calc(1px * sibling-index()) 2px" }`?

## @emilio — 2026-05-22

I think resolving them synchronously is quite unfortunate (causes a synchronous style update, which might also be a bit unintuitive). Plus you need to answer the questions of "what if the element is not rendered / out of document / etc".

Keeping them as specified and resolving them _later_ raises the additional question of "when" and what's the value in the interim.

Another alternative would be to do something like `IntersectionObserver`s `rootMargin` etc and only allow absolute length + percentages...

@weinig do you have a strong opinion here out of curiosity?

## @weinig — 2026-05-23

@Emilio, I am not super clear on the processing model for ViewTimeline, or when these insets will be needed, so I don't have a strong opinion, I just want it to be specified clearly.

Since it is outside the normal cascade, I think all sorts of additional questions probably will arise, particularly around what happens when the document changes (though if the processing model specifies that it is only resolved right before use, I guess that won't be a problem?).

(I also filed a similar bug for WebAnimation's rangeStart/rangeEnd attributes, https://github.com/w3c/csswg-drafts/issues/13853, and I think similar questions arise there, but potentially are more challenging, since the user can read back the values immediately).
