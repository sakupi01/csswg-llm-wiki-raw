`shorter hue` must be assumed when omitted after `<polar-color-space>`, in the [serialization algo for `<color-mix()>` in a declared value](https://drafts.csswg.org/css-color-5/#serial-color-mix).

Does this apply in other contexts? (`color-interpolate()`, gradients, `palette-mix()`)

If so, wouldn't it be appropriate to define this explicitly in [§ 9.1. Color Space for Interpolation](https://drafts.csswg.org/css-color-5/#interpolation-space)?

## @svgeesus — 2026-04-13

This was [already specified in CSS Color 4](https://drafts.csswg.org/css-color-4/#hue-interpolation):

> Unless otherwise specified, if no specific hue interpolation algorithm is selected by the host syntax, the default is shorter.

However, to make things clearer, I

 - added a mention of this in the main [Color interpolation](https://drafts.csswg.org/css-color-4/#interpolation) section of CSS Color 4
 - added a backlink from CSS Color 5 to the definitions in CSS Color 4

In general, this sort of issue is a consequence of CSS Color 5 being a diff spec.
