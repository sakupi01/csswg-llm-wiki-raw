I am not sure if the presence of a document in the [random cache name](https://drafts.csswg.org/css-values-5/#random-cache-name) implies that random cache names should be stored in the current global object rather than its associated document (like registered custom properties).

<!-- comment id=4661968794 author=tabatkins created=2026-06-09T16:48:14Z url=https://github.com/w3c/csswg-drafts/issues/13864#issuecomment-4661968794 -->
## @tabatkins — 2026-06-09

There is no implication in the spec of where anything is "stored", or that they're "stored" at all. The "document id" in the cache name just ensures that random values aren't associated with each other across documents.

<!-- comment id=4663148663 author=cdoublev created=2026-06-09T19:09:57Z url=https://github.com/w3c/csswg-drafts/issues/13864#issuecomment-4663148663 -->
## @cdoublev — 2026-06-09

More specifically, I wanted to know if random cache names are cleared with `document.open()`, as is the case for registered custom properties.

<!-- comment id=4663333520 author=tabatkins created=2026-06-09T19:32:50Z url=https://github.com/w3c/csswg-drafts/issues/13864#issuecomment-4663333520 -->
## @tabatkins — 2026-06-09

The spec states:

> The /element identifier/ and /document identifier/ must have the same lifetimes and equivalence semantics as a JavaScript reference to the Element or Document.

Which should answer that question, right?
