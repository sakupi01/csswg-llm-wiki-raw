Two relatively recent resolutions conflict with one another:

Resolution 1:
Allowing optional forward slash in border-*-radius longhands (https://github.com/w3c/csswg-drafts/issues/12861):

```css
border-top-left-radius: 24px 12px;
border-top-left-radius: 24px / 12px;
```

Resolution 2:
The slash separated `corner` shorthand for `border-radius` and `corner-shape` that Chrome is currently implementing:

```css
corner: round 24px / round 24px / bevel 24px 12px / bevel 24px 12px;
```
----------------------------------------------------------------------------------

If you combine resolutions 1 and 2 the final result is a confusing mess of slashes. How is the browser suppose to know what to do with which slash???:

```css
corner: round 24px / round 24px / bevel 24px / 12px / bevel 24px / 12px;
```

## @SebastianZ — 2026-06-30

So, what options do we have? I see three:

1. Revert the resolution from #12861. (I.e. don't allow optional slashes between the values.)
2. Disallow the slash syntax for border radii in `corner`.
3. Replace the slash as separator in `corner` by something else.

I guess option 2 is the least disruptive, but I don't have a strong opinion on that.

Sebastian

<!-- comment id=4848680196 author=jsnkuhn created=2026-06-30T23:15:29Z url=https://github.com/w3c/csswg-drafts/issues/13889#issuecomment-4848680196 -->
## @jsnkuhn — 2026-06-30

Another option:

4. revert the `corner` shorthand back to being a shorthand of the `border-radius` and `corner-shape` short hands. This would allow the slashes to stay in the long hands.

```css 
corner: round 24px / bevel 24px / round 12px / bevel 12px;
```

would go back to being the originally proposed

```css 
corner: round bevel 24px 24px 12px 12px;
```
