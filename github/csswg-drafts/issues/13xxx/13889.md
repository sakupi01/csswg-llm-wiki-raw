Two relatively recent resolutions conflict with one another:

Resolution 1:
Allowing optional forward slash in border-*-radius longhands (https://github.com/w3c/csswg-drafts/issues/12861):

```css
border-top-left-radius: 24px 12px;
border-top-left-radius: 24px / 12px;
```

Resolution 2:
The slash separated `corner` shorthand for `border-radius` and `corner-shape` that Chrome is currently implementing:

```css
corner: round 24px / round 24px / bevel 24px 12px / bevel 24px 12px;
```
----------------------------------------------------------------------------------

If you combine resolutions 1 and 2 the final result is a confusing mess of slashes. How is the browser suppose to know what to do with which slash???:

```css
corner: round 24px / round 24px / bevel 24px / 12px / bevel 24px / 12px;
```

## @SebastianZ — 2026-06-30

So, what options do we have? I see three:

1. Revert the resolution from #12861. (I.e. don't allow optional slashes between the values.)
2. Disallow the slash syntax for border radii in `corner`.
3. Replace the slash as separator in `corner` by something else.

I guess option 2 is the least disruptive, but I don't have a strong opinion on that.

Sebastian

Another option:

4. revert the `corner` shorthand back to being a shorthand of the `border-radius` and `corner-shape` short hands. This would allow the slashes to stay in the long hands.

```css 
corner: round 24px / bevel 24px / round 12px / bevel 12px;
```

would go back to being the originally proposed

```css 
corner: round bevel 24px 24px 12px 12px;
```

## @jsnkuhn — 2026-07-15

1. Still not sure how the browser is going to recognize the different uses of the forward slash. For example:

```css
corner: notch 24px / 12px / normal / normal / normal;
```

How does the browser know that the first forward slash is mean to separate the width and height of the top-left corner and that the second forward slash is mean to separate the `corner-top-left` code from the `corner-top-right` code?

-----------------------

2. The shorthand as spec-ed right now seems to contradict itself: 

"The `corner` shorthand sets the `corner-*-shape` and `border-*-radius` longhands all together." implies

```css
corner: round 24px / bevel 24px / round 12px / bevel 12px;
```

but

`Value: <'border-radius'> <'corner-shape'>` implies a shorthand of shorthands

```css
corner: 24px 24px 12px 12px round bevel;
```
--------------

3. Some examples in the spec could help to clear up the confusion. Especially concerning use of the `normal` keyword which I just don't think devs will intuit at all.
----------------
 
4. I'll say once again that, while the agreed upon `corner` shorthand does deal with the issue that I originally brought up of being frustrated with the forced `round` fallback of the more obvious choice, I think the agreed upon syntax is over complicated and confusing. It seems like another decision from the WG that will make sense at the time but in the long run will need be explained (like defaulting `background-repeat` to `repeat`). Given how quickly the other browsers seem to be following up on implementing `corner-shape` I'm questioning whether this work around for the fallback is even really necessary. It is also not easily discoverable by devs that the `corner` shorthand will have a different fallback than using long hands.

## @fantasai — 2026-07-15

+1 to @noamr. The current syntax, <'border-radius'> <'corner-shape'>, implies the following abilities:

```css
corner: round 3px;
    /* same as corner-shape: round; border-radius: 3px; */
corner: bevel 0.25em;
    /* same as corner-shape: bevel; border-radius; 0.25em; */
corner: round 5px / 3px; /* elliptical corners */
    /* same as corner-shape: round; border-radius: 5px / 3px; */
corner: square bevel bevel square 10px / 50%;         /* make an arrow pointing right */
    /* same as corner-shape: square bevel bevel square; border-radius: 10px / 50%; */
corner: bevel 0 5px 5px 0 / 0 50% 50% 0;              /* make an arrow pointing right */
    /* same as corner-shape: bevel; border-radius: 0 5px 5px 0 / 0 50% 50% 0; */
corner: bevel square bevel square 10px / 100%;        /* make a parallelogram */
    /* same as corner-shape: bevel square bevel square; border-radius 10px / 100%; */
```

Probably the spec should have examples here. It's legitimately a little hard to understand.
