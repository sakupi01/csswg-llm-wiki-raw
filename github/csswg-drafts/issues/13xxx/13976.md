The application of image orientation EXIF data in `<feImage>` nodes is not defined. On the one hand, cross-origin content should always be oriented as a privacy feature. On the other hand, Chrome at least was never orienting images in `<feImage>`. This was recently flagged as a privacy bug and we have just made a change to switch to always applying orientation.

The decision to go with "always" is because we need to orient for cross-origin and there's no good way to plumb the CSS `image-orientation` property into the filter. I also think it would be very confusing to potentially have a single filter applied to multiple elements change appearance depending on the CSS properties of each element.

I see at least 3 options:
(a) Always apply image orientation EXIF data in `<feImage>`
(b) Use the CSS `image-orientation` property from the element with the `filter` property for that instance of the filter.
(c) Define an attribute on `<feImage>` to control the orientation (analogous to the CSS property).

Option (b) is messy to implement in Chrome but could be done. I prefer option (c) because it is very obvious in how it applies and would be consistent across instances of the filter. I have implemented option (a) in Chrome to fix the privacy problem but the web-compat issues may force a roll-back.
