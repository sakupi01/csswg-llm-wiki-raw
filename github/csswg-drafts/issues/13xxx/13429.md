> **running**: the image animation plays, without synchronization with any other instance of the same image on the page.
> 
> If the value is changed from `normal` to `running`, does it:
> - keep running from where it was, but now with no guarantee of future synchronization
> - start running from the start of the animation 

 _Originally posted by @svgeesus in [#1615](https://github.com/w3c/csswg-drafts/issues/1615#issuecomment-3774246821)_

## @svgeesus — 2026-02-02

This issue was raised before the document was adopted as a CSS ED and refers to wording which has now changed. The [current wording](https://drafts.csswg.org/css-image-animation-1/#valdef-image-animation-running) is:

> **running**
>    Like [normal](https://drafts.csswg.org/css-image-animation-1/#valdef-image-animation-normal), the animation of [animated images](https://drafts.csswg.org/css-image-animation-1/#animated-image) is run normally, as determined by the image format and the host language,

>    However, animation timelines are scoped per element: among the [content image](https://drafts.csswg.org/css-image-animation-1/#content-image) and [decorative images](https://drafts.csswg.org/css-image-animation-1/#decorative-image) of a single element, any [animated images](https://drafts.csswg.org/css-image-animation-1/#animated-image) with the same [absolute URL](https://url.spec.whatwg.org/#syntax-url-absolute), the same image data, and with an [image-animation](https://drafts.csswg.org/css-image-animation-1/#propdef-image-animation) computed value of [running](https://drafts.csswg.org/css-image-animation-1/#valdef-image-animation-running) must be rendered synchronized to the same timeline as a group, distinct from the timeline of images in other elements, with the timeline starting at the time of the least recent addition to the group.

The original question still stands, however.

## @DevSDK — 2026-03-02

The neutral or intuitive way seems `keep running from where it was, but now with no guarantee of future synchronization`. 

On the implementer's perspective, the unsync is only happened after image is paused. So we can leave it keep synced until image has been paused.

## @frivoal — 2026-03-12

I've drafted https://github.com/w3c/csswg-drafts/pull/13638 in response to this. Feedback welcome. Even though this seems simple conceptually, I've found this surprisingly tricky to phrase a clear definition of where the animation starts from, in a way both takes into account the fact that the value of the property may be what's changing, but also the fact that adding new images to the element may be what's starting their timeline.

Let me know if you think I did a passable job, or if you have a better suggestion.
