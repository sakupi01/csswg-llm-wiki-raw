Currently the spec for `border-shape: <<basic-shape>> <<basic-shape>>` defines that the first shape is the outer one and the second shape is the inner one. I don't know if this was 100% thought out.

Having the borders go outwards is inconsistent with `stripes` where the borders go outwards.
Does this consistency matter? 
To me it felt more intuitive to go inwards but I can't entirely reason about it.

Opinions?
@SebastianZ @danielsakhapov @tabatkins @LeaVerou @fantasai

## @noamr — 2026-01-16

I think we have a few options:
1. Leave as is (outside->in, similar to fill rules)
2. Change to inside-out, similar to radial gradients
3. Separate to two properties (`inner-border-shape` and `outer-border-shape`), though that can become a bit messy in defining how that differentiates from the single shape variant
4. Use keywords instead of ordering, this can be nice but also perhaps more verbose than necessary:
```css
.target {
  border-shape: 
     circle() outside, rect() inside
}
```

I currently tend towards leaving it as is but open to other stronger opinions.

## @noamr — 2026-02-01

Looking at #13044, seems like tides are going towards inside->out, but I believe that polling `border-shape` would produce opposite results, see https://indieweb.social/@nomster/115994642801093006 and https://x.com/nomsternom/status/2017891964281094371.

Given the ambiguity, perhaps we shouldn't rule out keywords? It can be a single keyword, some variation of this:

```css
border-shape: circle() enclosing square();
border-shape: circle() clipping square();
border-shape: circle() enclosed-by square();
border-shape: circle() clipped-by square();
```

Also it might be good if the single-shape variant is clearly a stroke:

```css
border-shape: stroke circle();
```

## @Crissov — 2026-02-01

Like already mentioned elsewhere, CSS already has keywords for [compositing operators](https://drafts.csswg.org/css-masking-1/#typedef-compositing-operator) (which are almost what this is).

~~~~ ebnf
<compositing-operator> = add | subtract | intersect | exclude
~~~~

PS: If brevity is important, `in` would work if the order was flipped.
