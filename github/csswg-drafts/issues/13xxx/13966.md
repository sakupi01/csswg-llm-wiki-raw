If [paint a stacking context](https://drafts.csswg.org/css-position-4/#paint-a-stacking-context) is invoked with `root` being an inline-block, then I goes thru

> 8. If root is an [inline-level](https://drafts.csswg.org/css-display-4/#inline-level) box
>    For each line box root is in, [paint a box in a line box](https://drafts.csswg.org/css-position-4/#paint-a-box-in-a-line-box) given root, the line box, and canvas.

But "paint a box in a line box" will do:

> - If root is an [inline-level](https://drafts.csswg.org/css-display-4/#inline-level) [block](https://drafts.csswg.org/css-display-4/#block-box) or [table wrapper box](https://drafts.csswg.org/css-tables-3/#table-wrapper-box)
>      [Paint a stacking container](https://drafts.csswg.org/css-position-4/#paint-a-stacking-container) given root and canvas.

Which means

> [Paint a stacking context](https://drafts.csswg.org/css-position-4/#paint-a-stacking-context) given root and canvas, treating root as if it created a new stacking context, but omitting any positioned descendants or descendants that actually create a stacking context (letting the parent stacking context paint them, instead).

So it's circular.
