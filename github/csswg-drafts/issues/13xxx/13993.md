`light-dark(<image>, <image>)` was added recently, but the current definition of cursor doesn't allow it. I don't see why we should not allow it, as long as the arguments both follow the restrictions from cursor.

The only ambiguous case is `light-dark(none, url(...))` or `light-dark(none, none)`. I've disallowed this for now in WebKit since it wouldn't roundtrip, but maybe that's not the right way to go. It might also be confusing given the meaning of `cursor: none`.

cc @tabatkins @LeaVerou @emilio

## @SebastianZ — 2026-05-31

> But yeah I guess specifying what is the cursor size of an image without an intrinsic size would be nice.

Currently that's up to the UA:

> The UA may also support additional file formats, including SVG, as defined in [SVG11], in secure static mode or secure animated mode [SVG2], even if it does not have a natural size.
> ...
> The default object size for cursor images is a UA-defined size that should be based on the size of a typical cursor on the UA’s operating system.

So, technically, the spec already allows for `light-dark(<image>, <image>) in `cursor` while not enforcing it. But given the currently restricted syntax of `cursor`, I think it should be made explicit that `light-dark()` is allowed to work in `cursor` even with the restricted syntax by defining it in the syntax as [outlined in my previous comment](https://github.com/w3c/csswg-drafts/issues/13993#issuecomment-4587860375) plus a clarifying sentence.

Or we go further and define a new `<natural-size-image>` data type for `cursor` replacing the existing `[ <url> | <url-set> ]` that is specified to support everything `<image>` supports but is restricted to images with a natural size referenced by URL. This includes everything URL-related like `<url>`, `<image-set()>`, `light-dark()`, and also `<cross-fade()>`. Basically, the existing restriction is kept but extended to include `light-dark()` and `cross-fade()`.

Therefore, my concrete proposal would be to change the `<cursor-image>` to this:

```ebnf
<cursor-image> = <natural-size-image> <number>{2}?
```

`<natual-size-image>` is a limited version of `<image>`, where the `<image>` sub-production is restricted to `<url>` only.

Sebastian
