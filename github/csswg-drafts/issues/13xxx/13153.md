I had expected that something like `body:hover` or `body:has(:hover)` (for the new rule below) would match when hovering the page, but with the new top‑layer rule from #11185:

If `::picker()` itself matches `:hover`, and it has no nested elements that match `:hover`,
then `body:has(:hover)` won't match.

Example structure:
```html
<body>
  ...
  <parent>
    <::picker()>
      ::before
      <div></div>
      ::after
    </::picker()>
  </parent>
  ...
</body>
```

I think my expectation was unreasonable.

For base‑style `<select>`, the suggested workaround is to wrap the options in another element so that `:has(:hover)` works.
