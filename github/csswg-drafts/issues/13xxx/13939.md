I was reading the spec and wondering if `link-parameters` might run into some of the same issues we have with animations and transitions, where authors want to set multiple values from multiple style rules and have them aggregate naturally in some way. I don't have direct author feedback at hand, but one example I could imagine based on https://www.svgrepo.com/svg/522764/bolt-circle:

<img width="100" height="100" alt="lightning bolt inside a circle" src="https://github.com/user-attachments/assets/9f652059-1631-4ea1-8b47-14f8d9b4dfa5" />

```css
.circleicon {
  link-parameters: param(--circle-color, blue);
}
.yellowbolt {
  link-parameters: param(--bolt-color, yellow);
}
.redbolt {
  link-parameters: param(--bolt-color, red);
}
```
```html
<img src="bolt-circle.svg" class="circleicon yellowbolt">
<img src="bolt-circle.svg" class="circleicon redbolt">
```

Additive CSS has been discussed at length in #1594, but I'm also wondering if in this case it might be useful to pursue some other solution that lets each link parameter be its own property instead. That would also enable something like:

```css
.boltcircle {
  --link-bolt-color: yellow;
  --link-circle-color: blue;
}
.boltcircle:hover {
  --link-circle-color: lightblue;
}
```

This is purely straw example syntax; in reality I supect we'd need to come up with something that doesn't carve out a portion of the custom property namespace. But hopefully the idea comes across.

## @tabatkins — 2026-05-19

Right now, the only way to do it is to indirect thru some custom props, and manually aggregate those in the actual property:

```css
.icon {
  link-parameters: param(--circle-color, var(--link-circle-color, black)), param(--bolt-color, var(--link-bolt-color, yellow));
 /* or the same with `background-image: url(..., param(...) param(...));` */
}
```

The issue is that I don't know that we can *meaningfully* reduce the work here. You still need to link together (1) the param name, (2) the custom prop, and (3) the default value, somehow; my example above does just that, with a little bit of cruft with the function names.
