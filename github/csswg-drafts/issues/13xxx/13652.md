https://drafts.csswg.org/css-sizing-3/#behave-as-auto

This section needs some wording tweaks to make it clearer that we're not equating this with computing to `auto`, and also the note should probably clarify that these uses are largely around sizing and don't affect margin collapsing (which should continue to check the computed style, [testcase](https://software.hixie.ch/utilities/js/live-dom-viewer/?%3C!DOCTYPE%20html%3E%0A%3Cdiv%20style%3D%22margin%3A%202em%200%3B%20height%3A%20100%25%22%3E%0A%3Cdiv%20style%3D%22margin%3A%202em%200%22%3EInside%3C%2Fdiv%3E%0A%3C%2Fdiv%3E%0AEnd)).

## @fantasai — 2026-07-01

@Loirooriol Because that kind of action-at-a-distance is unpredictable and confusing. It's one thing to have an indefinite size change whether percentages resolve (this can be reasonably expected), but a different thing to have it also change the margin collapsing behavior. IMHO.
