When running a scoped view transition, we need to effectively pause rendering for an element so that it doesn't partially update (the callback is async).

When doing this, the size of the element may change so we have to gutter or overflow the pixels we're displaying here. In order to minimize this,  and possibly improve performance, we should apply `content-visibility: hidden` and `contain-intrinsic-size: auto` to this element while the capture is happening. We can do this automatically.

## @vmpstr — 2026-06-03

Ok, some investigations here:
* Starting view transition already has an effect of layout containment, which means that margins of children escaping is already prevented (so `content-visibility: hidden` would not change anything here)
* In terms of animations, I think we essentially pause the current state:

    > While an element is [skipped](https://www.w3.org/TR/css-contain-2/#skips-its-contents), CSS transitions and animations on the element do not update:
    > * New animations are not created even if newly-applied style would start one.
    > * Existing animations do not advance in their timeline.
    > * Running animations on the element do not end.

    I think that's fine
* The rest of the `content-visibility: hidden` (or specifically skips its content stuff) seems reasonable to me: resize observer shouldn't trigger, find-in-page shouldn't find the contents, etc. Generally, this is a phase which only remains there for the duration of the capture and the dom callback running. The whole point is for us not to expose partially rendered things while the async dom callback changes content. 

I'm happy to say that this is magic, but I would specifically say something along the lines of the following:

For the duration of keeping old painted contents in place (capture + dom callback running), the element skips its contents but retains its last rendered size. I'd point to stuff like remembered size for c-i-s: auto and skips its content in css-contain-2.

## @vmpstr — 2026-07-15

Another consideration here is a11y tree. If we use `content-visibility: hidden`, the content is going to temporarily disappear from the a11y tree. That's not ideal.

With that, I think the best course of action is to say that we treat this content as if it had `content-visibility: auto` but consider it offscreen. This means that any other means that would make this element relevant still apply (other than visibility), and it would still be in the a11y tree as any other `content-visibility: auto` contents.
