Having the ability to feature detect style queries has come up on several occasions:

* Chats with developers
* My own experiments
* The [most recent ShopTalk episode](https://shoptalkshow.com/716/), where @davatron5000 and @chriscoyier mention it at around the 40:00 mark
* The most recent CSSWG Call in which we discussed https://github.com/w3c/csswg-drafts/issues/13678#issuecomment-4556655505, where @LeaVerou brought up style queries feature detection.

There is a workaround one can use here — namely actively use style queries and detect it that way: https://www.bram.us/2024/10/06/feature-detect-style-queries-support-in-css/ — but there seems to be a need to do this in a simpler way.

Things to note here:

- Using `at-rule()` here won’t cut it, as `at-rule()` does not accept descriptors, preludes, or full blocks.
- Using a tell-tale property/value pair — such as `container-type: anchored` for example — won’t cut it either, as there is no `container-type: style` _(because all containers are implied style containers)_.
- A lot of time has passed since Chrome first shipped it in March 2023 and Safari Sept 2024, so any check would yield a lot of false negatives.

Some possible solutions:

- Extend `at-rule()` to accept preludes _(but to what extent?)_
- A new [@supports named-feature()](https://drafts.csswg.org/css-conditional-5/#typedef-supports-named-feature-fn) for this. E.g. `style-queries`.
  - We might want to be careful here to have it indicate that it’s custom props only. If a UA ends up implementing style queries for regular properties, then using `style-queries` here might be too broad.
- Bring back the `style` keyword for the `container-type` property, simply for the sake of feature detection?
- Leave it as is, because
  - There is a documented workaround.
  - The load of false negatives.

> Would `@supports-condition` be sufficient for this? [#12622](https://github.com/w3c/csswg-drafts/issues/12622)

Yeah, it would catch that.

But I’d also argue that authors would then be dragging this from stylesheet to stylesheet, whereas a `named-feature()` seems like a nicer thing to have as an author.

But also OTOH: `named-feature()` is reserved for detecting those things that you can’t detect by just parsing code, so adding `style-queries` would go against that.
