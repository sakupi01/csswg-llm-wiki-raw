We resolved in https://github.com/w3c/csswg-drafts/issues/3720#issuecomment-3999235838 to add `hairline` to `<line-width>` and to also extend `<line-width>` to more properties including `gap`, `stroke-width`, and `text-decoration-thickness`. I have two follow-up questions:

- Do we want to resolve that all properties accepting `<line-width>` are pixel-snapped like `border-width`?
- Are there other properties we should add to this list?

<!-- comment id=4001332813 author=kbabbitt created=2026-03-05T01:10:10Z url=https://github.com/w3c/csswg-drafts/issues/13599#issuecomment-4001332813 -->
## @kbabbitt — 2026-03-05

> Do we want to resolve that all properties accepting <line-width> are pixel-snapped like border-width?

For `text-decoration-thickness` I think this would be okay, maybe even desirable. For `gap` and `stroke-width` I'd be worried about breaking existing content.

<!-- comment id=4001478825 author=SebastianZ created=2026-03-05T01:41:08Z url=https://github.com/w3c/csswg-drafts/issues/13599#issuecomment-4001478825 -->
## @SebastianZ — 2026-03-05

> For `gap` and `stroke-width` I'd be worried about breaking existing content.

FWIW, @tabatkins already added it to `stroke-width` in https://github.com/w3c/csswg-drafts/commit/05005de971b9a63cc3df11f997378c91da77a19c.
As it is a strict extension to those properties, I don't think there is any risk of breaking existing content.
