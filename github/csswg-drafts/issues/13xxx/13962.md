The CSS Inline specification recently changed `vertical-align` to be a shorthand, and Firefox adjusted its implementation accordingly:
- https://bugzilla.mozilla.org/show_bug.cgi?id=1830771

However, current Typed OM WPT still expects many `vertical-align` values to reify into Typed OM objects:
- https://github.com/web-platform-tests/wpt/blob/master/css/css-typed-om/the-stylepropertymap/properties/vertical-align.html
- https://wpt.fyi/results/css/css-typed-om/the-stylepropertymap/properties/vertical-align.html

At the moment, Typed OM shorthand handling generally appears to treat shorthands as unsupported values (`CSSStyleValue`).

## @janvarga — 2026-05-25

Typed OM spec:
'overflow'
    For both specified and computed values, reify as a CSSStyleValue (unsupported)

'overflow-x'
    For both specified and computed values, reify an identifier from the value and return the result.

'overflow-y'
    For both specified and computed values, reify an identifier from the value and return the result.

WPT for `overflow-x` and `overflow-y`
https://github.com/web-platform-tests/wpt/blob/master/css/css-typed-om/the-stylepropertymap/properties/overflow.html
https://wpt.fyi/results/css/css-typed-om/the-stylepropertymap/properties/overflow.html?label=experimental&label=master&aligned

So the spec in this case does specify behavior for `overflow`, but there's no WPT it seems.

Quick console check:
```
document.body.attributeStyleMap.set("overflow", new CSSKeywordValue("auto"));
```
Chrome throws a TypeError and Safari/Firefox succeeds (I think this is because internally both serialize to css text and use CSSOM to set the value)

```
document.body.style.overflow = "auto";
console.log(document.body.attributeStyleMap.get("oveflow"));
```
All three throw a TypeError.
