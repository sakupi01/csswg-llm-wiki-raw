How should the shorthand associated with a [coordinated value list](https://drafts.csswg.org/css-values-4/#linked-properties), such as the [`animation`](https://drafts.csswg.org/css-animations/#animation) shorthand property or the [`scroll-timeline`](https://drafts.csswg.org/scroll-animations/#scroll-timeline-shorthand) shorthand property, serialize when the [coordinating list base property](https://drafts.csswg.org/css-values-4/#coordinating-list-base-property) has fewer values than a non base property?

For example, how should the computed style (via getComputedStyle) for `scroll-timeline` serialize when the following properties have been set:

```css
 scroll-timeline-name: '--a, --b;
 scroll-timeline-axis: 'inline, inline, inline;
```

(example comes from https://wpt.fyi/results/scroll-animations/css/scroll-timeline-shorthand.html)

Should it be `--a inline, --b inline`, as the test expects, or `--a inline, --b inline, --a inline` which would be closer to what `animation` and `transition` serializations would do?

<!-- comment id=3910269601 author=emilio created=2026-02-16T19:44:11Z url=https://github.com/w3c/csswg-drafts/issues/13500#issuecomment-3910269601 -->
## @emilio — 2026-02-16

Yes, that's correct. Serializing shouldn't change the computed style at all (even if some of the extra values wouldn't be used due to the different lengths). Changing the length of the computed style can have other observable effects, e.g. via inheritance (consider a descendant doing `scroll-timeline-name: inherit;` or so).

<!-- comment id=3911662126 author=weinig created=2026-02-17T02:28:49Z url=https://github.com/w3c/csswg-drafts/issues/13500#issuecomment-3911662126 -->
## @weinig — 2026-02-17

Ok, thinking through this for some additional cases:

```
scroll-timeline-name: --a, --b, --c;
```

Here, the computed value of `scroll-timeline-name` is, `--a, --b, --c`, and the computed value of `scroll-timeline-axis` is `block` (its initial value), so the computed value of `scroll-timeline` would have to be the empty string.

I think that means the rule is that for coordinated value lists:

"If you specify more than one value for **any** of the longhands, but **not all** of the longhands, the shorthand will serialize as the empty string."

Does that sound right to you?

## @fantasai — 2026-05-08

> "If you specify more than one value for any of the longhands, but not all of the longhands, the shorthand will serialize as the empty string."

This would cause forwards-compat problems as we introduce new longhands. I think if a longhand is the initial value (i.e. can be omitted from the shorthand), then the shorthand should still serialize.
