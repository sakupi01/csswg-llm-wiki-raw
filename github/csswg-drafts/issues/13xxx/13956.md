[CSS Cascade 5](https://drafts.csswg.org/css-cascade-5/#fragments) says that "where individual fragments are given different [specified values](https://drafts.csswg.org/css-cascade-5/#specified-value), any values that resolve based on the [computed value](https://drafts.csswg.org/css-cascade-5/#computed-value) of other properties", such as `currentColor` or `em` units, are resolved per box fragment.

CSS Pseudo 4 defines `::first-line` inheritance such that the portion of a child element on the first line inherits applicable inherited properties from `::first-line`: https://drafts.csswg.org/css-pseudo-4/#first-line-inheritance

[CSS Filter Effects 1](https://drafts.fxtf.org/filter-effects-1/#FilterProperty) says a non-`none` `filter` creates a stacking context, and that the "elements descendants are rendered together as a group with the filter effect applied to the group as a whole".

How should these rules interact for an inline element fragmented across `::first-line` and non-first-line fragments?
```html
<style>
  div { color: blue }
  div::first-line { color: green }
  span { filter: drop-shadow(100px 0 0 currentColor) }
</style>
<div><span>first line<br>second line</span></div>
```

Should `drop-shadow(currentColor)` resolve `currentColor` separately for the first-line and non-first-line fragments? If so, does that imply separate filter effect groups for those fragments, or should the element still produce a single filter group?

The distinction is observable even for filters that do not depend on `currentColor`:
```html
<style>
  div { color: blue; line-height: 7px }
  #fl::first-line { color: green }
  span { filter: opacity(.5) }
</style>
<div id="fl"><span>███████<br>███████</span></div>
```
(simplified example from https://issues.chromium.org/issues/40758581#comment14)

If `::first-line` fragmentation creates separate filter effects, this behaves like two separately filtered inline fragments. If `filter` remains one grouped effect for the element, the whole two-line source graphic is filtered together.

This came up while investigating Chromium issue https://crbug.com/40758581, where filter: `drop-shadow(... currentColor)` does not currently take ::first-line into account. A straightforward implementation can fix the `currentColor` result by creating a separate first-line filter effect, but that also changes grouping semantics for filters such as `opacity(.5)`.

Related issues:
- https://github.com/w3c/csswg-drafts/issues/1510
- https://github.com/w3c/csswg-drafts/issues/6383
- https://github.com/w3c/fxtf-drafts/issues/621

Which behavior is intended for filter on fragmented inline elements?
