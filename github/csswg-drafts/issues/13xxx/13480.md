Given this testcase: [scroll-timeline.html](https://github.com/user-attachments/files/25218711/scroll-timeline.html)

On clicking the "Change" button, it changes the animation scroller from `#outer` to  to `#inner`.
Corresponding `timeline.source` updates as well on WebKit/Blink. However, the timing differs slightly:

* On WebKit, the change is reflected after rAF.
* On Blink, the change is reflected immediately afterwards, before rAF.

Should the change be reflected synchronously or asynchronously?

(cc @emilio @BorisChiou @jwatt)

<!-- comment id=3944158710 author=graouts created=2026-02-23T11:16:50Z url=https://github.com/w3c/csswg-drafts/issues/13480#issuecomment-3944158710 -->
## @graouts — 2026-02-23

There is plenty of instances where a getter synchronously updates style throughout the Web Animations API, see https://drafts.csswg.org/css-animations-2/#requirements-on-pending-style-changes. I think it would make sense thus to do the same for the `source` and `axis` getters on `ScrollTimeline` and the `subject` getter on `ViewTimeline`.

Cc @birtles as well.
