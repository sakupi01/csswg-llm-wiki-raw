Somewhat separately from the ongoing [`segments` vs `intersections` discussion](https://github.com/w3c/csswg-drafts/issues/12784#issuecomment-3286670795), we still have an open question about **whether multicol row gaps should allow row decorations to break**, similar to the behavior in grid containers.

From the discussion linked above, it seems clear that the _**default**_ behavior we want is for the row decoration to run continuously across the multicol container, without breaking:

<img width="554" height="192" alt="Image" src="https://github.com/user-attachments/assets/6b85629d-401c-429a-9d43-e123e29c2667" />

However, it still might make sense for authors should have the _**option**_ to intentionally break this decoration, mirroring what grid (or flex) containers could allow, resulting in something like this:

<img width="1125" height="346" alt="Image" src="https://github.com/user-attachments/assets/3dbe95a5-bdc1-42d5-9abf-f1e4bce59895" />

One concern, raised by @rachelandrew, is that broken row decorations in multicol layouts may complicate or confuse the reading order, but perhaps the fact that the default behavior would be for the row decoration to run continuously across the multicol container is enough to alleviate this.
Nevertheless, if this is generally considered to be _very_ detrimental to readability, then perhaps we should **not** allow breaks at all.

So essentially, should we or should we not give authors the option? So far, we tend to lean towards giving authors the option, since this would make the behavior somewhat consistent across display types.

Thanks!

## @kbabbitt — 2026-01-19

Provided we have an `auto` value that gives a sensible default as suggested in #13127, I lean towards allowing this but could be swung against. Breaking row decorations at intersections in Multicol will, in the cases I can imagine, be a bad idea because it can make the reading order unclear. But right now I don't feel that's a strong enough reason to disallow it entirely. Providing the option for row decoration breaks would be consistent with how Grid and Flex operate, and maybe there's some use case I haven't imagined yet where it is what an author wants in Multicol.
