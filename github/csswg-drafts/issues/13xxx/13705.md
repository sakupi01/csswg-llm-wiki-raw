Given that:

1. Two features from CSS Color 5 are already listed in [Safe to Release pre-CR Exceptions](https://drafts.csswg.org/css-2026/#CR-exceptions):

 - `color-mix()`
 - relative colors

2. CSS Color 5 is listed in [Modules with Rough Interoperability](https://drafts.csswg.org/css-2026/#rough-interop)

3. The WPT results are fairly good

<img width="1158" height="260" alt="Image" src="https://github.com/user-attachments/assets/0e7d9f04-d55b-4f70-9064-026c21545b88" />

4. Wide review was [already done](https://github.com/w3c/csswg-drafts/issues/7297) (but in 2022 so would need a second round)

then I propose the following:

- stabilize, any new features get punted to CSS Color 6
- work to clear off the [remaining issues](https://github.com/w3c/csswg-drafts/issues?q=state%3Aopen%20label%3A%22css-color-5%22&page=1) currently **26** open, **165** closed
- quick second round of review, for changes since 2022
- request CR snapshot, preferably before 2027.

From the [18 June 2026 WD](https://www.w3.org/TR/2026/WD-css-color-5-20260618/)

> The following features are at-risk, and may be dropped during the CR period:
>    Custom Color Spaces, `@color-profile`, `device-cmyk()`, `Relative Alpha Colors` 

I would prefer to leave all of those in the spec for CR Snapshot; they can still be punted to Color 6 later, if implementation support is lacking (or hard to measure in an automated way).

## @u1f992 — 2026-11-11

Vivliostyle implements only `device-cmyk()`; the ICC-based CMYK and 7-color parts are not implemented yet. Prince and AH Formatter do not implement them either. Each of the three has its own option for setting an ICC profile as the PDF output intent, and leaves the colorimetric interpretation of DeviceCMYK to the PDF viewer. So I think the test that works for now is to check the `k`/`K` operators in the PDF, for `device-cmyk()` only.

## @faceless2 — 2026-11-11

I hadn't spotted you were doing a review for Color-5. We (BFO Publisher) support `@color-profile` and `device-cmyk` but we don't (yet) support `alpha()`. I haven't looked at this for a while, but I know we also support `color-mix` on components named in an ICC profile, the relatively color-syntaxes for CMYK and ICC etc.

It's probably worth underling that PDF (the current version) only accepts 1, 3 or 4 component ICC profiles - I believe there is work underway on changing this, I'm not involved in it so can't comment but I know it's not imminent. You can use color-spaces with more than four components in PDF, but not by embedding an ICC profile.

Given these are exceptionally rare and, realistically will only ever be used for print, if you're going to punt anything to Color-6 it might be a good idea to punt ICC where numc > 4. There's very little point in specifying them if the target format they're intended for can't support them.
