Given that:

1. Two features from CSS Color 5 are already listed in [Safe to Release pre-CR Exceptions](https://drafts.csswg.org/css-2026/#CR-exceptions):

 - `color-mix()`
 - relative colors

2. CSS Color 5 is listed in [Modules with Rough Interoperability](https://drafts.csswg.org/css-2026/#rough-interop)

3. The WPT results are fairly good

<img width="1158" height="260" alt="Image" src="https://github.com/user-attachments/assets/0e7d9f04-d55b-4f70-9064-026c21545b88" />

4. Wide review was [already done](https://github.com/w3c/csswg-drafts/issues/7297) (but in 2022 so would need a second round)

then I propose the following:

- stabilize, any new features get punted to CSS Color 6
- work to clear off the [remaining issues](https://github.com/w3c/csswg-drafts/issues?q=state%3Aopen%20label%3A%22css-color-5%22&page=1) currently **26** open, **165** closed
- quick second round of review, for changes since 2022
- request CR snapshot, preferably before 2027.

## @svgeesus — 2026-06-18

From the [18 June 2026 WD](https://www.w3.org/TR/2026/WD-css-color-5-20260618/)

> The following features are at-risk, and may be dropped during the CR period:
>    Custom Color Spaces, `@color-profile`, `device-cmyk()`, `Relative Alpha Colors` 

I would prefer to leave all of those in the spec for CR Snapshot; they can still be punted to Color 6 later, if implementation support is lacking (or hard to measure in an automated way).
