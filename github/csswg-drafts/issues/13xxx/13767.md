https://drafts.csswg.org/css-link-params-1/#funcdef-param says:

```
<param()> = param( <dashed-ident> , <declaration-value>? )
```

Per https://drafts.csswg.org/css-values-4/#comb-comma that means that the comma can be omitted, but... what's the point? It behaves as if the param wasn't there to begin with...

cc @tabatkins

## @Loirooriol — 2026-04-06

> If the [`<declaration-value>`](https://drafts.csswg.org/css-syntax-3/#typedef-declaration-value) is omitted, it represents an empty value.

Presumably having a custom environment variable with an empty value is different than if it doesn't exist?
E.g. with `param(--foo,)`

```css
fill: green env(--foo); /* green */
fill: green env(--bar); /* invalid at computed-value time */
```

Just like with `var()`:

```css
--foo:;
background: green var(--foo); /* green */
background: green var(--bar); /* invalid at computed-value time */
```

<!-- comment id=4191437159 author=emilio created=2026-04-06T09:38:10Z url=https://github.com/w3c/csswg-drafts/issues/13767#issuecomment-4191437159 -->
## @emilio — 2026-04-06

Well, sure, but `param(--foo, )` seems like relatively uncommon to write to make `param(--foo)` the same?

<!-- comment id=4195408142 author=tabatkins created=2026-04-06T22:42:46Z url=https://github.com/w3c/csswg-drafts/issues/13767#issuecomment-4195408142 -->
## @tabatkins — 2026-04-06

Yes, passing an empty param is indeed different from not passing a param; a missing param will cause `env(--foo)` to fallback.

The fact that this means `param(--foo)` is technically equivalent to `param(--foo, )` is more or less an accident of parsing. I don't see any particular reason to make it different? But I don't feel strongly either way about this.

<!-- comment id=4732504537 author=tabatkins created=2026-06-17T15:53:11Z url=https://github.com/w3c/csswg-drafts/issues/13767#issuecomment-4732504537 -->
## @tabatkins — 2026-06-17

To say a bit more: it's just that `param()` looked a lot like `var()` or `attr()`, with an arbitrary chunk coming at the end, so it seemed to make sense at the time to match them closely. But as I said, I don't feel strongly about this; semantically, the passed value definitely is different from an optional fallback.
