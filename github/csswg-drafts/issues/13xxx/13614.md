[The spec](https://drafts.csswg.org/css-values-5/#typedef-syntax-single-component) defines `<syntax-single-component> = '<' <syntax-type-name> '>' | <ident>` but Chrome (the only implementer) [disallows CSS wide keywords and the `default` keyword](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/css/css_syntax_definition.cc;l=138;drc=21558256637445c896f3905c198b8a1a31722790) (i.e. it only allows `<custom-ident>` rather than `<ident>`).

By allowing only `<custom-ident>` it would also align better with the syntax described by [the css-properties-values-api spec](https://drafts.css-houdini.org/css-properties-values-api-1/#syntax-component-name) (which I believe this intends to replace) as that defines it's equivalent "syntax component name" as `A sequence of code points which is either a data type name, or a sequence that can produce a <custom-ident>.` (i.e.  `'<' <syntax-type-name> '>' | <custom-ident>`)

## @cdoublev — 2026-03-08

I suspect that CSS-wide keywords, and perhaps `default`, should not be allowed in `@property/syntax` (w3c/css-houdini-drafts#1076), but allowed in `@mixin`, `@function`, `attr()`. And authors may want case-insensitive identifier parameters of `@function`/`@mixin`, which is not possible with `<custom-ident>` (w3c/csswg-drafts#11124).
