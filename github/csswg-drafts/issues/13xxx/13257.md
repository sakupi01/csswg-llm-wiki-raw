The overflow definition [has](https://drafts.csswg.org/css-overflow-3/#propdef-overflow-y):

> Applies to: block containers [[CSS2]](https://drafts.csswg.org/css-overflow-3/#biblio-css2), flex containers [[CSS3-FLEXBOX]](https://drafts.csswg.org/css-overflow-3/#biblio-css3-flexbox), grid containers [[CSS3-GRID-LAYOUT]](https://drafts.csswg.org/css-overflow-3/#biblio-css3-grid-layout)

However that predates `clip`.

Firefox has since ~forever supported `clip` (used to be `-moz-hidden-unscrollable` on inline boxes).

I don't feel too strongly either way, but should we consider making `clip` work on inline boxes?

cc @Loirooriol

## @Loirooriol — 2025-12-22

No strong opinion, but there is some overlap between `overflow: clip` and `contain: paint`, and the latter doesn't affect inline boxes. Being inconsistent would maybe be a bit weird.

<!-- comment id=3792800616 author=fantasai created=2026-01-23T22:17:24Z url=https://github.com/w3c/csswg-drafts/issues/13257#issuecomment-3792800616 -->
## @fantasai — 2026-01-23

If there isn't a strong use case for it, I think we should keep things as-is. If you're clipping, you likely also are wanting to use `inline-block` anyway.
