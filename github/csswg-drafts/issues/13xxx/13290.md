## @rifmj — 2026-10-31

One more data point for this question: an example in §3.5.1 is correct only if `<scope-end>` is matched relative to `:scope`. Under the current text it is not.

CSS Cascading and Inheritance Level 6, Editor's Draft 28 April 2026, §3.5.1 Effects of @scope (#scope-effects), last block of example #example-463550a5:

> However, authors can use the child combinator and universal selector to create scope boundaries that overlap, such that the inner scope root is part of both scopes:

```css
@scope ([data-scope='main-component']) to ([data-scope] > *) {
  p { color: red; }

  /* both sections are part of the outer scope */
  section { background: snow; }
}
```

applied to the second HTML snippet of the same example (the spec writes `<p>...<p>`; closing tags added here):

```html
<section data-scope="main-component">
  <p>...</p>
  <section data-scope="sub-component">
    <p>...</p>
  </section>
</section>
```

The current definitions. §3.5.2:

> <scope-end> is a <selector-list> selector used to identify any scoping limits.

§3.5.4:

> For each scope created by a scoping root, its scoping limits are set to all elements that are descendants of the scoping root and that match <scope-end>, interpreting :scope and & exactly as in scoped style rules.

§3.5, an element is in scope only if

> It is not an inclusive descendant of a scoping limit.

Reading 1 (current text): `[data-scope] > *` is an ordinary selector. The outer `section` has `[data-scope]`, so both of its children match: the first `p` and the inner `section`. Both are scoping limits and both are out of scope, together with everything inside the inner `section`. Result: `section { background: snow }` applies to neither section (under §3.5.3 the bare `section` is relative to `:scope`, so it does not match the root itself), and `p { color: red }` applies to no `p` at all. The comment "both sections are part of the outer scope" is false.

Reading 2 (`<scope-end>` relative to `:scope`, as this issue proposes): the limit is `:scope [data-scope] > *`, which matches only the children of the inner `section`. Then the inner section is in both scopes and the outer `p` is red, as the example says.

The difference arises while finding the scope, before any cascade sorting. So the example and the normative text disagree today. Either the example needs a different limit, such as `to (:scope [data-scope] > *)`, or the resolution here makes `<scope-end>` relative and the example becomes correct without change.
