CSS Grid and CSS Flex both ignore `align-self: stretch` and `align-items: stretch` when an item has a specified size.  Part of our motivations in this discussion: https://github.com/w3c/csswg-drafts/issues/10275#issuecomment-3666150085 were to fill out the masonry layout visually, avoiding empty bottoms.

Generally, it makes sense to me that web authors would just expect the same behavior as CSS Flex and CSS Grid, and not specify item sizes when also applying `align-items: stretch` to them. The concern I have here is a case where authors want uniformly-sized items, but want the last row to fill out the page with stretch. If we ignore the explicit sizes, we would end up with:
<img width="471" height="582" alt="Image" src="https://github.com/user-attachments/assets/8e1bef52-b1cf-46dd-8f33-321d1465975f" />

while if we were to follow the explicit sizes we'd get something more like:
<img width="442" height="589" alt="Image" src="https://github.com/user-attachments/assets/34b55e30-ec1a-490b-a887-c699645e181a" />

I think it makes sense to respect explicit sizes -- if an author is specifying explicit sizes, it's likely that they want to maintain that specific size of the item throughout the layout. It would also be the most expected behavior, in parity with CSS Grid and CSS Flex.

@Loirooriol I was referring to explicitly sized items, not auto-sized ones! I agree that auto-sized items should be affected.

Also, if I'm understanding the discussion correctly, the plan had been to only apply stacking-axis alignment to items above a span, where the placement of the span caused excess space, or the last item in a track.  So I wouldn't be selecting the items explicitly, it would be something more like the container having `align-items: stretch`, such that the last items end up being the only ones having the space to stretch.

@celestepan You are right: https://drafts.csswg.org/css-grid-3/#stacking-self-alignment

That said, it would seem very inconsistent to me to make stretch self-alignment override non-auto sizes in the stacking axis of grid lanes.

I think would rather add a new property specific for grid-lanes, or add a `strong-stretch` that takes precedence in all layouts, or something along these lines.

<!-- comment id=4836735628 author=celestepan created=2026-06-29T20:28:20Z url=https://github.com/w3c/csswg-drafts/issues/13950#issuecomment-4836735628 -->
## @celestepan — 2026-06-29

@Loirooriol I'm in agreement that we shouldn't be overriding nan-auto sizes in the stacking axis.  

I think adding a new keyword is a good idea, as I could see that being useful in the other layouts as well.  I don't mind `strong-stretch`, but am open to other suggestions from the working group.  Something `stretch-override` or `stretch-all` might also be more intuitive to the actual function.

<!-- comment id=5136105410 author=celestepan created=2026-07-30T20:47:09Z url=https://github.com/w3c/csswg-drafts/issues/13950#issuecomment-5136105410 -->
## @celestepan — 2026-07-30

@fantasai to make sure I'm understanding correctly, would an example of using `min-height` look like:
```<div style="min-height: 40px; align-item: stretch;" />```
And then the item will always be at least 40px, and stretch if necessary?  If that's the case, I agree that using `min-height` (and `max-height`, in the case authors don't want their items to stretch beyond a certain point) would be a good idea!

However, I'm not entirely sure that resolves the original case, which is where if authors _only_ set the explicit height of the item, should we stretch the item or not?  I still think that we shouldn't, and if authors want some more flexibility, they can use `min-height` as you suggested.
