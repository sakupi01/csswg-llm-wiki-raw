> - **content image**  
>   An element of the host language representing a static image or an animated image, at the exclusion of videos or programmatic images.
>
> - **decorative image**
>   An image inserted into the document rendering by CSS, through such properties as `background-image` or `border-image`.

This leaves open to interpretation which of these two definitions an image included with the `content` property falls into, especially if used with `attr()` to retrieve the resource location from the host document – this is currently not specified to work author-side (except within certain pseudo-elements), but is the logical browser-side implementation in CSS of replaced elements that represent an image as defined by the host language. 

I also note that the term _replaced element_ is not used even once in the draft and the CSS type [`<image>`](https://drafts.csswg.org/css-images-3/#typedef-image) is not referenced anywhere either. 

As far as I can tell, neither the CSS Images nor the Backgrounds module prohibits files using a video format within `<image>`, so it is hard to argue for this module not covering `<video>` as well.
