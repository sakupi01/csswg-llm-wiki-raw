[§14.1. Resolving sRGB values](https://drafts.csswg.org/css-color-4/#resolving-sRGB-values)

> This applies to:
> - [system colors](https://drafts.csswg.org/css-color-4/#css-system-colors)
> - [deprecated-colors](https://drafts.csswg.org/css-color-4/#deprecated-system-colors)

[§14.5. Resolving other colors](https://drafts.csswg.org/css-color-4/#resolving-other-colors)

> This applies to [system colors](https://www.w3.org/TR/css-color-4/#css-system-colors) (including the [`<deprecated-color>`](https://www.w3.org/TR/css-color-4/#typedef-deprecated-color)s), [`transparent`](https://www.w3.org/TR/css-color-4/#valdef-color-transparent), and `currentcolor`.

## @Loirooriol — 2026-02-05

I was looking at the 1st definition, but it wasn't clear to me that "deprecated-colors" means "deprecated system colors".
The 2nd definition makes it clearer with the parenthetical.

Also, from the 2nd definition:
> The declared value for each [&lt;system-color>](https://drafts.csswg.org/css-color-4/#typedef-system-color) keyword and [&lt;deprecated-color>](https://drafts.csswg.org/css-color-4/#typedef-deprecated-color) keyword is itself.

This is not clear in the 1st definition:
> If the sRGB color was explicitly specified by the author as a [named color](https://drafts.csswg.org/css-color-4/#named-color), or as a [system color](https://drafts.csswg.org/css-color-4/#css-system-colors), the [declared value](https://drafts.csswg.org/css-cascade-5/#declared-value) is that named or system color, converted to [ASCII lowercase](https://infra.spec.whatwg.org/#ascii-lowercase).

Does "system color" include deprecated ones? Above they are listed separately, so I would think it's not included, but then

> Otherwise, the declared, computed and used value is the corresponding sRGB color

which is wrong for deprecated system colors.

So please don't just use the 1st definition without making all of this clear.

## @alisonmaher — 2026-02-05

> > However, such colors must not be altered by 'forced colors mode'.

> @alisonmaher Do you recall the morivation for this?

Tried to find an old PR that might have had more context around this but came up short.

My guess is that this may be because we decided that in forced colors mode, we don't override a property if it is already set to a system color. So, for example, if an author sets `color: ButtonText` we won't override this to `color: CanvasText`. My read of the text is that this may allow us to preserve the author system color to ensure this is rule is maintained in forced colors mode.
