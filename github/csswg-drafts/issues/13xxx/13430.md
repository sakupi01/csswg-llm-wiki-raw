We're doing work to add elements to HTML that represent menus (see [explainer](https://open-ui.org/components/menu.explainer/) and [PR](https://github.com/whatwg/html/pull/12011)).  The initial work is for application menus, though we hope to follow that with similar work covering navigation menus, which would probably reuse many aspects of the design (including this choice of pseudo-element).

One issue we have is how to style the marker that indicates that a menu item opens a submenu.  This is typically a triangular marker at the right side, such as the one next to "Zoom" in this screenshot from the explainer:
![A menubar with an open View menu.  The first item in the View menu is a Zoom submenu, which is also open.  The Zoom submenu's label has a rightward pointing triangle at the right edge of the View menu, pointing to the Zoom submenu.](https://open-ui.org/images/menu-elements-example-2.png)

I think there are a few different options for how to style this, and we should choose one.  The main options I see are:

1. Use `::after`.
   * **Pro**: Matches the way a developer would typically have built this themselves if it weren't a platform feature.
   * **Con**: Uses something that maybe should be left for web developers to use rather than being part of a platform feature.
2. Use `::marker`.
   * **Pro**: Matches what we do for `<details>`/`<summary>` which is styled as a list-item and thus has a similar expansion triangle (although at the inline-start edge).
   * **Con**: Basically all other uses of `::marker` show up at the beginning rather than the end (for list items and for `<details>`/`<summary>`)
3. Create a new pseudo-element. 
   * **Pro**: Matches what we did for `option::checkmark` (see #10857 and #10908).
   * **Con**: Yet another pseudo-element.

## @dbaron — 2026-02-05

I think a bunch of possible names take the form `::A-B` where:
* `A` can be `submenu` or `reveal` [Edit: or `expand`]
* `B` can be `icon`, `indicator`, `marker`, or `arrow`

I'm curious if others have opinions within that space of 8 names, or other options (either additional A or B variants, or other options entirely).

<!-- comment id=3856043008 author=Crissov created=2026-02-05T20:33:04Z url=https://github.com/w3c/csswg-drafts/issues/13430#issuecomment-3856043008 -->
## @Crissov — 2026-02-05

In old drafts of css-ui, there was `display: icon` which fits this situation conceptually because the submenu is _displayed as_ only a triangle icon until it gets revealed fully – except that this icon stays visible then! 

Anyway, the important design question this raises is: Do you consider this pseudo-element to be a part of the parent (menu entry) or of the child (submenu block)?

If the latter, I would say `::marker` was sufficient. 

If you really must introduce yet another pseudo-element for the former, a handful of relevant terms to inspire bikeshedding are: _chevron, nest, reveal, fold, expand, cascade_.

Please note, that keyboard shortcuts are often shown in the same place as this indicator, although I’d say they belong in `::after`.

## @dbaron — 2026-02-05

This is associated with the menuitem, not the submenu.  It has to show when the submenu is not visible, so that the user knows that the item opens a submenu.  (Also note that there is not a parent-child relationship between the menuitem and the submenu that it invokes.)

## @dbaron — 2026-02-17

Some notes about existing names for this.  Based on the list in https://open-ui.org/components/menu.research/ I found:
* https://ant.design/components/menu has `expandIcon` as part of its API surface
* https://spectrum.adobe.com/page/menu/ calls this a chevron but doesn't have API for it
* https://www.lightningdesignsystem.com/2e1ef8501/p/40f658-menu requires that the user explicitly add a `utility:chevronright` icon for submenus to make the indicator show up!

We could use the name "chevron" given that precedent, but I think maybe "arrow" is clearer?

Out of the options in https://github.com/w3c/csswg-drafts/issues/13430#issuecomment-3855449759 I think my preference would probably be one of `::submenu-icon` or `::expand-arrow` or `::reveal-arrow`.

## @fantasai — 2026-02-17

We're currently using `::reveal-icon` in css-forms for something unrelated (password reveal), and `::picker-icon` for a related concept (opening a select menu). Maybe we could re-use `::picker-icon`?
