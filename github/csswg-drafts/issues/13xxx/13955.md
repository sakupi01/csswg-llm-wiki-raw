Discussion in #13807 [surfaced](https://drafts.csswg.org/scroll-animations-1/#timeline-scoping:~:text=an%20inactive%20timeline) that the any failed timeline lookup will return the inactive timeline.

WebKit and Blink currently do not do this. In fact, both engines seem to return the inactive timeline only if that name is present for `timeline-scope` up the ancestor chain, considering [this](https://github.com/user-attachments/files/28156324/timeline-change.html) testcase. That is, on STP and Chrome Canary, toggling in and out of a non-existing timeline by clicking "Toggle Scroll Timeline" twice causes the rightmost column (Whose non-existing timeline name isn't scoped) behave identically to the leftmost column (That specifies `animation-timeline: none` ending up with the null timeline), with the animation no longer responding to scroll.

FWIW I think the spec-specified value is consistent and makes sense, but I wanted to make sure there is no back-compat issue here.
