## @kripod — 2026-10-30

The [same commit](https://github.com/w3c/csswg-drafts/commit/1a57a4025c8778dab45ef8d5fbd482e4d6c4ebce) also removed three other parts of the `cursor` section, each from an earlier resolution:

- `pointer` is “often rendered as the backside of a hand with the index finger extended” (#1936, [May 9, 2018](https://github.com/w3c/csswg-drafts/issues/1936#issuecomment-387807607))
- Browsers must apply `cursor: pointer` to links (#2664, [June 6, 2018](https://github.com/w3c/csswg-drafts/issues/2664#issuecomment-395243086))
- The text cursor must follow the writing mode. The spec says “may” again now. (#3196, [October 17, 2018](https://github.com/w3c/csswg-drafts/issues/3196#issuecomment-430693269))

The changelog at the end of the spec still mentions most of these, so I think they went missing by accident. #13001 came from that commit too.

#14251 is related. On October 21, 2026, the Working Group [agreed](https://github.com/w3c/csswg-drafts/issues/14251#issuecomment-6322899089) to use `cursor: pointer` on buttons, selects, checkboxes and radios, summarized in the minutes as “Pointer = ‘click this thing.’” Without the author sentence, css-ui-4 only says `pointer` “indicates a link,” which contradicts that. Changing the definition itself would be a separate issue.

I can open a PR that restores these parts. cc @frivoal @tabatkins
