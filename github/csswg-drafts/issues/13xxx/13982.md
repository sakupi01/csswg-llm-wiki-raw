I'm splitting this issue out from https://github.com/w3c/csswg-drafts/issues/12437. (See also https://github.com/w3c/csswg-drafts/issues/13980 and https://github.com/w3c/csswg-drafts/issues/13981.)

Let's figure out what the right UA stylesheet rules should be for `::interest-button`. From [this comment](https://github.com/w3c/csswg-drafts/issues/12437#issuecomment-4462208949) (and tweaked according to that conversation), here's a proposal:

```css
[interestfor]::interest-button {
  display: inline-block;
  color: inherit;
  background-color: transparent;
  box-sizing: border-box;
  min-inline-size: 24px;
  min-block-size: max(24px, 1lh);
  vertical-align: middle;
  align-content: center;
  text-align: center;
  user-select: none;
  cursor: help;
}
[interestfor]::interest-button:hover {
  background-color: color-mix(currentColor 10%, transparent);
}
[interestfor]::interest-button:active {
  background-color: color-mix(currentColor 20%, transparent);
}
```

-----

When used with [proposed layout sibling approach](https://github.com/w3c/csswg-drafts/issues/13981#issuecomment-5688449044), and with a developer opt-in of:

```css
::interest-button {
  content: '\24D8' / '';
}
```

## @mfreed7 — 2026-10-01

Since the layout tree issue was [resolved](https://github.com/w3c/csswg-drafts/issues/13981#issuecomment-5934363148) to make `::interest-button` a trailing sibling layout box, I believe the UA stylesheet in the OP here makes sense. It roughly:
- sets up the pseudo element to look "button-ish"
- includes hover/active styling like a button (but we should follow whatever is resolved in https://github.com/w3c/csswg-drafts/issues/14496)
- it has min 24px sizes so that touch target size rules are met
- it aligns the button with the originating element
- is has `cursor: help` to help indicate what it does, and `user-select:none` to avoid selecting it

Suggestions appreciated for improvements. Otherwise, my proposed resolution is:

```
Proposed resolution: accept the proposed UA rules in the OP
```

## @mfreed7 — 2026-10-16

Well, yeah something *like* that can work, and we discussed that on the other issue. See [this discussion, and in particular the comments from @fantasai](https://github.com/w3c/csswg-drafts/issues/13981#issuecomment-5528407811). The issue with it is that the actual code would need to be this, right?

```css
 /* What the author would write */
  --width-of-the-thing: 43.72px; /* width of "HELLO" */
  --borderwidth: 5px;
  --padding: 5px;
  border-width: var(--borderwidth);
  padding: var(--padding);
  margin-inline-end: var(--width-of-the-thing);
  &::after {
    content: 'HELLO' / '';
    margin-inline-start: calc(-var(--width-of-the-thing));
    position: relative;
    left: calc(var(--width-of-the-thing) + var(--borderwidth) + var(--padding)); /* pseudo width + padding end + border */
  }
```

Your version hard-coded the width of "ⓘ" as 24px, and hard-coded the border and padding. Accounting for the width of the content is a pain for developers, right? The sibling approach means the author CSS can just be this:

```css
 /* What the author would write */
  &::interest-button {
    content: 'HELLO' / '';
  }
```

and the result looks the same as the huge CSS chunk above.
