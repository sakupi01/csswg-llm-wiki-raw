The `stroke-width` property grammar appears to be inconsistent between the CSS Fill and Stroke specification and the SVG2 definition referenced by implementations.

CSS Fill and Stroke currently defines:

  `[ <length-percentage> | <line-width> ]#`

which allows comma-separated lists of values.

However:

* SVG2 defines `stroke-width` without `#`
* Chrome, Safari, and Firefox do not accept multiple values such as:  stroke-width: 10px, 20px;

This suggests the `#` may have been introduced accidentally during the `<line-width>` edits or that the specifications are currently out of sync.

Could the spec clarify whether `stroke-width` is actually intended to be list-valued?
