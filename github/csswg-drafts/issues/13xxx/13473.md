Since the FXTF specs got moved into this repo by @svgeesus, recently, I take the chance and question whether we should change their current naming scheme.

The [Masking spec](https://drafts.csswg.org/css-masking-1/) (and the abandoned [Shaders spec](https://drafts.csswg.org/css-shaders-1/)) has "CSS" as prefix in its title and shortname, while all the others don't.
I guess the reason for that is that many of them were initially designed having mainly/only SVG in mind, though that line got blurred over time and more and more CSS features got introduced that are shared between SVG and HTML.

So I wonder, wouldn't it make sense to unify the naming scheme with the other specs, i.e. add the "CSS" prefix to all of them (maybe except those that only contain APIs like Geometry and Web Animations)?

Concretely, these are the changes I have in mind:

| Current title | Current shortname | New title | New shortname | Notes |
|--------|--------|--------|--------|--------|
| Compositing and Blending Module Level 1 | compositing-1 | CSS Compositing and Blending Module Level 1 | css-compositing-1 | - |
| Compositing and Blending Module Level 2 | compositing-2 | CSS Compositing and Blending Module Level 2 | css-compositing-2 | - |
| CSS Fill and Stroke Module Level 3 | fill-stroke-3 | CSS Fill and Stroke Module Level 3 | css-fill-stroke-3 | Why is that Level 3 and not 1? Due to being defined in SVG 2? Then why is Masking Level 1 and not 3? |
| Filter Effects Module Level 1 | filter-effects-1 | CSS Filter Effects Module Level 1 | css-filter-effects-1 | - |
| Filter Effects Module Level 2 | filter-effects-2 | CSS Filter Effects Module Level 2 | css-filter-effects-2 | - |
| Geometry Interfaces Module Level 1 | geometry-1 | CSS Geometry Interfaces Module Level 1 | css-geometry-1 | Maybe not, as it only contains APIs? |
| Motion Path Module Level 1 | motion-1 | CSS Motion Path Module Level 1 | css-motion-1 | - |
| Web Animations Module Level 1 | web-animations-1 | CSS Web Animations Module Level 1 | css-web-animations-1 | Possibly not, as it only contains APIs and might be confused with css-animations-1? Then again, they are related and we also have css-transitions and css-view-transitions. |

Sebastian

## @birtles — 2026-08-17

I don't think we should rename Web Animations since:

- like you said, it will be too easy to confuse with css-animations-1
- also like you said, it's possible to think of Web Animations as providing the primitives that CSS Animations maps onto CSS syntax (although even without the CSS syntax Web Animations is not independent of CSS since it interacts with style resolution)
- level 1 is quite stable (I'm currently working through the issues to get us to CR) so renaming it would cause significant unnecessary churn

Dropping the web-animations-1 label for now. Please re-add if you disagree.

## @Crissov — 2026-08-17

I believe that, in general, a specification (co-)authored by the CSS WG which defines *properties* (or even just *values* for them, e.g. easing functions or counter styles) _should_ have “CSS” at the start of its name and usually (i.e. unless it is something like a *snapshot* or a *profile*) have “Module” at its end (before level or year), whereas one that only specifies selectors (including media queries), attributes or APIs _should not_ have either of those. Its title _may_, however, contain a qualifier like “for CSS” or “in CSS”. (None do at the moment.)

Currently, not just former FXTF/SVG specs fail to meet these expectations. 
Some should be called CSS Modules explicitly:

- [<ins>CSS</ins> Animation Triggers <ins>Module</ins>](https://drafts.csswg.org/animation-triggers/)
- [<ins>CSS</ins> Compositing and Blending Module](https://drafts.csswg.org/compositing/)
- [<ins>CSS</ins> Filter Effects Module](https://drafts.csswg.org/filter-effects/)
- [<ins>CSS</ins> Motion Path Module](https://drafts.csswg.org/motion/)
- [<ins>CSS</ins> Pointer-driven Animations Module](https://drafts.csswg.org/pointer-animations/)
- [<ins>CSS</ins> Scroll-driven Animations Module](https://drafts.csswg.org/scroll-animations/)

Some should drop “CSS” or “Module” from their title, or should be more explicit about what they specify:
- [<del>CSS</del> Custom Highlight <ins>Interfaces</ins> <del>API Module</del>](https://drafts.csswg.org/css-highlight-api/)
- [<del>CSS</del> Shadow <ins>DOM Selectors and Attributes *or just:* Interfaces</ins> <del>Module</del>](https://drafts.csswg.org/css-shadow/)
- [Geometry Interfaces <del>Module</del>](https://drafts.csswg.org/geometry/)
- [Resize Observer <ins>Interfaces</ins> <del>Module</del>](https://drafts.csswg.org/resize-observer/)<!--?-->
- [Web Animations <ins>Interfaces</ins> <del>Module</del>](https://drafts.csswg.org/web-animations/)
- [<del>CSS</del><ins>Stylesheet</ins> Object Model (CSSOM) <del>Module</del>](https://drafts.csswg.org/cssom/)
- [CSSOM View <del>Module</del>](https://drafts.csswg.org/cssom-view/)
