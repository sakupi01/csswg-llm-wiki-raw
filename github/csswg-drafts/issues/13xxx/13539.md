https://drafts.csswg.org/css-align-3/#valdef-justify-self-first-baseline

> The [fallback alignment](https://drafts.csswg.org/css-align-3/#fallback-alignment) for [`first baseline`](https://drafts.csswg.org/css-align-3/#valdef-justify-self-first-baseline) is `safe self-start` (for [self-alignment](https://drafts.csswg.org/css-align-3/#self-align))

https://drafts.csswg.org/css-align-3/#valdef-justify-self-last-baseline

> The [fallback alignment](https://drafts.csswg.org/css-align-3/#fallback-alignment) for [`last baseline`](https://drafts.csswg.org/css-align-3/#valdef-justify-self-last-baseline) is `safe self-end` (for [self-alignment](https://drafts.csswg.org/css-align-3/#self-align))


But browsers seem to use `start` and `end` instead:

```html
<!DOCTYPE html>
<style>
article { display: grid; width: 200px; height: 50px; border: solid }
article > div { background: cyan; direction: rtl }
article > div::before { content: attr(style) }
</style>
<article><div style="place-self: start"></div></article>
<article><div style="place-self: self-start"></div></article>
<article><div style="place-self: end"></div></article>
<article><div style="place-self: self-end"></article></article>
<article><div style="place-self: baseline"></div></article>
<article><div style="place-self: first baseline"></div></article>
<article><div style="place-self: last baseline"></div></article>
```

## @fantasai — 2026-05-27

The intention of the fallback alignment was to match the direction of the baseline alignment. For example, if you have `first baseline` alignment, you want to align towards the first line's side of the paragraph.

I think that intention still make sense, so I would lean towards matching the spec behavior, at least in the axis in which baseline alignment can occur.

<!-- comment id=4556380274 author=tabatkins created=2026-05-27T16:13:07Z url=https://github.com/w3c/csswg-drafts/issues/13539#issuecomment-4556380274 -->
## @tabatkins — 2026-05-27

Strong agree. This appears to best be considered simply an impl bug, in a corner-case that shouldn't be troublesome to fix. Having the fallback match the intended alignment as best as possible seems optimal.
