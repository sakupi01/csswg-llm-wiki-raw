https://drafts.csswg.org/css-align-3/#distribution-block

> For table cells, the behavior of [align-content: normal](https://drafts.csswg.org/css-align-3/#propdef-align-content) depends on the computed value of [vertical-align](https://drafts.csswg.org/css2/#propdef-vertical-align): [top](https://drafts.csswg.org/css-inline-3/#valdef-baseline-shift-top) makes it behave as [start](https://drafts.csswg.org/css-align-3/#valdef-self-position-start) and [bottom](https://drafts.csswg.org/css-inline-3/#valdef-baseline-shift-bottom) makes it behave as [end](https://drafts.csswg.org/css-align-3/#valdef-self-position-end); otherwise [middle](https://drafts.csswg.org/css-inline-3/#valdef-alignment-baseline-middle) makes it behave as [center](https://drafts.csswg.org/css-align-3/#valdef-self-position-center), and all other values make it behave as [baseline](https://drafts.csswg.org/css-align-3/#valdef-justify-self-baseline). [[CSS2]](https://drafts.csswg.org/css-align-3/#biblio-css2)

This is based on CSS2, and obsolete. It needs to explain the behavior in terms of the new longhands: [`alignment-baseline`](https://www.w3.org/TR/css-inline-3/#alignment-baseline-property) and [`baseline-shift`](https://www.w3.org/TR/css-inline-3/#baseline-shift-property).

For example,

 - Should `align-content: normal` behave as `end` for `alignment-baseline: central; baseline-shift: bottom`? Firefox nightly says yes.
 - Should `align-content: normal` behave as `center` for the new `vertical-align: center` / `baseline-shift: center`? Firefox nightly says no.

## @kbhomes — 2026-02-06

Relevant issue is #5234. I think the spec language in both css-inline-3 and css-align-3 were actually already updated as a result of the shorthand conversion — adding the "otherwise" there to indicate that a `baseline-shift: top/bottom` takes precedence over any other value.

But I agree that it's confusing that it still uses `vertical-align` in the wording, since e.g. `alignment-baseline: central; baseline-shift: bottom;` computes to `vertical-align: central bottom`, not `vertical-align: bottom`. I think these should be replaced with the longhands for clarity. I filed a similar issue, #13277, for a different usage of `vertical-align` that I think should be expanded.

(I'll leave it to the CSSWG for whether the new `central` and `center` values should be treated like `middle`.)
