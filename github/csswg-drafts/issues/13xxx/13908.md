Hello. I am an eleven-year-old junior web developer. I noticed that it would be useful to have more possible text transformations that are valid in CSS.

# What are they?

I've got a couple in mind. You can use some of them, I'm fine with not all of them being chosen. They are:

- alternating-upper (Hello world! --> HeLlO wOrLd!)
- alternating-lower (Hello World! --> hElLo WoRlD!)
- inverse (Hello WORLD! --> hELLO world!)
- random (Hello world! --> hELlo wORlD if the character code of the character + char index in string modulo 2 is 0, invert its case)
- title (basically capitalize but smart, it doesn't capitalize conjunctions or articles, harry potter and the philosopher's stone --> Harry Potter and the Philosopher's Stone)
- sentence (hello! how are you? --> Hello! How are you?)
- camelcase (variable number one --> variableNumberOne)
- pascalcase (variable number one --> VariableNumberOne)
- snakecase (variable number one --> variable_number_one (if you do text-transform: uppercase, snakecase it becomes: VARIABLE_NUMBER_ONE))
- kebabcase (variable number one --> variable-number-one (if you do text-transform: uppercase, kebabcase it becomes: VARIABLE-NUMBER-ONE))
- traincase (variable number one --> Variable-Number-One)
- flatcase (Variable number-one_yeah --> variablenumberoneyeah)
- dotcase (Variable number one --> variable.number.one, can also be used with uppercase)

These transformations should use Unicode-aware word segmentation and locale-aware casing behavior.

## @fantasai — 2026-08-11

Hi! The transforms in the `text-transform` property are intended for common stylistic variations. Most of these you're suggesting are pretty uncommon, or should be applied to the text source (rather than as a stylistic overlay that may or may not be appropriate for the current style).

Are there particularly strong use cases for any of these where a) the underlying text is in fact correct (we're not fixing incorrect capitalization, or changing what information is actually being represented) and b) flipping this variation on or off is a reasonably common stylistic choice?

## @frivoal — 2026-08-13

I think the various ones at the end (from `camelcase` onwards) are more likely things you want to do in the source. These are real casing conventions that people do use in different contexts (typically programming related), but I'm not sure there are cases where you'd want to store one in the document and display it as a different one for stylistic reasons.

I'd say the most useful one, which is indeed a stylistic one, is likely `title`, but that's challenging to do internationally, as the user agent would need to be aware of which words in which language should not be capitalized. Maybe we could get away with saying that it behaves the same as `capitalize` if the browser doesn't know how to deal with that particular language… But with no guarantee that it'd work reliably, it is actually useful?

`sentence` is in a similar situation: first word of each sentence is good for English (though you have to be smart to tell the different between "." that ends a sentence vs "." that ends an abbreviation), but correct casing based on the grammar for the language can be more complicated than that. For instance, in German, it's the first word of every sentence AND all the nouns. If we cannot get something that works reliably, nor across languages, I'm not sure it's a good idea to have it. Besides, this raises the question of why the source document doesn't have correct casing.

Are there use cases for `alternating-upper`, `alternating-lower`, `inverse`, and `random` other than humorous/fanciful styling? If that's the use case, I'd agree it's generally stylistic, but I don't know if these are used with enough regularity to warrant their inclusion.
