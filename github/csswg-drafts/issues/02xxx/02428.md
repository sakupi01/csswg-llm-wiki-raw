https://drafts.csswg.org/cssom-view-1/

Though I find disparate mentions of `scroll-padding`/`scroll-margin` values being used in scroll position decision making for `scrollIntoView` and general "jump links", I see implementations of [css-scroll-snap](https://drafts.csswg.org/css-scroll-snap-1/) not going so far as enabling the properties effects outside of snapports.

- [https://drafts.csswg.org/css-scroll-snap-1/#change-2017-scroll-margin](https://drafts.csswg.org/css-scroll-snap-1/#change-2017-scroll-margin)
- [#1707 - Consider more specific guidance for scroll-into-view](https://github.com/w3c/csswg-drafts/issues/1707)
- [#1708 - Define interaction of ScrollIntoView options and scroll-snap](https://github.com/w3c/csswg-drafts/issues/1708)
- [#1954 - Should scroll-snap-margin lose it's snap?](https://github.com/w3c/csswg-drafts/issues/1954)

In hopes that we can get rid of hacks like...
```css
.target-sentinel-for-reference     { position: relative; top: -3rem; }
.target-sentinel-for-section-title { position: relative; top: -6rem; }
```
In relation to articles like...
- [css-tricks - Hash Tag Links That Don’t Headbutt The Browser Window](https://css-tricks.com/hash-tag-links-padding/)
- [nicolasgallagher.com - Jump links and viewport positioning](http://nicolasgallagher.com/jump-links-and-viewport-positioning/demo/).

I think these properties should be referenced/highlighted in [cssom-view](https://drafts.csswg.org/cssom-view-1/)?

_Edited - Blink has now enabled these properties for use outside of snapports, though only in the block (or maybe just vertical) axis._
