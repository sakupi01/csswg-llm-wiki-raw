In b39a87c4b31cb5feab06ad60dce5cbae4f530048 @fantasai changed [`max-lines`](https://drafts.csswg.org/css-overflow-3/#max-lines) from applying to "all non-inline elements" to "block containers (excluding multi-column containers)".

But what about things like flex or grid containers? I'm not convinced that this feature should work across formatting context boundaries, but the spec mentions flex or grid containers, so it seems it does

> line boxes are counted in document order OR visual order (grid order in grid containers, flex order in flex containers, and document order in all other display types)

So if my understanding is correct, it seems I can use

```html
<div style="max-lines: 1">
  <p style="display: flex; width: 0">Lorem ipsum</p>
</div>
```
and I will get

> Lorem

But if I use

```html
<div style="max-lines: 1; display: flex; width: 0">Lorem ipsum</div>
```

then `max-lines` does not apply and I will get

> Lorem
> ipsum

Doesn't make much sense to me.

## @frivoal — 2018-03-08

@fantasai and I considered that possibility, but we thought it was better not to skip:
* We did not think it would make a big difference in implementation complexity
* Counting lines in nested BFCs doesn't seem to introduce strange corner cases
* The various reasons block container get BFCfied did not seem to be particularly relevant to the issue of counting lines, do we expect authors will prefer it this way
* Authors can always turn their BFCs into some other kind of formatting contexts if they want to exclude them (e.g. a single item vertical flexbox)

For scroll containers, we were more on the edge. Many of the same arguments work to some extend, but seemed less convincing. For these, I could easily go either way, depending on use cases.

## @frivoal — 2018-03-13

Right. The idea for not going through Flexbox/Grid/Table formatting context was a combination of being more complicated, and not seeming that it is particularly related to the original use case. It is still possible to apply this to flex items or grid items, just not to the container as a whole.

We could make it work if we wanted to, but it doesn't seem worth the effort.
