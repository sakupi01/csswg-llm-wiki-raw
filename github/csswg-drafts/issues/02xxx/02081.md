## @birtles — 2017-12-11

This is about being able to specify keyframes at, e.g. -10% so that when you have a timing function of `cubic-bezier(0, -0.5, 1, 1.5)` you can control the interpolation (or actually extrapolation) outside the 0%~100% range.

<!-- comment id=4464370081 author=BorisChiou created=2026-05-15T22:57:34Z url=https://github.com/w3c/csswg-drafts/issues/2081#issuecomment-4464370081 -->
## @BorisChiou — 2026-05-15

So now for scroll-driven animation, it is possible to have a resolved computed offset outside [0, 1], e.g. `cover -20%` could be resolved to `-0.2` for `computedOffset`. So this should be reasonable now to allow the percentage offset be outside [0, 1].

<!-- comment id=4464430227 author=BorisChiou created=2026-05-15T23:10:59Z url=https://github.com/w3c/csswg-drafts/issues/2081#issuecomment-4464430227 -->
## @BorisChiou — 2026-05-15

Oh I found this: https://github.com/w3c/csswg-drafts/issues/7825. So it seems we would like to keep the percentage offset within [0, 1]. Only do some special handle for timeline range name at 0% and 100%.
