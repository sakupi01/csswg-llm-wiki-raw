[Fonts 3 says](https://www.w3.org/TR/css-fonts-3/#font-variant-position-prop) " In the case of OpenType fonts that lack subscript or superscript glyphs for a given character, user agents must synthesize appropriate subscript and superscript glyphs. ".

In the features at risk for the March 2018 CR:

> Synthesis of the ‘font-variant-position’ property 

So, how to handle dropping this?

1. Remove the sentence
2. Change `must` to `should` or even `may`

<!-- comment id=398227372 author=fantasai created=2018-06-18T23:32:35Z url=https://github.com/w3c/csswg-drafts/issues/2796#issuecomment-398227372 -->
## @fantasai — 2018-06-18

I think this is an important requirement: losing the synthesis backup means a page's content can become garbled, either incomprehensible and/or incorrect. We need to get implementations to fix it, and I would be uncomfortable going to REC with the `font-variant-position` feature if it's not implemented safely.

<!-- comment id=398403370 author=svgeesus created=2018-06-19T13:43:12Z url=https://github.com/w3c/csswg-drafts/issues/2796#issuecomment-398403370 -->
## @svgeesus — 2018-06-19

Notice that the requirement at-risk here is not "synthesizing super/sub", which implementations have done since forever. Instead, if an OpenType font has special sup/sub glyphs for some, but not all, of the characters that a given page needs, the requirement is to **synthesize all of them** rather than using a _mix_ of some synthesized and some designed sup/sub glyphs (which is readable but ugly).

In the figure below, the font has a superscript `2`, `[` and `]` but does not have a superscript `a`. In red is the naive but ugly implementation where these are both superscript, but do not fit well together. The central part shows the designed superscript 2 not being used, so that the superscript 2a is consistent.

<!-- comment id=398405576 author=svgeesus created=2018-06-19T13:49:44Z url=https://github.com/w3c/csswg-drafts/issues/2796#issuecomment-398405576 -->
## @svgeesus — 2018-06-19

Fonts 3 [introduced the font-synthesis property](https://drafts.csswg.org/css-fonts-3/#font-synthesis-prop), covering fake-bold and fake-italic/oblique. Fonts 4 [extends this to fake-smallcaps](https://drafts.csswg.org/css-fonts-4/#font-synthesis-prop). Perhaps a better way to deal with this would be to add fake sub/sup to font-synthesis in Fonts 4?
