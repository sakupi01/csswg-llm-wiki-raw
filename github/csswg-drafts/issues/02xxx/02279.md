In §7.2. Feature and variation precedence,[1] a number of instances of font *properties* in steps 7 through 10 are linked to the corresponding *descriptor* definitions instead. (This affects mentions of font-variant, font-feature-settings, and font-variation-settings.)

Also, references in step 2 to the font-weight, font-stretch, and font-style properties are not linkified, although they are colored blue.

Actually, I think the problem is wider than just this section: a small sampling elsewhere in the spec looks like many (all?) occurrences of these *properties* (font-feature-settings, font-variation-settings, font-variant) are linked to the *descriptor* definitions instead. I guess having descriptors and properties with the same name may be confusing a process somewhere.

[1] https://drafts.csswg.org/css-fonts-4/#feature-variation-precedence

## @svgeesus — 2018-02-06

> Any of the above shorthands (besides the biblio varieties) that encompass multiple types can have their type specified explicitly, by appending the type and separating it with a !!, like the following to indicate that you want the IDL attribute named "bar", rather than the dictionary member of the same name:
> {{bar!!attribute}}
> https://tabatkins.github.io/bikeshed/#autolinking

So instead of 'font-family' we can use 'font-family!!property' or 'font-family!!descriptor', it seems. Testing some more locally.
