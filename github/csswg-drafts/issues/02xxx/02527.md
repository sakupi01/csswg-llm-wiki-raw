During the discussion we just had in the face-to-face in #1457, @smfr mentioned the interaction of containment and boxes with multiple fragments.  It's not clear how this will work.

For example, if an element inside a multicol has layout and size containment, its contents shouldn't affect its layout.  So even if it has a width and height, its contents can't affect where it fragments.  It seems like, then, the only two choices are that (a) it doesn't fragment or (b) it fragments as though it could break anywhere.  I suspect (b) is probably better.

<!-- comment id=380379157 author=frivoal created=2018-04-11T08:56:48Z url=https://github.com/w3c/csswg-drafts/issues/2527#issuecomment-380379157 -->
## @frivoal — 2018-04-11

Proposed solution, discussed with @tabatkins @dbaron @smfr @eaenet:

> Elements with size containment are [**monolythic**](https://drafts.csswg.org/css-break/#monolithic) for the purpose of fragmentation (see [[CSS-BREAK-3]).

<!-- comment id=380827863 author=css-meeting-bot created=2018-04-12T14:36:06Z url=https://github.com/w3c/csswg-drafts/issues/2527#issuecomment-380827863 resolution=true -->
## @css-meeting-bot — 2018-04-12

The Working Group just discussed `How do layout and size containment interact with column/page fragmentation?`, and agreed to the following resolutions:

* `RESOLVED: You're allowed to have forced breaks inside a layout contained thing but you can't propagate the break to the parent.`
* `RESOLVED: Elements with size containment are monolithic for the purpose of fragmentation`
