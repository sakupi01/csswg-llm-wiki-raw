_From @henke37 on May 16, 2017 4:49_

There are many tricky rules for how to interpolate css properties for
animation. The transform matrix being one of the more complicated examples.

Scripting will surely find good use for a way to interpolate between
property values on demand. Perhaps to do some crazy betterer animation
engine. Perhaps to do something crazy that nobody else would have
thought of.

Only one problem, there is no way to do it. There is no interface to ask
the user-agent to interpolate between two properties for a given position.

Keyframes seem very useful to be interpolated between with, but they do
have one complicating factor: they have associated times. Some uses
would benefit from being able to interpolate on a ratio of 0 % to 100 %
progress. As such I ask for an interface that supports a number in the
range of 0 to 1 to specify the interpolation progress.

## @birtles — 2017-12-05

Yes, this seems like a useful thing to have.

We have previously discussed having a means to get the output of a `KeyframeEffect(ReadOnly)` (i.e. before it is composited with an element) so if we have that, then all we would need is a way to directly feed progress values to effects without having to hook them up to an `Animation` first. Perhaps it could simply be a `getStyleAtProgress`-like interface which returns a `StylePropertyMap`.

I'm not entirely sure it *has* to be a progress value, however. You could just setup an effect with a duration of 1 and then any input times would be effectively progress values. The advantage of making the input a time value is that it lets you do things like specify a value for `iterationComposite` then provide a time in a non-zero iteration and get a result that includes iteration composite behavior.

Ideally, it would be something similar to what we need for `WorkletAnimation` too: either the same method/interface or something very similar and consistent with that.
