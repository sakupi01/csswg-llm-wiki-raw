As discussed in a side conversation in #1887, the description of how the `content` property is scoped for the purpose of style containment is unclear:
* ` content` is "scoped (for the purpose of open-quote/etc values)". "etc" is unclear
*  `content` but then content can read counter values from ancestors. So it doesn't really act as the root.

<!-- comment id=377214307 author=Loirooriol created=2018-03-29T12:06:05Z url=https://github.com/w3c/csswg-drafts/issues/2483#issuecomment-377214307 -->
## @Loirooriol — 2018-03-29


```css

}
```

## @Loirooriol — 2018-04-06

OK! Also consider this generalization of the example in the spec:

```html
<div></div>
```
```css
div {
  contain: style;
  counter-increment: n;
}
div::before, div::after {
  content: counters(n, '.') ", ";
}
div::after {
  counter-increment: n 2;
}
```

When `content` refers to a counter which does not exist, a new counter is created (#2348).

So what happens if you use `counter()` or `counters()` inside a scoped subtree, and the counter does not exist in the subtree, but does exist in some ancestor?

I think creating a new counter seems more consistent with scoped `counter-increment` and `counter-set`. But since this is a read-only operation, it may not be necessary.

So should the example produce `1.0, 1.2,` or `1, 1.2,`? Chrome renders `0, 2,`.

<!-- comment id=379760234 author=frivoal created=2018-04-09T13:54:22Z url=https://github.com/w3c/csswg-drafts/issues/2483#issuecomment-379760234 -->

<!-- comment id=380360015 author=tabatkins created=2018-04-11T07:47:02Z url=https://github.com/w3c/csswg-drafts/issues/2483#issuecomment-380360015 -->
## @tabatkins — 2018-04-11

Yes, `1, 1.2` is the correct rendering.

The ::before 'content' sees only a single counter, established outside the style boundary (on the `div`), so it will print `1`.  The ::after pseudo tries to increment the counter, but it's within the style boundary, so it instead creates a new counter and nests it; the the 'content' property then sees two nested counters, and will print `1.2`.

@dholbert Yes, my previous understanding was that 

> any uses of the property outside the scoping element must have no effect on the uses of the property on or in the scoping element, and vice versa

meant that reading an outer value from the inside was not allowed. But in the F2F it was clarified that reading is OK, what's not allowed are modifications.

Then the span can see that the div incremented the quote nesting level, but the div ignores that the span also did so.

For counters it's the same, see the example in the spec.

`div` increments the counter and `div::before` can read that. However, when `div::after` attempts to increment, a new counter is created.
