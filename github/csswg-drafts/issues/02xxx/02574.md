https://drafts.csswg.org/css-backgrounds-3/#the-background-size says the computed value of `background-size` is:

> as specified, but with lengths made absolute and omitted `auto` keywords filled in

https://wpt.fyi/css/css-backgrounds/background-size-001.html shows that only Firefox outputs the computed value with missing `auto`s. It seems this was added in https://github.com/w3c/csswg-drafts/commit/bfd84cfbfe39e8ace84e003080f1753c7674f8e8 by @fantasai, but I don't see any reasoning there. Perhaps this should be changed to remove the portion about omitted `auto` keywords, as it would also conform to the shortest serialization principle outlaid in #1564.

## @BorisChiou — 2019-06-21

Actually, what I thought is:
For example,
(`input` => `serialzation of the computed value`)
1. `auto` => `auto`
2. `auto auto` => `auto`
3. `12px` => `12px`
4. `12px auto` => `12px`

In other words, we omit the 2nd value if it is `auto`.
Both Chrome and Safari follow this rule, and it makes sense to me.

## @dholbert — 2019-06-26

Also, it looks like the "omitted auto keywords filled in" text has been replaced in the ED, and I think the new text makes it clearer that it's describing something conceptual rather than a specified serialization format.  (Nice!)

The ED's current text is:
>Computed value:
> list, each item a pair of sizes (one per axis)
> each represented as either a keyword or a computed `<length-percentage>` value

Link: https://drafts.csswg.org/css-backgrounds-3/#the-background-size

(For comparison, the old text with "omitted auto keywords filled in" is in the CR snapshot at https://www.w3.org/TR/2017/CR-css-backgrounds-3-20171017/#the-background-size )
