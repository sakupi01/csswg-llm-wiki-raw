It should be non-ambiguous when then CSS variable is defined (on the left of `:`) or used (on the right)

so this would be really great to have:
```css
:root {
  --x: blue;
}
div > span {
  color: --x;
}
```

<!-- comment id=352132043 author=Loirooriol created=2017-12-15T22:53:42Z url=https://github.com/w3c/csswg-drafts/issues/2111#issuecomment-352132043 -->
## @Loirooriol — 2017-12-15

`--x` is a valid identifier, and some properties accept arbitrary identifiers as their values.

```css
:root {
  --x: lower-roman;
}
@counter-style --x {}
li {
  list-style-type: --x;
}
```

Right now `--x` is the user-defined counter style and `var(--x)` is the inherited variable. With your proposal it's ambiguous.

One could argue that `--x` should have remained as an invalid identifier (as it was in CSS2), and reserve this syntax just for variables. But now it's probably too late, and being able to define counters that won't conflict with future specs is also nice.
