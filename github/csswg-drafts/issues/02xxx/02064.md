_From @caub on August 10, 2016 23:48_

I don't think it's a good idea to mix `offset` between other css properties

```
el.animate([
    { background: '#ff004d', offset: 0 },
    { background: '#ff77ab', offset: 0.20 },
    { background: '#00e756', offset: 0.5 },
    { background: '#29adff', offset: 0.80 },
    { background: '#ff77ab', offset: 1 }
], {
    duration: 2000,
    direction: 'alternate',
    iterations: Infinity
});
```

In comparison below, it's not ideal (you could have both '0.2', '0.20' as keys), but it helps separating concerns

```
el.animate({
    '0': { background: '#ff004d' },
    '0.2': { background: '#ff77ab' },
    '0.5': { background: '#00e756' },
    '0.8': { background: '#29adff' },
    '1': { background: '#ff77ab' }
}, {
    duration: 2000,
    direction: 'alternate',
    iterations: Infinity
});
```

## @birtles — 2017-12-05

I'm not particularly keen on adding yet more possible ways of specifying keyframes (we still need to support the currently specced means since the are shipping in two browsers and the polyfill, so this would simply be adding to that set). However see #148 which extends the existing object-syntax to allow:

``` js
{ width: [ '20px', '30px', '50px' ],
  offset: [ 0, 0.2, 1 ] }
```

_From @shans on August 12, 2016 5:33_

I'm not sure this would work - if that's supported, what would

```
{ width: [ '20px', '30px', '50px' ], 
  offset: [ 0, 0.2 ] }
```

do?

One option would be to 'distribute' the offsets and widths separately, so the offsets apply to the first and last keyframes and the '30px' frame is 0.1. This makes

```
{ width: [ '20px', '30px', '50px' ], 
  offset: [ 0, 0.2, 0.4, 0.9 ] }
```

weird though, because that would distribute the 30px keyframe half-way between 0.2 and 0.4 (actually this isn't terrible).

We could also make mismatched offsets an error, but that gets strange if there are multiple property lists of different lengths.

We could just duplicate the last offset value too.
