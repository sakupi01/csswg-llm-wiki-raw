I found problems with `<fieldset/>` element. This occured also on one of my websites and it cannot be removed with any style. Only change to non-semantic `<div/>` helps me.  

Does any draft describe this behaviour? Please look on Cr and FF behaviour. 
http://jsfiddle.net/mbgyem8b/

Moz and Cr do have reported this bug (?) many time but on Moz there is status "unconfirmed" or "closed+resolved" and wont-fix. Multiple duplication of this problem (resolved+duplicated).

Can you please add note in new drafts that the `<fieldset/>` is not a "replaced element" and all CSS styles should work for it like for `<div/>` and `<section/>`?

**ONLY MSIE** shows the element correctly if no extra behaviour is provided. 

The bug is confirmed on stack overflow:
https://stackoverflow.com/questions/8084343/google-chrome-fieldset-overflow-bug
https://stackoverflow.com/questions/1673346/fieldset-firefox-overflow-css-fix
but big part of these solutions have stopped to work anymore. 

An example of "RESOLVED" problem by Moz developers but really not resolved. 
https://bugzilla.mozilla.org/show_bug.cgi?id=261037
