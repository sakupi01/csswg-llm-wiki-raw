_From @hiikezoe on November 29, 2016 8:11_

The definition of addition for transform in [spec](https://w3c.github.io/web-animations/#transform-list-animation-type-section) is:
 addition: performed by concatenating transform lists as ‘Va Vb’.

But,  here, Va is underlying value, Vb is a value to combine,  so the list means Vb is firstly applied then Va.  We should apply Va, underlying value first, I think.

Maybe the wording is confusing. By "first", I mean we do the translation, and then inside that translated coordinate space we do the rotate. In terms of the resulting effect though, maybe you can think of it as happening in reverse too? Is this producing buggy content somewhere?

Ultimately this definition should not be in Web Animations, but in CSS transforms anyway. I've just left it in Web Animations for the time being as an example of how to spec these definitions until we spec them correctly in the relevant places.
