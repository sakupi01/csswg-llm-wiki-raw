In [writing-modes §3 Logical Box Properties](https://drafts.csswg.org/css-logical-props/#logical-box-props), it says

> Which pairs of properties share computed values depends on the computed values of writing-mode, text-orientation, and direction. For a summary of these dependencies, see [Abstract-to-Physical Mappings](https://drafts.csswg.org/css-writing-modes/#logical-to-physical)

The actual linked abstract-to-physical mappings do not mention text-orientation at all. They should, if there indeed is a dependence.

## @fantasai — 2018-08-17

CSS Logical Properties normatively references the mapping rules in CSS Writing Modes:

<a href="https://www.w3.org/TR/css-writing-modes-3/#logical-directions">CSS Writing Modes Level 3 &sect;6.2. Flow-relative Directions</a>:
> inline-start
> The side from which text of the inline base direction would start. For boxes with a _used_ `direction` value of `ltr`, this means the line-left side. For boxes with a _used_ `direction` value of `rtl`, this means the line-right side. 

<a href="https://www.w3.org/TR/css-writing-modes-3/#text-orientation">CSS Writing Modes Level 3 &sect;5.1. Orienting Text: the text-orientation property</a>:
> upright
> &hellip;  This value causes the _used value_ of `direction` to be `ltr`, and for the purposes of bidi reordering, causes all characters to be treated as strong LTR.

I think we just need to clarify here that the used value is what's used... this still means the mapping depends only on computed `writing-mode`, `direction`, and `text-orientation`: `text-orientation: upright` basically forces used `direction` to `ltr` in vertical writing modes, that's all.
