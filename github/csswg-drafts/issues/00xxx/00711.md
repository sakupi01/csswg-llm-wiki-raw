Ok, let's try to summary possible options to solve `<u>aaa<del>bbb</del></u>`.
1. **Not to fix.** Just heard from a Latin native that skipping ink for strikethrough is quite natural. I don't have a good sense to assert this, if we can reach consensus that this is a common understanding and commonly seen typographic tradition, this may not be an issue.
2. **Change `text-decoration-skip` to non-inherited, propagated property.** This has pros/cons as in [comment above](https://github.com/w3c/csswg-drafts/issues/711#issuecomment-261460533).
3. **Change `text-decoration-skip: ink` only applicable to underlines/overlines.** drott@ commented this will limit when authors want to skip-ink strikethrough. WebKit does this in its prefixed `-webkit-text-decoration-skip`.
4. **A separate property for skip ink.** We can then make it to propagate, or have values for each line types. Blink/WebKit doesn't implement propagation well yet, so relying on propagation isn't easy at this moment.

## @Crissov — 2016-12-08

@upsuper’s screenshot made me wonder whether there should be another value for [`text-decoration`](https://drafts.csswg.org/css-text-decor/#propdef-text-decoration) / [`text-decoration-line`](https://drafts.csswg.org/css-text-decor/#propdef-text-decoration-line) or new properties `text-overline-position` and `text-line-through-position` (or a compound `text-decoration-position`).

> - `underline`: Each line of text is underlined.
> - `overline`: Each line of text has a line over it (i.e. on the opposite side from an underline).
> - `line-through`: Each line of text has a line through the middle.

The most important reason (in Western typography) to desire `text-decoration-skip` is that `underline` cuts through descenders of lowercase letters (like _g, j, p, q, y_). However, neither `overline` nor `line-through` regularly cuts through the ascenders of lowercase letters (like _b, d, f, h, [i, j], k, l, t_), because `overline` is usually placed above the ‘H’ height of uppercase letters (without diacritic marks) and `line-through` is set lower than the ‘x’ height of lowercase letters to affect short ones (like _a, c, e, m, n, o, r, s, u, v, w, x, z_), too.

Then, this would make more sense:

~~~css
s, strike, del {
    text-decoration: line-through;
    text-decoration-skip: ink;
    text-line-through-position: over; /* over unspecified “middle”, i.e. above x-height */
}
~~~

Should I move this into a new issue?
