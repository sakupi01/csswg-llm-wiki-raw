[From the text on the spec](https://drafts.csswg.org/css-ui/#propdef-caret-color):
> Applies to:	elements that accept input

I guess this include the form entries (inputs, textares, etc.), but also the `contenteditable` elements.

However, even if it's a regular element, I'm wondering if we should be able to modify the `caret-color`, for example, for caret navigation.

@frivoal what do you think?

## @frivoal — 2016-11-21

I think caret navigation is entirely unspecified, so we cannot really say much about it.
I think it would be reasonable for an implementation to apply caret-color to the navigation caret, but I would not require it.

How about making it explicit in the spec that the effect of this property on caret navigation is undefined?

## @tabatkins — 2016-11-30

I'm not sure why we should leave this undefined.  Navigation carets are indeed undefined, but they're still *a caret*; it makes sense to me that caret-color can control that color.  (Functionally they act identically to a contenteditable caret.)

So I support defining it to be valid on all elements, perhaps with a note pointing out that navigation carets, if they exist, count as a "caret" which is affected by this property.

<!-- comment id=263947499 author=frivoal created=2016-11-30T18:04:36Z url=https://github.com/w3c/csswg-drafts/issues/725#issuecomment-263947499 -->
## @frivoal — 2016-11-30

Resolutions: 
* change the apply line to apply to all elements
* add a note to clarify that this can apply to other caret like things (like the navigation caret), but that this does not include the cursors (since people tend to confuse the two).

<!-- comment id=263948089 author=tabatkins created=2016-11-30T18:07:02Z url=https://github.com/w3c/csswg-drafts/issues/725#issuecomment-263948089 -->
## @tabatkins — 2016-11-30

Suggested text of the note:

Note: UAs might have additional things that count as "carets". For example, some UAs can show a "navigation caret", which acts similarly to an insertion caret but can be moved around in non-editable text, and is functionally a caret. On the other hand, the cursor image shown when hovering over text, tho it sometimes resembles a caret, is not a caret (it's a cursor).

Note: UAs might have additional things that count as "carets". For example, some UAs can show a "navigation caret", which acts similarly to an insertion caret but can be moved around in non-editable text, and is functionally a caret. On the other hand, the cursor image shown when hovering over text when the 'cursor' property is ''auto'', or when hovering over an element where the 'cursor' property is ''text'' or ''vertical-text'', though it sometimes resembles a caret, is not a caret (it's a cursor).
