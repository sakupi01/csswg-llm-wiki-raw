https://drafts.csswg.org/css-shapes/#basic-shape-serialization

The spec mentions that while serialization, we should:

> [omit] components when possible without changing the meaning

However, in the examples below, it also mentions that `circle(closest-side at center)` should serialize to `circle(at 50% 50%)`. Earlier it's mentioned that `at center` is the default, so really this should be `circle()`.

<!-- comment id=236579715 author=astearns created=2016-08-01T13:26:56Z url=https://github.com/w3c/csswg-drafts/issues/365#issuecomment-236579715 -->
## @astearns — 2016-08-01

The <position> values serialize to their 2- or 4-value forms only, so even a default circle() gets forced into it's 2-value form. I don't precisely recall the reason we settled on this, but it is one less code path for checking the serialized value. Do you have a reason to prefer adding the 0-value form for this one case, or were you just checking for consistency in the examples?

<!-- comment id=236580055 author=Manishearth created=2016-08-01T13:28:17Z url=https://github.com/w3c/csswg-drafts/issues/365#issuecomment-236580055 -->
## @Manishearth — 2016-08-01

No, just checking for consistency. Could this be more explicitly mentioned? As it stands this is only concretely specified by the examples; the spec text itself should be clearer about this.

<!-- comment id=236584345 author=astearns created=2016-08-01T13:45:03Z url=https://github.com/w3c/csswg-drafts/issues/365#issuecomment-236584345 -->
## @astearns — 2016-08-01

Thanks for checking!

It is mentioned in the second paragraph of 3.3 above the examples. I've added "(including the defaults)" to the normative text to make this particular case more explicit.
