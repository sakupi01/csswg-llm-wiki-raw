> one predefined profile for HDR (e.g. BT.2100 / PQ), especially since I heard

Requires some study beforehand; probably not color-4 but rather color-5

<!-- comment id=258631900 author=svgeesus created=2016-11-05T18:32:02Z url=https://github.com/w3c/csswg-drafts/issues/553#issuecomment-258631900 -->
## @svgeesus — 2016-11-05

D65 whitepoint and primaries on spectral locus, so a D50 adapted primary set has negative Z values in XYZ (which is forbidden by ICC v2 and v4) and over-range a and b values in Lab (resulting in clipping to -128 - 127 a and b range and hue shifts).

ICCMax solves this, infinite PCS range. Can do spectral, or colorimetric (directly in D65, no need to adapt to D50), or colorspace encoding profile.

## @svgeesus — 2016-11-05

colorspace encoding profiles are a name only, so small to download and equivalent to a predefined name.

## @svgeesus — 2016-11-05

PQ is absolute intensity (ICCMax has AtoB3 tags to deal with that, with an absolute radiance-based tag, luminance in candelas). HLG uses a variable transfer function that relates to the display blackpoint and whitepont.

## @svgeesus — 2020-05-28

On reflection, given the relative maturity of SDR color management (several decades, although of course with improvements over time) and HDR (especially HDR on devices other than television, and integration of Web content with HDR video and still images) which is in rapid flux, I think it best to keep CSS Color 4 to be SDR only.

To be sure that we are not painting ourselves into a corner, I have made an Unofficial Draft to explore adding HDR to CSS. To avoid the current problems with delta specs and version numbering, I called it [CSS Color HDR](https://drafts.csswg.org/css-color-hdr) although I expect it will either get merged into CSS Color 5 or become CSS Color 6 if the CSS WG adopts it.

## @palemieux — 2023-11-13

The Color on the Web CG recommends adding three HDR color spaces to cover common use cases:  `"rec2100-hlg"`, `"rec2100-pq"`, and `"rec2100-display-linear"`.

Details at https://github.com/w3c/ColorWeb-CG/blob/hdr_canvas_r2/hdr_html_canvas_element.md#add-color-spaces-intended-for-use-with-hdr-images

<!-- comment id=1816506449 author=svgeesus created=2023-11-17T14:15:10Z url=https://github.com/w3c/csswg-drafts/issues/553#issuecomment-1816506449 -->
## @svgeesus — 2023-11-17

Two of those are already specified:

- [rec2100-pq](https://drafts.csswg.org/css-color-hdr/#valdef-color-rec2100-pq)
- [rec2100-hlg](https://drafts.csswg.org/css-color-hdr/#valdef-color-rec2100-hlg)

For the third one, the need is clear. 

About the naming, CSS Color 4 and Canvas both have a linear sRGB color space named [`srgb-linear`](https://drafts.csswg.org/css-color-4/#predefined-sRGB-linear). Why the longer name `rec2100-display-linear` here, is it to allow a later scene-referred space as well?

<!-- comment id=1816690287 author=palemieux created=2023-11-17T16:03:43Z url=https://github.com/w3c/csswg-drafts/issues/553#issuecomment-1816690287 -->
