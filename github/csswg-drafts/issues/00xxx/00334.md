In light of recent discussions on commas inside functional notations (issue #266, https://wiki.csswg.org/ideas/functional-notation#general-principles) ... shouldn't the comma in `repeat()` be dropped?

<!-- comment id=234117579 author=FremyCompany created=2016-07-20T23:45:15Z url=https://github.com/w3c/csswg-drafts/issues/334#issuecomment-234117579 -->
## @FremyCompany — 2016-07-20

It could be confusing though because repeat(3 0) would be a valid way to create 3 empty tracks.

<!-- comment id=234154148 author=rachelandrew created=2016-07-21T04:30:42Z url=https://github.com/w3c/csswg-drafts/issues/334#issuecomment-234154148 -->
## @rachelandrew — 2016-07-21

I think it would be very confusing. The comma is useful here and I see no benefit from removing it.

<!-- comment id=235412336 author=fantasai created=2016-07-26T21:33:03Z url=https://github.com/w3c/csswg-drafts/issues/334#issuecomment-235412336 -->
## @fantasai — 2016-07-26

The benefit would be to have the contents of the functional notation follow the syntax conventions of CSS property values. (Which don't use commas except for fallbacks/layering/lists.)
