The official name for OpenType variation fonts are "variable fonts." However, TrueType used (uses?) the term "variation" instead.

"Variation" may be confusing because it is very similar to "Variant" which is used in the font-variant properties, which have nothing to do with variations.

"Variable" may be confusing because CSS Variables already exist and are completely unrelated.

A quick google shows "variable fonts" with lots of hits in the first few pages about the new OpenType 1.8 stuff and "variation fonts" with less hits, some about GX. So I have a weak preference for "variable fonts" as the name.

## @behdad — 2016-10-05

The team intended the technology to be called "OpenType Font Variations", and actual fonts "variable fonts".

<!-- comment id=254294834 author=litherum created=2016-10-17T18:38:56Z url=https://github.com/w3c/csswg-drafts/issues/516#issuecomment-254294834 -->
## @litherum — 2016-10-17

TrueType GX fonts should still be able to be controlled with this new stuff. There's no reason to make this stuff OpenType-specific. (Same thing with font features - AAT fonts respond to features too)

<!-- comment id=263452799 author=litherum created=2016-11-29T01:50:17Z url=https://github.com/w3c/csswg-drafts/issues/516#issuecomment-263452799 -->
## @litherum — 2016-11-29

The spec currently uses "font variations" in most places, which is correct. I fixed the incorrect uses and added a note for the terminology saying that the technology is "font variations" and an instance of one is a "variable font."

<!-- comment id=263481882 author=litherum created=2016-11-29T05:43:07Z url=https://github.com/w3c/csswg-drafts/issues/516#issuecomment-263481882 -->
## @litherum — 2016-11-29

Also, because the properties should be named font-*, it is much more natural to write font-variation instead of font-variable. So I didn't rename the properties.
