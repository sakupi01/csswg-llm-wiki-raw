gh-3971 generalized the specification's references to "form controls" to simply "controls". However, neither term has a precise definition in either CSS or HTML. This is particularly hazardous because the term "control" may be interpreted to involve interactivity, but (as noted in gh-3971) it is actually intended to include non-interactive elements like `<meter>`.

https://drafts.csswg.org/css-ui-4/#control-styling

HTML doesn't define the term "widget" in a way that Bikeshed is aware of. We could link informally using anchor tags, but that's prone to rot. To properly reference the term "widgets" here, we'll need to update HTML to formally define it.

@frivoal could you verify that replacing the undefined term "control" with [the term "widget" as defined in HTML](https://html.spec.whatwg.org/#widgets) is appropriate?

## @zcorpan — 2019-06-19

I think "widget" for these things is OK.

"Widget" is also a term in ARIA, which is a class of roles, closely related to these but also including e.g. `link` (which wouldn't be an HTML/CSS "widget").

https://w3c.github.io/aria/#widget_roles
