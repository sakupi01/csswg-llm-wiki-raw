I'm currently [tidying up the CSS Transitions WPT](https://github.com/web-platform-tests/wpt/compare/master...birtles:fix-transition-tests?expand=1) and I've come across [detached-container-001.html](https://github.com/web-platform-tests/wpt/blob/master/css/css-transitions/detached-container-001.html) which tests that we don't run transitions in a disconnected element.

As far as I know, no browser runs transitions for elements that are not [connected](https://dom.spec.whatwg.org/#connected) ([test case](https://codepen.io/birtles/pen/gypbBJ)) but I'm not sure what to link for as the spec link for this test.

See also: #3309.

For the purposes of `css-cascade` disconnected elements are not part of the flat tree, and thus don't have any style.

<!-- comment id=479765916 author=ewilligers created=2019-04-04T06:21:04Z url=https://github.com/w3c/csswg-drafts/issues/3790#issuecomment-479765916 -->
## @ewilligers — 2019-04-04

SVG 2 added [similar language](https://svgwg.org/svg2-draft/render.html#Rendered-vs-NonRendered):

> An element is not rendered in any of these five situations:
> 
> - never-rendered element types
> - elements excluded because of conditional processing attributes or ‘switch’ structures
> - elements with a computed style value of `none` for the `display` property
> - detached from the DOM tree
> - descendent elements of other non-rendered elements

The last three are relevant here: we don't have transitions if an ancestor has `display: none`.

<!-- comment id=479769795 author=birtles created=2019-04-04T06:37:44Z url=https://github.com/w3c/csswg-drafts/issues/3790#issuecomment-479769795 -->
## @birtles — 2019-04-04

Thanks, that's helpful.

(There's a slight distinction between these cases for transitions, however. For changes to a node's parent, we cancel the transition immediately. For changes to `display`, however, we won't cancel the transition until the next style change event.)
