This topic has been split from #3404 at the request of @fantasai

When fragmenting monolithic replaced elements, e.g. images, it would in many cases be useful to have functionalities similar to `orphans` and `widows`, to avoid splitting off too small parts at the beginning or end. 

Our current approach is actually using the `orphans` and `widows` properties, multiplying their values with the used `line-height` of the image box, causing breaks to be avoided or happen earlier, as in text.

<!-- comment id=700417546 author=fantasai created=2020-09-29T04:23:04Z url=https://github.com/w3c/csswg-drafts/issues/3405#issuecomment-700417546 -->
## @fantasai — 2020-09-29

Agenda+ to see if adding a `<length>` value to the widows/orphans properties would be an acceptable way to solve this, or if we should do something else.

<!-- comment id=700660090 author=faceless2 created=2020-09-29T12:09:44Z url=https://github.com/w3c/csswg-drafts/issues/3405#issuecomment-700660090 -->
## @faceless2 — 2020-09-29

It seems reasonable to me. Evaluating a length in a non-replaced context, we would presumably convert it back to a regular number with `Math.ceil(length / lineheight)` where `lineheight` is the height of the block container that orphans or widows would apply to.

<!-- comment id=700790424 author=bernhardf-ro created=2020-09-29T15:38:34Z url=https://github.com/w3c/csswg-drafts/issues/3405#issuecomment-700790424 -->
## @bernhardf-ro — 2020-09-29

We like the idea of a `<length>` value. However, we would prefer it to be applied via new properties, like `orphan-/widow-size`. Those should not be inherited, unlike `orphans` and `widows`. Then they could be applied to any block container, preventing breaks inside areas at the beginning or end with the specified height.

This would, for example, cover the use case that sections/chapters should not start in the bottom 7cm of a page, for which our customers currently require JavaScript. 

`<percentage>` values would also be useful, when resolved against the height of the fragment container (or to `0` if that height is not definite).

The precision of the used `<length>` should not be limited to multiples of `line-height`. If that is required the `lh` unit can be used.

**edit**: *Changed to use separate properties for `<length>` value, as our use cases require them to not be inherited, unlike `orphans` and `widows`.*
