For `text-combine-upright` the spec currently says:
> This property only has an effect in vertical writing modes.

And for sideways writing modes:
> The writing mode is vertical, while the typographic mode is horizontal.

So it sounds like `text-combine-upright` should be applied there? Is my understanding correct?

It may be worth a note stating that the four writing modes are included.

<!-- comment id=424961786 author=frivoal created=2018-09-27T05:16:31Z url=https://github.com/w3c/csswg-drafts/issues/3175#issuecomment-424961786 -->
## @frivoal — 2018-09-27

That seems like a mistake to me. Applying `text-combine-upright` in a `sideways-*` writing mode does not seem usecase driven, and probably complicates implementation of these `sideways-*` writing modes.

I think we should change to:
> This property only has an effect in vertical typographic modes.

<!-- comment id=424963316 author=upsuper created=2018-09-27T05:27:15Z url=https://github.com/w3c/csswg-drafts/issues/3175#issuecomment-424963316 -->
## @upsuper — 2018-09-27

It's not necessarily complicating implementation. Firefox can render it "as expected" and it doesn't seem to me that we have any specific code for handling that. It happens just because I used a condition similar to `writing_mode != horizontal-tb` for the corresponding flag.

But I'm fine removing that support as well if it's not desired, though. It should be as simple as just extending that condition mentioned above :)
