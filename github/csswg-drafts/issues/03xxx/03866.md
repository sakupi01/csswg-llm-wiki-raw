The CSSOM spec has various mentions of the terms "[content,padding,border,margin] edge" and "viewport", e.g.:
> The clientWidth attribute must run these steps:
> [...]
> Return the width of the **padding edge** excluding the width of any rendered scrollbar between the padding edge and the **border edge**, [...]
https://drafts.csswg.org/cssom-view/#dom-element-clientwidth

These terms are pretty consistently linkified, but their links targets do not point to a definition -- they just points to https://drafts.csswg.org/cssom-view/#content-edge which is this statement:

> Content edge, padding edge, border edge, margin edge, and viewport are defined by CSS.

There should be a link that points in the direction of an actual definition of these terms -- not just a statement saying they're defined.

## @dholbert — 2019-04-22

At least for the 4 "edge" types, I think the real definitions are at
https://www.w3.org/TR/CSS22/box.html#box-dimensions

Moreover, I think the mention of "padding edge" that I quoted above ("return the width of the padding edge") really wants to say "padding **box**", which is a term that is defined in the same section of CSS22 ( https://www.w3.org/TR/CSS22/box.html#box-dimensions ).

(The current "width of the padding edge" text in the clientWidth definition is nonsensical -- the term "padding edge" is defined in CSS22 as a boundary, which is not a thing that has a width.  In contrast, the "padding box" is **the space enclosed by that boundary**, and that is the thing that has a width which this spec text intends to refer to.)

## @Loirooriol — 2019-06-28

Actually I think the box terminology is confusing. For example the spec says "box’s content box", where the former "box" refers to https://drafts.csswg.org/css-display-3/#box and the latter to an area of that box. So I prefer "content area" instead of "content box". CSS Box defines both terms, but they seem synonyms.
