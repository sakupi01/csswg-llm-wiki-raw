In [§ 4.3. @page rule grammar](https://www.w3.org/TR/2018/WD-css-page-3-20181018/#syntax-page-selector) of css-page-3:

```css
@page { ... }
@page :left { ... }
@page :right { ... }
@page LandscapeTable { ... }
@page CompanyLetterHead:first { ... } /*  identifier and pseudo page. */
@page:first { ... }
@page toc, index { ... }
@page :blank:first { ... }
```

I'm wondering if `@page:first { ... }` is correct or not?

<!-- comment id=432259802 author=tabatkins created=2018-10-23T14:02:55Z url=https://github.com/w3c/csswg-drafts/issues/3239#issuecomment-432259802 -->
## @tabatkins — 2018-10-23

That's probably unintentional, but it's also technically valid. The grammar doesn't explicitly require whitespace between `@page` and the following stuff, so per the standard grammar rules, all that's required is that the tokenizer properly separate things. `@page:first` correctly tokenizes (as AT-KEYWORD DELIM IDENT), so it should parse.

## @faceless2 — 2020-02-06

* We allow it
* Prince allows it
* VivlioStyle allows it

They are the only three I tested.

Edit: it was allowed in CSS2.1 ([ref](https://www.w3.org/TR/CSS21/grammar.html#q25.0)) and is tested by [page-grammar-001.xht](https://github.com/web-platform-tests/wpt/blob/master/css/CSS2/page-box/page-grammar-001.xht) and [page-grammar-002.xht](https://github.com/web-platform-tests/wpt/blob/master/css/CSS2/page-box/page-grammar-002.xht).

So I think you could reasonably conclude that this is both intentional and allowed. Closeable?
