In section 3.2. Layout Containment...
https://drafts.csswg.org/css-contain/#containment-layout
...the spec mentions three specific values for the `display` property, as follows:
> If the element does not generate a principal box (as is the case with `display: contents` or `display: none`), or if the element is an internal table element other than `display: table-cell`, or...

Right now, the `display: contents` string is a link and it points at https://drafts.csswg.org/css-display-3/#propdef-display , and the other values aren't linkified at all.

I'd expect that:
(1) all three should be linkfiied
(2) they should point to their actual specific value definition, not to the property definition -- i.e. they should have these three targets
https://drafts.csswg.org/css-display-3/#valdef-display-contents
https://drafts.csswg.org/css-display-3/#valdef-display-none
https://drafts.csswg.org/css-display-3/#valdef-display-table-cell

## @tabatkins — 2019-05-07

Bikeshed handles `''prop: value''` by autolinking to the property. CSSWG also has the "suppress repeated links" feature turned on, so multiple links to the same thing in a single paragraph will be suppressed and only the first will remain, which is why the latter two aren't linkified. (In other words, they're linked in source, but suppressed in output.)

This is the generic way we handle this sort of prop:value inlining; I can change it to link as you desire, but it would be much more manual, and not consistent with how those sorts of snippets are linked anywhere else across our specs. Is it important for the understanding of this section that it link specifically to those values?

> Bikeshed handles ''prop: value'' by autolinking to the property.

I guess that's the part I would change, and make bikeshed link "prop: value" to the value instead. If you just meant the property, there's not need to specifiy the value, but when you mean the value, showing the property can be useful for context, but you're still talking about a particular value.

If that was changed, the rest would just fall out, since we'd no longer have 3 links going to the same place.

## @ewilligers — 2019-05-08

For this particular example, I uploaded a [PR](https://github.com/w3c/csswg-drafts/pull/3898) that changes
`''display: contents'' or ''display: none''
`to
`'display' values of ''display/contents'' or ''display/none''
`
This is similar to the approach taken in a number of other CSS specs.

It results in links to both the property and the values.
