Testcases:
- `z-index`: http://dabblet.com/gist/f1685a573380ef3f9041842a10965e3d
- `grid-column-end`: http://dabblet.com/gist/e2e7d3bceef592569f8eadbd66c6b7f1

[`z-index` accepts `<integer>`](https://drafts.csswg.org/css-position-3/#propdef-z-index).
`grid-column-end` [accepts an `<integer>` after `span`](https://www.w3.org/TR/css-grid/#line-placement). 

`calc()` [is allowed everywhere that an `<integer>` is accepted](https://drafts.csswg.org/css-values/#calc-type-checking): 

> Additionally, math functions that resolve to <number> can be used in any place that only accepts <integer>. (It gets rounded to the nearest integer, as specified in §8.1.4 Range Checking.)

However, no browser seems to support this properly (see linked test):

- Blink, WebKit, Gecko support multiplication but not division
- Edge does not seem to support `calc()` at all in `grid-column-end`, and supports multiplication but not division in `z-index`.

<!-- comment id=421663986 author=SelenIT created=2018-09-16T00:55:53Z url=https://github.com/w3c/csswg-drafts/issues/3114#issuecomment-421663986 -->
## @SelenIT — 2018-09-16

AFAIK, browsers currently treat the result of division in `calc()` as `number` (even when the result has no fractional part), according to [the previous level](https://drafts.csswg.org/css-values-3/#calc-type-checking) of the spec, so it is not accepted where `<integer>` is expected. I suppose the change request should be made for them to switch to the Level 4 behavior. It appears that [Chrome](https://bugs.chromium.org/p/chromium/issues/detail?id=874332) and [Mozilla](https://bugzilla.mozilla.org/show_bug.cgi?id=1440251) already have such bugs filed.
