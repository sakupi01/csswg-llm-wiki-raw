<https://drafts.csswg.org/css-box-4/#borders> defines the term "border properties", and while it doesn't explicitly list which properties these are, the text implies that it's just the properties set by the 'border' shorthand (-color, -width, -style).

It would be useful to have border-radius and border-image included in this definition, as anything that wants to reference the border properties for some purpose almost certainly wants to reference all of these. (For example, Anchor Positioning was just resolved to allow setting the border properties in fallback styles, and we do indeed intend for -radius and -image to be settable there; there's no good reason to allow setting a border-color but not a border-image.)

@SelenIT Yeah, I think if we want to go in this direction, it wouldn't be "all border-* properties" but "all properties that affect the size, shape, and rendering of the border area".

But that does leave the 'border-*' properties in the awkward place of not having a dedicated name to refer to them by, so I wonder if we could come up with a new name for the grouping that Tab wants here.

<!-- comment id=1989194194 author=tabatkins created=2024-03-11T18:45:47Z url=https://github.com/w3c/csswg-drafts/issues/9245#issuecomment-1989194194 -->
## @tabatkins — 2024-03-11

Even if we *had* named it `corner-radius`, it's still defined in terms of shaping the border box (and then, additionally, the padding and content boxes if necessary), so it's appropriate to include in the "border properties" term imo.

(If the Borders spec specifically needs a term for "the longhand of 'border'" (excluding the radius stuff), well, "the longhands of 'border'" is already a technical term for that grouping. We can dfn it as `'border' longhands` if needed.)
