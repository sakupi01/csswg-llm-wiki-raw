The current [editor's draft](https://drafts.csswg.org/css-view-transitions-2/) defines a few new names.
We should resolve whether they're the right names or should be changed.

Current spec:
```css
/* css */
@view-transition {
  navigation: auto | none;
  type: foo bar;  
}

:root:active-view-transition(foo) {
  img.hero {
    view-transition-name: hero;
  }
}
```

```js
/* js */
document.startViewTransition({
  update: () => { ... },
  type: ["foo", "bar"]
});

viewTransitionRule.type // DOMTokenList
```

**Proposed Resolution**
- The navigation-type descriptor is `navigation`, and its current possible values are `auto` and `none`.
- The type descriptor is `type`. Its default value is an empty list. There is no `none` value or so.
- The JS parameter for `startViewTransition` as well as the property name in the CSSOM rule can be `typeList`, to be consistent with `classList`, as it receives some sort of iterable. Alternatively we can keep it as `type` or use `types`.
- Bonus: decide whether the types can be regular idents vs. using dashed-idents for future compatibility with keywords.

One question which can use the group's input, should we require dashed idents for `type`? That helps in making sure we can add UA defined keywords later. But we don't have any such requirement for other VT properties with keywords like `view-transition-name`.

## @cdoublev — 2026-06-30

I do not think that is specified anywhere, and that it needs to be, but I would say that something is ignored *usually* because it is invalid, and is a consequence of this state, but this state is not a mandatory condition for something to be ignored. 

For example, CSS Values says:

  > If a property value contains more than the supported number of repetitions, the declaration must be ignored as if it were invalid.

This is probably not the best example. Some values of a coordinated value list can be ignored, but the spec actually says that they are *not used*, which is similar.

Anyway, when I read *"`none`, as well as any `<custom-ident>` starting with `-ua-`, are ignored"*, I understand that `none, foo, -ua-, bar` must be interpreted as `foo, bar`. Similarly, `:is(:unknown, foo, ::unknown, bar)` is interpreted as `:is(foo, bar)` and serializes as specified.

But I could also be wrong. ^^
