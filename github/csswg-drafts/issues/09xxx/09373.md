I think implementor wise the consensus is the former. They're not useless, they just don't expose the OS preference directly. It's still an accent color for example.

<!-- comment id=1828501749 author=svgeesus created=2023-11-27T19:55:28Z url=https://github.com/w3c/csswg-drafts/issues/9373#issuecomment-1828501749 -->
## @svgeesus — 2023-11-27

I added this, how does it look:

> 	User Agents may, 
	to mitigate privacy and security risks such as fingerprinting,
	elect to return fixed values for the used value of system colors
	which do not reflect customisation or theming choices
	made by the user.

I _think_ that this still allows testing, things like [`system-color-consistency`](https://wpt.fyi/results/css/css-color/system-color-consistency.html?label=experimental&label=master&aligned) are verifying internal consistency, not color matching with user preferences.
