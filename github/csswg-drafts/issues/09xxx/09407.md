Spun out from 
 - https://github.com/w3c/csswg-drafts/issues/9292 

In [the section on system fonts](https://drafts.csswg.org/css-fonts-4/#font-prop) we read:

> System fonts can only be set as a whole; that is, the font family, size, weight, style, etc. are all set at the same time. 

which is seemingly contradicted by

> These values can then be altered individually if desired. 

I _think_ what this means is that the system font name can only be set using the `font` shorthand, but once set then things like `font-weight` etc can be changed. Right?

<!-- comment id=1734488599 author=Loirooriol created=2023-09-25T21:28:40Z url=https://github.com/w3c/csswg-drafts/issues/9407#issuecomment-1734488599 -->
## @Loirooriol — 2023-09-25

Yes. In Blink, system fonts behave somewhat like `var()`: they set all the longhands to a magical internal value that won't be resolved until computed-value time. But you can still use the cascade to change individual longhands as you please.
I think other browsers are similar.

<!-- comment id=1734840579 author=cdoublev created=2023-09-26T05:10:21Z url=https://github.com/w3c/csswg-drafts/issues/9407#issuecomment-1734840579 -->
## @cdoublev — 2023-09-26

  > I think other browsers are similar.

FF seems to reset reset-only subproperties instead of setting them to a magical internal value.

```js
el.style.font = 'caption'
el.style.fontVariantPosition; // 'normal' in FF / empty string in Chrome
```

<!-- comment id=1738921290 author=emilio created=2023-09-28T10:55:22Z url=https://github.com/w3c/csswg-drafts/issues/9407#issuecomment-1738921290 -->
## @emilio — 2023-09-28

We have a magic internal value as well, just not for all the `font` longhands, only the ones we actually use, see [bug 1797146](https://bugzilla.mozilla.org/show_bug.cgi?id=1797146).

As of right now, that's only `font-family`, `font-size`, `font-style`, `font-stretch`, and `font-weight`.
