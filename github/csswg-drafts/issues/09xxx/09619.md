## @flackr — 2023-11-22

Why not though? Is there a reason having it animateable makes the implementation more complex? In https://www.w3.org/TR/web-animations/#not-animatable we say:

> Note: Properties are typically excluded from animation because animating them would create excessive complications. For example, properties defining animation parameters are [not animatable](https://www.w3.org/TR/web-animations/#not-animatable) since doing so would create complex recursive behavior.

In the past we've defined several properties as not animateable because we didn't see reasons to animate them, and then later reasons to animate them came up and we took compat risk in making them animateable. I'd prefer if we err on the side of everything is animateable unless doing so results in complex recursive behavior.

## @fantasai — 2023-11-22

The logic for leaving as `discrete` was that, since animating `view-transition-name` doesn't affect a running view transition, there's no need to make it "not animatable". But if there's some complication that wasn't captured in the discussion, @nt1m, since you weren't here, we can put it back on the agenda to review.

## @nt1m — 2023-11-22

If animating view-transition-name doesn't affect the running VT then I guess my question is what are the use cases? It's not terribly hard to implement the behavior of switching the name without affecting the current VT, but I don't see much of a point for developers. It's confusing at best IMO.

<!-- comment id=1823310610 author=flackr created=2023-11-22T18:55:03Z url=https://github.com/w3c/csswg-drafts/issues/9619#issuecomment-1823310610 -->
## @flackr — 2023-11-22

I think you could make the same argument for many discrete animateable properties - but allowing properties to be discretely "animated" allows using the animation infrastructure to implement delayed or timed changes of property values which can often be useful in certain circumstances.

E.g. 
* You could use an "animation" with a view-timeline such that only the on screen elements participate in a view transition.
* You could temporarily unset view-transition-name to avoid separately capturing elements that are currently animating.
