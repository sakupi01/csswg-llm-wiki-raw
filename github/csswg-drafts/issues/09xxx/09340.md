Can you please clarify what is the value of the end point when a single length is specified?

  > **Name:** [text-decoration-trim](https://drafts.csswg.org/css-text-decor-4/#propdef-text-decoration-trim)
  > **Value:** `<length>{1,2} | auto`

`0` seems a sensible option. The inverse of the start point may be more intuitive, eg. `-1em` when the start point is `1em`. Or `auto`, but the syntax does not allow to explicitly declare it.

<!-- comment id=3167259866 author=jfkthame created=2025-08-08T09:47:13Z url=https://github.com/w3c/csswg-drafts/issues/9340#issuecomment-3167259866 -->
## @jfkthame — 2025-08-08

It seems pretty clear to me (though arguably could be made more explicit) that the intent of the spec is that if only a single `<length>` value is specified, it applies to both the start and end of the decoration.

This means that a single `<length>` will either _shorten_ (positive) or _lengthen_ (negative) the line at both ends; to _shift_ the line, it will be necessary to provide two values with opposite signs, and to adjust only one side, an explicit zero must be provided for the other.

<!-- comment id=3167711485 author=cdoublev created=2025-08-08T12:24:39Z url=https://github.com/w3c/csswg-drafts/issues/9340#issuecomment-3167711485 -->
## @cdoublev — 2025-08-08

The property name includes *"trim"* so it may be suprising that the line decoration is actually *shifted* when a value is omitted. And authors might think that the first value trims to the left, and the second to the right.

In my experience, default values are almost always defined explicitly, although they often default to the first value specified. If I had been 100% sure of the expected default value when I created this issue, I would have made a PR to make it explicit. Do you want me to do that now?

<!-- comment id=3168265375 author=jfkthame created=2025-08-08T15:12:01Z url=https://github.com/w3c/csswg-drafts/issues/9340#issuecomment-3168265375 -->
## @jfkthame — 2025-08-08

> The property name includes _"trim"_ so it may be suprising that the line decoration is actually _shifted_ when a value is omitted. And authors might think that the first value trims to the left, and the second to the right.

But it's _not_ shifted when a value is omitted. With a single positive value, it's trimmed (shortened) at both ends; with a single negative value it's "negatively trimmed" (i.e. extended) at both ends.

<!-- comment id=3168282482 author=jfkthame created=2025-08-08T15:18:40Z url=https://github.com/w3c/csswg-drafts/issues/9340#issuecomment-3168282482 -->
## @jfkthame — 2025-08-08

The [spec draft](https://drafts.csswg.org/css-text-decor-4/#text-decoration-skip-inset-property) currently says:

> If two component values are given, the first applies to the [start](https://drafts.csswg.org/css-writing-modes-4/#css-start) and the second to the [end](https://drafts.csswg.org/css-writing-modes-4/#css-end).

Would you find it helpful if we added something like:

> If a single `<length>` value is given, it applies to both the [start](https://drafts.csswg.org/css-writing-modes-4/#css-start) and [end](https://drafts.csswg.org/css-writing-modes-4/#css-end) of the decoration line. Note that when the same value is applied to both ends, they will be adjusted in opposite physical directions (i.e. both _inset_ if the value is positive, both _outset_ if it is negative).

to make things clearer?
