We currently use `width` and `height` when setting up the default animation for pseudo-elements [here]( https://drafts.csswg.org/css-view-transitions-1/#setup-transition-pseudo-elements-algorithm:~:text=Set%20capturedElement%E2%80%99s%20group%20keyframes%20to%20a%20new%20CSSKeyframesRule%20representing%20the%20following%20CSS). And for keeping the end state in sync with the DOM elements [here]( https://drafts.csswg.org/css-view-transitions-1/#style-transition-pseudo-elements-algorithm:~:text=Set%20width%20to%20capturedElement%E2%80%99s%20old%20width).

This should probably use logical properties like block-size/inline-size? @noamr @fantasai @vmpstr 

<!-- comment id=1638294004 author=vmpstr created=2023-07-17T14:42:57Z url=https://github.com/w3c/csswg-drafts/issues/9057#issuecomment-1638294004 -->
## @vmpstr — 2023-07-17

Since we're animating both, I don't think this matters too much. However, width/height are far more used than inline-size/block-size by a wide margin. I feel like if the developer was to customize or see what the values are, they would start with checking width and height. 

<!-- comment id=1638880622 author=khushalsagar created=2023-07-17T21:05:19Z url=https://github.com/w3c/csswg-drafts/issues/9057#issuecomment-1638880622 -->
## @khushalsagar — 2023-07-17

I'm good with using width/height. Looping in @fantasai for an opinion. There was a general suggestion to use logical properties in UA CSS as a part of i18n review.

<!-- comment id=1639560630 author=fantasai created=2023-07-18T06:19:14Z url=https://github.com/w3c/csswg-drafts/issues/9057#issuecomment-1639560630 -->
## @fantasai — 2023-07-18

@vmpstr They map to each other during the cascade, so as long as we're setting both to explicit values, it doesn't really matter which one we use in the UA origin.

<!-- comment id=1640351047 author=khushalsagar created=2023-07-18T14:35:18Z url=https://github.com/w3c/csswg-drafts/issues/9057#issuecomment-1640351047 -->
## @khushalsagar — 2023-07-18

Great, in that case proposed resolution for this issue is to leave the spec as-is: "use width/height for size animation on ::view-transition-group".
