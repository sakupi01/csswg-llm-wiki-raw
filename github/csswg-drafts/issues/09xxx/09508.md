Is the [CSS Scrollbars Level 1](https://drafts.csswg.org/css-scrollbars/) specification ready to published as a recommendation? Currently it's a candidate and has been for a while. The only changes from the current draft compared to the CR is a minor correction.

It has long been supported in Firefox, but will soon also be supported in Chromium (see my [I2S](https://groups.google.com/a/chromium.org/g/blink-dev/c/PkEsMirl2zE/m/ArphSa39AAAJ)), it also has a positive standards position from WebKit [`scrollbar-width` position](https://github.com/WebKit/standards-positions/issues/133) [`scrollbar-color` position](https://github.com/WebKit/standards-positions/issues/134).

## @frivoal — 2024-01-25

As a result of reading the spec and test suite to check if they were indeed ready for REC, I have a found a few issues, and filed a few spec bugs as well as a few test bugs accordingly. 

* spec issues: https://github.com/w3c/csswg-drafts/labels/css-scrollbars-1

* test issues: https://github.com/web-platform-tests/wpt/labels/css-scrollbars

We should try to reduce these to zero before pushing as PR.

Help welcome as well for making PRs that would solve the issues inline in the spec (they're about making diagrams and illustrations).
* https://drafts.csswg.org/css-scrollbars-1/#issue-94d93028
* https://drafts.csswg.org/css-scrollbars-1/#issue-012ab64f

See also https://drafts.csswg.org/css-scrollbars-1/test-coverage for some information about the overall coverage of this spec.

All in all, I don't think we're that far off, but we're not there yet.

----
Side note:
> Safari trails somewhat with 74/115

This says more about the quality of the test suite than about the status of interoperability, given that as of now, Safari does not implement either of the properties defined in the specification.
