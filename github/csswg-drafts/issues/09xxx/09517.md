Per <https://github.com/w3c/csswg-drafts/issues/8169#issuecomment-1632890687>, there might be a remaining circularity issue if font-relative lengths are used in custom properties with `<length>` type. 

<!-- comment id=1776182704 author=Loirooriol created=2023-10-23T23:24:13Z url=https://github.com/w3c/csswg-drafts/issues/9517#issuecomment-1776182704 -->
## @Loirooriol — 2023-10-23

The problem isn't just for `<length>` type. https://github.com/w3c/css-houdini-drafts/issues/1080

<!-- comment id=2878136011 author=fantasai created=2025-05-13T22:54:51Z url=https://github.com/w3c/csswg-drafts/issues/9517#issuecomment-2878136011 -->
## @fantasai — 2025-05-13

Maybe you need two different `<length>` types: those that can be used in unit-influencing properties like `font-size` and `line-height`, and those that can't.

<!-- comment id=2939410532 author=lilles created=2025-06-04T10:04:37Z url=https://github.com/w3c/csswg-drafts/issues/9517#issuecomment-2939410532 -->
## @lilles — 2025-06-04

As @Loirooriol points out, this is not just limited to `<length>` values.

Assume `--number` is a registered custom property with the `<number>` syntax:

```css
p {
  --number: calc(10 + 2 * sign(1em - 20px));
  font-size: calc(var(--number) * 2px);
}
```
