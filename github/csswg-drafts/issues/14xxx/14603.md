https://drafts.csswg.org/css-overscroll-2/#overscroll-area-positioning describes (in a rather weird place) a variety of style adjustments:

> * If area’s specified [position](https://drafts.csswg.org/css-position-3/#propdef-position) is not [absolute](https://drafts.csswg.org/css-position-3/#valdef-position-absolute) or [fixed](https://drafts.csswg.org/css-position-3/#valdef-position-fixed), its computed position is absolute. If area’s specified [display](https://drafts.csswg.org/css-display-4/#propdef-display) is [contents](https://drafts.csswg.org/css-display-4/#valdef-display-contents), its computed display is [block](https://drafts.csswg.org/css-display-4/#valdef-display-block); otherwise its display is [blockified](https://drafts.csswg.org/css-display-4/#blockify). area’s [containing block](https://drafts.csswg.org/css-display-4/#containing-block) is scroller’s [local containing block](https://drafts.csswg.org/css-position-4/#local-containing-block).

I don't think there's a precedent for that `contents` -> `block` transformation, but there is for `contents` -> `none`. So maybe we should do the later?

I think once `position: absolute` / `fixed` is at play, blockification happens per CSS2, so you don't need to do that?
