**Title:** `[css-borders-4] "get the border-aligned corner clip-out path" references undefined `unitVectorFromStartToControlPoint``

**Spec:** [CSS Borders and Box Decorations Level 4 — §3.9.4.2 Computing a contoured path](https://drafts.csswg.org/css-borders-4/#contour-path)

## Problem

In the *get the border-aligned corner clip-out path* algorithm, the `controlPoint` step references a term **`unitVectorFromStartToControlPoint`** that is never defined:

> Let controlPoint be the result of calling mapPointToCorner given vectorFromStartToControlPoint's y and 1 - **unitVectorFromStartToControlPoint**'s x.

The normalized (unit) vector defined earlier in the same algorithm is named **`singlePixelVectorFromStartToControlPoint`**:

> Let **singlePixelVectorFromStartToControlPoint** be the vectorFromStartToControlPoint, normalized.

`unitVectorFromStartToControlPoint` appears nowhere else and has no definition, so it looks like an un-unified rename of `singlePixelVectorFromStartToControlPoint`.

## Suggested fix

Rename `unitVectorFromStartToControlPoint` to `singlePixelVectorFromStartToControlPoint`:

> Let controlPoint be the result of calling mapPointToCorner given vectorFromStartToControlPoint's y and 1 - **singlePixelVectorFromStartToControlPoint**'s x.

(If a different vector was intended here, the definition is missing entirely and should be added.)

Editorial (undefined-term) fix.
