The productions are [currently](https://drafts.csswg.org/css-color-4/#rgb-functions) as follows:

~~~~ ebnf
rgb() = [ <legacy-rgb-syntax> | <modern-rgb-syntax> ]
rgba() = [ <legacy-rgba-syntax> | <modern-rgba-syntax> ]
<legacy-rgb-syntax> = 	rgb( <percentage>#{3} , <alpha-value>? ) |
                  rgb( <number>#{3} , <alpha-value>? )
<legacy-rgba-syntax> = rgba( <percentage>#{3} , <alpha-value>? ) |
                  rgba( <number>#{3} , <alpha-value>? )
<modern-rgb-syntax> = rgb(
  [ <number> | <percentage> | none]{3}
  [ / [<alpha-value> | none] ]?  )
<modern-rgba-syntax> = rgba(
  [ <number> | <percentage> | none]{3}
  [ / [<alpha-value> | none] ]?  )
~~~~

Though technically correct, it looks rather redundant. Could `rgb()` and `rgba()` grammars not share the part between parentheses? 

~~~~ ebnf
rgb() = rgb( [ <legacy-rgb-syntax> | <modern-rgb-syntax> ] )
rgba() = rgba( [ <legacy-rgb-syntax> | <modern-rgb-syntax> ] )

<legacy-rgb-syntax>
= <percentage>#{3} , <alpha-value>?
| <number>#{3} , <alpha-value>?

<modern-rgb-syntax>
= [ <number> | <percentage> | none]{3}
  [ / [<alpha-value> | none] ]?
~~~~

The actual legacy syntax of former levels, i.e. with commas, did not allow alpha within `rgb()` and `hsl()`, as noted in the [respective subsection](https://drafts.csswg.org/css-color-4/#color-syntax-legacy):

>* non-opaque forms use a separate notation …

However, this restriction seems to have been lifted in the grammars and in browsers alike. This should be noted explicitly, perhaps.

Also, for `rgb()` and `rgba()`, the color component values used to be restricted to integers. (I’m not sure whether browsers already support sRGB with more than 8bit precision, but they probably successfully parse floats there.) Should the grammar reflect that or has this restriction also been lifted intentionally in legacy syntax?

Another minor detail, perhaps it would help if the [numeric range](https://drafts.csswg.org/css-values/#numeric-ranges) was expressed within the grammar. (This point applies elsewhere as well.) However, since values outside the range are not invalid, just clamped, this could be technically wrong. 

~~~~ ebnf
<legacy-rgb-syntax>
= <percentage>#{3} , <alpha-value>?
| <integer [0,255]>#{3} , <alpha-value>?

<modern-rgb-syntax>
= [ <number [0.0,255.0]> | <percentage> | none]{3}
  [ / [<alpha-value> | none] ]?
~~~~
