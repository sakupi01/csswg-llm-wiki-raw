```css
text-align: justify;
text-justify: inter-character;
```

The code above can only express a very rough justification strategy. A true justification mechanism should contain a priority system.

For example, [Chinese](https://www.w3.org/International/clreq/#line_adjustment) might be:


```text
1. spacing in punctuation marks at the end of a line
2. spacing between Western words within a line
3. spacing within interpuncts
4. spacing within brackets
5. spacing within commas
...
```

English could be:

```text
1. word space
2. tracking
3. alternate line break
```

Is it possible to design properties similar to this:

```css
text-justify-priority:
    punctuation,
    word-space,
    letter-space;
```

## @astearns — 2026-11-10

I think anyone (like me) that wants better text layout results would want more control over how the browser justifies text.

But it’s not just priorities that go into better justification decisions. It’s weights as well. If there are two break opportunities that are roughly equivalent (does an ‘a’ go at the end of a line or the beginning of the next) then not very much word spacing should be applied before choosing the other break. But if the other line breaks are quite different much more word spacing could be valid. Merely prioritizing word spacing over line breaks doesn’t cover this subtlety.

In the composition systems I’ve worked on where more justification features are available, allowing priority ordering was considered, evaluated, and mostly passed over. Instead, we added more expressivity in the weights applied to a feature. Min, desired, and max word and letter spacing, hyphenation ladder limits, and other hyphenation controls were provided instead. Authors could place strict limits to effectively change priorities. And when (as always happens) the authored limits could not be respected the increased penalty weight from exceeding the limits would also have the effect of priority reordering.

I think browsers should come up with what they think are reasonable defaults priorities and weights for `line-break: pretty`. Then we can look at adding controls for use cases that are not covered by those defaults.
