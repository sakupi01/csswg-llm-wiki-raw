Over time, CSS has organically sprouted a number of features that act at the stylesheet level. Questions have inevitably arisen about how those features interact with each other. With some of the mixins discussions, it seems to me that the web of interactions has become sufficiently complex that it would be worth defining a holistic model.

To catalog some of these effects; likely an incomplete list:
* Layers
* Custom conditionals (media/supports)
* Mixins
* Container queries
* Import rules, optionally with conditionals, which may be custom queries, and which may place their contents into a layer

Recent resolutions to help inform direction:
* https://github.com/w3c/csswg-drafts/issues/12627#issuecomment-3666535941 
  * `Treat contextual conditionals as always true for global rules i.e. the condition doesn't affect the rule`
* https://github.com/w3c/csswg-drafts/issues/12417#issuecomment-3204738440
  * `@layer is invalid inside mixins (for level 1)`
  * `@mixin is valid wherever @keyframes is valid`
  * `Still open question of whether @mixin declarations are layered -- either way is acceptable implementation-wise`
* https://github.com/w3c/csswg-drafts/issues/13041#issuecomment-3819756713
  * `Revert earlier resolution about order-dependence, instead make @custom-media/supports and @mixins use the mechanism in this issue to resolve name collisions` *(note: needs further discussion)*

Ideally, I would like to minimize coupling between features, for example it would be great if we could de-tangle custom conditionals and mixins from each other; see https://github.com/w3c/csswg-drafts/issues/13041#issuecomment-4860394928

`@import` with custom conditionals also seems like it could get weird. Importing a stylesheet with custom conditional definitions seems like a valid thing to do, but then you can wind up with situations like: imported stylesheet A defines a condition that imports stylesheet B, but stylesheet B redefines that condition in a way that would exclude itself from importation.

If we set custom conditionals aside, I think it becomes easier to develop a coherent processing model among the rest:

1. Process importations
1. Organize stylesheet contents into layers
1. Determine winning definitions for mixins (and maybe some other at-rules?)
1. Apply mixins
1. Determine winning definitions for other at-rules (keyframes, font-face, ...?)

The issue I see is that custom conditionals could potentially muck with every step of that model. I'm not sure what to do about that.
