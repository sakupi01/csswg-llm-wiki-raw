The [`nav-…` properties for _directional focus navigation_](https://drafts.csswg.org/css-ui-4/#nav-dir) in CSS UI basically bind targets to d-pad buttons, e.g. on television remote controls.
They traditionally accept a local URL in the host document as their value; I have proposed to let them use CSS-defined anchors instead. #13166

* ⬆️ `nav-up`:`VK_UP`
* ⬇️ `nav-down`:`VK_DOWN`
* ➡️ `nav-right`:`VK_RIGHT`
* ⬅️ `nav-left`:`VK_LEFT`

There are some other buttons or controls on certain input devices that are neither used for standard actions (like primary and secondary click on mice) nor for text entry, but for navigation in some sense. I would like to suggest that CSS UI adds the same declarative method to assign navigation targets to them. This may include, among others perhaps:

- TV remote color buttons:
  * 🔴 `nav-red`<!-- ≈ PS ⏺️▶️-->: `VK_RED`
  * 🟢 `nav-green`<!-- ≈ PS 🔺🔼-->: `VK_GREEN`
  * 🟡 `nav-yellow`<!-- ≈ PS ⏹️◀️-->: `VK_YELLOW`
  * 🔵 `nav-blue`<!-- ≈ PS ❎🔽-->: `VK_BLUE`
- info button:
  * ℹ️ `nav-info`: `VK_INFO`
- scanning/reeling/winding, inner progress buttons, track/item controls:
  * ⏩️ `nav-forward`:`VK_FAST_FWD` fast forward, `VK_PAGE_DOWN` page down
  * ⏪️ `nav-backward`:`VK_REWIND` rewind, `VK_PAGE_UP` page up
  * ⏫️ `nav-start` ≈ `nav-top`: home
  * ⏬️ `nav-end` ≈ `nav-bottom`: end
- skipping, outer progress buttons, list/sequence index controls:
  * ⏭️ `nav-next`:`VK_NEXT`, _skip (forward)_, channel down
  * ⏮️ `nav-prev`(`ious`):`VK_PREV`, _skip backward_, channel up
  * ⏮️ `nav-first`
  * ⏭️ `nav-last`
  *  `nav-list` (`nav-index` has different legacy meaning): channel list
- playback control buttons (I’m not quite sure about these):
  * ▶️ `nav-play`(`-forward`): `VK_PLAY`
  * ⏸️ `nav-pause`: `VK_PAUSE`
  * ⏯️ `nav-toggle`(`-playback`): `VK_PLAY_PAUSE`
  * ⏹️ `nav-stop`: `VK_STOP`

I deliberately excluded 🔙`nav-back` (`VK_BACK`, backspace), 🔚 `nav-exit` (`VK_EXIT`, escape, abort, ❌ cancel, hang up, ⏏️ eject) and 🔝🏠 `nav-home` (in the TV RC sense, incl. 🔛 EPG/guide), as well as audio volume controls including 🔇 `nav-mute`, and did not include mode (🔀 shuffle/random, 🔁 repeat, scroll lock, 💬 subtitles/closed captions, 🗣️ language/variant) and action (🔄 reload/refresh, `VK_ENTER` ✅ submit, ⏺️🎙️ record/listen, 💟❇️ fave/like) controls either. Some of them might be okay to add, but I expect more severe accessibility issues with them than with the rest.

I was not sure about additional mouse (middle click, thumb click) and gamepad buttons (left and right, both primary and secondary), and will assume they map to one of the behaviors mentioned above. 

Scrolling, i.e. the directional or axial effects of gamepad sticks and mouse/trackpad movement and scrollwheels, is handled elsewhere (css-overscroll, css-scroll-anchoring, scroll-animations).
