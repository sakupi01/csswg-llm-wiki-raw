(Written with help from GPT-6 Astra Max.)

The [basic-shape computed-value rules](https://drafts.csswg.org/css-shapes-1/#basic-shape-computed-values) compute components with explicit exceptions for positions and rectangle shapes. They do not clearly require converting relative SVG path commands to absolute commands.

For example:

```css
shape-outside: path("M10 10 h80 v80 h-80z");
```

- WPT's `css/css-shapes/parsing/shape-outside-computed.html` expects an absolute-command path.
- Chromium uses absolute commands across `clip-path`, `offset-path`, `shape-outside`, and `d`
- Firefox preserves relative commands in the supported consumers
- WebKit preserves relative commands in `clip-path` but converts them in `offset-path`.

(Firefox/WebKit did not support the tested `shape-outside: path()` syntax.)

Should all `path()` consumers share a normalization rule? Please specify the treatment of relative commands, including an initial relative moveto and a relative moveto after closepath, or clarify that the computed value retains the command forms.
