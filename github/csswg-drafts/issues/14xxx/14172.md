I wrote an article on [the ideal height for custom select](https://jakearchibald.com/2026/goldilocks-select-height/), and it boils down to this:

```css
select::picker(select) {
  /* Prevent the picker getting too small */
  min-block-size: calc-size(fit-content, min(size, 12em));
  /* Prevent the picker getting too big */
  max-block-size: calc-size(stretch, min(size, 30em));
  /* Add a margin to the viewport, so it's clear the picker isn't overflowing the viewport */
  margin-block-end: 1em;
  /* Allow the margin to flip */
  position-try-fallbacks: 
    flip-block,
    flip-inline,
    flip-block flip-inline;
}
```

Are any of these worth baking in?

[The group has already resolved to adding something like the `flip-` stuff](https://github.com/w3c/csswg-drafts/issues/13541#issuecomment-4732677022), but what about the rest?

- **Prevent the picker getting too big** - Maybe this is too opinionated, but I figured I'd throw it in for discussion.
- **Add a margin to the viewport** - Even if the gap is small, I think it's useful to be able to tell that the picker isn't overflowing the viewport.
- **Prevent the picker getting too small** - This is the one I feel strongest about. Chrome includes `min-block-size: 1lh`, which isn't in the spec, but that seems far too small. Something like `calc-size(fit-content, min(size, 5lh))` seems more useful.

I don't have strong feelings about particular length values.
