The `auto` keyword for `text-spacing-trim` and `text-autospace` is about matching the system behavior, not some automatic behavior that CSS derives. It might make sense to be more explicit and call it `match-system`.

## @MurakamiShinyu — 2026-11-10

I think it would be better to keep the current definition of `text-spacing-trim: auto` = "The user agent chooses a set of typographically high quality spacing values." It can match the system, but if the system has no high quality text spacing behavior, the user agent should choose high quality one, e.g., `text-spacing-trim: trim-both` which is close to MacOS's text spacing behavior. `trim-start` is also fine but it should not fall back to `normal`, because `normal` does not trim at line start.

In EPUB/ebook readers, the behavior of `text-spacing-trim: space-first` is observed, in Kindle and Kinoppy, as far as I know.
