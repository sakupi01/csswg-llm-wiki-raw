Transitional animations moderate the abruptness of UI, making it feel softer and more natural to interact with. We suggest adding some basic transitions to the appearance of the picker:

* Transition from `opacity: 0` to `opacity: 1`.
* Transition from `transform: scale(.95)` to `transform: scale(1)`.

We use transform here rather than scale so that it is easy and nearly automatic for the author to override the effect with their own.

The rules would look something like:

```css
select::picker(select) {
  transform-origin: block-start center;
  transition:
    display 150ms allow-discrete,
    opacity 150ms cubic-bezier(0, 0, 0.58, 1),
    transform 150ms cubic-bezier(0, 0, 0.58, 1);
}
select:not(:open)::picker(select) {
  opacity: 0;
  transform: scale(0.95);
  transition:
    display 125ms allow-discrete,
    opacity 100ms cubic-bezier(0.42, 0, 1, 1),
    transform 125ms cubic-bezier(0.42, 0, 1, 1);
}
@starting-style {
  select::picker(select) {
    opacity: 0;
    transform: scale(0.95);
  }
}
@media (prefers-reduced-motion) {
  select:enabled::picker(select) { /* need to add some specificity; disabled select can't open anyway */
    transition-duration: 0.01ms;
  }
}
```

Note: There are also some technical issues with `display` and top-layer transitions that still need to be worked out....

I've been reading through the various issues, and this is the first where I thought - "ok, that's too much". Especially the `@media` with transition properties, and the `@starting-style {}` which is tricky enough on its own to use, without it silently being in the UA stylesheet. Even just setting transitions feels like a lot for the UA stylesheet to be doing.

<!-- comment id=5301743261 author=JoshTumath created=2026-08-15T10:07:03Z url=https://github.com/w3c/csswg-drafts/issues/14325#issuecomment-5301743261 -->
## @JoshTumath — 2026-08-15

Although this would be a nice-to-have, I agree it would be too cumbersome for authors to override.

Also, authors follow different best practices on how to use prefers-reduced-motion, so this might force authors to do it a certain way. For example, at the BBC, we define the reduced-motion behaviour by default and then contain our animation code in `@media (prefers-reduced-motion: no-preference)`. And we'd rather make the reduced-motion version a fade rather than turn it off.

## @sorvell — 2026-08-16

I think it's fair that most customizations of `<select>` will likely include some kind of transition for the picker.

However, there are a few ways to do this. For example, if you want to use an animation, you likely have to fiddle a good bit with the transition to remove it. 

I also don't think this is required to make the `<select>` "acceptable in production out of the box."

This suggests to me that this should just be left up to users to manage themselves.
