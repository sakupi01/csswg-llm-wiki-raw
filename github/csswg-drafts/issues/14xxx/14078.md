The treatment of `vo=Tr` characters in vertical writing mode has been problematic since long time ago and got worse after the update of [UAX#50](https://www.unicode.org/reports/tr50/) in Unicode 17.0 which changed the vertical orientation property value of U+2018, U+2019, U+201C, and U+201D from `R` to `Tr`.

There are two Chromium issues related to this problem:
- [334110491: The default glyph forms with vo=Tr in vertical texts do not fit UAX#50.](https://issues.chromium.org/issues/334110491)
- [509983812: In Chrome 148, the OpenType `vert` / `vrt2` feature is no longer applied to U+201C, U+201D, U+2018](https://issues.chromium.org/issues/509983812)

These issues are about vo=Tr characters being displayed upright in vertical writing mode, and Chromium team has decided not to fix this issue (Status: Won't fix (Intended behavior)) because they believe that the CSS Writing Modes specification requires vo=Tr characters to be typeset upright.

So I think it is necessary to modify the specification to recommend that vo=Tr characters should fall back to rotated if vertical glyphs are missing.

The current spec https://drafts.csswg.org/css-writing-modes-4/#typeset-upright has the following description:

> Typographic character units which are classified as `Tr` or `Tu` in [UAX50] are expected to have alternate glyphs or positioning for typesetting upright in vertical text. In the case of `Tr` characters, if such vertical alternate glyphs are missing from the font, the UA may wish to [RFC6919] (but is not expected to) synthesize the missing glyphs by typesetting them sideways etc.

Regarding the last sentence, "may wish to …" is not strong enough to recommend that vo=Tr characters should fall back to rotated if vertical glyphs are missing. I think it should be changed to "should" or "are expected to" instead of "may wish to (but is not expected to)".

I made a test HTML file to check the vertical writing mode display of vo=Tr characters (using the Google Fonts "Noto Sans JP"):
https://murakamishinyu.github.io/bugtest/uax50/vo-tr-chars-noto.html

When this is displayed in Chrome, the following characters are displayed upright in vertical writing mode (same orientation as horizontal writing mode):

- 2018	‘	LEFT SINGLE QUOTATION MARK
- 2019	’	RIGHT SINGLE QUOTATION MARK
- 201C	“	LEFT DOUBLE QUOTATION MARK
- 201D	”	RIGHT DOUBLE QUOTATION MARK
- 3030	〰	WAVY DASH
- FE59	﹙	SMALL LEFT PARENTHESIS
- FE5A	﹚	SMALL RIGHT PARENTHESIS
- FE5B	﹛	SMALL LEFT CURLY BRACKET
- FE5C	﹜	SMALL RIGHT CURLY BRACKET
- FE5D	﹝	SMALL LEFT TORTOISE SHELL BRACKET
- FE5E	﹞	SMALL RIGHT TORTOISE SHELL BRACKET
- FF1B	；	FULLWIDTH SEMICOLON

Interestingly, when this is displayed in Firefox, all of these characters are displayed rotated in vertical writing mode. Safari (WebKit) behaves similarly, but U+FF1B FULLWIDTH SEMICOLON is displayed upright.

Firefox has implemented the behavior that vo=Tr characters should fall back to rotated if vertical glyphs are missing, and this was fixed 8 years ago in the following issue:
- [Bug 1431305 - Wavy Dash doesn't fall back to "rotated" in vertical writing-mode](https://bugzilla.mozilla.org/show_bug.cgi?id=1431305)

I believe that the expected behavior of vo=Tr characters without vertical glyphs is to fall back to rotated, as Firefox do, and I think it is necessary to modify the CSS Writing Modes specification to recommend it.
