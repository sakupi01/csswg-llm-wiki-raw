`calc-size()` can accept all the sizing keywords as its first argument, plus the keyword `any`. But what does `any` mean? It took me awhile (and reorganizing the spec) to figure it out.

AFAICT, it just represents a generic fixed size, i.e. a non-intrinsic size. Which is actually a pretty simple concept, but not one I would associate with `any`.

I suspect the naming came from the fact that it's _compatible_ with "any" other calc-size() type, but that's not what it _is_. Can we rename it to a keyword that better represents what it _is_, like `fixed` or something?

## @dbaron — 2026-09-23

So the one other piece here is that this is something we've been shipping for slightly over two years -- I think a new name at this point is something that should have a slightly stronger justification.  The [`calc-size()` use counter](https://chromestatus.com/metrics/feature/timeline/popularity/5195) is at almost 0.3%, and the [`interpolate-size` use counter](https://chromestatus.com/metrics/css/timeline/popularity/798) is at almost 11%.  (Note that use of `interpolate-size` could cause `calc-size()` values to be serialized.)

So I could probably go add both parsing *and serialization* use counters for `calc-size(any, ...)`, but I'm also not convinced that it's worth going ahead with that when it's not clear that I could get the intent to ship and particularly the intent to remove approved by API owners based on the justification given in this issue.

So I'd actually like to reopen this discussion.
