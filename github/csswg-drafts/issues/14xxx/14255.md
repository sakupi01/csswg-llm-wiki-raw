Currently if the contents of an option are too long but wrappable, they will wrap onto multiple lines. But this can disturb the general page layout, so option text is typically restricted to one line in a `<select>` control. We should disable wrapping for the base appearance in-page select button text also, to help maintain this height expectation, by moving  `white-space: nowrap` from `option` to `select` itself.

```
select <del>option</del> {
  white-space: nowrap;
}
```

Also, if the text is too long and can’t be wrapped, it will overflow the in-page select button, which looks terrible and can be confusing. We should control overflow by clipping it and using `text-overflow: ellipsis`.

```
select {
  overflow: clip;
}
selectedcontent {
  overflow: clip;
  text-overflow: ellipsis;
  min-inline-size: 0; /* Allow flex shrinking. */
}
```

<hr>

This brings up a related problem: the `selectedcontent` is only styleable when the author provides `<button><selectedcontent></selectedcontent></button>`. This creates some awkward situations for the more basic `<select>` markup pattern, for example:

- We can't use `text-overflow: ellipsis` to control clipping.
- If the option content is too long, it pushes the `::picker-icon` out of the `<select>`'s box, instead of fitting it while clipping the option text.

We should consider either a) automatically generating these elements when they aren't present or b) introducing a pseudo-element (maybe reuse `::field-content`?) that allows them to be styled. This would let us use `flex` on the text rather than `margin-inline-start: auto` on the `::picker-icon`, freeing up the margins to control spacing, and giving us a better layout pattern that we can re-use for `<input>`.

## @josepharhar — 2026-08-19

I'm supportive of adding a part-like pseudo-element for the [select fallback button text div](https://html.spec.whatwg.org/multipage/rendering.html#select-fallback-button-text).

I'm not sure exactly which styles would achieve this, but I think it would be best if we made the fallback button text div have some sort of clipping so that when the text gets too long, the picker icon stays inside the control and clips the text so that it looks like appearance:auto does here, which might not be possible with customizable select currently:

<!DOCTYPE html>
<style>
.grid {
  display: grid;
  grid-template-columns: auto 1fr;
  grid-gap: 0.5em;
}
select {
  width: 60px;
}
.base select {
  appearance: base-select;

.none select {
  appearance: none;
}
</style>

<h3>appearance:base-select</h3>
<div class="grid base"></div>
<hr>
<h3>appearance:auto</h3>
<div class="grid auto"></div>
<hr>
<h3>appearance:none</h3>
<div class="grid none"></div>

<script>
document.querySelectorAll('.grid').forEach(grid => {
  [null, 'hidden', 'clip', 'visible'].forEach(overflowValue => {
    grid.insertAdjacentHTML('beforeend',
      `<div>${overflowValue ? 'overflow:' + overflowValue : 'default'}</div>
       <div>
         <select style="${overflowValue ? 'overflow:' + overflowValue : ''}">
           <option>loooooooooooooooooong</option>
           <option>short</option>
         </select>
       </div>`);
  });
});
</script>
