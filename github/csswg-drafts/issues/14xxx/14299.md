The naming of the `reading-flow` values is confusing to me, and with too many values. I think any `reading-flow` value, including `normal`, should accept `reading-order` values without having to also explicitly set `reading-flow` too. Then for `normal`, just define it in a way that says `reading-order` only creates a reading flow container for certain display types. Thus, `normal` would be very similar to what is currently defined as `source-order`, and we don’t need a separate `source-order` for that. 

The `grid-order` value is also odd. The name somewhat implies that the `order` property only affects the reading order when using grid along with this value, or that the other grid values do not take order into account. But surely `flex-visual` and `flex-flow` also take `order` into account (though that doesn’t seem to be mentioned anywhere). 

If the reading order should include modifications `made` by order, the author shouldn’t have to change this value when changing display types (within media queries for example). There should just be a value that says “DOM order + `order` changes“ (as grid-order does) and have it apply to all the display types that can use `order` (and fall back to DOM order for everything else). I would call *that* value `source-order` or maybe `ordered-source`. 

Therefore I’d suggest the following value definitions:

### normal
For grid, flex, and block layouts, creates a reading flow container, and enables the use of the reading-order property on direct children. Other than respecting the reading-order property for children of those display types, this follows the order of elements in the DOM.

### ordered-source 
Follows the order-modified document order, when order is valid (e.g. in flex or grid). Therefore, as normal unless the order property has been used to change the order of items.

### flex-visual
Only takes effect on flex containers. Follows the visual reading order of flex items, taking the writing mode into account. Therefore, a document in English, with flex-direction: row-reverse and reading-flow: flex-visual would have a reading order of left to right. The `order` property affects the visual order. 

### flex-flow
Only takes effect on flex containers. Follows the flex-flow direction. The `order` property affects the flex flow order. **[Functionally the same as ordered-source, so we can probably omit this value.]**

### grid-rows
Only takes effect on grid containers. Follows the visual order of grid items by row, taking the writing mode into account.

### grid-columns
Only takes effect on grid containers. Follows the visual order of grid items by column, taking the writing mode into account.
