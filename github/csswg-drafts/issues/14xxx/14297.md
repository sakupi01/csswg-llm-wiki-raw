The current ED defines:

- `mix-blend-mode: <blend-mode> | plus-lighter`
- `background-blend-mode: <'mix-blend-mode'>#`

Since `background-blend-mode`'s grammar references the `mix-blend-mode` grammar, `plus-lighter` is grammatically a valid value for `background-blend-mode`. However:

- No engine supports it: `CSS.supports("background-blend-mode", "plus-lighter")` returns `false` in Chrome, Edge, Opera, Chrome Canary (Blink), Safari (WebKit), and Firefox (Gecko) — verified today.
- A WPT test exists — [css/compositing/background-blending/background-blend-mode-plus-lighter.html](https://wpt.live/css/compositing/background-blending/background-blend-mode-plus-lighter.html) — and [fails in all browsers](https://wpt.fyi/results/css/compositing/background-blending/background-blend-mode-plus-lighter.html).

Tracing the history, the gap appears to have gone unnoticed rather than been decided:

- `plus-lighter` was added to `mix-blend-mode` for the View Transitions cross-fade use case. Chromium's tracking issue [40205651](https://issues.chromium.org/issues/40205651) was closed as Fixed, but the implementing CL ([3289717](https://chromium-review.googlesource.com/c/chromium/src/+/3289717)) covered `mix-blend-mode` only.
- The failing WPT was subsequently triaged by adjusting test expectations ([CL 3423340](https://chromium-review.googlesource.com/c/chromium/src/+/3423340)) rather than by implementing or filing a follow-up.
- Because `background-blend-mode` picks up `plus-lighter` automatically through the `<'mix-blend-mode'>` grammar reference, it is unclear whether its inclusion there was ever a deliberate decision.

(Possibly related: [w3c/fxtf-drafts#446](https://github.com/w3c/fxtf-drafts/issues/446), still open, questions the relationship between `plus-lighter` and `lighter` in general.)

**Question:** Is `plus-lighter` intended to apply to `background-blend-mode`?

- **If yes**, implementations are missing everywhere and browser bugs should be (re)filed. There is a real use case: additive composition of background layers (e.g., summing multiple gradients as light) within a single element. Notably, the spec already requires background layers to composite as an isolated group, so `background-blend-mode: plus-lighter` would be free of the stacking-context pitfalls that make `mix-blend-mode: plus-lighter` hard to use — arguably the safer of the two is the one that was never implemented.
- **If no**, the grammar should be adjusted so that `background-blend-mode` excludes `plus-lighter` (e.g., by referencing `<blend-mode>#` directly), and the WPT test should be removed or updated to match.

Either resolution would end the current state, where the spec, the tests, and all implementations disagree with one another.
