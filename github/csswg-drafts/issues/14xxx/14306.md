In the definition of [font-relative units](https://drafts.csswg.org/css-values-4/#font-relative-lengths) there is the text:

> When used in the value of any 'font-*' property on the element they refer to...

Rather than leaving it to chance that the set of properties this refers to are the right set and all font effecting properties have the prefix `font-` and there are no non-font effecting properties that have the prefix `font-`, it would be clearer if this linked to either a complete list of properties or some other definition. 

I believe the intent is that it is any property that might influence one of the font's metrics used by font-relative units. One option would be for CSS Fonts could define that concept and this could link to it.

## @tabatkins — 2026-08-11

Checking my own understanding here.

In Fonts 4:
* The 'font' longhands are all font-affecting
* So are the 'font-synthesis' longhands, I think? Assuming that, say, synthetic bold might adjust the ch width or something.
* Are the [font-feature properties](https://drafts.csswg.org/css-fonts-4/#font-rend-props)? Hmm, I guess they can affect which glyph is used for 0, and thus the ch width too. font-variant-east-asian could affect `ic`, too. And I guess the generic `font-variant` can affect both of them in theory.
* I guess font-optical-sizing is too?
* And font-language-override, as it could affect the glyph used for `ic`.
* font-variant-emoji is *not* font-affecting, the affected characters aren't relied on by font-relative lengths nor are we likely to add font-relative lengths that are in the future reliant on those characters (or we can define them to be equal to the image variant, if we ever want to expose an emoji-width unit)
* Nor is font-palette, as it's just colors

Fonts 5 doesn't introduce any relevant new properties.

MathML will need to define that math-depth is font-affecting.

And that's it, maybe?
