https://drafts.csswg.org/css-color-4/#interpolation-space

> However, user agents must handle interpolation between legacy sRGB color formats (hex colors, named colors, rgb(), hsl() or hwb() and the equivalent alpha-including forms) in gamma-encoded sRGB space. This provides Web compatibility; legacy sRGB content interpolates in the sRGB space by default.

> This also means that authors can choose to opt-in to better interpolation, even between sRGB colors, by using the non-legacy `color(srgb r g b)` form for at least one of their colors, or by explicitly specifying an [interpolation color space](https://drafts.csswg.org/css-color-4/#interpolation-color-space).

----

Legacy `sRGB` color **formats** aren't fully clear to me.

Legacy **syntaxes** for `rgb` and `hsl` are defined but the list above also includes hex, named colors and `hwb`.

So I am unsure exactly where to draw the line.

-----

Are these legacy formats?

- space separated `rgb(255 0 0)` -> yes?
- none keyword `rgb(255 none none)` -> yes?
- relative color `rgb(from red r g b)` -> no, because these have a computed value of `color(srgb ...)`?
- color-mix `color-mix(in srgb, red, blue)` -> no, because these have a computed value of `color(srgb ...)`?

----

@svgeesus can you clarify?

## @svgeesus — 2026-11-03

> Legacy **syntaxes** for `rgb` and `hsl` are defined but the list above also includes hex, named colors and `hwb`.

The motivation was to have no change for content authored to CSS Color 3 (and possibly unmaintained since then) while content authored to the new features in CSS Color 4 is expected to have known about, and opted into, the better interpolation of Oklab.

Thus, I don't think `hwb` should be on that list, at all: it only has a modern syntax. As CSS Color 4 [says](https://www.w3.org/TR/css-color-4/#the-hwb-notation)

> There is no Web compatibility issue with [hwb](https://www.w3.org/TR/css-color-4/#valdef-hwb-hwb), which is new in this level of the specification, and so [hwb()](https://www.w3.org/TR/css-color-4/#funcdef-hwb) does not support a [legacy color syntax](https://www.w3.org/TR/css-color-4/#legacy-color-syntax) that separates all of its arguments with commas. Using commas inside hwb() is an error.

So I think the "interpolates in sRGB, if you only use these color formats" list should be:

1. legacy sRGB formats (the syntactic definition, commas instead of space and slash, so `rgb()`, `rgba()`, `hsl()`, `hsla`)
2. Hex colors
3. [Color Keywords](https://www.w3.org/TR/css-color-4/#color-keywords) so not just Named colors but also system colors, deprecated system colors, `transparent`, and `currentcolor`

All of those were defined in CSS Color 3, so that is an objective list.

## @romainmenke — 2026-11-04

How about:
- if a color has a serialized computed value of comma separated `rgb()`/`rgba()`, then interpolate in `srgb` (also see: https://github.com/w3c/csswg-drafts/issues/10368#issuecomment-6417297961)
- if a color is `transparent`, `currentcolor` or a System color, then interpolate in `srgb`
- anything else uses `oklab`

(assuming the other part of interpolation matches the same list)

This has the benefit that round tripping a color through JS doesn't suddenly change it's interpolation space.

## @romainmenke — 2026-11-04

It's not really a limitation.
You can still pick a modern notation for the other color you're interpolating with. If any of the two are modern you get `oklab`.

Interpolation between `currentColor` and `currentColor` isn't really useful. That it interpolates in `srgb` or `oklab` doesn't really matter, being the same color.

-----

I might be mistaken but I don't think `currentColor` is stable.
If there is a transition or animation on `color`, then the used value for `currentColor` might flip between legacy and modern and the interpolation might also suddenly flip between `srgb` and `oklab`.

So making `currentColor` interpolate in `srgb`, if the other color would also interpolate in `srgb`, costs nothing in terms of capabilities and gives a bit of stability.

----

Edit: interpolations between system colors and `currentColor` would always use `srgb`, even if you use a modern format for the `color` property. That is the one limitation I can think of.
