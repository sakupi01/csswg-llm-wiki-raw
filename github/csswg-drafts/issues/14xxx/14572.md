It would be nice to be able to use the attr type() function to parse a list of differently typed syntax-components, rather than just a list of the same kind of syntax-component. For example:


```css
[data-margin] {
 margin: attr(data-margin type( (auto | <length>)+ ));
}
```

This would parse attribute values like: `auto 10px`.

Currently the only way I can see this working is via `type(*)`.

The particular syntax I used above was just to illustrate the idea, and is not something I'm suggesting is an idiomatic way of writing this.

I'm a bit puzzled by this omission, nearly every property can admit some or all of the css-wide values like `auto` or `initial`, and so naturally places where we use a space or comma separated list will need to support combinations of types and keywords. Is there a way to write this already (without things like `type(*)`) that the spec doesn't clearly identify? Perhaps this is an intended limitation, if so it could be clarified in [section 3.3](https://drafts.csswg.org/css-values-5/#css-syntax)

If this is the wrong venue for non-member feedback on the spec I apologise for the noise, but I'm not really sure where else to direct this 😅
