Currently matching based on a `url-pattern` or `@location` is a simple `URLPattern` match (or `URL` equality).
In some cases, however, we would like to also match one or more of the parameters of the URL pattern with the equivalent parameter from the navigation, or a given value.

For example, the following matches a link to *any* movie
```css
@location --movie {
  path: "/movie/:movie-id";
}

:link-to(--movie) {
}
```

How would I match a particular movie, or the movie I'm currently navigating to/from?

Some examples:
```css
/* Extending @location */
@location --movie {
  path: "/movie/:movie-d";
}
@location --other-movie {
  pattern: --movie;
  params: {
    movie-id: from-navigation;
  }
}
@location --specific-movie {
  path: "/movie/:movie-id";
  params: {
    movie-id: 16;
  }
}

/* Extending :link-to*/
:link-to(--movie / movie-id from navigation)

/* other options? */
```

## @Crissov — 2026-08-04

Naive but intuitive expectations inspired by attribute value selectors:

~~~~ css
:link-to(--movie:movie-id="16") {}
:link-to-origin(--movie:movie-id) {}

:link-to(--movie[movie-id="16"]) {}
:link-to-origin(--movie[movie-id]) {}
~~~~

## @noamr — 2026-08-05

Maybe:
```css
:link-to(--movie[movie-id=16])
:link-to(--movie[movie-id of nav-at])
:link-to(--movie[movie-id of nav-to])
:link-to(--movie[movie-id of nav-from])
```

Where after `of` you can put any URL, and those `nav-*` are keywords representing URLs.
