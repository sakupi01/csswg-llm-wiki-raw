`string-set` is defined as taking a value of `none | [ <custom-ident> <string>+ ]#`, but that's not strictly accurate:

* it accepts `<string>`
* it accepts the `attr()` function
* it accepts the `counter()` function
* it accepts the special value `contents`, meaning the text-content value of the DOM element.

This is demonstrated in the [example](https://drafts.csswg.org/css-content-3/#example-208227c0) in the spec and described in prose in the the first paragraph of [Named Strings](https://drafts.csswg.org/css-content-3/#named-strings):

> The [string-set](https://drafts.csswg.org/css-content-3/#propdef-string-set) property accepts values similar to the [content](https://drafts.csswg.org/css-content-3/#propdef-content) property, including the extraction of the current value of counters.

The definition of the property should probably be updated to something more like

 `none | [ <custom-ident> <set-content-list>+ ]#`,
`set-content-list = [ <string> | <attr()> | <counter> | contents ]`

And we should note that
* if an element is `display:none`, values other than `<string> | attr() | contents` are ignored,
* that `contents` applies to the text-content value of the DOM element and is unaffected by CSS properties that may format this value including `white-space`, `visibility` or `display` properties.
