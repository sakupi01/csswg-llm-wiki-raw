[The css-position-4 draft from 2025-12-25](https://drafts.csswg.org/css-position-4/) says that:

* Elements in the top layer are rendered in the top layer if they have `overlay:auto`, but author stylesheets are not allowed to change `overlay`.
* Elements rendered in the top layer have a computed `position` of either `absolute` or `fixed`.

This seems to preclude any way of forcing an element *out* of the top layer using CSS.

Please consider allowing `position` to have any computed value even on elements in the top layer, and causing elements to be rendered in the top layer if and only if their computed `position` is `absolute` or `fixed`.

---

My use case is website navigation with popovers and submenus. I need the navigation menu to behave as follows:

* When on a phone (i.e. display device is a screen with sufficiently low width), the navigation menu should be a popover, and submenus should be in the normal flow.
* When not on a phone (i.e. display device is not a screen and/or has high width), the navigation should be in the normal flow, and submenus should be popovers.

Currently it looks like I can only accomplish this using a script that adds and removes `popover` attributes as appropriate. The problem with this is that it causes layout shifts/FOUCs and doesn't work if scripting is disabled.

If turning a popover into a non-popover were as simple as setting `position:static` on it, then this would be no problem.
