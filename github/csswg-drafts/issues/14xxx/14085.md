All implementations agree on this:

| specified | computed |
| --- | --- |
| `rgb(127.49999, 127.5, 127.5)` | `rgb(127, 128, 128)` |
| `rgb(127.499999, 127.5, 127.5)` | `rgb(128, 128, 128)` |

But I can't figure out why.

------

In my implementation `hsl(180, 0%, 50%)` is converted to `srgb` as `color(srgb 0.49999999999999983 0.5 0.5)` or `rgb(127, 128, 128)`.

While browser implementations have `rgb(128, 128, 128)`

I need to check why a color with `0` saturation doesn't come out with clean channel values but aside from that I was also curious how/why browsers make this difference between the two values above.

## @facelessuser — 2026-06-25

@romainmenke If I had to guess, I would attribute this to unit types. I suspect they are using 32-bit unit types, while you may be using 64-bit (if using something like JavaScript to compare).

9 decimals is going to exceed the precision of 32-bit values. So 127.49999 will likely still be recognized as 127.49999, but 127.499999 will likely be recognized as 127.5. When you apply rounding up on half, you will get 127 for the first, but 128 for the second.

```py
>>> import ctypes
>>> ctypes.c_float(127.49999).value
127.49999237060547
>>> ctypes.c_float(127.499999).value
127.5
```
