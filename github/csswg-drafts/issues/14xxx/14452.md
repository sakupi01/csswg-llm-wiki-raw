Currently, [palette-mix()](https://drafts.csswg.org/css-fonts-4/#funcdef-palette-mix) only supports taking exactly two mix components, much like color-mix() did in the past.

To match the other mix functions, it should be updated to support an arbitrary number of mix components.

## @weinig — 2026-09-09

@cdoublev I tried to follow the rules specified here -> https://drafts.csswg.org/css-color-5/#serial-color-mix. It only specifies that percentages should be omitted when all "effective percentages" are known and equal to 100% / number of components:

> If all [effective percentage](https://drafts.csswg.org/css-color-5/#effective-percentage)s are known and equal to 100% / N, no percentages are serialized..."

The declared value tests have two test that fall into that camp (one where all the percentages are explicit, one where one is omitted):

```
test_valid_value(`font-palette`, `palette-mix(in srgb, light 50%, dark 50%)`, `palette-mix(in srgb, light, dark)`) // both 50%
...
test_valid_value(`font-palette`, `palette-mix(in srgb, light 50%, dark)`, `palette-mix(in srgb, light, dark)`) // only p1 specified, is 50%
```

Serializing a value where the balanced percentages sum to less than 100, like `palette-mix(in srgb, light 20%, dark 20%)`, need to maintain the serialization since omitted them would give a different output due to the leftover.

Serializing a value where the balanced percentages sum to more than 100, like `palette-mix(in srgb, light 75%, dark 75%)`, probably could drop the percentages, but it is not currently spec'd that way.
