From https://github.com/w3c/csswg-drafts/issues/14551

Table layout queries the max-content size of a table cell in one case, if its placed within a non-constrained column:
https://drafts.csswg.org/css-tables-3/#outer-min-content

An algorithm that *may* work for this is to introduce an addition pass in the column sizing algorithm.

We change how we calculate the cell min/max sizes in the first pass by using the min-content size in the definition above, and apply these sizes to the columns.

We then:
 - determine the tentative max-content size of all of the columns
 - determine the free_space
 - rerun the column-sizing algorithm now using the correct max-content size instead, however this time distributing the extra evenly free-space to any columns which are not constrained, and have non-constrained cells, and the cells had a different min-content/max-content size[1].

This algorithm should work in most situations. 

[1] A constrained `<col style="width: 100px;">` won't use the max-content size of a cell. And a non-constrained column `<col>` may only have constrained `<td style="width: 50px">` cells contained within it.
[1++] We can relatively cheaply detect when the min-content and max-content size are the same in an unconstrained scenario. (E.g. the max-content size will be the min-content size always, and wont change with a different constrained inline-size). We should also treat these cells as inflexible.
