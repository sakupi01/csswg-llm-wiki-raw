Our spec boilerplate has this:

> This specification follows the [CSS property definition conventions](https://www.w3.org/TR/CSS2/about.html#property-defs) from [[CSS2]](https://www.w3.org/TR/css-fonts-5/#biblio-css2) using the [value definition syntax](https://www.w3.org/TR/css-values-3/#value-defs) from [[CSS-VALUES-3]](https://www.w3.org/TR/css-fonts-5/#biblio-css-values-3). Value types not defined in this specification are defined in CSS Values & Units [[CSS-VALUES-3]](https://www.w3.org/TR/css-fonts-5/#biblio-css-values-3). Combination with other CSS modules may expand the definitions of these value types.

Values 4 is the current work; looking at the [Additions and Changes from Values 3 to Values 4](https://www.w3.org/TR/css-values-4/#additions-L3) shouldn't we at least update this boilerplate to Values 4?

Potentially to Values 5, as there are [a bunch of changes there too](https://www.w3.org/TR/css-values-5/#additions-L4). But at least to Values 4.

But for the boilerplate specifically... the reason I pointed at L3 is that you can interpret all of our specs largely based on L3, and then future levels, as quoted, "may expand the definitions of these value types".
