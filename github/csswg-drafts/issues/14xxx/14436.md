Suppose we pass `currentColor` as param value, should this resolve against referenced document's own color?

ex:

```
img { color: green; link-parameters: param(--c, currentColor); }
<img src="foo.svg" />
```

```
<-- foo.svg -->
<circle fill="env(--c)"/>
```

<!-- comment id=5546567729 author=tabatkins created=2026-09-04T21:19:07Z url=https://github.com/w3c/csswg-drafts/issues/14436#issuecomment-5546567729 -->
## @tabatkins — 2026-09-04

As currently defined, the link params are unresolved to the same extent as an untyped custom property. That is, using `attr()`/`var()`/`if()`/etc in the value will resolve based on the element, but any other value (like `currentcolor`) will stay as an unresolved token. The SVG would not receive the `img`'s currentcolor, in this case, it would just get the keyword, which would resolve as normal based on the 'color' of whatever element in the SVG used it.

That's pretty unfortunate, and it applies more widely, like passing a `1em` length won't resolve based on the element's font-size.

You *can* often do a two-step thru a registered custom property, or thru a custom function, but that won't work for used-time values like `currentcolor`, and it's clumsy in general. I agree we should solve this more generally.

We really can't do this automatically in the general case, but we could certainly allow a `<css-type>` in `param()`, like:

```css
img { color: green; link-parameters: param(--c <color>, currentColor); }
```

And then specify that we actually go a little further than normal for custom properties/etc and this resolves down to the used value when possible.

## @tabatkins — 2026-09-10

I've gone ahead and defined the `<css-type>` argument, and defined precisely how values resolve (all the way to a used value).

The example in the OP still just passes the keyword `currentcolor`, and thus is somewhat useless, but writing it instead as `param(--c <color>, currentcolor)` will do as expected and resolve to `green` before passing to the linked SVG.
