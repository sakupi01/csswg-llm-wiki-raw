From https://github.com/web-platform-tests/wpt/pull/62706:

> [...] A featureless element is never matched by a universal selector, so defaultns|*:is(:host) cannot match the shadow host, while a compound containing only :host is exempt. Gecko, Blink and WebKit all agree on that. [...]
>
> That last part may want a spec clarification: [Selectors-4](https://drafts.csswg.org/selectors-4/#featureless) does not distinguish :host from a compound containing it, so read literally it would have :is(:host) match too.

## @Loirooriol — 2026-09-18

I'm not really following. https://drafts.csswg.org/selectors/#type-nmsp

> If a [default namespace](https://drafts.csswg.org/css-namespaces-3/#default-namespace) is declared, [compound selectors](https://drafts.csswg.org/selectors/#compound) without [type selectors](https://drafts.csswg.org/selectors/#type-selector) in them still only match elements in that default namespace

So both `:host` and `:is:(:host)` are restricted to the default namespace. It doesn't actually say to add `defaultns|*`, so featureless elements should still be allowed to match. I'm not getting why `:host` and `:is:(:host)` would be different in this regard.

And anyway, assuming that's web compatible, I think the spec should change so that only type selectors get the default namespace restriction. See #9810

<!-- comment id=5731616138 author=annevk created=2026-09-18T14:40:31Z url=https://github.com/w3c/csswg-drafts/issues/14504#issuecomment-5731616138 -->
## @annevk — 2026-09-18

Selectors also says:

> If a selector would otherwise match a [featureless](https://drafts.csswg.org/selectors/#featureless) element, except for the existence of the default namespace [[CSS-NAMESPACES-3]](https://drafts.csswg.org/selectors/#biblio-css-namespaces-3) (because featureless elements do not have a namespace unless otherwise defined), the default namespace does not prevent the match.

<!-- comment id=5736877396 author=tabatkins created=2026-09-18T22:20:22Z url=https://github.com/w3c/csswg-drafts/issues/14504#issuecomment-5736877396 -->
## @tabatkins — 2026-09-18

I *do* think we should try and change the default namespace behavior as described in #9810. The current behavior is unintuitive and weird, since it affects selectors that don't mention a single namespace-relevant feature.

But putting that to the side, yeah, featureless elements intentionally ignore the default namespace when doing matching, and `:is(X)` can match featureless elements if `X` can, so `:host` and `:is(:host)` *should* both match in the presence of a default namespace.
