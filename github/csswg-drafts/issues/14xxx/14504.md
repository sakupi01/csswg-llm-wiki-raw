## @tabatkins — 2026-09-24

> Well, not sure, what about :is(:host, div), should that match? Should it remove the default namespace constraint for div? That would be unfortunate.

No, what about the spec or my comment would lead you to believe that is what would happen? (Not a rhetorical question - I'm interested in making sure the spec is easy to read, altho this is an inherently somewhat confusing thing.)

The behavior is well-defined by three pieces of spec text:

1. [Default namespaces apply to every compound selector by default.](https://drafts.csswg.org/selectors/#type-nmsp:~:text=If%20a%20default%20namespace%20is%20declared%2C%20compound%20selectors%20without%20type%20selectors%20in%20them%20still%20only%20match%20elements%20in%20that%20default%20namespace.)
2. [Default namespaces do not apply to the compound selectors in any of the logical combination pseudos' arguments, unless they contain a type/universal selector.](https://drafts.csswg.org/selectors/#matches:~:text=Default%20namespace%20declarations%20do%20not%20affect%20the%20compound%20selector%20representing%20the%20subject%20of%20any%20selector%20within%20a%20%3Ais()%20pseudo%2Dclass%2C%20unless%20that%20compound%20selector%20contains%20an%20explicit%20universal%20selector%20or%20type%20selector.)
3. [Featureless elements ignore the default namespace when matching.](https://drafts.csswg.org/selectors/#featureless-elements:~:text=If%20a%20selector%20would%20otherwise%20match%20a%20featureless%20element%2C%20except%20for%20the%20existence%20of%20the%20default%20namespace%20%5BCSS%2DNAMESPACES%2D3%5D%20(because%20featureless%20elements%20do%20not%20have%20a%20namespace%20unless%20otherwise%20defined)%2C%20the%20default%20namespace%20does%20not%20prevent%20the%20match.)

Combine these three, and exactly the correct behavior falls out. `:host` ignores the default namespace. `:is(:host)` ignores the default namespace. `:is(:host, div)` ignores the default namespace for matching the host element, but pays attention for matching divs. 

(Note that the `:host` default-namespace behavior is *not* applied at the selector-interpretation level, like the `:is()` arguments behavior is; rather, it applies at the selector *matching* level. A selector that nominally applies the default namespace, but wants to try and match a featureless element which *can't* match a default namespace, will still successfully match.)

And then ignoring host elements for a moment, `.foo, .bar` pays attention to the default namespace (each of the compounds uses it), as does `:is(.foo, .bar)` (the top-level `:is()` compound uses it, even tho its arguments don't). `svg|a.foo, svg|a.bar` does not (because it specifies a namespace explicitly), nor does `svg|a:is(.foo, .bar)` (top-level compound specifies it explicitly, `:is()` arguments don't use it).

(If we made the #9810 change, then none of those cases would use the default namespace.)
