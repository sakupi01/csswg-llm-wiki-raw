For context, `track-reverse` is where we reverse the placement direction of items.  In `grid-template-columsn`, that would mean instead of placing items from left-to-right, we'd place items from right-to-left, and in `grid-template-rows`, that would mean we're placing items from bottom-to-top.

In the case that we're reversing the placement of items through `track-reverse`, should we be changing the start edge of where we're placing items?

@yanlingwang23 made a helpful diagram for this case, where in the normal case, we'd have this:

**Behavior A:**
<img width="308" height="249" alt="Image" src="https://github.com/user-attachments/assets/33357527-c1fb-457e-8004-64f64775dc36" />

or **Behavior B:**
<img width="321" height="272" alt="Image" src="https://github.com/user-attachments/assets/57e85506-945e-4d9b-9724-0d94d9d5d573" />

I'm in favor of Behavior A, because if we wanted behavior B, then web authors would use writing direction.  From this related issue about `track-reverse` [HERE](https://github.com/w3c/csswg-drafts/issues/12971), it makes sense that ONLY the placement direction should change (like in Behavior A), but all of the other semantics like starting edge, line names, etc remain the same.
