The Web App Manifest spec is adding a new discrete CSS media feature, `application-context`, and we'd like the CSSWG's review of the media feature design, naming, and syntax.

PR: https://github.com/w3c/manifest/pull/1218 (preview linked in the PR)

What it does: `application-context` reflects the application context a top-level traversable is running in. It's a discrete media feature with two values:

- `installed` — the top-level traversable is an installed web application context
- `browser` (default) — otherwise

```css
@media (application-context: installed) {
  .install-banner { display: none; }
}
```

It's orthogonal to the existing `display-mode` media feature (also defined in Web App Manifest): `application-context` answers "what context is this running in?", while `display-mode` answers "what presentation mode is used?". Same-origin child navigables inherit the top-level value; cross-origin nested documents always evaluate to `browser`.

Background: this was agreed in principle at TPAC 2025 (w3c/manifest#1092) and is aligned with Microsoft Edge's [Application Context Media Feature explainer](https://github.com/MicrosoftEdge/MSEdgeExplainers/blob/main/ApplicationContextMediaFeature/explainer.md).

We'd particularly appreciate feedback on the feature name and value names, whether the discrete media feature framing fits CSS conventions, and the forward-compatibility note about adding future values.
