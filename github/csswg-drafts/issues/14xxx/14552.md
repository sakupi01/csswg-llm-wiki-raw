The feConvolveMatrix `edgeMode` values `duplicate`, `wrap`, `mirror` and `none` have no definitions. 

Since w3c/fxtf-drafts#452 (2022) narrowed the shared `dfn-for=edgeMode` to `feGaussianBlur/edgeMode`, feConvolveMatrix has had none of its own. The grammar line is wrapped in `dfn-for=feConvolveMatrix/operator` (feConvolveMatrix has no `operator` attribute) and contains links, not definitions, so every value link in the feConvolveMatrix section goes to the feGaussianBlur definitions.

Proposed fix: define the four values for `feConvolveMatrix/edgeMode`, like `feComposite/operator`, and add `for=` to the links that become ambiguous.

For the record, how the markup got here. 

- 2014, w3c/fxtf-drafts@fb00fbf0e5a602238928e383edb5ee8cf2916947: the values were defined once, in the feGaussianBlur section, as `dfn-for=edgeMode` with no element name. feConvolveMatrix linked to those same definitions. The feConvolveMatrix grammar line had a single `</span>` (no opening tag).
- 2022, w3c/fxtf-drafts#452: `dfn-for=edgeMode` was narrowed to `feGaussianBlur/edgeMode`, which is right for that section. From then on the feConvolveMatrix links pointed at definitions belonging to feGaussianBlur.
- 2024, w3c/fxtf-drafts@9c6cf9a2e3df6a3161d027dd215f57531c9d75fe (w3c/fxtf-drafts#527): `mirror` was added to both elements, defined in the feGaussianBlur section as `feGuassianBlur`, fixed in #14549.
- 2025, c390fbe8c506b79c6e8ace94ab6e589ae4d32ddf: the unmatched `</span>` got an opening tag modelled on the feComposite `operator` line, which is where `dfn-for=feConvolveMatrix/operator` comes from.
