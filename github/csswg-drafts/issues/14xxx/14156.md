### Context

The gap-decoration properties accept value lists, including `repeat( <n>, … )`
and `repeat( auto, … )`. For grid and multicol, values are assigned to gaps in a
well-defined order along each axis. For grid lanes containers, the assignment
order along the **stacking axis** is undefined, because that axis has no shared
lines/tracks and its gutters are misaligned across lanes.

### Problem

`column-rule-*` / `row-rule-*` lists, and the expansion of `repeat( auto, … )` 
should have mapping onto stacking-axis gutters.

### Proposal

- **Grid axis.** Assign values to track gaps sequentially along the grid axis, as
  for grid containers today.
- **Stacking axis.** Assign values in **lane by lane** order, with each lane being **independent**
(i.e. the assignment of values in one lane does not affect the others).
- **Same-item rule.** All gap segments belonging to the same item receive the
  same value. Specifically, a **spanner occupies a single assignment slot** (one
  value), even though the gutter it owns/interrupts spans multiple tracks.
  This same thing applies to the gutters "below" a spanner, even though they are technically not owned by the spanner.
