This is a parent issue to discuss five interlinked `css-mixins-1` threads together at the
F2F. They are really *one* design conversation about **how a mixin is authored and how
its arguments/locals resolve**. Tracking them jointly matters so we land an
architecturally coherent design rather than five ad hoc decisions.

**The convergence:** these threads point at a single question: **can `@mixin` and
`@macro` be collapsed into one construct?** The path (proposed on #13680, confirmed
workable by @tabatkins) is:

1. **Drop `@result`**, treat the whole body as the result: **#13524**
2. **Adopt a general hygienic-locals rule** (`@locals`/`@private`) as the shared locals
   mechanism: **#14004**
3. Define **where locals/arguments resolve** (capture on the applying element vs.
   per-element) so `@locals` ships with defined semantics: **#13454**
4. Given 1–3 plus the already-resolved **#13727** (scoping dropped), an argument-less,
   locals-less `@mixin` and `@macro` become the same thing, so one can be dropped
   (name: keep `@mixin`): **#13680**
