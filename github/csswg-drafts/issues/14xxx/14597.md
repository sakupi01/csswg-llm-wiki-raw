From: https://github.com/w3c/csswg-drafts/issues/14551

We need to consider 4 different cases for flex layout:
1. Wrapping row
2. Non-wrapping row
3. Wrapping column
4. Non-wrapping column

Non-wrapping column is the easiest, it behaves the same as block layout, and you just give the whole `tentative_inline_size` to each child to determine what their max-content size is.

Wrapping row is also simple. As wrapping is allowed between the items you can also give the whole `tenative_inline_size` to each child. (At worst there will be a line-break between each item, behaving like block layout).

Non-wrapping row is a little complex. And we probably something similar as described by tables: https://github.com/w3c/csswg-drafts/issues/14568
 - Determine the rows min-content size.
 - Determine the free-space.
 - Distribute the free-space evenly to each child's `tentative_inline_size` if it is flexible (min-content size != max-content size).

Wrapping column may be impossible to get a good result.

Today we layout the items at their max-content inline-size, then perform layout, line-break based on the `tentative_block_size` based on these item block-sizes, and produce the result.

The issue we are fighting with two different constraints (the block-axis line wrapping constraint, and the inline-sizes max-content constraint). E.g. if we change the max-content size we'll change how they line wrap, which will change the max-content size. It's circular.

The best thing to do for this case may be just to give each child the full `tentative_inline_size`. It'll be correct if the columns are non-wrapping, but will overflow a `max-inline-size` from a parent if wrapping occurs.
