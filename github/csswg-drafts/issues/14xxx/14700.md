**Where:** CSS Animations Level 1, Editor's Draft 13 September 2026, §3 Declaring Keyframes (#keyframes), against CSS Cascading and Inheritance Level 5, Editor's Draft 13 April 2026, §6.4 Cascade Layers (#layering).

**Text.** CSS Animations 1 §3:

> If multiple @keyframes rules are defined with the same name, the last one in document order wins, and all preceding ones are ignored.

CSS Cascade 5 §6.4:

> At-rules (such as @keyframes, @font-face, @page, etc.) that are defined inside cascade layers also use the layer order when resolving collisions or cascading.

The Candidate Recommendation Snapshot of 13 January 2022 already had the rule:

> Name-defining at-rules such as @keyframes or @font-face that are defined inside cascade layers also use the layer order when resolving name collisions.

**Example** (Cascade 5's own, #example-14540e6d):

```css
/* establish the layer order, so the "override" layer takes precedence */
@layer framework, override;

@layer override {
  @keyframes slide-left {
    from { translate: 0; }
    to { translate: -100% 0; }
  }
}

@layer framework {
  @keyframes slide-left {
    from { margin-left: 0; }
    to { margin-left: -100%; }
  }
}

.sidebar { animation: slide-left 300ms; }
```

Both `@keyframes` rules are in the author origin and the same tree context, so only layer order and document order can separate them. By Cascade 5, `override` is later in the layer order and its `slide-left` is used: the sidebar animates `translate`. By CSS Animations 1, the last rule in document order wins, which is the one in `framework`: the sidebar animates `margin-left`.

**Why it is a problem.** #6404 (closed, accepted by resolution) settled this in Cascade 5 in 2021, and the Cascade 5 changes list records it as "Name-defining at-rules follow layer order for collision resolution". The sentence in CSS Animations 1 was not updated. Its §12 list of pending resolutions still carries the 2012 item:

> - When you encounter duplicate animations names, last one wins.

So a reader of CSS Animations 1 alone gets the other answer.

Found during an AI-assisted review of the cascade specs.

**Request:** could CSS Animations 1 §3 defer to the layer order, for example: "If multiple @keyframes rules are defined with the same name, the one in the latest cascade layer wins ([css-cascade-5]); within the same layer, the last one in document order wins, and all preceding ones are ignored."?
