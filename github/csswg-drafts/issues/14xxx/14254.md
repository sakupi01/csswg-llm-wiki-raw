We are using mixes of `currentColor` and `transparent` to indicate various form control states. However, the coloration is based on using `border-color: currentColor` as the default state, whereas our survey of design systems showed that common authoring practices tend to use more muted shades of gray rather than black or undiluted currentColor.

To bring the [default style sheet](https://drafts.csswg.org/css-forms-1/#basic-appearance-stylesheet) in line with existing practices, we suggest the following adjustments:

* Make the default border color on inputs 50% instead of 100% (opaque).
* Adjust the `:disabled` colors (which currently have the color and border-color) by increasing `color` from 50% to 55% (improve contrast) and decreasing `border-color` to 25% (half of the new default).
* Use border color at 100% as the `:hover` effect, instead of using a background color. This is a more subtle effect, which fits better with a UA default stylesheet.
* Use an 8% background as the `:active` effect, as 20% seems too strong; and apply it to `select` as well as `button` etc.
* Adopt a subtle bit of background shading in dark modes, to make the inputs look more input-y.

We're open to other tunings or suggestions, but this is what we came up by merging findings from a survey of design systems with the existing decisions about UA styles.

```
select, input, textarea {
	border: 1px solid color-mix(in srgb, currentColor 50%, transparent);
	background: light-dark(transparent, color-mix(in srgb, CanvasText 4%, transparent));
}
:is(select, input, textarea):hover {
	border-color: color-mix(in srgb, currentColor 70%, transparent);
}
:is(select, input, textarea):hover {
	background-color: color-mix(in srgb, currentColor 8%, transparent);
}
:is(select, input, textarea):disabled {
	color: color-mix(in srgb, currentColor 55%, transparent);
	border-color: color-mix(in srgb, currentColor 25%, transparent);
	background-color: color-mix(in srgb, currentColor 6%, transparent);
}
```

<hr>

We also suggest inserting (before the `:disabled` rule) a red border-color to indicate `:user-invalid`, e.g.

```
:is(select, input, textarea):user-invalid {
    border-color: light-dark(#db2a37, oklch(from #db2a37 calc(l + 0.17) c h));
}
```

<!-- comment id=5273892171 author=fantasai created=2026-08-12T23:14:02Z url=https://github.com/w3c/csswg-drafts/issues/14254#issuecomment-5273892171 -->
## @fantasai — 2026-08-12

@Psychpsyo If the author sets the border color to _literally anything_, it'll override this effect. This is because author rules absolutely override UA rules, regardless of specificity.

(Note this also means that if the author sets any border/background/color rules, they'll have to set their own :focus/:active/:disabled colors, too, because they've now blown those UA rules away also.)

Having these rules in the UA stylesheet just makes it work nicely by default.

## @phaux — 2026-08-14

I don't think that the hover/active styles are necessary. I think that the elements look good enough without them. Inputs already indicate hover by changing the cursor anyways. In this case I would keep it simple (same with animation and shadow but that's a separate issue).

On the other hand, I would change the disabled style to use opacity: 50% so it actually doesn't get overridden by simply specifying a custom text/border color. From my experience it's too easy to forget about styling the disabled state and reducing opacity is what I usually do anyways but maybe that's just me.
