In https://github.com/w3c/csswg-drafts/issues/14235#issuecomment-5191610001 the WG resolved on using the [fragment directive delimiter defined in URL Fragment Text Directives spec](https://wicg.github.io/scroll-to-text-fragment/#fragment-directive-delimiter) for link parameters to avoid clashes with fragments being used for routing.

The `image()` function currently also uses a bare hash sign for defining fragments by referring to the Media Fragments spec.

I've just filed https://github.com/w3c/media-wg/issues/63 for the Media Fragments spec asking to change their delimiter.

So, ideally Media Fragments gets updated. In that case CSS Images only needs to be updated to reflect that change in its examples.
Though we might also define to use the fragment directive delimiter, diverging for what's currently specced in Media Fragments to solve the issue.
