Originally raised in [#14447](https://github.com/w3c/csswg-drafts/issues/14447#issuecomment-6042665113).

How should or could contextual information that is not in properties be passed to linked resources?

## Main use case: selective i18n
 
SVG can switch between elements by language. In HTML, this works by providing the `lang` attribute on the embedding element or an ancestor; this cannot be expressed by CSS.

Likewise, CSS cannot set the language for resources it references itself with `url()` or `src()`. That means, CSS authors cannot enforce a particular variant rendering of the embedded resource, but HTML authors can. 

[At first](https://github.com/w3c/svgwg/issues/201), I thought this should be handled by (possibly format-specific) fragment identifiers like `foo.svg#lang=en-INT`, [then](https://github.com/w3c/svgwg/issues/1191) I considered link parameters like `foo.svg#:~:param(lang:en-INT` or `url(foo.svg param(lang: en-INT))`, but now I’m almost certain that a dedicated new [Request URL Modifier](https://drafts.csswg.org/css-values-5/#request-url-modifiers), either `language()` or `lang()`, would be a better way to select the preferred content language of multilingual resources. Other data would need their own modifiers, though. 

~~~~ css
/* hypothetic user agent stylesheet */
img[src$=".svg"][lang] {
  content: src(attr(src type(<url>)) language(attr(lang))) / attr(alt);
}
~~~~
~~~~ css
/* setting language from within CSS */
selector {
  background-image: src("i18n.svg" language(en-INT));
}
~~~~

Besides SVG internationalized with `<switch>`es, this could also apply to multimedia container formats that may carry video, audio and text (“subtitle”) tracks or metadata fields in various natural languages.
