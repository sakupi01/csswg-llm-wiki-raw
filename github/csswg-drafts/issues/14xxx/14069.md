There are two related but separate issues:
1. How can gamut mapping be tested in WPT? Without the feature being testable, it cannot be prioritized in Interop, cannot have a web-feature id, and many other cannots, not to mention the obvious direct problem of it not being testable.
2. How can authors detect whether gamut mapping is available? There should be a way for authors to detect support given how long we've gone without it. 

As UAs are starting to implement gamut mapping, it's urgent that we find a way to solve these issues, otherwise once browser versions ship with GMAs but no way to test for it the ship has sailed…

Some ideas, none great:
1. For 2, a custom ident to be used in `@supports`. I really don't like this, but there's precedent for other features.
2. A `color-map(<color> [p3 | srgb | rec2020]?)` function that is guaranteed to follow the UAs GMA and ship at the same time. Then, we can test for that instead. If the gamut argument is omitted, the widest gamut that passes the `color-gamut` MQ is used.
3. ???

## @LeaVerou — 2026-06-19

> If this is granular, what happens when you interpolate a gamut mapped color with a non-gamut mapped color or two colors mapped to different gamuts? Keeping in mind that gamut mapping only happens when displaying a color, which happens later than interpolation.

To clarify, this does not **replace** GM at the output. GM cannot be opt-in! The function affects the *computed* color, allowing you to do math on it, use relative color syntax etc, whereas otherwise the GM happens later in the pipeline and is thus not observable, not testable, and any operations on it need to operate on the un-mapped color (and map at the output as well, of course).

> [@LeaVerou](https://github.com/LeaVerou) what is an example of something an author might do with the ability to feature detect if gamut mapping is enabled?

One use case is to define tints differently. See https://apps.colorjs.io/tints/, clipped tints are unusable.

That also serves for a use case of what to do with a `gamut-map()` method: light tints often need additional chroma reduction *beyond* what gamut mapping does. Multiplying chroma by a factor (e.g. `calc(c * .8)` doesn't help tremendously in that case because if the result is gamut mapped in the end, you've now desaturated each color by an unpredictable amount.
