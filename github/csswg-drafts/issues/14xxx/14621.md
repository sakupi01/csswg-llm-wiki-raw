(Written with the help of GPT-6 Astra Max.)

The [`box-shadow` shorthand](https://drafts.csswg.org/css-borders-4/#propdef-box-shadow) lists its initial value as `none`, suggesting that `box-shadow: initial` and `box-shadow: none` should produce the same longhand values. However, the current definitions give them different shadow colors.

`box-shadow: initial` resets each longhand to its own initial value: [`box-shadow-color`](https://drafts.csswg.org/css-borders-4/#propdef-box-shadow-color) becomes `currentcolor`, and [`box-shadow-offset`](https://drafts.csswg.org/css-borders-4/#propdef-box-shadow-offset) becomes `none`. In contrast, the shorthand's expansion rules say that an omitted color becomes `transparent` when the specified offset is `none`.

| Declaration | `box-shadow-offset` | `box-shadow-color` |
| --- | --- | --- |
| `box-shadow: initial` | `none` | `currentcolor` |
| `box-shadow: none` | `none` | `transparent` |

Both initially draw no shadow, because the offset is `none`. But the color is still observable through the longhand, and it affects rendering if only the offset is subsequently changed:

```css
.a {
  color: red;
  box-shadow: initial;
  box-shadow-offset: 10px 10px;
}

.b {
  color: red;
  box-shadow: none;
  box-shadow-offset: 10px 10px;
}
```

Applying the draft's rules, `.a` would have a red shadow, while `.b` would have a transparent, invisible shadow.

This also matters when CSSOM reconstructs shorthand text from the initial longhand values. Serializing that combination as `none` would change the color from `currentcolor` to `transparent` when the text is parsed again. Writing `currentcolor none` preserves it. An authored `box-shadow: initial` declaration can retain the `initial` keyword; the problem arises when reconstructing the shorthand from the individual values.

In jsdom's implementation of these longhands, the initial values therefore reconstruct as `currentcolor none`, while WPT's `css/css-backgrounds/inheritance.sub.html` expects `none`.

Should omitted color with a `none` offset default to `currentcolor`, should the longhand initial become `transparent`, or is the distinction intentional, requiring a change to the shorthand's initial-value entry? Please clarify which values are intended so that expansion, shorthand serialization, and the initial-value test can agree.
