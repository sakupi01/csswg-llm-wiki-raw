https://drafts.csswg.org/css-values-5/#interpolation-stop-fixup

For example, how should `calc-interpolate(0, 0: 0, ease-in, 1: 1, ease-out, 0.5: 0.5)` be fixed up?

  1. `calc-interpolate(0, 0: 0, ease-in, 0.5: 0.5, ease-out, 1: 1)`
  2. `calc-interpolate(0, 0: 0, ease-out, 0.5: 0.5, ease-in, 1: 1)`
  3. `calc-interpolate(0, 0: 0, ease-in, 0.5: 0.5, 1: 1)`

Or how should `calc-interpolate(0, 0 1: 0, ease-in, 0.5: 0.5, ease-out, 2: 2)` and `calc-interpolate(0, 0px: 0, ease-in, 0.5: 0.5, ease-out, 2: 2)`, which I think are equivalent, be fixed up? There are many options for them depending on if:

  - which of the preceding stop or the next stop owns the easing
  - whether the easing is duplicated for implicit stops

A [keyframe](https://drafts.csswg.org/web-animations-1/#keyframes-section) object owns the easing that applies to the period of time between the keyframe and the next one, and the keyframe generated from an implicit keyframe uses the default easing (`linear`). When applying this model to interpolation stops, the expected result should be `calc-interpolate(0, 0: 0, ease-in, 0.5: 0.5, ease-out, 1: 0, 2: 2)`, if I am not mistaken. It is a bit unfortunate that the syntax does not mirror this ownership: `<input-position>{1,2} : <calc-sum>, [<easing-function>? , <input-position>{1,2} : <calc-sum>]#?)`.
