https://drafts.csswg.org/css-color-5/#example-dddffb4a

This example illustrates how the `hue` is preserved, even when the `chroma` is zero.
But this no longer works when following the latest spec.

As we now always have a powerless to missing step the `hue` becomes missing.
https://drafts.csswg.org/css-color-4/#color-conversion

The example follows these steps:

1. `lch(62.753 62.571 326.973)`
2. `lch(from lch(62.753 62.571 326.973) l 0 h)`
3. `lch(from lch(from lch(62.753 62.571 326.973) l 0 h) l 30 h)`

Or:

1. `lch(62.753 62.571 326.973)`
2. `lch(62.753 0 none)`
3. `lch(62.753 30 none)`

While the example has an outcome of `lch(62.753 30 326.973)` where the `hue` is preserved.

@svgeesus Is it correct that the example is outdated?

🤔 even if we preserve powerless `hue` in RCS/interpolation when the start and destination space are the same, we would still lose that `hue` for `hsl` and `hwb` in computed/serialized values. Because `hsl` and `hwb` without `none` compute/serialize as `color(srgb ...)`

|  | specified | current spec computed | preserving powerless `hue` computed |
| ---- | ---- | ---- | ---- |
| hsl | `hsl(from hsl(180 0 50%) h s l)` | `hsl(none 0 50%)` | `color(srgb 0.5 0.5 0.5)` |
| lch | `lch(from lch(20 0 180) l c h)` | `lch(20 0 none)` | `lch(20 0 180)` |

So if we want to preserve `hue` in these cases then we could also update https://drafts.csswg.org/css-color-4/#css-serialization-of-srgb to cover powerless `hue`.

**If step 2 isn't applied in RCS then powerless hue's would be preserved.**

----

For `color-mix()` however all steps are required:

https://drafts.csswg.org/css-color-4/#interpolation

1. checking the two colors for [analogous components](https://drafts.csswg.org/css-color-4/#analogous-components) and [analogous sets](https://drafts.csswg.org/css-color-4/#analogous-set) which will be carried forward
2. prepare both colors for conversion. this changes any [powerless](https://drafts.csswg.org/css-color-4/#powerless-color-component) components to [missing](https://drafts.csswg.org/css-color-4/#missing-color-component) values
3. converting them both to a given color space which will be referred to as the interpolation color space below.

The order and definition of these steps means that any powerless component becomes `0`.

Here the `hue` is powerless: `lch(100% 0% 90deg)`

steps:
1. no component is missing, so nothing will be carried forward
2. set the `hue` to missing as it is powerless
3. convert any missing components to `0` so that the color conversion maths receive numbers for all components

So the result is always a hue of `0` (not `none`!) when the hue is powerless and interpolation happens to be in the same colorspace as the input colors.

In interpolation:
- `color-mix(in lch, lch(50% 50% 180deg), lch(100% 0% 0deg))` -> `(180deg + 0deg) / 2` -> `90deg`
- `color-mix(in lch, lch(50% 50% 180deg), lch(100% 0% 90deg))` -> `(180deg + 0deg) / 2` -> `90deg`!
- `color-mix(in lch, lch(50% 50% 180deg), lch(100% 0% 180deg))` -> `(180deg + 0deg) / 2` -> `90deg`!
- `color-mix(in lch, lch(50% 50% 180deg), lch(100% 0% none))` -> `(180deg + 180deg) / 2` -> `180deg`

@LeaVerou @svgeesus this is the result of the last resolution from this thread: https://github.com/w3c/csswg-drafts/issues/10211
