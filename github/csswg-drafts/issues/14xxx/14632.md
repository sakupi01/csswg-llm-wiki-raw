(Written with help from GPT-6 Astra High.)

Please clarify the computed serialization prose to describe the existing interoperable behavior when one axis is `span-all`.

[§3.1.3](https://drafts.csswg.org/css-anchor-position-1/#position-area-computed) currently says that a computed `<position-area>` serializes “with the logical keywords serialized in their short forms”. Taken literally, that suggests `inline-start` should serialize as `span-all start`, and `block-start` as `start span-all`.

Chromium, Firefox, and WebKit instead produce these computed values, matching the existing [WPT](https://github.com/web-platform-tests/wpt/blob/master/css/css-anchor-position/position-area-computed.html):

| Specified value | Computed serialization |
| --- | --- |
| `inline-start` | `inline-start` |
| `span-all start` | `inline-start` |
| `block-start` | `block-start` |
| `start span-all` | `block-start` |
| `block-start inline-end` | `start end` |
| `block-start inline-start` | `start` |

The behavior follows the intent of [#11828's resolution](https://github.com/w3c/csswg-drafts/issues/11828#issuecomment-2776447178). It is also described explicitly in [the implementation algorithm in #12759](https://github.com/w3c/csswg-drafts/issues/12759#issuecomment-3273676002), which was subsequently [closed with no change](https://github.com/w3c/csswg-drafts/issues/12759#issuecomment-3779464931).

Could §3.1.3 explicitly state that, when one axis is `span-all` and the other is a logical start/end or span-start/span-end keyword, including the self-relative variants, serialization uses the axis-specific long keyword and omits `span-all`? Otherwise the short logical keywords are used, and equal keywords collapse to one.

This would clarify the existing computed-value behavior without changing implementations or WPT, and without changing the distinct specified-value serialization rules retained by #12759. It would also explain why `span-all center` and `center span-all` remain two keywords: `center` has no axis-specific long form.
