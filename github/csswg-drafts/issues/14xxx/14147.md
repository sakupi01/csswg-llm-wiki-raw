One issue some people are facing with (concave) corner shapes as well as with some border shapes, is that concave parts of the shape can clip the internal content, like in this example:

<img width="224" height="191" alt="Image" src="https://github.com/user-attachments/assets/6a129317-2582-41b5-8e8d-8b6a1abbbe4a" />

In some cases padding is enough, but maybe some times the designer would want to make the text follow the curve when it's at the edge.

An existing unfinished spec for this is `shape-inside` - however a huge problem with `shape-inside` is that it doesn't have a good solution for the question of "where does the overflow content go to?", and developers who ignore this question might create frustrating situations for users e.g. when content becomes bigger due to translation etc.

A possible solution to this is to allow "box-like" shapes, like the regular boxes with corners, to grow their *middle* bit in both the inline and block direction, shaping only the edges of the content based on the `border-shape` or `corner-shape`+`border-radius`.

For regular boxes this axis can be automatically derived from the border radii, and for `border-shape` we can perhaps allow some syntax to define that some of the points can use `fr` units or some such to allow them to grow by content.
