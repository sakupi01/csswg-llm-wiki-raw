The current description of the `:nth-child` only explains the meaning of the `A`, `n` and `B` values, but it doesn't explain when these values actually evaluate to `true` at runtime.

I propose to add an explanation in the form of an `if` statement explaining when an `:nth-child (An+B)` expression actually applies, provided a given `index` value.

Example:

```javascript
if ((index - B) % A === 0 && (index - B) / A >= 0)
{
    // matches
}
```

## @Loirooriol — 2026-10-02

I don't really see why the CSS spec would need to provide a JS algorithm? It's already defined in prose: https://drafts.csswg.org/selectors/#the-nth-child-pseudo

>  it represents any index i = An + B for any non-negative integer n

In other words, `:nth-child(An+B)` matches an element with index `i` if there exists a non-negative integer `n` such that `i = An + B`

The existing spec is missing the final conclusion.

> if there exists a non-negative integer `n`

`A` and `B` do not play any role in this statement. `i` not even in the evaluation.

There's an infinite amount of non-negative `n`. The current specification doesn't provide any information on the expected Boolean result.
