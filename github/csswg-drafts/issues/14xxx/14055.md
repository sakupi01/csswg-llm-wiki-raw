External links are a common concept in web development with many sites adding an icon to links navigating to a different origin. For example: wikipedia.org and developer.mozilla.org which both use a class called "external" to identify and style such links.

There is little discussion around styling local links specifically. However, if you look up how to style external links, you may encounter resources such as [this StackOverflow question](https://stackoverflow.com/questions/5379752/css-style-external-links), which provides a rather convoluted and error-prone attribute-based string matching solution.

While the `:local-link()` pseudo-class can provide this functionality via inversion: `:not(:local-link(0))`, it is:
- Less readable
- Less discoverable
- Indirect for expressing a common pattern

This proposal introduces the pseudo-class: `:external-link` defined as the logical inverse of `:local-link(0)`.
While building directly on the existing semantics of `:local-link()`,  `:external-link` would:
- Improve readability
- Encourage consistent handling of external navigation
- Provide a clear and declarative way to express a common pattern

Example:
```css
:external-link::after {
    mask: url(/icon/external-link.svg);
}
```
