In §2 (Color Terminology), the leaf measured as `lch(51.2345% 21.2 130)` is written in five RGB spaces. Four of them match the spec's own sample code (§19). The rec2020 value does not:

| | printed | computed from lch(51.2345% 21.2 130) |
|---|---|---|
| srgb | 0.41587 0.503670 0.36664 | 0.41585 0.50370 0.36664 |
| display-p3 | 0.43313 0.50108 0.37950 | 0.43309 0.50109 0.37955 |
| a98-rgb | 0.44091 0.49971 0.37408 | 0.44088 0.49972 0.37412 |
| prophoto-rgb | 0.36589 0.41717 0.31333 | 0.36591 0.41716 0.31331 |
| **rec2020** | **0.6295 0.9657 0.3633** | **0.47428 0.52316 0.41425** |

The printed rec2020 value decodes to about `lch(87.8% 113.3 134.4)`, a bright saturated green rather than the leaf. It isn't the old transfer function either: with the BT.2020 OETF the leaf is `0.39188 0.44676 0.32509`.

Suggested fix: `color(rec2020 0.47428 0.52316 0.41425)`.

Computed with the §19 sample code (`lin_2020` / `gam_2020`, gamma 2.4) and with colorjs.io 0.7.1; the color-space npm library agrees.
