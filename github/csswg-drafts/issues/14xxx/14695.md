LaTeX distinguishes `table` environments from `tabular` environments, where the difference basically is: the former contains the caption, the latter does not. 

[Docbook](https://tdg.docbook.org/tdg/5.2.1/tgroup.html) has `<table>` and `<tgroup>` in its [CALS-based](https://www.oasis-open.org/specs/a502.htm) variant. 

HTML only has a `<table>` element type which contains `<caption>`, column definitions and row groups (head, bodies, foot). 

CSS Tables distinguishes the [_table wrapper box_](https://drafts.csswg.org/css-tables/#terminology) from  the [_table grid box_](https://drafts.csswg.org/css-tables/#fixup-algorithm), but – like HTML – has a keyword value, `table`, only for one of them, used in the [`display` property](https://www.w3.org/TR/css-display-4/#propdef-display) for the _inner display layout model_ (but also for the _outer display role_ `block`, distinguished from `inline-table`). The difference between the two box types is basically the same as in TeX: [`table-caption`](https://drafts.csswg.org/css-tables/#table-caption) boxes are included in the former, excluded from the latter.

Tables are therefore really like captioned figures with a tabular instead of an image (or other content). The HTML `<figure>` and `<figcaption>` elements have no comparable box style assigned to them by default, so the caption appears where it has been specified.

In printed documents, captioned blocks are often tabulated in a separate listing (or multiple ones) after the table of contents, where their heading acts like the caption.  All of those are usually enumerated. Most other types of blocks that are frequently captioned, e.g. formulas, quotations or examples, do not have dedicated element types in HTML. 

## Proposal
- [ ] Add a new `table-tabular` or just `tabular` [display type keyword](https://drafts.csswg.org/css-tables/#display-types).
- [ ] Add a new `figure` keyword to [`<display-inside>`](https://drafts.csswg.org/css-display/#typedef-display-inside) which acts like `flow-root` but, like `table`, also supports _caption_ children that are positioned according to the [`caption-side` property](https://drafts.csswg.org/css-tables/#caption-position).
- [ ] Add a new `caption` keyword to either [`<display-outside>` or `<display-internal>`](https://drafts.csswg.org/css-display-4/#typedef-display-outside) which acts like `table-caption` but does not depend on a `table`.

PS: HTML could also add a `<tabular>` element type, but that’s a different issue, although some coordination would make sense, of course.

## @Crissov — 2026-10-31

That was indeed what got me started thinking about this, and the `table` handling in CSS Tables had always bothered me a bit. 

Other elements possibly as well, though, e.g. `<summary>`, `<legend>`, `<label>`.

~~~~ css
figure {display: table; caption-side: bottom;}
figcaption {display: table-caption;}
~~~~
This kinda works, of course, but gets you other table-specific behavior like shrink-wrapping. 

PS: If HTML then added `<tabular>` and it becomes too wide or tall, the `<table>` and `<caption>` could remain static while the contents becomes scrollable, especially when you have more than one row-group.
