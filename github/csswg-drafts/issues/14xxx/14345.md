In css-text, only [fullwidth closing punctuation](https://www.w3.org/TR/css-text-4/#text-spacing-trim-property) at the end of each line are adjusted:

> set [fullwidth closing punctuation](https://www.w3.org/TR/css-text-4/#fullwidth-closing-punctuation) with half-width glyphs (flush) at the end of each line

Here's the definition for fullwidth closing punctuation:

> Includes any closing punctuation character (Unicode category Pe) that belongs to the CJK Symbols and Punctuation block (U+3000–U+303F) or is categorized as East Asian Fullwidth (F) by [[UAX11]](https://www.w3.org/TR/css-text-4/#biblio-uax11). Also includes RIGHT SINGLE QUOTATION MARK (U+2019) and RIGHT DOUBLE QUOTATION MARK (U+201D). May also include [fullwidth colon punctuation](https://www.w3.org/TR/css-text-4/#fullwidth-colon-punctuation) and/or [fullwidth dot punctuation](https://www.w3.org/TR/css-text-4/#fullwidth-dot-punctuation) ([see below](https://www.w3.org/TR/css-text-4/#fullwidth-ambiguous)). When trimmed, the right (for horizontal text) or bottom (for vertical text) half is kerned.

CLReq currently [adjusts](https://www.w3.org/TR/clreq/#id104) every one-em-wide punctuation at the end of each line, in accordance with the national standard of Mainland China:

> According to section 5.1.10 of the *General Rules for Punctuation* (GB/T 15834—2011), when a full-width punctuation character appears at the end of a line, it SHALL be trimmed to half-width.

This also includes commas, periods, secondary commas, colons, semicolons, question marks, and exclamation marks.

Currently, Chinese authors are unable to create pages that comply with the national standard. CSS mechanisms need to be adjusted to address this.

I guess this is because Japanese typography (per [jlreq 3.8.4](https://www.w3.org/International/jlreq/#procedures_for_intercharacter_space_reduction)) generally doesn't adjust (trim) other punctuation marks, and the national standard of Mainland China weren't taken into account when the feature was first proposed.

## @xfq — 2026-08-25

The exclamation mark and question mark fall under the Unicode Po category. They are neither Pe nor included in the current special cases for colons and dots, so no existing value allows for their adjustment at the end of a line. Commas, periods, colons, and semicolons are currently handled only conditionally.

We could consider adding a new category, such as "fullwidth line-end-trimmable punctuation", with the following characteristics:

1. It includes existing fullwidth closing punctuation.
2. It additionally includes other punctuation marks that can be safely adjusted to half-width, based on content language and writing mode.
3. It includes U+FF01 and U+FF1F, at least for horizontal Simplified Chinese text.
4. Update the line-end behavior for relevant value keywords to reference this new category.
5. Adjustments for other punctuation marks continue to reference the existing opening, closing, and middle-dot categories. This approach ensures that question marks and exclamation marks are not inadvertently trimmed when appearing within sequences of punctuation marks elsewhere in the line.

Relevant WPT and i18n tests also need to be added.
