Spec: https://drafts.csswg.org/css-inline-3/#text-box-trim

I'm looking at using `text-box-trim` broadly, for example as part of a reset:

```css
* {
  text-box: trim-both cap alphabetic;
}
```

With that, a normal button works as expected:

```html
<button class="button">Add list</button>
```

But if the same component uses flex layout, for example to support optional icons and `gap`:

```css
.button {
  display: inline-flex;
  align-items: center;
  gap: .5em;
}
```

the trim no longer affects its direct text. The text gets wrapped in an anonymous flex item, `text-box-trim` is non-inherited, and that anonymous item cannot be matched by author CSS.

This seems likely to be a common case for buttons, tabs, chips, navigation items, etc. A component may use flex all the time because some instances have icons, spinners or badges, while text-only instances still unexpectedly lose the trim.

Adding a wrapper makes the reset work again:

```html
<button class="button"><span>Add list</span></button>
```

The `span` matches `*`, while the anonymous flex item cannot. Without a broad rule like the reset above, the workaround is worse: the author needs both the extra wrapper and another rule applying `text-box-trim` to it.

I think there is a reasonable argument that each flex/grid item could be treated as its own trimming context, with its own first and last formatted line. For example, a vertical flex stack containing several text items seems like a natural case for trimming each item independently before applying `gap`.

However, I realize the current non-propagation behavior for flex/grid is already specified and implemented, so changing that more generally would be a much larger compatibility question.

The anonymous direct-text case seems narrower and harder for authors to work around cleanly. Authored flex/grid items can at least receive `text-box-trim` themselves, including through a broad reset like `* { text-box: ... }`. An anonymous item generated for direct text cannot be targeted at all.

Would it make sense to at least make an exception for anonymous flex/grid items generated from the container's own direct text?

For multiple direct text runs, I would expect each generated anonymous item to trim its own first and last formatted line. In a column flex container with `gap`, that would leave the gap between the trimmed text boxes, which seems like useful and unsurprising behavior.

This seems related to [#11038](https://github.com/w3c/csswg-drafts/issues/11038), which discussed `text-box-trim` propagation through flex/grid; [#1118](https://github.com/w3c/csswg-drafts/issues/1118), where meaningless wrappers changing text styling was considered surprising; and [#2208](https://github.com/w3c/csswg-drafts/issues/2208), which discusses the more general problem of applying non-inherited properties to raw text. [#14136](https://github.com/w3c/csswg-drafts/issues/14136) is also currently discussing other `text-box-trim` propagation boundaries.

Since `text-box-trim` has only recently become broadly available across browsers, this seems like a good time to settle this behavior before wrapper-based workarounds become established.
