It's rather common to register a number of properties with the same descriptors. E.g. most `<integer>`, `<number>` or `<length>` properties are registered to have an initial value of `0` and most properties are registered to have `inherits: true`. So, the multiple `@property` rules can get quite repetitive. For a particularly egregious example of this, look [here](https://github.com/propjockey/css-conways-game-of-life/blob/main/game-of-life.css#L140).

#13212 is about wildcard registration, which is more powerful, but also a bigger lift.
This issue is about the much smaller ask of being able to combine custom property declarations with the same descriptors.

@tabatkins [wrote](https://github.com/w3c/csswg-drafts/issues/13212#issuecomment-3646870459):

> The first one (multiple comma-separated names in the registration) we should definitely do, no question. Such an obvious improvement.

As @Crissov [wrote](https://github.com/w3c/csswg-drafts/issues/13212#issuecomment-3646870561):

> For at least 4 years now, everybody has agreed the syntax for [`@property`](https://drafts.csswg.org/css-variables-2/#typedef-custom-property-name) should be :
> 
> ```
> @property <custom-property-name># {
>   <declaration-list>
> }
> ```
> but in the current draft it still lacks that `#`.

This is such low hanging fruit, that the MDN and web.dev docs on `@property` [originally included it](https://github.com/mdn/content/issues/5830) even though it was never a thing on the CSS side! 

## Proposed spec change

https://drafts.css-houdini.org/css-properties-values-api/#at-property-rule

From 

```
@property <custom-property-name> {
  <declaration-list>
}
```

to

```
@property <custom-property-name># {
  <declaration-list>
}
```

Plus something about the CSSOM expansion (see below).

## Out of scope

These are all useful, but in the interest of making this uncontroversial so it can ship, this is scoped tightly to `@property` declarations with **all descriptors being the same**. 

### Cascading `@property` rules

Meaning, this:

```css
@property --number, --scale {
	syntax: "<number>";
	initial-value: 0;
	inherits: true;
}

@property --scale {
	initial-value: 1;
}
```

would _not_ cascade. It would be be a new declaration, with implied `syntax: "*"; inherits: true`.

### No CSSOM changes

- No `CSSPropertyRule` changes. The rule just expands to multiple `CSSPropertyRule` rules at parse time. Yes this means serialization doesn't roundtrip. I think that's fine and we do it for other things.
- `CSSPropertyRule.prototype.name` is read only so we don't need to answer the question "how does the setter behave?"
- No `CSS.registerProperty()` changes. If you're in JS-land, you can just just loop.
