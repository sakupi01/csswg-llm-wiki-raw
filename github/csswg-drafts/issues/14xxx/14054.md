https://drafts.csswg.org/css-transforms-2/#grouping-property-values

> The following CSS property values require the user agent to create a flattened representation of the descendant elements before they can be applied, and therefore force the element to have a used style of `flat` for `preserve-3d`.
> -    [`overflow`](https://drafts.csswg.org/css-overflow-3/#propdef-overflow): any value other than [`visible`](https://drafts.csswg.org/css-overflow-3/#valdef-overflow-visible) or [`clip`](https://drafts.csswg.org/css-overflow-3/#valdef-overflow-clip).
> - ...

Does this refer to the computed or the used value?

For example, `overflow` doesn't apply to table-rows (so it could be said it behaves as `visible`), but they are transformable.

- Gecko: N/A, `transform-style: preserve-3d` is borken on table-rows. https://bugzilla.mozilla.org/show_bug.cgi?id=2047902
- Blink: non-applying `overflow: hidden` still forces `transform-style` to behave as `flat`
- WebKit: non-applying `overflow: hidden` doesn't force `transform-style` to behave as `flat`
- Servo: `overflow` never forces `transform-style` to behave as `flat`, regardless of whether it applies. https://github.com/servo/servo/pull/45629/ will align with WebKit.

## @Loirooriol — 2026-06-17

Another testcase, now changing the used value via [propagation to viewport](https://drafts.csswg.org/css-overflow-3/#overflow-propagation):

```html
<!DOCTYPE html>
<style>
:root {
  background: white;
}
body {
  transform-style: preserve-3d;
  overflow: hidden; /* Does this force `transform-style: flat` ? */
  width: max-content;
  background: #623e3f;
}
body::before {
  content: "lorem ipsum";
  display: block;
  transform: rotate3d(1, 1, 1, 45deg);
  background-color: #ffba08;
}
</style>
<body></body>
```

- Gecko, Servo: an `overflow: hidden` propagated away doesn't force `transform-style` to behave as `flat`
- Blink, WebKit: an `overflow: hidden` propagated away still forces `transform-style` to behave as `flat`
