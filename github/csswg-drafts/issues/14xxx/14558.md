I do no think there is already an issue open for this:

  > **Issue:** The [`size`](https://drafts.csswg.org/css-sizing-4/#propdef-size) property needs to be omitted from the [preferred shorthand order](https://drafts.csswg.org/cssom-1/#concept-shorthands-preferred-order) in CSSOM, to avoid compat problems and conflicts with `@page`.

Instead of excluding `size` from the preferred shorthand order, I think generalizing [§ 6.6. CSS Declaration Blocks](https://drafts.csswg.org/cssom-1/#css-declaration-blocks) seems relatively straightforward. It was originally written when all declarations were for style properties, but now `CSSStyleDeclaration` can store declarations for descriptors and "property-like descriptors".

[Serialize a CSS value](https://drafts.csswg.org/cssom-1/#serialize-a-css-value) (i.e. a declaration) and [serialize into a shorthand form](https://drafts.csswg.org/cssom-1/#serialize-into-a-shorthand-form) would take `shorthands` as an additional argument representing the shorthands accepted in the current context. Or more simply, their steps could resolve *"the preferred shorthand order **for the current context**"*, similarly as in the steps for the [parser algorithms](https://drafts.csswg.org/css-syntax-3/#parser-algorithms).
