https://drafts.csswg.org/css-font-loading/#fontface-interface

```
dictionary FontFaceDescriptors {
  CSSOMString width;
  CSSOMString stretch = "normal"; // alias for width, sets the same attribute
  ...
};

interface FontFace {
  [Throws]
  constructor(CSSOMString family,
              (CSSOMString or BufferSource) source,
              optional FontFaceDescriptors descriptors = {});
  ...
}
```

But https://drafts.csswg.org/css-font-loading/#dom-fontface-fontface doesn't say which wins.

```js
var ff = new FontFace("", "", { width: "condensed", stretch: "ultra-condensed" });
[ff.width, ff.stretch]
// Firefox: [ "condensed", "condensed" ]
// Safari: ["normal", "normal"]
// Chrome: [undefined, 'ultra-condensed']
```

`width` wins on Firefox. Safari is broken and seems to ignore the descriptors param. Chrome hasn't implemented `width` yet.

## @Loirooriol — 2026-09-07

I guess `CSSOMString stretch = "normal"` means that `stretch` always has a value, so it must be `width` the one that wins. Otherwise `{ width: "condensed" }` would be ignored and use the `"normal"` fallback for `stretch`.

But I think it should be stated more clearly.
