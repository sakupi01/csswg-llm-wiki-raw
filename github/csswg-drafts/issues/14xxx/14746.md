In [the grammar for the `shape() function`](https://drafts.csswg.org/css-shapes/#shape-function) there's both `<control-point>` (for commands started with an absolute position) and `<relative-control-point>` (for commands started with a relative position):

```
<control-point> = [ <position> | <relative-control-point> ]
<relative-control-point> = <coordinate-pair> [ from [ start | end | origin ] ]?
```

As currently written, you can use a relative CP with an absolute command, which is just fine from a feature perspective, but is grammatically ambiguous - a value like `20px 20px` is both a `<position>` and a `<coordinate-pair>`.

I *suspect* what's intended is that, for absolute commands, you want to allow a `<position>` *or a relative CP with a `from X` value*. Relative commands don't need to specify a `from`, as they default to being `from start`.
