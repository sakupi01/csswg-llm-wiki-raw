In https://github.com/w3c/csswg-drafts/issues/13980, we resolved to make `::interest-button` show up via an inline media condition, like `display: if(media())`. This issue is about what goes inside the inner parenthesis.

Essentially, the desire is to show the pseudo element on systems where it's "difficult" to show interest via other means. The canonical example is touchscreens, where it's possible to show interest, but only via long-press-and-choose-from-context-menu. On those systems, we want to make the `::interest-button` show up. I see two possible ways to implement that:

1. `display: if(media(hover:hover): none; else: inline-block);`  (the [hover](https://drafts.csswg.org/mediaqueries/#hover) media query)
2. `display: if(media(showing_interest_is_easy): none; else: inline-block);`  (a newly invented media query that is purpose-built for this feature (cribbed from the [TAG review](https://github.com/w3ctag/design-reviews/issues/1058#issuecomment-4627034201)))

Here, the first option (`media(hover:hover)`) seems to align almost perfectly to the use case. In the spec, it is well designed, to take into account things like touchscreens with optional mice attached, etc. However, on the TAG review, a point was made that some systems (e.g. VisionOS) might want to add a custom feature to the browser that shows an "easy" way to show interest that isn't exposed to the site, so that it's privacy preserving. Such a system would want the media query to match, so that an additional `::interest-button` does not show up. Hence the second suggestion above. It's also possible (and perhaps much easier?) if the `hover:hover` media query just matched in this case, but that likely would break other things that are really looking for "hover".

Are there other suggestions for what goes inside the `media()` in the display rule?
