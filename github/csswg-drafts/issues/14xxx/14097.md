## @kbhomes — 2026-06-28

@astearns Checked with both `hb-info` and `ttx` that this font doesn't have a `hang` baseline and doesn't have a `bsln` table either. So the baseline is from glyph measurement per [CSS Inline 3 § A.2: Synthesizing Baselines (and Other Font Metrics) for Text](https://drafts.csswg.org/css-inline-3/#baseline-synthesis-fonts). Firefox actually calls into HarfBuzz's [hb_ot_layout_get_baseline_with_fallback](https://harfbuzz.github.io/harfbuzz-hb-ot-layout.html#hb-ot-layout-get-baseline-with-fallback) which actually measures and synthesizes according to these CSS Inline 3 rules, so that's what's being used in the prototype above.

<!-- comment id=4827799949 author=kbhomes created=2026-06-28T23:54:34Z url=https://github.com/w3c/csswg-drafts/issues/14097#issuecomment-4827799949 -->
## @kbhomes — 2026-06-28

I also think that the list of baselines in [CSS Inline 3 § A.3: Synthesizing Baselines for Atomic Inlines](https://drafts.csswg.org/css-inline-3/#baseline-synthesis-box) makes a reasonable case that `hanging` should be included as an allowed edge metric. For atomic inline boxes with no content, it treats:

 - `text-under`, `ideographic-under`, `ideographic-ink-under`, and `alphabetic` as being on the `under` side of the box
 - `text-over`, `ideographic-over`, `ideographic-ink-over`, `cap-height`, `hanging`, and `x-height` as being on the `over` side of the box

And so I think that conceptually, these baselines are meant to be treated as meaningful "under" and "over" edges for text. From this set of baselines, every one can currently be targeted in `text-box-edge` except for `hanging`.
