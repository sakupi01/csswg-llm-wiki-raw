> I'd like to know under what circumstances “none” can be safely converted to 0, as this is very useful for CSS minifiers.
> 
> e.g.
> 
> ```css
> .foo { background: linear-gradient(in oklab, rgb(none none none), green ); }
> ```
> 
> This cannot be converted to `linear-gradient(in oklab, #000, green)` in a gradient.
> But `background-color: rgb(none none none)` can safely be converted to `background-color: #000`, right?

As far as I know it is only safe when you are absolutely sure that the value won't be used in interpolation. 

see: https://codepen.io/romainmenke/pen/QwpMayq

```css
#a {
  background-color: oklch(50% 0.3 none);
  transition: background-color 2s ease-in-out;
}

#a:hover {
  background-color: oklch(50% 0.3 130deg);
}

#b {
  background-color: oklch(50% 0.3 0);
  transition: background-color 2s ease-in-out;
}

#b:hover {
  background-color: oklch(50% 0.3 130deg);
}
```

Safari implements this correctly if I am not mistaken and illustrates how `none` is taken into account in transitions.

Also consider that the value might be read through JavaScript.

So I don't think you can safely remove a `none` in a color value unless you do "whole program analysis" and know how each declaration will be used.
