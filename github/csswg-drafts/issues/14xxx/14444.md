https://drafts.csswg.org/css-grid-3/#grid-lanes-baseline-alignment

In the following example we have a Grid Lanes container which needs to determine a baseline so that it can get aligned properly:

```
  hello
  <div style="display: inline grid-lanes; grid-template-columns: auto auto auto; border: 4px solid magenta;">
    <div style="background-color: aqua; width: min-content; height: 80px; padding-top: 40px;">foo bar bazz</div>
    <div style="background-color: magenta; width: 100px; height: 40px; padding-top: 10px; font-size: 32px;">zoinks</div>
    <div style="background-color: grey; width: 100px; height: 150px; margin-top: 40px; padding-top: 40px;">world</div>
  </div>
```
Here is how WebKit (left) and Blink (right) render this

<img width="944" height="263" alt="Image" src="https://github.com/user-attachments/assets/c514a3b5-1c4a-4422-b215-4207a6ee8543" />

From the current spec text I think Blink is correct here since the baseline of the container comes from the visually highest baseline of the items that are placed first in each track.

Here is the same example but with the text content removed from the items:

<img width="946" height="264" alt="Image" src="https://github.com/user-attachments/assets/e44c6317-403c-4008-b2b8-4693ae7c8746" />

In this case it seems like Blink synthesizes a baseline from the Grid Lanes container's border box. To me it seems like we should be synthesizing a baseline from the items instead and using one of those values. The steps for determining this are pretty well defined for a Grid container so I think we just need to do the same for a Grid Lanes one.
