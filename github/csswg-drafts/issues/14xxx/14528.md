In https://github.com/w3c/csswg-drafts/issues/13804 we resolved to support all tree abiding pseudos in CSSPseudoElement type (or maybe it's selectorText). I can't find specific text in the discussion, but I assume that we're keeping the parameters of pseudos that have parameters, e.g. `::view-transition-group(foo)`.

A question came up from https://github.com/w3c/csswg-drafts/issues/12161#issuecomment-3531224633 is whether ::scroll-button parameters should return physical or logical parameter. 

This of course depends on the writing mode. I propose that we should use the logical parameters using the writing mode of the button. It's tricky since I think the CSSPseudoElement can exist without the underlying pseudo being created yet, or the spec at least suggests that the underlying pseudo can be destroyed and recreated for convenience.

I think the easiest thing to do if we're in a state where the underlying pseudo doesn't exist or the originating element is disconnected, is to use the default writing mode for this.
