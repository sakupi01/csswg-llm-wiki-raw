The prose of [3.2](https://drafts.csswg.org/css-anchor-position-1/#anchor-pos) allows `anchor()` "as a value in its [inset properties](https://drafts.csswg.org/css-logical-1/#inset-properties)", and that term covers `top`/`left`/`bottom`/`right`, their flow-relative longhands `inset-block-start`, `inset-block-end`, `inset-inline-start`, `inset-inline-end`, and the `inset-block`, `inset-inline` and `inset` shorthands. The property table right below it extends only the four physical ones:

> Name: top, left, right, bottom
> New values: `<anchor()>`

The same holds for `anchor-size()` in [5.1](https://drafts.csswg.org/css-anchor-position-1/#anchor-size-fn): the prose allows it in the [accepted @position-try properties](https://drafts.csswg.org/css-anchor-position-1/#accepted-position-try-properties), which include all the inset properties, but the table's Name row lists `top, left, right, bottom` and no flow-relative inset.

The logical margins pick up `anchor-size()` through `<'margin-top'>`, which `margin-inline-start` is defined as. The logical insets are defined in css-position-3 as `auto | <length-percentage>` on their own, so nothing in the tables reaches them, and tooling that reads the tables, such as `@webref/css`, gets a grammar where the shorthand accepts `anchor()` and its own longhand does not.

### Steps to reproduce

1. Open https://drafts.csswg.org/css-anchor-position-1/#anchor-pos and read the property table under the first paragraph, then the one in https://drafts.csswg.org/css-anchor-position-1/#anchor-size-fn.
2. Follow the "inset properties" link in the first paragraph of 3.2 to https://drafts.csswg.org/css-logical-1/#inset-properties.
3. Run the gist https://gist.github.com/YevheniiKotyrlo/f2c7e8c353b3f8f4ef387567ab11bd7f. `check.mjs` prints both tables' Name rows from the live draft and the syntax `@webref/css` extracts for four inset properties, and exits 1 while either table leaves out a flow-relative inset; `browsers.mjs` asks Chromium, Firefox and WebKit whether the flow-relative insets accept `anchor()` and `anchor-size()`:

```sh
git clone https://gist.github.com/f2c7e8c353b3f8f4ef387567ab11bd7f.git anchor-logical-insets
cd anchor-logical-insets
npm install
node check.mjs
npx playwright install chromium firefox webkit
node browsers.mjs
```

**Expected:** both tables name every inset property, so `inset-inline-start` gets the same value grammar as `top`: `auto | <length-percentage> | <anchor()> | <anchor-size()>`. The physical insets keep the values they have.

**Actual:** both tables name only the physical insets, and the extracted grammar follows them:

```
node v26.12.1; css-anchor-position-1 Editor's Draft, revision cb8227b68d1b67b905744e24c31d6633de52511a
  #anchor-pos table, Name: top, left, right, bottom
  #anchor-size-fn table, Name: block-size, inline-size, width, height, min-block-size, min-inline-size, min-width, min-height, max-block-size, max-inline-size, max-width, max-height, top, left, right, bottom, margin-top, margin-left, margin-right, margin-bottom

@webref/css 8.7.8
  top                 auto | <length-percentage> | <anchor()> | <anchor-size()>
  inset-inline        <'top'>{1,2}
  inset-inline-start  auto | <length-percentage>
  inset-block-start   auto | <length-percentage>

SUMMARY: the anchor() and anchor-size() tables leave out 8 flow-relative insets: #anchor-pos: inset-block-start, #anchor-pos: inset-block-end, #anchor-pos: inset-inline-start, #anchor-pos: inset-inline-end, #anchor-size-fn: inset-block-start, #anchor-size-fn: inset-block-end, #anchor-size-fn: inset-inline-start, #anchor-size-fn: inset-inline-end
```

Implementations and WPT already follow the prose. [anchor-parse-valid.html](https://github.com/web-platform-tests/wpt/blob/master/css/css-anchor-position/anchor-parse-valid.html) and [anchor-size-parse-valid.html](https://github.com/web-platform-tests/wpt/blob/master/css/css-anchor-position/anchor-size-parse-valid.html) test the flow-relative longhands, and every engine accepts them (Playwright 1.65.0 builds, Windows 11):

```
chromium 158.0.8127.18
  top: anchor(--a top) -> true
  inset-inline-start: anchor(--a start) -> true
  inset-block-end: anchor(--a end) -> true
  inset-inline-start: anchor-size(--a width) -> true
```

Firefox 159.0 and WebKit 27.2 print the same.

### Suggested fix

Add `inset-block-start, inset-block-end, inset-inline-start, inset-inline-end` to the Name row of both tables.
