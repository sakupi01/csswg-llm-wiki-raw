The [grammar of `@mixin`](https://drafts.csswg.org/css-mixins/#mixin-rule) is currently:

```
<@mixin> = @mixin <function-token> <function-parameter>#? )
{
  <declaration-rule-list>
}
```

And [`<function-parameter>` is defined](https://drafts.csswg.org/css-mixins/#typedef-function-parameter) as:

```
<function-parameter> = <custom-property-name> <css-type>? [ : <default-value> ]?
<css-type> = <syntax-component> | <type()>
<default-value> = <declaration-value>
```

If I’m reading this right, it seems to me that there is no way to provide a default parameter that includes commas. 
Should we make these `;`-separated?

As a nice side effect, especially if we allow trailing semicolons too, folks can more easily experiment between moving declarations inside the mixin (internal private state) vs to the mixin arguments (private state that can be parameterized if need be).

Side note, multiple params have very poor test coverage in WPT with only two tests in [mixin-parameters.html](https://github.com/web-platform-tests/wpt/blob/066d3a8ae20887b6f2534aaf15a22ff8869d96d2/css/css-mixins/mixin-parameters.html), none with defaults, and one [in cssom.tentative.html](https://github.com/web-platform-tests/wpt/blob/066d3a8ae20887b6f2534aaf15a22ff8869d96d2/css/css-mixins/mixin-cssom.tentative.html).
