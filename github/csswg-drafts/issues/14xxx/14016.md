Currently, the optional return type of a custom function is used solely to double-check that the return value is an expected type (and replace it with the guaranteed-invalid value if it's not).

But it would probably be more consistent (and still achieve the above) if we treated the return type the same as we do argument types, and use it as a local custom property registration for [the 'result' descriptor](https://drafts.csswg.org/css-mixins/#the-result-descriptor) inside the function. (Currently, 'result' doesn't have a grammar at all; it's effectively an unregistered custom property.) This will then *additionally* trigger the normal "typed custom property" behavior, such as resolving typed values.

The spec change is pretty tiny, but it'll have some downstream effects, like causing `result: random(...)` to evaluate *inside* the function rather than be emitted as-is (#13661).

Unless anyone has objections, I'm gonna go ahead and accept this change.
