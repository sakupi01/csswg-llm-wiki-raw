We have [scoped view transitions](https://drafts.csswg.org/css-view-transitions-2/#scoped-vt) that require that an element has layout containment.

However, layout containment doesn't apply to some elements, like non-atomic level inlines. I propose that we throw a invalid state exception for startViewTransition if it's called on an element that does not qualify for layout containment. Similarly during the transition, if style changes in such a way that precludes the element from having layout containment, I believe that we should abort the transition (possibly rejecting some promises: TBD).

## @vmpstr — 2026-07-20

Re first part:

> In other words, is the resolution A or B?

It's A. Layout containment is applied through spec text. Step 5 of https://drafts.csswg.org/css-view-transitions-2/#dom-element-startviewtransition

> If [this](https://webidl.spec.whatwg.org/#this) is not the [document root element](https://drafts.csswg.org/css-display-4/#root-element), force this to have both [layout containment](https://drafts.csswg.org/css-contain-2/#layout-containment) and [view transition scoping](https://drafts.csswg.org/css-view-transitions-2/#view-transition-scope-view-transition-scoping) for the duration of the transition.

I think the following text in https://drafts.csswg.org/css-view-transitions-2/#scoped-vt needs to be updated, since it seems to contradict the algorithmic steps.

> In order to host a [scoped view transition](https://drafts.csswg.org/css-view-transitions-2/#scoped-view-transitions), an element must have [layout containment](https://drafts.csswg.org/css-contain-2/#layout-containment), so its painted output can be captured as an atomic unit.

Specifically it should be updated to the following (emphasis added to highlight differences)

> In order to host a [scoped view transition](https://drafts.csswg.org/css-view-transitions-2/#scoped-view-transitions), an element **must qualify for** [layout containment](https://drafts.csswg.org/css-contain-2/#layout-containment), **which will be applied automatically**, so its painted output can be captured as an atomic unit.

As well, corresponding changes need to be made to the algorithmic steps to indicate what happens if the containment cannot be applied.

------
Re second part:

This is not a new pattern. We have a bunch of exceptions as part of activating the transition (https://drafts.csswg.org/css-view-transitions-2/#activate-view-transition), visibility change (https://drafts.csswg.org/css-view-transitions-2/#page-visibility-change-steps), and generally running the transition (https://drafts.csswg.org/css-view-transitions-2/#handle-transition-frame)
