Currently, we have a WPT that seems to test how space distribution works when a grid is being sized under a min-content constraint and has a flexible track: https://wpt.fyi/results/css/css-grid/grid-flex-spanning-items-001.html?label=experimental&label=master&aligned

```
<style>
#mygrid {
    display: grid;
    grid-template-columns: 1fr 30px;
    border: 10px solid fuchsia;
    width: min-content;
}
#item {
    grid-column: 1 / span 2;
}
#filler {
    width: 300px;
    height: 50px;
    background: aqua;
}
</style>
<div id="mygrid">
  <div id="item">
    <div id="filler"></div>
  </div>
</div>
```

It looks like WebKit, Gecko, and Blink all agree with what the layout should be here but from what I can tell this does not seem to be what the spec expects. I think this is specifically about what happens when we are deciding how to distribute space to the flexible track. Before that nothing really happens with respect to the sizing of the columns since it is just really the second column which has a 30px base size and growth limit due to it being fixed. 

When trying to accommodate the intrinsic minimums the spec says that we should be using the limited min-content contribution here which would give the first column a size of 270px. However, WPT seems to indicate that engines are giving this column a size of 0px. Presumably this comes from using the minimum contribution?

Do we think that this is just a bug that could be safely fixed by all engines or does the spec need to be updated to reflect what is actually happening at this point?
