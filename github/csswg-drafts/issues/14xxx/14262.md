## `:has()` amplifies CSS data exfiltration through descendant attributes

**Concern:** PING has already raised [the general issue of observable user state, including amplification by `:has()`](https://github.com/w3cping/privacy-request/issues/194#issuecomment-4609612953). And although attribute-value matching existed in Level 3, `:has()` in Level 4 makes CSS data exfiltration more practical by allowing a renderable ancestor to match based on a sensitive attribute value in a hidden descendant. [CSS Data Exfiltration](https://dev.to/matemiller/css-data-exfiltration-1p3l) documents the inherited attribute-selector primitive and [Blind CSS Exfiltration](https://portswigger.net/research/blind-css-exfiltration) demonstrates `:has()` amplification, including when the sensitive element is hidden or the surrounding page structure is unknown.

**Impact:** An attacker can test sensitive attribute values even when the target element cannot itself produce the observable request or the surrounding structure is unknown.

**Recommendation:** Please document this Level 4 amplification, its prerequisites, and relevant limitations or mitigations in Security Considerations.
