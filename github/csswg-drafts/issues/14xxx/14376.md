The [spec](https://drafts.csswg.org/css-values-4/#font-affecting-property) defines that *"they resolve against the computed `line-height` and font metrics of the parent element"*.

But the computed [`line-height`](https://drafts.csswg.org/css-inline-3/#propdef-line-height) is not always an absolute `<length>`: it can be also be `normal` or `<number>`.

For `<number>` and `normal`, they must resolve *using the computed `font-size` of the parent element*, and for `normal`, they must also resolve *using the first available font in the computed `font-family` of the parent element*, if I am not mistaken.

So, wouldn't it be clearer to say that *they resolve using the computed values that allow determining the `line-height` of the parent element as an absolute `<length>`*?

Besides, since the updates from #13616, the definitions of `normal` and `<number>` for `line-height` refers to used value.

So while the expected behavior might be obvious to experienced implementers and spec authors, this seems much less so for others.

## @weinig — 2026-08-23

Just a little above your link, CSS Values 4 states:

> "lh" - Equal to the computed value of the [line-height](https://drafts.csswg.org/css2/#propdef-line-height) property of the element on which it is used, converting [normal](https://drafts.csswg.org/css-inline-3/#valdef-line-height-normal) to an absolute length by using only the metrics of the [first available font](https://www.w3.org/TR/css3-fonts/#first-available-font).

(https://drafts.csswg.org/css-values-4/#lh)
