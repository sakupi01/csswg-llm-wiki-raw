I was working on a file input and instinctively wanted to use `input[type="file"]:placeholder-shown {}` but that didn't work (of course?). The closest I could get was to use `input[type='file']:not(:user-invalid, :user-valid)`, which works, but it is verbose and it does not immediately convey intent.

[The spec](https://drafts.csswg.org/selectors/#placeholder) does mention that:

>  The :placeholder-shown pseudo-class matches an input element that is showing such placeholder text, whether that text is given by an attribute or a real element, or is otherwise implied by the UA.

So my child-like brain thinks that `No file selected.` (or whatever the UA may decide to show around the input) would be a sort of placeholder, but also not quite. It feels like muddy territory.

Similar to https://github.com/w3c/csswg-drafts/issues/2517, but that was about `<select>` only and resolved to using `:blank`.
Similar to https://github.com/w3c/csswg-drafts/issues/6669, but that was about `<textarea>` and other elements that actually have a placeholder.
