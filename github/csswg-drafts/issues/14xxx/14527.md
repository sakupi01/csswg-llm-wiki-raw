We restricted style queries to custom properties because defining comparisons for arbitrary properties was a huge, fuzzy project. But one thing that layout and style often depends on is the writing-mode. How do we feel about making an exception to allow `writing-mode` (which has a very simple value space) in style queries?

## @xfq — 2026-09-27

I think it's useful.

Logical properties only solve cases where there is a straightforward logical/physical mapping. There are plenty of component decisions that aren't mappings:

```css
/* Hypothetical */
@container style(writing-mode: vertical-rl) {
  .decorative-arrow {
    rotate: 90deg;
  }
}
```

Design can genuinely change in vertical Chinese/Japanese or Mongolian layouts.

And the computed value `writing-mode` is essentially its specified keyword. It is inherited and not animatable. So you avoid a lot of the nastiness that makes style queries hard (like unit resolution etc.). And engines already have to react when a container's `writing-mode` changes because logical size queries like `inline-size` depend on it.

Not sure if a selector-level mechanism like `:dir()` works better, tho.
