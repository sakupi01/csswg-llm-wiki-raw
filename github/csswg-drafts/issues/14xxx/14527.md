We restricted style queries to custom properties because defining comparisons for arbitrary properties was a huge, fuzzy project. But one thing that layout and style often depends on is the writing-mode. How do we feel about making an exception to allow `writing-mode` (which has a very simple value space) in style queries?

## @xfq — 2026-09-27

I think it's useful.

Logical properties only solve cases where there is a straightforward logical/physical mapping. There are plenty of component decisions that aren't mappings:

```css
/* Hypothetical */
@container style(writing-mode: vertical-rl) {
  .decorative-arrow {
    rotate: 90deg;
  }
}
```

Design can genuinely change in vertical Chinese/Japanese or Mongolian layouts.

And the computed value `writing-mode` is essentially its specified keyword. It is inherited and not animatable. So you avoid a lot of the nastiness that makes style queries hard (like unit resolution etc.). And engines already have to react when a container's `writing-mode` changes because logical size queries like `inline-size` depend on it.

Not sure if a selector-level mechanism like `:dir()` works better, tho.

## @fantasai — 2026-10-29

If we want a separate function to split out some of these aspects, maybe `writing-mode()` which takes the following values: `horizontal`, `vertical`, `sideways`, `rl`, `lr`, as well as the full value space of `writing-mode`? We could do something more sophisticated for `rl` and `lr`, but it's nice that it's conceptually just "split on the hyphen and match".

We could also throw in `text-orientation`. I'm unsure if that's needed... though it does bring up the question of whether `sideways` matches only the sideways writing modes or also the sideways text orientation when in vertical writing modes. Probably it should match both... so `sideways` would match the `sideways-*` writing modes as well as `text-orientation: sideways` in vertical writing modes, and `upright` should match `text-orientation: upright` in vertical writing modes as well as `horizontal-tb` writing mode.

WebKit has a [bunch of useful queries](https://searchfox.org/wubkat/source/Source/WebCore/platform/text/WritingMode.h#63) against the resolved writing mode, but that seems like overkill for an author-facing feature.
