The CSS Font Loading Module 3 only specifies [support for stretch](https://drafts.csswg.org/css-font-loading/#fontface-interface). However, the equivalent font-face attribute has since been renamed from `font-stretch` to `font-width` with aliasing support for the old property ([1](https://drafts.csswg.org/css-fonts-5/#idl-index)). It feels appropriate to give the same treatment to the loading equivalent. Since stretch and width refer to the same property we would also have to resolve which to prioritize if both are declared. I think the most straight-forward way of doing so is to always take the new syntax if specified and only use the old one if the new one isn't used. For example: an initializer with the options `{width: "condensed", stretch: "expanded"}` would set font-width to `"condensed"` while `{stretch: "expanded"}` sets it to `"expanded"`.

This should probably reference [legacy name aliases](https://drafts.csswg.org/css-cascade-5/#legacy-name-alias)

> When the old property’s value syntax is identical to that of the new property, the two names are aliased with an operation on par with case-mapping: at parse time, the old property is converted into the new property. This conversion also applies in the CSSOM, both for string arguments and property accessors: requests for the old property name transparently transfer to the new property name instead.
