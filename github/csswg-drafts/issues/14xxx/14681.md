```html
<!DOCTYPE html>
<style>
body { width: 100px; border: solid magenta }
div { border: solid cyan }
table { width: 100%; table-layout: fixed; border: solid; }
</style>
<div style="width: min-content">
  <table><td>A</td><td>A</td></table>
</div>
<div style="width: fit-content">
  <table><td>A</td><td>A</td></table>
</div>
<div style="width: max-content">
  <table><td>A</td><td>A</td></table>
</div>
```

All major browsers agree that, if a table with [fixed layout](https://drafts.csswg.org/css-tables/#table-layout-property) has a percentage inline size, the max-content contribution is a gazillion amount.

But I think it's quite bad that the size explodes in such a way when using `max-content`. The author doesn't even need to use it explicitly, e.g. flex items items default to a `max-content` basis.

Could we maybe use automatic layout instead? After all,
1. The percentage is cyclic while computing the intrinsic contributions
2. Therefore it behaves as `auto` as per https://drafts.csswg.org/css-sizing-3/#cyclic-percentage-contribution
3. Therefore `table-layout: fixed` has no effect

Or maybe only for the max-content contribution?

Worth noting that Blink already seems to do something like that for `max-content` in these cases:

```html
<!DOCTYPE html>
<style>
table { width: 100px; table-layout: fixed; border: solid; }
</style>
<table style="width: 100px; max-width: min-content"><td>A</td><td>A</td></table>
<table style="width: 100px; max-width: max-content"><td>A</td><td>A</td></table>
<table style="width: 100px"><td>A</td><td>A</td></table>
<hr>
<table style="width: 0; "><td>A</td><td>A</td></table>
<table style="width: 0; min-width: min-content"><td>A</td><td>A</td></table>
<table style="width: 0; min-width: max-content"><td>A</td><td>A</td></table>
```
