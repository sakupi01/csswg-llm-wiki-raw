It seems that per spec (https://drafts.csswg.org/css-page/#page-properties) page margin boxes inherit from `@page`, which inherit from the root element. But what exactly does that mean? Page descriptors don't exactly match CSS properties.

This was introduced in https://github.com/w3c/csswg-drafts/commit/9d45749752bb90c263e511a0b4f792c5ade74b97, cc @fantasai 

It seems Blink does this (e.g. you can use custom properties from the root element in `@page`), Gecko doesn't. Not sure about WebKit.

I guess since we're already exposing the fact that we implement these via regular styles via custom properties, might as well implement this, but other than custom properties what other requirements steam from this?

## @faceless2 — 2026-10-26

counter-values!

See https://github.com/w3c/csswg-drafts/issues/4760, although the management summary is:

* a counter drops out of scope when the _parent_ of the block it's defined in is closed.
* changes to a counter in a page-margin box are expected to apply to page-margin box on the next page (and not just the "page" counter; any counter)

Using the rules we have (i.e. assuming there's no special magic processing), this works if page-margins are considered to "inherit" from the root element, and if there is an implied `:root { counter-reset: page 0 }`
