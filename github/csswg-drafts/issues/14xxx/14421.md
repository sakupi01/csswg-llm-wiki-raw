The ["preferred order"](https://drafts.csswg.org/cssom/#concept-shorthands-preferred-order) of a set of shorthands currently sorts primarily by the number of longhands it covers, and secondarily by whether it's standard, -webkit prefixed, or other-vendor-prefixed.

This means that, if a vendor-prefixed shorthand has more longhands than the standard shorthand, it'll be first in preferred order. Is this actually what we want? I suspect this is a spec error, but I also don't *think* there's an example of this right now, at least in browsers. (Possibly in print formatters there might be an example, since they sometimes have more properties than the web standard defines.)
