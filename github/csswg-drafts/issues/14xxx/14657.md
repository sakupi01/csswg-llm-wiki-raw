(Written with help from GPT-6 Astra High.)

The grammar added after https://github.com/w3c/csswg-drafts/issues/9926 restricts `@styleset` indexes to 0–20 and requires two `@character-variant` indexes, with the first limited to 0–99. But the [multi-valued feature prose](https://drafts.csswg.org/css-fonts-4/#multi-value-features) still says large styleset indexes parse successfully and have no rendering effect; its example uses `dumb: 125`.

All three engines accept the values excluded by the newer grammar:

```js
const sheet = new CSSStyleSheet();
sheet.replaceSync(`@font-feature-values Example {
  @styleset { a: 120 124; }
  @character-variant { b: 0; c: 111; d: 111 13; }
}`);
console.log(sheet.cssRules[0].cssText);
// Chromium 151, Firefox 153, WebKit 26.5: all four declarations are retained.
// Formatting and block order differ between engines.
```

The existing [WPT parsing test](https://github.com/web-platform-tests/wpt/blob/master/css/css-fonts/test_font_feature_values_parsing.html) also requires retaining these declarations.

We could preserve this behavior by changing the parsing requirements to:

- Each `@styleset` declaration must match `<font-feature-index [0,∞]>+`.
- Each `@character-variant` declaration must match `<font-feature-index [0,∞]>{1,2}`. If only one index is supplied, the feature's selected value defaults to 1.
- Whether an index names an available OpenType feature is handled when applying the declaration, rather than by rejecting otherwise valid integer syntax.

This would retain the cardinality restrictions discussed in #9926 while separating syntax validity from the available OpenType feature identifiers.

Either way, the rendering prose and examples should be reconciled with whichever grammar is chosen.
