We've had a bug report (as has Blink) requesting that letter-spacing should apply to Arabic digits, even though it is suppressed for the (cursively-connected) letters in this script:

https://bugzilla.mozilla.org/show_bug.cgi?id=2079008
https://issues.chromium.org/570417348

Reviewing the spec, [§7.2.1 Cursive Scripts](https://drafts.csswg.org/css-text-3/#cursive-tracking) says that we:

> _must not_ apply spacing between any pair of that script’s typographic letter units at all

This references the definition of [typographic letter unit](https://drafts.csswg.org/css-text-3/#typographic-letter-unit), which includes **Number** as well as **Letter** codepoints:

> A typographic letter unit (or letter for the purpose of this specification) is a typographic character unit belonging to one of the Letter or Number general categories.

So as it stands, it looks like numbers in Arabic should **not** get letter-spacing (contrary to what the reporter is requested); however, punctuation and symbol codepoints would still get it (which I don't think is what anyone actually implements).

Why are **Number** codepoints included in the definition of _typographic **letter** unit_, and should we reconsider this, at least for the purposes of letter-spacing?

## @fantasai — 2026-10-08

> Why are Number codepoints included in the definition of typographic letter unit, and should we reconsider this, at least for the purposes of letter-spacing?

Because they're usually typeset the same as letters (as opposed to punctuation, symbols and spacing, which typically have special rules).

## @jfkthame — 2026-10-09

That's true for some purposes, but it doesn't really hold in this case, I think. The only reason to inhibit the application of `letter-spacing` to Arabic _letters_ is because it would break their cursive joins. (Note that if the UA is capable of using kashidas to "stretch" the text, it is allowed to map `letter-spacing` to such elongation.)

But the digits don't have cursive joining behavior, so there's no reason for this restriction to apply to them.

As it stands (assuming a UA that doesn't do kashida elongation), the spec appears to require that if `letter-spacing` is applied to a block of Arabic content, it should take effect _only_ on punctuation/symbols/spacing characters. That seems weird.

Perhaps a more reasonable result would be if `letter-spacing` were _completely_ disabled (including for punctuation/symbols/spacing) in cursive scripts, but that runs into the problem of characters that are not unique to a script but may be used with both cursive and non-cursive writing systems, so in practice I don't think it is reliably implementable.

So I think the rule about not applying `letter-spacing` to cursive scripts should apply only to their _letters_, not to numbers.
