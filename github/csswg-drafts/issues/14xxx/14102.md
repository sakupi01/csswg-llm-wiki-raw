https://drafts.csswg.org/css-display-3/#valdef-display-contents

> This value computes to [`display: none`](https://drafts.csswg.org/css-display-3/#propdef-display) on replaced elements

First, at computed value time it's not known whether an element will be replaced or not, so it seems this should be "behaves as" instead.

But then, browsers aren't doing that either:

```html
<!DOCTYPE html>
<style>
div {
  display: block;
  width: 100px;
  height: 100px;
  content: linear-gradient(cyan);
  border: solid;
}
</style>
<div>text</div>
<div style="display: contents">text</div>
```

## @Loirooriol — 2026-06-29

My understanding is that https://drafts.csswg.org/css-display/#unbox-html just lists some special HTML elements, including some examples that are (or may be) replaced or kinda-replaced.

But the definition of "replaced" would still be the usual one: https://drafts.csswg.org/css-display-3/#replaced-element

So in my example, `content: linear-gradient(cyan)` makes the element become replaced.

From https://drafts.csswg.org/css-content/#typedef-content-content-replacement

> Makes the element or [pseudo-element](https://drafts.csswg.org/selectors-4/#pseudo-element) a [replaced element](https://www.w3.org/TR/CSS2/conform.html#replaced-element), filled with the specified [`<image>`](https://drafts.csswg.org/css-images-3/#typedef-image). Its normal contents are suppressed and do not generate boxes, as if they were [`display: none`](https://drafts.csswg.org/css-display-4/#propdef-display).
