Per [spec](https://drafts.csswg.org/css-color-5/#serial-color-mix), `color-mix(red 75%, red 75%, red)` must serialize with `color-mix(red 75%, red 75%, red -50%)`, which does not roundtrip (invalid `<percentage [0,100]>`):

  > For each argument, let its effective percentage be:
  >
  > - if its `<percentage>` was omitted [...]: `(100% − specified sum) / omitted count`, where `specified sum` is the sum of the explicitly specified `<percentage>`s and `omitted count` is the number of arguments with omitted `<percentage>`s;

`specified sum` is `150%`. 

`omitted count` is `1`. 

The omitted `<percentage>` is `(100% - 150%) / 1`, which results to `-50%`.

I guess the omitted `<percentage>` should be `max(0, (100% − specified sum)) / omitted count` .

I think there should be a corresponding [WPT test](https://github.com/web-platform-tests/wpt/blob/abe5302d378b690cbb89696f7a69546103fee9e0/css/css-color/parsing/color-valid-color-mix-function.html#L465).
