A [scroll-marker-group](https://drafts.csswg.org/css-overflow-5/#propdef-scroll-marker-group) can operate in either **links** or **tabs** mode based on the [scroll-marker-group](https://drafts.csswg.org/css-overflow-5/#propdef-scroll-marker-group) property value. Today, this is not the case for a [scroll-target-group](https://drafts.csswg.org/css-overflow-5/#scroll-target-group) in **auto** mode, which only supports anchor tags. It would be nice if developers had further markup options to customize accessibility and localization in scenarios where rendering anchor tags isn't the appropriate accessibility choice. An example of one such use-case would be a **tabs pattern** based carousel built on `scroll-target-group` due to localization needs.

Since markup may take many shapes I propose this to be solved with a new event, `currenttargetchange`, fired on the element carrying the CSS `scroll-target-group` attribute, whenever the browser [calculates the active marker](https://drafts.csswg.org/css-overflow-5/#active-scroll-markers-calculation). Ideally the event would also fire when the marker target element is not rendered, since the event may drive rendering itself. To support alternative markup to anchor tags, a new CSS attribute would be introduced to mark an element as a `scroll-marker` inside of a `scroll-target-group: manual`.
