Dear Group,

The following comments result from the [Security Review](https://github.com/w3c/security-request/issues/114) and have been checked against the current Working Draft.

**Reviewed version:** https://www.w3.org/TR/2026/WD-css-anchor-position-1-20260327/

**Security review request:** https://github.com/w3c/security-request/issues/114

I have one non-blocking editorial suggestion.

## Security Considerations state the conclusion without making the relevant design reasoning explicit

**Description:** The current [Security Considerations](https://www.w3.org/TR/2026/WD-css-anchor-position-1-20260327/#sec) section states only that no security issues have been raised. The [security review request](https://github.com/w3c/security-request/issues/114) similarly says that the Group does not believe the self-review concerns apply, but neither location makes the security reasoning behind that conclusion explicit.

For example, [Applying Position Fallback](https://www.w3.org/TR/2026/WD-css-anchor-position-1-20260327/#fallback-apply) states:

> Implementations may choose to impose an implementation-defined limit on the length of position options lists, to limit the amount of excess layout work that may be required. This limit must be at least five.

The same section explains that layout cannot go backward after a fallback decision and gives the following reason:

> At best, this can result in exponential layout costs; at worst, it’s cyclic and will never settle.

These passages make two design choices explicit that are relevant to availability (e.g., to avoid a denial-of-service), but the relationship between them is not currently visible in the Security Considerations section.

**Impact:** The current wording records the security conclusion, but does not expose the relevant reasoning already present in the specification. This makes it harder for implementers and reviewers to understand and later revisit the assumptions underlying that conclusion.

**Suggestion:** Add a brief explanation of the security-relevant reasoning reflected in the specification, including the assumptions and design constraints that are currently implicit in the Security Considerations section.

**Affected sections:**

- [Security Considerations](https://www.w3.org/TR/2026/WD-css-anchor-position-1-20260327/#sec)
