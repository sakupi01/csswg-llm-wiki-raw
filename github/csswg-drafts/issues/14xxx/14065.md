Right now, the `<syntax>` (https://drafts.csswg.org/css-values-5/#typedef-syntax) is pretty limited:

> […] which resembles a limited form of the CSS [value definition syntax](https://drafts.csswg.org/css-values-4/#css-value-definition-syntax) used in specifications to define CSS features, and which represents a [syntax definition](https://drafts.css-houdini.org/css-properties-values-api-1/#syntax-definition)

From time to time, I and others stumble upon various limitations of it.

Some quick examples (more are welcome in the comments!)

1. Multi-value types like `<length> <ident>` etc — most recent request I saw for this in the context of `attr()`: https://indieweb.social/@bigandy/116766124334595428, but this is something I also wanted to have in many cases.

2. Individual instances of `<length>`, `<number>`, `<integer>` etc, for example, something like `4px | 8px | 16px` etc., which can be very useful for design systems and other cases. We already can have lists of custom idents which represent the wider `<ident>`, but would be great to have individual values as well.

Are there reasons we don’t have those available for `type()`/registered custom properties?
