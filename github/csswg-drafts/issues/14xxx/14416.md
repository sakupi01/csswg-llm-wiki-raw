It's unclear from the spec right now what happens when the scope itself becomes disconnected or not rendered (via display: none for example). 

We have some requirements on the scope, from step 4 of https://drafts.csswg.org/css-view-transitions-2/#Element-ViewTransition-prepare:
> If [this](https://webidl.spec.whatwg.org/#this)’s [principal box](https://drafts.csswg.org/css-display-4/#principal-box) is [not rendered](https://drafts.csswg.org/css-images-4/#element-not-rendered), or is an [internal table box](https://drafts.csswg.org/css-display-3/#internal-table-box) other than [table-cell](https://drafts.csswg.org/css-display-4/#valdef-display-table-cell), or is an [internal ruby box](https://drafts.csswg.org/css-display-3/#internal-ruby-box) or a [non-atomic](https://drafts.csswg.org/css-display-3/#atomic-inline) [inline-level](https://drafts.csswg.org/css-display-3/#inline-level) box, then [skip](https://drafts.csswg.org/css-view-transitions-2/#skip-the-view-transition) viewTransition with an "[InvalidStateError](https://webidl.spec.whatwg.org/#invalidstateerror)" [DOMException](https://webidl.spec.whatwg.org/#idl-DOMException), and return viewTransition.

That's only written in startViewTransitions, though. I think we should have a similar block in per frame steps, maybe in https://drafts.csswg.org/css-view-transitions-2/#handle-transition-frame-algorithm

TL;DR: we should skip the transition with invalid state if the scope at any point in the transition becomes not qualified, based on the quote above.
