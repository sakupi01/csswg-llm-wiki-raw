For example:

```html
<div id=container style="container-type: inline-size; width: min-content;">
  <div id=element style="height: 10cqw">height?</div>
</div>
<script>
  getComputedStyle(element).height; // ?
</script>
```

`<length>` in [`height`](https://drafts.csswg.org/css-sizing-3/#propdef-height) must compute to an absolute value, but `min-content` resolves at used value time. Should the computed/used `height` resolve to `0px`?

https://drafts.csswg.org/css-conditional-5/#container-lengths

## @emilio — 2026-08-24

Container queries need to interleave layout and styling, thus `width: min-content` is a definite width by the time you get to resolving `10cqw` in `#element`. So the height of `#element` is just a pixel value.

## @cdoublev — 2026-08-25

  > Height also resolves at used value time, and should just return the used value? (I'm not sure I understand your concern).

Correct. I should have used `font-size: 10cqw` instead of `height: 10cqw`, because the resolved value of `font-size` must be its  computed value, which must be an absolute `<length>`.

My concern was that the [spec](https://drafts.csswg.org/css-conditional-5/#container-size-query) says that `cq*` values *"are evaluated based on the computed values of the query container"*. And the computed value of `min-content` for [`width`](https://drafts.csswg.org/css-sizing-3/#propdef-width) is *"as specified"*.

  > Container queries need to interleave layout and styling

Thanks for this clarification.

  > thus `width: min-content` is a definite width by the time you get to resolving `10cqw` in `#element`. So the height of `#element` is just a pixel value.

To be clear, in Chrome 151 and Firefox ESR 140, the resolved `height` is `0px` in my example. So I assume you are saying that the height of `#element` is *expected* to be that pixel value computed between style and layout.

I also assume it might be worth clarifying this in the spec, and so I am leaving this issue open.
