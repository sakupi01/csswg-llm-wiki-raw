According to the [spec](https://drafts.csswg.org/css-grid-3/#grid-lanes-orientation), the default direction of the container (either `grid-lanes-direction` or `grid-auto-flow`) is determined accordingly: "The [initial value](https://drafts.csswg.org/css-cascade-5/#initial-value) of this property is normal, which determines the orientation from the grid-template-* properties".

If both `grid-template-columns` and `grid-template-rows` are `none`, should we determine the direction based on the `grid-auto-*` properties as a fall back?

For example, should the following container be a row or column direction grid lanes?

```
.grid-lanes {
  display: grid-lanes;
  grid-auto-rows: 15px;
}
```

To get rows, you'd need to set the direction explicitly to indicate this, otherwise, you'll end up with columns according to the current spec since both templating properties are set to the default of `none`.

## @fantasai — 2026-07-29

`grid-auto-rows` is often used for the secondary axis, so I think I'd prefer to keep things simple here and only key off of the `grid-template-*` properties.

<!-- comment id=5123877647 author=tabatkins created=2026-07-29T22:10:11Z url=https://github.com/w3c/csswg-drafts/issues/14072#issuecomment-5123877647 -->
## @tabatkins — 2026-07-29

Agreed. I don't think we need to do anything particularly smart here in the first place; not providing *any grid-template at all* is an unusual thing to do, and it's fine to just give it a default behavior in that case.
