According to the [MDN Web Docs](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/counter), the `counter()` function returns a `<string>` value. However, when a custom property is explicitly registered with `syntax: "<string>"` via `@property`, assigning `counter()` output to it doesn’t work. 

Because `counter()` evaluates to a string, it should logically be permitted anywhere a string token is expected. 

**Steps to Reproduce**
1. Register a custom property with a `<string>` syntax.
2. Set up a standard CSS counter with a numerical value.
3. Attempt to save the `counter()` value into the registered custom property.
4. Pass the custom property variable into a pseudo-element's `content` rule (or use it in a container style query)

**Why it’s useful to save `counter()` output string to a custom property?** The custom property can be used in container style query for conditional styling. It’s also handy for string concatenations across parent-child flow. 

An example use: 

```
@property --items-cleared { 
  syntax: "<string>"; 
  inherits: true; 
  initial-value: "0"; 
}
.todo-app {
  counter-reset: cleared-count;
  --items-cleared: counter(cleared-count);
}
.todo-item:checked {
  counter-increment: cleared-count;
}
/* When a user checks three items off the to-do list*/
@container style(--items-cleared: "3") {
  .celebration-badge { 
     display: block; 
  }
 }
```

## @tabatkins — 2026-07-17

That's a browser bug; `counter()` represents a `<string>` and so should be allowed. Please report this as a bug to the individual browsers. ^_^

(It's not computationally-independent, so you can't use it as an *initial value*, but setting it normally is absolutely valid per spec.)
