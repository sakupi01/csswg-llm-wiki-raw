### CSS `:autofill` styling limitations

When a user selects a value from the browser's autofill suggestions, browsers may apply their own styles to the autofilled input.

For example:

```css
input:-webkit-autofill {
  font-family: "Vazir", sans-serif;
  transition: color 9999999s, background-color 9999999s;
}
```

The `transition` workaround can help hide the browser's autofill background/color, but it is a hack and does not reliably provide full control over the autofilled state.

More importantly, properties such as `font-family` may not be applied as expected to the autofilled value in some browsers.

It would be useful if `:autofill` provided predictable author-level control over properties such as:

* `font-family`
* `color`
* `background-color`
* `font-size`
* `font-weight`
* `border`

without requiring browser-specific workarounds.

The goal is not to disable autofill, but to make its visual styling consistently controllable by web authors.

## @SabziDev — 2026-10-01

Tnks for pointing that out. I agree that privacy and security should be considered here, especially if exposing more ":autofill" state could make it observable in ways similar to ":visited".

My intent is not to expose any sensitive autofill information or make the autofill state script-observable. The main goal is to give authors predictable control over the visual presentation of an autofilled form control (e.g. "font-family", "color", "background-color", and "border") while preserving the browser's privacy and security constraints.

Perhaps the specification could allow more author control over presentation without exposing additional information about the user's stored autofill data.
