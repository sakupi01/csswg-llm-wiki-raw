In https://drafts.csswg.org/css-link-params/ it feels like an important use case is efficiently animating the parameter, and I'm not sure that passing it in through the URL is going to be efficient, unless a lot of URL handling/resource loading code is made smarter which is a big ask.

I think the URL fragment form is a red herring here. Per #14238, fragment params aren't CSS-evaluated at all. So nothing should be animating it.

The real case is the property. 

<!-- comment id=5626723202 author=tabatkins created=2026-09-10T23:17:26Z url=https://github.com/w3c/csswg-drafts/issues/14030#issuecomment-5626723202 -->
## @tabatkins — 2026-09-10

Note that actually passing it in the URL is the *least* convenient way to pass a value. Using 'link-parameters' or a url() parameter gives you a more indirect channel to the linked resource that shouldn't require going thru URLs at all.

That said, currently I *do* allow parameters passed in the URL to resolve against the element, if they're in an element's attribute (like `<img src>`). I'd be okay with banning that if necessary, so attempting to pass values directly in the URL that *need* an element context would always be invalid (but you could still pass values that don't need that context, like `param(--foo, blue)`).

Do you think that's needed, @smfr ?
