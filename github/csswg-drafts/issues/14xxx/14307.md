The [spec says](https://drafts.csswg.org/css-shadow/#the-has-slotted-pseudo):

> The :has-slotted pseudo-class matches [slot](https://html.spec.whatwg.org/multipage/scripting.html#the-slot-element) elements which have a non-empty list of [flattened slotted nodes](https://dom.spec.whatwg.org/#find-flattened-slotables).

> When [:has-slotted](https://drafts.csswg.org/css-shadow/#selectordef-has-slotted) matches a slot with fallback content, we can conclude that the fallback content is not being displayed.

This is contradicting since a slot's flattened assigned nodes includes its fallback content, meaning the 2nd sentence is not necessarily true since fallback content *may* be displayed when `:has-slotted` matches.

The first sentence matches the csswg's resolution here: https://github.com/w3c/csswg-drafts/issues/6867#issuecomment-2593536333.

The 2nd sentence should likely just be removed.

## @woody-li — 2026-08-17

Why not using:
```
`:has-slotted` should match when the fallback content is not being displayed
```

It's unambiguous.

- Using `:has-slotted` only to match an element which has any flatten assigned nodes (excludes the fallback content).
- Using `:not(:has-slotted, :empty)` to match which the fallback content is displayed.
- Using `:empty:not(:has-slotted)` to match the real empty slot.

## @keithamus — 2026-08-18

Generally speaking we want `:has-slotted` to align to `.assignedNodes({flatten:true})`. This means the fallback content _does_ make `:has-slotted` apply. This adheres to the original request in https://github.com/w3c/csswg-drafts/issues/6867#issue-1074568049 because the ask was to determine if the slot has _any content_ (which `:empty` cannot satisfy because it does not account for slotted content).

Ultimately, I think it comes down to two options:

## Option A (including):

- `:has-slotted` would match if an element has any flattened nodes, _including_ fallback content.
- `:has-slotted:not(:empty)` would match on a slot which declared fallback content and was either displaying the fallback content, or _non-fallback_ content.
- This is useful for styling a slot based on whether or not it is rendering _something_.

## Option B (excluding):

- `:has-slotted` would match if an element has any flattened nodes, _excluding_ fallback content.
- `:has-slotted:not(:empty)` would match on a slot which declared fallback content but was displaying _non-fallback_ content instead.
- This is useful for styling a slot based on whether or not it is rendering _non-fallback content_.

In both of these cases:

- `:has-slotted:empty` would match if a slot never declared fallback content, but it is being slotted by outside content.


The question then becomes whether or not it is useful to know if the slot is rendering its fallback or not. The original request asked to style a slot has content or not, but did not specify if that content had to be fallback or not. Therefore Option A seems to satisfy that. I haven't seen a compelling usecase for Option B, so we would need evidence of that. 

Given we've been unable to decide async, it seems worth taking to the proper agenda.
