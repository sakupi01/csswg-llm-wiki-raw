Heya, me again

[Section 5.5.7](https://www.w3.org/TR/css-syntax-3/#consume-list-of-components), detailing the "Consume a list of component values" algorithm, doesn't appear to consume or discard the stop token:

> \<eof-token>
stop token (if passed)
Return values.

Was that intentional?

The "[Consume a declaration](https://www.w3.org/TR/css-syntax-3/#consume-declaration)" algorithm invokes the other, with a `<semicolon-token>` as the stop token. However it also doesn't discard the `<semicolon-token>`. Shouldn't one of these algorithms discard that stop token? Or is it intentionally left in the token stream?

Apologies if I've missed something obvious.

<!-- comment id=6334371126 author=cdoublev created=2026-10-22T06:31:37Z url=https://github.com/w3c/csswg-drafts/issues/14649#issuecomment-6334371126 -->
## @cdoublev — 2026-10-22

A semicolon is never part of a list of component values or a declaration. It is part of a declaration list. Therefore it is consumed in [consume a block's contents](https://drafts.csswg.org/css-syntax-3/#consume-a-blocks-contents) or [parse a list of declarations](https://drafts.csswg.org/css-syntax-3/#parse-list-of-declarations) (for `style.csstext`).
