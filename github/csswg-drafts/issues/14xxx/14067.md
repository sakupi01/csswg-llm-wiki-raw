In #12665 and #13668, we resolved that inside a line-clamp container, floats are clipped to the block-end content edge of the container. But it's not clear how that should work when the container has a `border-radius`.

Per css-backgrounds, a border-radius causes the content edge to also have a radius. But radii apply to corners, not edges. Since there's no clipping on the inline-start or -end edges, if we apply the radius to the block-end edge, where does the curve stop?

It's probably better to ignore the radius and treat the edge as an infinite horizontal line.

When discussing this with Andreu the challenging case leading to "treat the edge as an infinite horizontal line" come about when the float overflows _both_ the inline side of the line-clamp container, and the bottom edge. There seems no sensible way to define a clip when border radius is present. Here's an example without the clipping that I hope demonstrates the issue. According to spec the float is clipped to the bottom content edge, which in this case would leave the line-clamp container's border still curving when it hits the float (see the bottom image). Looking at it here that doesn't seem so bad.
