Should a random base value be generated and a random cache name be stored when evaluating support of `random()` in `CSS.supports()`, `@supports`, `supports()`?

I cannot think of how that could be a real author problem if a random cache name must be stored.

If the random base value must be generated, is it correct that `CSS.supports('animation-duration', 'random(--key, -1, 1)')` should evaluate to false if it is lower than `0.5`? (I assume `random(--key, -1, 1)` resolves at parse time.)

<sup><a href="https://drafts.csswg.org/css-animations-2/#propdef-animation-duration" target="_blank"><code>animation-duration</code></a> does not accept a negative value.</sup>

Or does this need to be specific, like with [selectors](https://drafts.csswg.org/css-conditional-4/#dfn-support-selector)?

## @tabatkins — 2026-07-29

At parse time, that `random()` is a `<number>`, which is invalid for `animation-duration` in the first place.

Assuming you meant `-1s, 1s` for the values, that's perfectly valid, as `random()` is a math function and thus clamps its result to the range allowed by the context.

`random()` doesn't resolve at parse-time at all anyway.
