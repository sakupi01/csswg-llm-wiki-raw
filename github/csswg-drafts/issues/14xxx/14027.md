What is the expected outcome in these cases?

```
color( srgb calc(infinity) 1 0 )
color( srgb calc(-infinity) 1 0 )
color( xyz calc(infinity) 1 0 )
color( xyz calc(-infinity) 1 0 )
```

Currently each engine does something different.

I think Firefox makes the most sense:

```
color( srgb calc(infinity) 1 0 ) /* bright yellow */
color( srgb calc(-infinity) 1 0 ) /* bright green */
color( xyz calc(infinity) 1 0 ) /* bright pink */
color( xyz calc(-infinity) 1 0 ) /* bright green */
```

## @Loirooriol — 2026-06-08

It should behave like a huge number: https://drafts.csswg.org/css-values-4/#css-infinity

> [Infinities](https://drafts.csswg.org/css-values-4/#css-infinity) do not escape a [top-level calculation](https://drafts.csswg.org/css-values-4/#top-level-calculation); they’re clamped to the minimum or maximum value allowed in the context, as defined in [§ 10.12 Range Checking](https://drafts.csswg.org/css-values-4/#calc-range).

## @weinig — 2026-06-08

This unfortunately comes down to how browsers should gamut map colors out of range of their users monitors. I don’t think we have agreement on a way forward on this yet, and the status quo is that the engines tend to just do whatever their graphics backend happens to do (usually some form of component clamping). 

Cc @svgeesus in case their have been more developments in the gamut mapping discussions I am not up to date on.
