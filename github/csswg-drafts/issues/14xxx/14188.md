I'd like to clarify how the [`zoom`](https://drafts.csswg.org/css-viewport/#zoom-property) property should work with [`animation-range-start`](https://drafts.csswg.org/scroll-animations/#propdef-animation-range-start) and [`animation-range-end`](https://drafts.csswg.org/scroll-animations/#propdef-animation-range-end).

My expectation is that when using [`animation-range-start`](https://drafts.csswg.org/scroll-animations/#propdef-animation-range-start) and [`animation-range-end`](https://drafts.csswg.org/scroll-animations/#propdef-animation-range-end) from CSS, pixel lengths are scaled using the effective zoom of the same element's style just like all other properties.

Similarly, the pixel values returned from an [Animation](https://drafts.csswg.org/web-animations-2/#the-animation-interface) object's (when used with a style backed animation that has not overridden anything) [rangeStart](https://drafts.csswg.org/web-animations-2/#dom-animation-rangestart) and [rangeEnd](https://drafts.csswg.org/web-animations-2/#dom-animation-rangeend) attributes should be unscaled values due to the viewport spec [stating](https://drafts.csswg.org/css-viewport/#zoom-om) "All other APIs related to element geometries must return unscaled lengths (except as detailed below)". (Though, is this relative to "element geometries"? Kinda?).

Where I am not sure is when setting pixel values on the programatic interfaces.

For example, if you have a style backed [Animation](https://drafts.csswg.org/web-animations-2/#the-animation-interface) object, and the style that defined it was something like:

```css
.animation-element {
    animation: go 1ms linear;
    animation-range-start: 100px;
    animation-range-end: 200px;
    zoom: 2;
}
```

and you override it in script with something like:

```javascript
animation.rangeEnd = "20px";
```

Should the [`zoom`](https://drafts.csswg.org/css-viewport/#zoom-property) of the backing animation element's style (in this case with value `2`) affect that? In this case meaning the used value would be `40px`?

One argument in favor of having [`zoom`](https://drafts.csswg.org/css-viewport/#zoom-property) apply to overridden values is that it round trips. Reading the value and then setting it back keeps the value the same.

In the case of non-style backed [Animation](https://drafts.csswg.org/web-animations-2/#the-animation-interface) objects, there is no style to get the [`zoom`](https://drafts.csswg.org/css-viewport/#zoom-property) property from, so my assumption is pixel lengths are unscaled throughout in that case.
