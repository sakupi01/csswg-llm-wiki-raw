Currently, there is no official term for the element that uses the trigger in the animation-triggers specification. 

I suggesting using "trigger-using element" as the name for the element on which `animation-trigger` is set. The text is used in the specification, but not as a term:

```md
A [=trigger=] is <em>used</em> on potentially any element,
	creating a <dfn export for=CSS>trigger instance</dfn> on the element.
	(For example, 'animation-trigger' associates a [=trigger instance=]
	with a specific animation on the element.)
	The trigger-using element specifies what actions to take
	when the [=trigger=] activates.
```

Having a succinct term will enable consistency within explanations / documentation.

I suggest:

```md
A [=trigger=] is <em>used</em> on potentially any element,
	creating a <dfn export for=CSS>trigger instance</dfn> on the element.
	(For example, 'animation-trigger' associates a [=trigger instance=]
	with a specific animation on the element.)
	The [=trigger-using element=] specifies what actions to take
	when the [=trigger=] activates.
```

## @ydaniv — 2026-07-10

@estelle, thanks for the feedback, and great to see an article coming up on MDN!

Essentially it's not an element that's using the trigger, but an animation. The spec does have a term for [`triggered animations`](https://drafts.csswg.org/animation-triggers-1/#triggered-animation):

> This specification extends the Web Animations model by defining [triggered animation](https://drafts.csswg.org/animation-triggers-1/#triggered-animation) and allowing to perform [playback control](https://www.w3.org/TR/web-animations-1/#playback-control) functions on them using triggers.

The animation has an associated effect, and that, in turn, has an associated target element.

You can have multiple animations on an element, some triggered and some not. So it's not a one-to-one relation, and there's no actual change to any attribute/behavior of the element itself. Or, in other words, the element doesn't really "know" about the trigger.
