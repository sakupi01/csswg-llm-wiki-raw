The UA stylesheet currently applies block-axis centering in a few places: options, radio buttons, checkboxes, and [buttons](https://github.com/w3c/csswg-drafts/issues/14190). But actually, when an input or select is sized larger than the text and icons it contains, its contents should also be centered.

We should apply centering systematically to all single-line form controls:

```
input, select, option {
  align-content: center;
  align-items: center;
}
```

I think the main question I have is how much of this needs to be restricted to `appearance: base`.

<!-- comment id=5283839436 author=fantasai created=2026-08-13T16:59:54Z url=https://github.com/w3c/csswg-drafts/issues/14319#issuecomment-5283839436 -->
## @fantasai — 2026-08-13

Also thinking about this and #14190 a bit more -- buttons should probably have `safe center`, since they can accept block-level content. But input and select might be better to use just `center`. They're clipped, you can't scroll to see their contents, and they're a single line of text. The best we can do for showing information is to vertically center: fully showing ascenders is not as important as showing the middle of the text.

## @fantasai — 2026-08-26

> how we're enforcing that all content is a single line

We're not. But that's the vast majority of how content renders for these elements, it's super unusual to do anything multiline. Button yes, input/select, not so much. And `option` doesn't get clipped by default.

> since typically the start contains the most important context

Not always :)

> I'm also not sure how text-ellipsis is meant to work with unsafe alignment, does it elide both sides?

This is only aligning in the block axis. The inline axis continues to be start-aligned.
