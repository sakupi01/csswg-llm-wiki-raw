https://drafts.csswg.org/selectors/#lang-pseudo does not mention the language code maximization (e.g. zh → zh-Hans-CN) stipulated in [Likely Subtags in UTS #35 Unicode Locale Data Markup Language (LDML)](https://www.unicode.org/reports/tr35/#Likely_Subtags).

HTML:

```html
<p class="test" lang="en"></p>
    <p class="test" lang="fr"></p>
    <p class="test" lang="zh-Hans"></p>
    <p class="test" lang="zh"></p>
    <p class="test" lang="zh-CN"></p>
    <p class="test" lang="zh-SG"></p>
    <p class="test" lang="zh-Hans-CN"></p>
    <p class="test" lang="zh-Hant"></p>
    <p class="test" lang="zh-TW"></p>
    <p class="test" lang="zh-HK"></p>
    <p class="test" lang="zh-MO"></p>
    <p class="test" lang="zh-Hant-TW"></p>
```

CSS:

```css
.test {
  &::before {
    content: "??";
  }

  &:lang(*-Latn)::before {
    content: "Ab";
  }

  &:lang(zh)::before {
    content: "汉";
  }

  &:lang(zh-Hans)::before {
     content: "简"; 
  }

  &:lang(zh-Hant)::before {
    content: "繁";
  }
}
```

- `:lang(*-Latn)` should match `en`, `fr`, `de`, and so on. Currently, CSS doesn't provide a method to simultaneously change fonts for these languages without explicitly naming each language. Who in the world prefers the verbose `en-Latn` or `fr-Latn` to `en` or `fr`?


  ```css
  [lang] {
    font-family: sans-serif;
  }
  @media screen {
    /* How many languages worldwide use these scripts? Listing them all would be insane! */
    [lang]:lang(*-Latn, *-Cyrl, *-Grek) {
      /* I'm sick of the Helvetica family. System fonts rule! */
      font-family: -apple-system, BlinkMacSystemFont, Segoe UI, Roboto, Noto Sans, sans-serif;
    }
  }
  ```

  -  `en` → <code>en<strong><em>-Latn</em></strong>-US</code>
  - `fr` → <code>fr<strong><em>-Latn</em></strong>-FR</code>
  - `de` → <code>de<strong><em>-Latn</em></strong>-DE</code>

- Currently, matching either Simplified or Traditional Chinese is somewhat cumbersome:

  ```css
  [lang] {
    font-family: sans-serif;
  }

  /* It's insane that you have to write such a long selector just to specify a few fonts explicitly for Simplified Chinese */
  [lang]:where(:lang(zh):not(:lang(zh-Hant), :lang(zh-TW), :lang(zh-HK), :lang(zh-MO))) {
    font-family: PingFang SC, Noto Sans CJK SC, Noto Sans SC, Microsoft YaHei, sans-serif;
  }
  ```

  `zh-Hans` (or `*-Hans`) should match `zh`, `zh-CN`, and `zh-SG`, and `zh-Hant` (or `*-Hant`) should match `zh-TW`, `zh-HK`, and `zh-MO` (maximized to `zh-Hant-*`) in a lang attribute value:

  ```css
  [lang] {
    font-family: sans-serif;
  }

  /* or [lang]:where(:lang(zh-Hans)) */
  [lang]:where(:lang(zh):not(:lang(zh-Hant))) {
    font-family: PingFang SC, Noto Sans CJK SC, Noto Sans SC, Microsoft YaHei, sans-serif;
  }
  ```

* Expected: neither "??" nor "汉" is displayed
* Actual: some are "??" or "汉"

At first, I considered reporting this as a Firefox-specific bug in Firefox's Bugzilla, but then I noticed that this maximization is not mentioned in the [CSS Selectors specification](https://drafts.csswg.org/selectors/#lang-pseudo).
