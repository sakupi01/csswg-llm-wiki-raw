Not sure if I'm filing this for the right spec because I can't actually find anything in https://drafts.csswg.org/css-inline/ with regards to how inline borders/paddings/margins should affect line breaking.
But consider the following:
```html
<!DOCTYPE html>
<style>
body {
    margin: 0;
}
span {
    border-inline: 50px solid;
    padding: 1em;
    background: green;
    > span {
        padding-block: 0;
        background: lime;
        margin-inline-end: -10em;
    }
}
</style>
<br>
<span><span>The quick brown fox jumps over the lazy dog.</span></span>
```
This looks like this in all three browsers:
<img width="1580" height="148" alt="Image" src="https://github.com/user-attachments/assets/46e5a4ac-f95f-48e0-a0e4-19a92f27c714" />
The red lines indicate (in order) at which window widths WebKit, Chromium and Gecko decide that there is not enough space left on the line and start breaking "dog." onto the next line. So this is the slimmest I can drag the window in each of these without having it wrap:
<img width="824" height="419" alt="Image" src="https://github.com/user-attachments/assets/7f3548e6-582a-49cd-935e-ddb0d6b7d74d" />

Personally, I'd say the most sensible point to break would be inbetween Chromium and Firefox, where the visibly rightmost border ends because that avoids having any text or borders overflow out of the containing block.
It'd be nice if the spec could standardize that. Alternatively, having any one of these options standardized would be nice. Any consistency would be better than what we have right now.

I came across this while implementing `box-decoration-break` into Servo, with regards to how to calculate the amount of space to reserve for cloned borders/paddings/margins. at the end of a line.

## @fantasai — 2026-06-15

That is a really confusing testcase.

You have:
- 56px border+padding+margin on the outer span
- -144px border+padding+margin on the inner span

That gives you net -88px margin on the end side. You *should* expect overflow; I don't understand why you think there shouldn't be any.

Anyway, line breaking is intentionally underdefined in CSS. It's a quality-of-implementation issue, and implementations are allowed to vary.
