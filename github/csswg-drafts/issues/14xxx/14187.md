```html
<!DOCTYPE html>
<ol>
  <button style="display: list-item">1</button>
  <input style="display: list-item" value="2">
  <canvas style="display: list-item; height: 1lh">3</canvas>
  <li>4</li>
</ol>
```

Gecko allows them to increase the automatic `list-item` counter. `<button>` can generate a `::marker` (even with outside position!), but `<input>` and `<img>` can't - presumably, same logic as for `::before`.

Blink and WebKit don't allow them to be list items at all.

## @Loirooriol — 2026-07-16

Well, `list-item` can only be combined with specific display types. So it wouldn't be that surprising if it wouldn't work with `<button>`, since a `flow-root` inner display type generates an anonymous button content box around the contents, unlike a typical BFC. It can be understood as behaving as an internal `display: button` or such.

Also, being a widget is close enough to being replaced, that it surprised me a bit that the `::marker` doesn't get contained to be inside positioned or something.

But not opposed to allowing it.

> Whether a [replaced element’s](https://drafts.csswg.org/css-display-4/#replaced-element) descendants (such as HTML [option](https://html.spec.whatwg.org/multipage/form-elements.html#the-option-element), or SVG [rect](https://w3c.github.io/svgwg/svg2-draft/shapes.html#elementdef-rect)) can set, reset, or increment a counter is undefined.
