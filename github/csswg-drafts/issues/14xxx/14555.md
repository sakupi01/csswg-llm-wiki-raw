#10234 resolved on _"extending `.insertRule()` to parse declarations"_. For example, `styleRule.insertRule('color: green')` results in the addition of a `CSSNestedDeclarations` rule representing `color: green` in `styleRule`.

In Chrome, `CSSFunctionRule.insertRule()` does not parse declarations at the moment. It throws an error.

```js
const sheet = new CSSStyleSheet
sheet.replaceSync('@function --name() {}')
const rule = sheet.cssRules[0]
rule.insertRule('result: 1')
rule.cssRules[0] // Expected: CSSFunctionDeclarations
```

In [insert a CSS rule](https://drafts.csswg.org/cssom-1/#insert-a-css-rule), the resolution was translated into this particular step, when the result from parsing a rule returned a syntax error:

  > Otherwise, set `new rule` to a new [nested declarations rule](https://drafts.csswg.org/css-nesting-1/#nested-declarations-rule) with `declarations` as it contents.

"Nested declarations rule" links to CSS Nesting and implicitly refers to `CSSNestedDeclarations` as the `new rule`, whereas in `@function`, it would need to be a `CSSFunctionDeclarations`, which is defined in CSS Mixins.

Therefore I do not know whether this resolution should apply to `CSSFunctionDeclarations`.

If it should apply, perhaps this step could be:

  > Otherwise, set `new rule` to the appropriate nested declaration rule for the context with `declarations` as its contents.
