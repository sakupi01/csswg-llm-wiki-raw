In July 2024, the Web Preferences API proposal was incorporated into the Media Queries Level 5 specification following [CSSWG issue #6517](https://github.com/w3c/csswg-drafts/issues/6517).

Since then, there have been no shipping implementations of the API. The original WICG proposal has since been retired/moved into the Media Queries specification, and the original explainer is now noted as potentially outdated.

I would like to use TPAC to establish whether there is still sufficient interest from implementers and the Working Group to continue developing this feature, or whether it should be removed from the specification.

In particular:

* Do browser vendors still see value in providing a mechanism for sites to override user preferences such as `prefers-color-scheme`, `prefers-reduced-motion`, etc.?
* Are there plans or interest in implementing the current proposal?
* If there is implementation interest, is the current design still the right approach?

If there is interest in continuing the feature, we would also like to discuss some of the outstanding design questions, including:

* Preference propagation to iframes and subresources, how an override should interact with same-origin and cross-origin iframes. [#11577](https://github.com/w3c/csswg-drafts/issues/11577)
* Retrieving the original preference value, whether and how a site should be able to distinguish its override from the underlying user-agent preference. [#11580](https://github.com/w3c/csswg-drafts/issues/11580)
* Security and privacy, including the implications of persistent, origin-scoped overrides, propagation to third parties, and potential fingerprinting or cross-site information leakage.
* Persistence and storage, how overrides should be persisted, cleared, and synchronised, and how this interacts with existing browser storage and privacy models (there was a lengthy discussion on this last time).

The desired outcome from the discussion would be to determine if we continue, revise or remove the feature completely
