The syntax for `line-clamp` is given as:

```
none | [<'max-lines'> || <'block-ellipsis'>] -webkit-legacy?`
```

Meanwhile, the syntax for `max-lines` is given as `auto || <integer [1,∞]>`.

As written, this implies that if both of the options for `max-lines` are given, then they must go together. So `3 ellipsis auto` would be disallowed.

It's probably better to remove this restriction, giving authors freedom to write the keywords in any order, since they're unambiguous. We'd then rewrite the syntax as:

```
none | [<integer [1,∞]> || auto || <'block-ellipsis'>] -webkit-legacy?
```

(See #14671 for the separate question on the relative order of the integer and `auto`.)

## @frivoal — 2026-10-26

Priority of constituencies makes me thing we should indeed take that change. It's a little more annoying to write the spec for that, but authors are likely to perceive the `auto` part, the number of lines part, and the block ellipsis part, as effectively independent of each-other, and will not expect constraints in how these can be ordered or interleaved.

So I think we should accept the proposal in the original comment, and I think we can do so asynchronously.
