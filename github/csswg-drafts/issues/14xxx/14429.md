The spec currently specifies:

> For backwards-compatibility,  the <a>resolved value</a> of this keyword is zero for boxes of all [[!CSS2]] <a>display types</a>:
>  block and inline boxes, inline blocks, and all the table layout boxes.
> It also resolves to zero when no box is generated.

However, testing shows that implementations return zero for all block-<em>level</em> and inline-<em>level</em> boxes. (A block-level grid container is a block-level box, but not a block box.)

This is fine, but not strictly necessary for the back-compat concern. Do we want to specify that it's zero for all of these? Or should we consider it implementation bugs?

[Testcase:](https://software.hixie.ch/utilities/js/live-dom-viewer/saved/14852)
```html
<!DOCTYPE html>
<body style="display: flex; min-width: auto;"><div style="min-width: auto;"></div>
<script>
w("display:flex - " + getComputedStyle(document.body).minWidth);
w("flex item - " + getComputedStyle(document.body.children[0]).minWidth);
</script>
```
