In [Scroll Snap section 4.1.2](https://drafts.csswg.org/css-scroll-snap/#captures-snap-positions), we define that a container "captures snap positions" if it's a scroller *or* if it has a non-initial `scroll-snap-type`. Snappable children only contribute to the nearest ancestor that captures snap positions. This means that, if you set `overflow:visible; scroll-snap-type: both;` on an element, per spec it should "hide" its children from any higher elements that are actually scroll containers, even tho it's not actually snapping those children in any way.

This was talked about back in 2019 in #4496, as nobody implemented that behavior (only scroll containers could trap snap positions), but we left the behavior in as "at-risk" in case other browsers wanted to implement it; Blink was ambivalent about it.

It's 2026 now, and nobody's implemented it.  See [this testcase](https://jsfiddle.net/lcdavid94/bdztrLa2/1/):

```html
<!DOCTYPE html>
<style>
#parent {
  width: 200px;
  height: 200px;
  overflow: auto;
  scroll-snap-type: both mandatory;
}

#capture {
  width: 600px;
  height: 400px;
  background: red;
  display: grid;
  place-items: center;
  scroll-snap-type: both mandatory;
}

#target {
  width: 100px;
  height: 100px;
  background: blue;
  color:white;
  scroll-snap-align: center;
}
</style>
<div id="parent">
  <div id="capture">
    <div id="target">Hello world</div>
  </div>
</div>
```

Per spec, the `#capture` element should capture snap positions for `#target`, then do nothing with them, so `#parent`, the actual scroll container capable of snapping, has nothing to work with. In practice, tho, `#parent` *does* snap, in both Chrome and Firefox (I couldn't easily test WebKit), implying that we only scroll containers capture snap positions.

I think we should go ahead and remove the behavior, so that only scroll containers capture snap positions.

## @vmpstr — 2026-09-18

Based on the fact that no (major) browser implements this behavior, the proposed resolution is the following:

Remove the behavior where a non-initial scroll-snap-type captures snap positions, so that only scroll containers capture snap positions.
