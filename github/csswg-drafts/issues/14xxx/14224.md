This is meant as a parent issue to track selective wildcarding of parts of css-syntax: classes, attributes, CSS properties, whatever. Tracking these issues together is important to end up with an architecturally coherent design, rather than individual ad hoc solutions.

One thing that most (all?) of these share: the majority of use cases involves matching a **hyphen-bounded prefix**. If we restrict the MVPs to that, we could cover the common cases while UAs can use (or continue using) Bloom filters that are not that much bigger than those required for exact matches. 

I think this also offers author-facing benefits: with substring matching it's easy to unintentionally match more than intended, whereas enforcing whole words is more robust.

And if enough use cases emerge later for general substring matching, the syntax is already compatible.

* `RESOLVED: Unless there is good use case based motivation, the minimum to support is hyphen-asterisk for prefixes. We can explore potential relaxing on a case by case basis based on use cases, but it would need to be well motivated.`
