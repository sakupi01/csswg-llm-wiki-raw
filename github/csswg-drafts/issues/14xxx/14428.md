## Abstract

This proposal introduces two new media features, `display-state` and `resizable`, to CSS [Media Queries Level 5](https://www.w3.org/TR/mediaqueries-5/) (`mediaqueries-5`). These features allow authors to declaratively adapt their web application's styling based on the operating system-level state of the window (e.g., maximized, minimized, or fullscreen) and whether the window is user-resizable.

## Motivation

The [Additional Windowing Controls API](https://github.com/w3c/window-management/blob/main/EXPLAINER_additional_windowing_controls.md) exposes capabilities for web applications to maximize, minimize, restore, and restrict the resizing of windows via JavaScript. To allow web applications to introspect their state related to those capabilities, the accompanying CSS Media features are proposed.

Currently, developers lack a native, declarative CSS mechanism to style the UI based on the window state and its resizability. For instance:

- If a web app is running in a `maximized` window, the app might want to hide its own "Maximize" button and show a "Restore" button instead.  
- If the application restricted the resizability of the window or the OS enforces a fixed window size, the application might want to hide custom resize handles or collapse flexible UI panels.

## Proposal

### The `display-state` media feature

The `display-state` media feature allows developers to query the current OS-level display state of the application window.

```css
/* Hide the maximize button if the window is already maximized */
@media (display-state: maximized) {
  .maximize-btn {
    display: none;
  }
}

/* Adjust padding when in fullscreen mode */
@media (display-state: fullscreen) {
  .title-bar {
    padding-top: 20px;
  }
}
```

### The `resizable` media feature

The `resizable` media feature evaluates whether the window can be resized by the user.

```css
/* Only show custom drag handles if the window can actually be resized */
@media (resizable: true) {
  .custom-resize-handle {
    display: block;
    cursor: se-resize;
  }
}
```

## Specification

The `display-state` and `resizable` media features are provisionally defined in the Window Management specification ([`display-state`](https://www.w3.org/TR/window-management/#media-descriptor-display-state) and [`resizable`](https://www.w3.org/TR/window-management/#media-descriptor-resizable)), and Media Queries Level 5 would be the most fitting host specification.

## Specification Considerations

- **Interaction with `display-mode`**: We should clarify the distinction between the existing `display-mode` (which is the "frame decoration style") with the states `fullscreen | standalone | minimal-ui | browser | picture-in-picture`) and `display-state` (which tracks the window manager's window state).  
- **Privacy & Fingerprinting**: Exposing `display-state` and `resizable` provide new bits of entropy about the user's window configuration, akin to others . However, since this data is already partially exposed via `window.innerWidth`/`outerWidth`. Additionally, the risk of fingerprinting with `display-state` and `resizable` properties is mitigated by the CSS properties not being updated when the page is in the background. Because of this, the events related to the window state changes are triggered once the page switches to foreground. This makes it impossible to do fingerprinting based on the time of the window events across multiple tabs open in the same browser window.  

## Conclusion

The addition of `display-state` and `resizable` media features provides the missing declarative styling primitives necessary to support the Additional Windowing Controls API. By adopting these features, CSS authors can build responsive, native-feeling desktop web applications without relying on fragile JavaScript workarounds.
