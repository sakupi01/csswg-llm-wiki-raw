Following up on #4653 with a compatibility report from Chromium: should `text-decoration-skip-spaces: start end` have a special case for lines consisting entirely of preserved spaces?

Spec: https://drafts.csswg.org/css-text-decor-4/#text-decoration-skip-spaces-property

The current initial value is `start end`, which skips spacers at the start and end of a line. For a line containing only preserved U+0020 spaces, applying those rules skips the entire text, leaving no decoration.

### Compatibility report

In https://issuetracker.google.com/issues/573538444, enabling `text-decoration-skip-spaces` in Chromium caused underlines to disappear from inline-block elements whose entire text content was a single U+0020 space preserved by `white-space: pre`. Otherwise identical elements containing visible characters still painted their underlines.

The reporter uses these spaces to represent underlined blank character positions. The spaces retain their advance width, but their underline disappears. Chromium reverted the feature's default enablement in response to this regression.

### Reduced example

```html
<!doctype html>
<meta charset="utf-8">
<style>
  body { font: 24px monospace; }
  .cell {
    display: inline-block;
    width: 24px;
    height: 32px;
    line-height: 32px;
    border: 1px solid #777;
    text-align: center;
    white-space: pre;
    text-decoration: underline;
  }
</style>
<span class="cell">A</span>
<span class="cell"> </span>
<span class="cell">A</span>
```

The middle element contains exactly one ASCII space. In the reported regression, it lost its underline while the two elements containing `A` remained underlined. Each inline-block contains its own line, so the middle space is at both the start and end of that line.

### Questions

Could `start` and `end` preserve decorations when the entire line consists of preserved spacers, while retaining the existing skipping behavior for leading/trailing spacers on lines that also contain other text? `all` would continue to skip those spaces, and `none` would continue to decorate them.

If such an exception is appropriate, should it apply consistently to lines in ordinary blocks as well as inline-blocks, including spaces preserved by `pre`, `pre-wrap`, and `break-spaces`?

In #4653, the WG proceeded with the specified behavior and left room to revisit it if implementation feedback revealed problems. This report provides compatibility feedback for the case where skipping the line's leading/trailing spaces removes its decoration entirely.
