### Context

In grid lanes, stacking-axis gutters exist only between items in a track. Each gutter is placed above the item that follows it.

### Example

<details>
<summary>Test case</summary>

```html
<!DOCTYPE html>
<style>
  body { margin: 0; }
  .lanes {
    background: #cdd5e0;
    column-rule: 4px solid blue;
    column-rule-break: intersection;
    row-rule: 4px solid gold;
    display: grid-lanes;
    flow-tolerance: 0;
    gap: 20px;
    grid-lanes-direction: column;
    grid-lanes-pack: dense;
    grid-template-columns: repeat(4, 60px);
    width: max-content;
  }
  .lanes > div {
    background: #5b8def;
    color: white;
    font: 600 12px/1 sans-serif;
    height: 40px;
  }
  .lanes > .tall { height: 200px; }
  .lanes > .spanner { background: #8a6df0; grid-column: 1 / -1; }
  .lanes > .centered {
    align-self: center;
    background: #1f9d6b;
    height: 20px;
    grid-column: span 3;
  }
  .left { align-self: start; grid-column: 1; }
</style>
<div class="lanes">
  <div class="tall">1</div>
  <div>2</div>
  <div>3</div>
  <div class="spanner">4</div>
  <div class="centered">5</div>
  <div class="left">6</div>
  <div class="left">7</div>
  <div style="grid-column: 4">8</div>
  <div style="grid-column: 4">9</div>
</div>

### Current behavior per spec as written

First, consider the example from the html above but without an item below the first spanner:

<img width="619" height="782" alt="Image" src="https://github.com/user-attachments/assets/a1afef53-864b-452b-8a9f-87a81ff2b133" />

Here, item 5 has available space for alignment. The empty space below item 5 is part of its alignment, so we do not expect column rules below item 5 in the second and third column gaps.

Now with an item below it:

<img width="616" height="773" alt="Image" src="https://github.com/user-attachments/assets/dad15b84-16f8-48c3-a088-3010a8c0cfbd" />

Items 4 and 5 are spanning items, and neither has available space for alignment below it.

- Item 4 spans all tracks.
    - 4 gutters are created above it, *none* are created below it, outside of the one created by item 6.
- Item 5 spans tracks 2 to 4. A gutter is created below it above item 9, but no other gutters exist directly below it.

We believe that authors would probably expect column rules to continue below these spanners between every track, however, as written currently due to the absence of gutters immediately below the spanners this isnt possible.
### Options

**1. Add a new type of junction (sort of a fake gap) below spanners (name TBD).**

When a spanner has no available space for alignment, a new gutter-like region is placed below it, in each track that does not already have a gutter there.
This region creates segment endpoints like a gutter does, but it does not contain stacking-axis rules.

<img width="613" height="776" alt="Image" src="https://github.com/user-attachments/assets/7f0eeb94-4086-4733-bfff-a5ffbd9aea10" />

- Pro: Small change. Current gutter and rule behavior does not change.
- Con: Adds a new concept only for this case.

**2. Spanners with no available space for alignment create a real gutter below them.**

The column rules resume. But these gutters also get row rules where nothing is below the spanner.
This raises the question of whether `rule-visibility-items` should also apply to rules in the stacking axis,
even though previously we had indicated that they would only be applicable in the grid axis.

<img width="616" height="776" alt="Image" src="https://github.com/user-attachments/assets/f16c9266-2e74-4278-9052-9db5dd8449bf" />

The new gutter can also be very close to the next gutter. In the example below, item B spans tracks 2 and 3. Item D (4px tall) follows B in track 3, so B has no available space for alignment. Item C spans all tracks. In track 2, only 4px of empty space separates the new gutter below B from the gutter above C, so the row rules are almost back to back.

</style>
<div class="lanes">
  <div class="a">A</div>
  <div class="b">B</div>
  <div class="d"></div>
  <div class="c">C</div>

```

</details>

<img width="415" height="290" alt="Image" src="https://github.com/user-attachments/assets/07624f3c-4dee-44c1-b54c-c50576820620" />

- Pro: Uses existing gutter concepts.
- Con: Row rules that seem to separate empty space. Would probably need to support rule-visibility-items for stacking axis rules as well.
- Con: some complexity as far as special casing that iff a spanner has no available alignment space then it creates gutters below it.

**3. Revisit #14507 and use its proposed model, similar to multicol spanners.**

- https://github.com/w3c/csswg-drafts/issues/14507

Only spanning items split the grid-axis gaps. Each column rule ends at the top of a spanner and starts again at its bottom, as in multicol with `column-span: all`.
Unlike the current behavior, the rules continue through the stacking-axis gutter and touch the spanner edges directly
Rules below spanners work without a new concept.

<img width="618" height="772" alt="Image" src="https://github.com/user-attachments/assets/a0c4e953-a58f-43da-abb6-f83ddd1f11ec" />

- Pro: Consistent with multicol. No new concepts. Also makes the resolution for #14489 (rule-vis items) simple.
- Con: `rule-break: intersection` gives the same result as `rule-break: normal` in grid lanes.
- Con: Can look strange with some spanner scenarios due to the fact that gutters above spanners are disjoint rather than a single gutter that spans the length of the spanner.
- Note that with rule inset authors would still be able to adjust these endpoints

### Proposal

I lean towards option 3 or option 1:
- Option 1 keeps the current endpoint model and we essentially do a special case fix only this case.
- Option 3 I still think conceptually makes the most sense, is consitent with existing spec and the concepts in different layout types.

## Update
After some more discussion, we came up with an almost comprehensive case that has led us to add `option 4` which is the one what we'd like to propose.

## Option 4 **_(Proposal)_**:
1. We keep the current spec behavior that gutters are only placed above items
2. We keep the resolution we made that makes it such that alignment does not shift gutters.
3. The only addition is that for grid axis gutters, in addition to adding segment endpoints where we usually do (start/end of container, intersection and abutment of gutters) we _also_ add segment endpoints anywhere the grid axis gutter collides with any item spanning the gutter, offset by the stacking axis width. See `C1.3, C1.4, C5.4, C6.2`

## @kbabbitt — 2026-10-22

Thanks @jav099 for the detailed diagrams!

One note I'll add from our discussion:

*Why do grid-axis decorations extend into alignment space?* Consider an empty grid-lanes container with decorations. Now add an item spanning 2 tracks. That item is in an [alignment container](https://drafts.csswg.org/css-grid-3/#stacking-self-alignment) covering the full height of the grid-lanes container. If we *didn't* draw decorations in alignment space, the decoration between the tracks spanned by the item would disappear when the item was added. Now add another item in just 1 of the 2 tracks. The decoration between the tracks may or may not reappear depending on the relative positions of the items. Which would be weird.

## @kbabbitt — 2026-10-27

Had a chat with @bfgeek @tabatkins and @fantasai today about this issue. I think we have agreement that: when a spanner is the last item in more than one column, we should paint grid-axis decorations below it *at least* as high up as the bottom of the spanner's alignment space, minus one gutter width.

The question of whether to extend grid-axis decorations into alignment spaces drew conflicting opinions. No matter what we do we're going to end up with a weird result in some cases, and I think it's just a question of which weirdness we'd rather accept.

-----

If decorations *do* extend into alignment space, you get the result depicted above as Option 4:

<img width="1278" height="849" alt="Complex grid-lanes example with gap decorations extending into alignment space" src="https://github.com/user-attachments/assets/e8557bb6-4955-4ce8-9037-89ee74bcf8e3" />

There are two things I would call weird about this rendering: (1) item 10 being align-self: center means that grid-axis decorations jut past the crossing decorations into what looks like 10's personal space; (2) item 14 leaves the same amount of space above and below but only has a decoration above, which looks asymmetrical. (We previously [resolved](https://github.com/w3c/csswg-drafts/issues/14153#issuecomment-5191855003) that decorations are generated only above items, and I still think that's the right call.)

-----

If decorations *do not* extend into alignment space, you solve those problems but create new ones.
It would look approximately like this:

<img width="807" height="1044" alt="Complex grid-lanes example with gap decorations not extending into alignment space" src="https://github.com/user-attachments/assets/77d05e86-47c9-4ab4-8af5-2f30461df91f" />

The problem you create is the one I outlined above: decorations disappear and reappear as items are added to a container. Demo: https://codepen.io/editor/kevinbcmu/pen/01a17e28-04bd-7a3c-9d8e-69c8d21cc5ad
