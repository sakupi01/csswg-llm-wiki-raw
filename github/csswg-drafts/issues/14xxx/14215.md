Images taken by cameras will often, for efficiency, encode the captured image based on the physical orientation of the sensor (first row of the image data reflects the top row of the sensors, or similar), but will indicate via some metadata that the image is *meant* to be viewed at a different orientation (portrait vs landscape, for example). The [`image-orientation` property](https://drafts.csswg.org/css-images-3/#propdef-image-orientation) defines whether images should render in their "original" orientation (first row of pixel data is the "top" of the image) or respect their built-in orientation metadata (or manually control the orientation to one of the 8 possibilities).

Originally, we defined the initial value of 'image-orientation' to be "none", matching implementations at the time, and allowed authors to specify "from-image" to make photos on the web display "correctly", like many desktop photo viewers did. Later, we changed the initial value to "from-image", hoping that it would be safe to do so and give pages the "correct" behavior by default. We left a note (at the end of the spec section) that *if* this proved to be web-compatible, we should try and deprecate/remove 'image-orientation' entirely.

Well, it's been years, and browsers appear to have all switched their initial values without any compat issues. Other APIs, like canvas's `drawImage()`, also respect the orientation metadata by default. Cross-origin images *always* respect orientation metadata *regardless* of the property, as a small privacy issue to avoid accidentally exposing the original orientation of the image (in general, we try to keep cross-origin images to exposing the absolute minimum of info, just sizing/density).

So, shall we go ahead and deprecate the property? It's already marked as "optional to implement" in the spec, this would just be moving it further into an appendix and being more explicit that it doesn't need to be supported. We'd clarify in the image rendering section that orientation metadata is always respected. (Subject to the constraints in <https://drafts.csswg.org/css-images-3/#url-metadata>)
