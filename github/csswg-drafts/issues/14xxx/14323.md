This is a follow-up from https://github.com/w3c/csswg-drafts/issues/14255. The `<select>` element has two possible markup patterns. "Customizable select" adds an extra `button` and optional `selectedcontent` element to represent the duplicated `option` content and allow it to be styled independently. But traditional markup doesn't have these elements, it just contains `option`s.

```
<select>
  <!-- Optional <button><selectedcontent></selectedcontent></button> would go here -->
  <option>Option 1
  <option>Option 2
  <option>Option 3
</select>
```

The problem with the traditional markup is that you cannot style the text directly -- and this means that the select button's content overflows by pushing the picker icon out of the button. (!!) We can style `selectedcontent` with `overflow` and keep the picker-icon inside, but afaict with traditional markup it's not possible. We either need to automatically generate these elements in the DOM, or we need a pseudo-element.

The `::field-text` pseudo element (potentially [renamed](https://github.com/w3c/csswg-drafts/issues/13516) to `:field-content`?) exists to allow the content of an `<input>` to be styled independent of its associated icons etc. Can we reuse it here to wrap the selected option's representation?

Then we can style this text consistently, applying `overflow` and even `text-ellipsis` in both markup patterns.

It also becomes possible to switch from using `margin-inline-start: auto` on the `::picker-icon` to using `flex: 1` on this pseudo-element. (This is less critical for `<select>`, but for `<input>` consider what happens if there's both a "clear" button and a "password reveal" button, for example.)

```
::field-text { overflow: clip; text-overflow: ellipsis; flex: 1; }
```
