The UA stylesheet for `<select>` currently uses `disclosure-open` for the `::picker-icon`. However this kind of large filled triangle tends to be too bold and pointy in comparison to the adjacent text, which has led many design systems, including the demo styles from last week's `<select>` styling discussion, to adopt a chevron design.

The solution in the demo styles, however, is very hacky. (It's using U+2335 COUNTERSINK and adjusting the glyph's vertical position with a negative margin.) We'd prefer the UA stylesheet to use a glyph that doesn't require adjustments. It also doesn't work for `vertical-lr`, because (unlike the `disclosure` triangles) the UA isn't adapting the direction to the writing mode.

@tabatkins and I discussed this during the F2F and our suggestion is to create some new `picker-open` and `picker-closed` list styles that draw the appropriate glyphs for the picker-icon, just like `disclosure-open` and `disclosure-closed` do for `<details>`. (We also think it would be good to clean up the syntax by fixing https://github.com/w3c/csswg-drafts/issues/14003.)

See also earlier discussions in https://github.com/whatwg/html/issues/12516

## @fantasai — 2026-08-13

`disclosure-closed` points inward and `disclosure-open` points down, while `picker-closed` points down and `picker-open` points up. In other words, `disclosure` icons point at the thing to focus on, whereas `picker` icons point at the direction of movement for the picker.

An alternative naming scheme would be to use `picker-up` and `picker-down`, which might be more adaptable to other UIs (such as popovers that preferentially open upward). Or `chevron-up` and `chevron-down` if we want to commit to that look and give it a more general-usage name.

## @fantasai — 2026-08-19

Agenda+ to follow up with names. Options we could consider:
- `picker-open`/`picker-closed` - Adjective form. Syntax matches disclosure keywords, but `picker-closed` matches `disclosure-open`, which might be kinda confusing. 
- `picker-open`/`picker-close` - Verb form. Direction of `picker-open` and `disclosure-open` match, but tense of `close` mismatches.
- `picker-up`/`picker-down` - Direction rotates with writing-mode relative to the line. More adaptable to pickers that preferentially open upwards.
- `chevron-up`/`chevron-down` Same thing, but the name is a) less specific to pickers and b) more specific about the expected shape. Maybe more confusing if it adapts to writing-mode because of that specificity.

My preference would be one of the last two, given the confusingness of the open/closed relationship with the disclosure keywords if we adopt an open/closed naming pattern.

## @Crissov — 2026-08-30

Please consider that some GUIs use two triangles or chevrons pointing in opposite vertical directions. Semantic naming may be more appropriate than visual naming. 

I believe that the UI symbol keywords proposed here, together with `disclosure-open` / `disclosure-closed`, should start a named subset of [simple symbolic predefined counter styles](https://drafts.csswg.org/css-counter-styles/#simple-symbolic), perhaps within css-ui or css-forms. 
Unlike plain single-character strings, they should respect writing direction automatically if applicable. 
They would not need to map to a specific character, because Unicode does not accept arbitrary symbols, and if it does it may specify incompatible directionality. 
They should be usable in `content` directly. #14003 
This predefined set of keywords should eventually cover a lot of what common “symbol fonts” have.
