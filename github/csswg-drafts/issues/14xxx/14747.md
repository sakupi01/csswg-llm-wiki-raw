The page context inherits from the root element (https://drafts.csswg.org/css-page-3/#page-properties) but the spec doesn't say whether the root's zoom applies to lengths in @page.

:root { zoom: 2; }
@page { size: 4in 3in; margin: 0.5in; }

Chrome prints a 4in × 3in page with 1in margins: it zooms every length in @page and margin boxes except size.
Firefox prints 0.5in margins: it zooms none of them.
Safari doesn't currently implement the page context inheritance. Hence when implementing this question was raised.

Since zoom doesn't affect the page size should it affect page margins?
Should padding border and font-size in @page and margin boxes stay zoomed to match how the page looks on screen?

## @mstensho — 2026-11-10

https://drafts.csswg.org/css-page-3/#page-properties

> page-margin boxes inherit from the page context. The page context inherits from the root element.

https://drafts.csswg.org/css-viewport/#zoom-property

> The effective zoom of an element is the product of its computed value of [zoom](https://drafts.csswg.org/css-viewport/#propdef-zoom) and all flat tree ancestors' computed values of zoom.

That doesn't quite answer our question, indeed. Only the way inheritance works is defined. Should `:root` also be seen as an ancestor of the page context (`@page`), and page context be seen as an ancestor of page margin contexts? Any good reasons they *shouldn't*?

This isn't entirely correct: 
> Since zoom doesn't affect the page size should it affect page margins?

Although `zoom` doesn't affect `size` in any implementations, it may actually affect the page size nevertheless, by using `width` and/or `height`. Try this in Chrome:

```css
<style>
  :root {
    zoom: 2;
  }
  @page {
    width: 200px;
    margin: 50px;
  }
</style>
<div style="width:50px; height:50px; background:yellow;">hello</div>
```

I think we should just zoom all the things. Not sure about `size`, since it's not a real property.
