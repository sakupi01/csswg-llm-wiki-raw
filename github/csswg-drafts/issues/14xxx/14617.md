'scroll-transform-audio'
'scroll-audio-timing-function'

**Description:**
As you scroll through a container or website the audio subtly transforms to match the content within a given container or within a given website and scroll-position. It's akin to anchoring the audio "scrubber" to the scrollbar. 

-----
Currently there exists: 
- Various scroll-animations
- As well as Audio for HTML

Proposal would be for a property called `scroll-transform-audio`
Values would be:
`fade`
`fade-duration`
`fade-volume-start`
`fade-volume-end`
`scrollX` 
`scrollY`

1. **fade:** with values of (fade-duration, fade-volume-start) (fade-duration, fade-volume-end). 
Example use case: at the start of the scroll position the audio has fade-volume-start of 25% with fade duration of 2s and fade-volume-end of 50% with fade-duration of 3s. 
Example usage: scroll-transform-audio: fade(2s, 25%, 3s, 50%);

2. **fade-duration:** With values in milliseconds or seconds. Following standard CSS patterns found in other properties (e.g. animation-duration). For usage, fade-duration would define the length of time it would take to gradually complete the fade-volume-start and fade-volume-end.  
Example usage: scroll-transform-audio: fade-duration(200ms);


3. **fade-volume-start:** values in percentages (0%-100%) | alternate values ranging from 0 to 1. For usage, the fade-volume-start defines at what volume the audio starts before it gradually progresses to the [intended volume | user's computer selected volume | user's controlled selected volume on the webpage]. 
Example usage: scroll-transform-audio: fade-volume-start(25%);

4. **fade-volume-end:** values in percentages (0%-100%) | alternate values ranging from 0 to 1. For usage, the fade-volume-end defines at what volume the audio ends.
Example usage: scroll-transform-audio: fade-volume-end(80%);

5. **scrollX:** Has values in percentages (0%-100%) or in pixels. Following CSS standards for x-axis values (e.g. translateX). This determines at which scroll position for the container the audio starts to play.
Example usage: scroll-transform-audio: scrollX(25%);

6. **scrollY:** Has values in percentages (0%-100%) or in pixels. Following CSS standards for y-axis values (e.g. translateY). This determines at which scroll position for the container the audio starts to play. 
Example usage: scroll-transform-audio: scrollX(45%);


Proposal would be for a property called  `scroll-audio-timing-function`
The intention is to indicate how and whether or not the speed of the song is affected by the speed of scrolling the container.  

Values would be:
`scroll-speed-audio`
`play-start-delay`
`scrollStop`
`scrollRewind`

1. **scroll-speed-audio:** With values 'true' and 'false'. Where 'true' states that the speed of the audio will either increase or decrease depending on the speed at which a given container is scrolled. And 'false' states that the speed of the audio will not be affected by how fast someone is scrolling through a container. Example use case: Starting at the start of the scroll container with 0 and reaching speeds of up to 3. Example usage: scroll-audio-timing-function: scroll-speed-audio(true);  

2. **play-start-delay:** where values are set in milliseconds or seconds. Following standard CSS patterns found in properties like 'animation-duration.' Used to set the duration of the amount of time it takes for the audio to begin playing. Use cases include 1) setting a delay while the page is loading and 2) for when the audio-clip is placed at the start of the scroll of the container. 
Alternatively: scrollX | scrollY can be used as the audio clip can be moved anywhere up and down the x-axis | y-axis of the scroll length of the container giving the same effect as starting the audio at a delay.
Example usage: scroll-audio-timing-function: play-start-delay(200ms);

3. **scrollStop:** Has values of 'pause' and 'play'. Example: As you scroll through a container the music plays per parameters defined. When you stop scrolling the music pauses. Then as you scroll it continues to play where it left off per the parameters defined. Once the end of the scroll container has been reached, audio 'pauses.'
Example usage: scroll-audio-timing-function: scrollStop(pause); 

4.  **scrollRewind:** With values of ‘true’ and ‘false’. This would make the audio play in reverse as you scroll in the reverse direction (e.g. down to up or right to left) in a container at audio speeds ranging from 0 to 3 where the song sped up to 3x the speed. The speed would be 
Example usage: scroll-audio-timing-function: scrollRewind(true);



**Audio for 'music' use cases:**
1. marketing site, as you scroll the item reveal out of the case, if scroll fast airpods reveal fast and music speeds up, scroll slow, airpods reveal slow, music slows down
2. animated media, runner speeds up music speeds up content reveals faster as you scroll faster, scroll slow: runner slows down music slows down content reveals slower
3. blogs/text: as you scroll faster audio speeds up, scroll slower audio slows, scroll in reverse audio reverses, scroll pause audio pauses and prompts you to re-listen to the highlighted audio snippet

**Audio for 'sound' use cases:** 
Sound defined as ephemeral-notifications/alerts (e.g. duration, volume), clicks/taps (e.g. clicking/tapping 'like'), pull-to-refresh, screen-reader-cues, etc))

1. Adding an item to a cart, as you scroll up you can see the item being added to the cart and a pleasant ping confirmation sound alerts you of successfully adding the item to the cart. 
2. In a messaging web application as you receive a new live message in an active thread, as you scroll to the bottom of the thread you can hear a pleasant branded sound indicating that you reached the new message. 
3. In a content heavy webpage such as blogs, scrolling to affect the speed of which the audio-clip assigned to the blog content plays. 


**Accessibility Research:**
Automatic Audio: If any audio on a webpage plays automatically for more than 3 seconds, a mechanism must be provided to pause or stop the audio, or to control the volume independently from the overall system volume. [1]
Background Sound Levels: Best practices recommend keeping background sounds at least 20 dB lower than foreground narration or dialogue, or providing a way to turn background sounds off. [1]

**Things to consider:**
1. How long it takes for a song to play or audio to play and whether the audio can be played for the whole scroll duration. This is where 1) scrollStop = a pause would be used for defining the end of the audio at the stop/end of the scroll 2) the 'loop' parameters from html could be used 3) placing an additional audio-clip along the x-axis | y-axis of the scroll container. 
2. Latency/performance/general loading and connectivity. This is handled with play-start-delay and scrollStop. Combined with indicators can be used to show error in loading audio. 
3. Where scrolling is broken then audio 'pauses'.
4. The indicator to trigger usage of the audio must be a speaker (rather than a play button) and it must be set by default to mute. This would have to be so because a 'play' button would make the user think they were playing a 'video clip' or an 'audio-clip' unaffected by scroll position rather than enjoying 'audio' that is affected while you scroll. Put simply, the scrolling of the container affects the 'audio.' Ergo having an indicator that sets expectations of something different (something breaking current audio conventions) occurring with the audio would be necessary. The speaker indicator would need to be triggered by the user in order to align with browser autoplay policies (e.g., Chrome/Safari Autoplay Policy requiring user gesture before unmuting).

**Other attributes considered, but not chosen:**
1. **speed-x-axis | speed-y-axis:** with values fast-normal, normal-fast, slow-fast, fast-slow, normal-slow, slow-normal. These values indicate the starting and stopping speeds so as you scroll vertically up or down you can change the speed. Example: you can start with double the speed and scroll to normal speed. 
_Rationale: indicates that the speed's x-axis | y-axis is being effected rather than the speed is effected by scrolling along the x-axis | y-axis. Speed of audio does not have a standard cartesian planar x-axis | y-axis._ 

2. **volume-x-axis | volume-y-axis:** with values of crescendo-decrescendo, crescendo, decrescendo, decrescendo-crescendo. where crescendo increases the volume from 0 to 1, decrescendo decreases the volume from 1 to 0. 
_Rationale: Just as with speed, volume does not have a standard cartesian planar x-axis | y-axis. The desired outcome is to make the volume be affected by the scroll position of the container rather than the volume's x-axis | y-axis position being affected._ 

3. **volume:** values in percentages (0%-100%) or alternate values ranging from 0 to 1. 
_Rationale: volume is set at both the system level of a user's computer and at the webpage level. Ultimately the goal is to effect the fading of the volume rather than the volume set for the entire play-state of the audio._

4. **volume-start | volume-end:** values in percentages (0%-100%) or alternate values ranging from 0 to 1. 
_Rationale: for the same reasons as volume. Ultimately the goal is to effect the fading of the volume rather than just changing the starting state of the volume. The goal is to also indicate 'fading' rather than the ambiguity of 'volume-start' which could imply effecting when the volume starts to be unmuted or muted._ 

5. **volume-max | volume-min:** where values are set from 0% through to 100%. For usage: you can state the maximum volume is 50% or any percentage. Following accessibility standards requiring that volume should not reach a greater volume than [20dB]. 
_Rationale: As it follows that volume | volume-start | volume-end will not be used then volume-max | volume-min will be tabled. Instead fade-volume will be used. Setting the max and min volumes might be redundant as fade-volume-start and fade-volume-end can be set with values in percentages. In HTML, the <audio> and <video> elements do not have min and max volume attributes because the volume property is strictly defined as a linear scale from 0.0 (silent) to 1.0 (loudest).
Because 0.0 and 1.0 are already the permanent, universal minimum and maximum bounds for the media element, adding separate attributes to change those limits would be redundant._

6. **duration:** with values in milliseconds or seconds. Following standard CSS patterns found in other properties. 
_Rationale: Instead 'scroll-audio-timing-function' would be used to effect greater aspects of the audio. And scrollStop would be used to 'pause' the audio at different areas of the scroll position of the container. This can affect the duration of the audio._

7. **speed-range:** with values that start from 0 to 3.
 _Rationale: when using scroll-audio-timing-function speed of audio should be affected by speed of scrolling._

8. **speed-start:** With values that start from 0 to 3. Where 0 is the natural speed of the song. And where 3 is the song sped up to 3x the speed. 
_Rationale: when using scroll-audio-timing-function speed of audio should be affected by speed of scrolling. Defining a speed-start would negate the intent of the scroll-audio-timing-function._

9. **speed-end:** With values that start from 0 to 3. Where 1 is the natural speed of the song. And where 3 is the song sped up to 3x the speed.
_Rationale: when using scroll-audio-timing-function speed of audio should be affected by speed of scrolling. Defining a speed-start would negate the intent of the scroll-audio-timing-function._


**General other thoughts:**
If one were to consider a scrubber analogous to a scrollbar found on a video or audio clip.
This is distinct and different from a scrubber due to the natural state of a scrubber auto "scrolling" through the video clip once a button is pressed. In other words, the video/audio "plays continuously" once a button is triggered to play the "video/audio" done-so without the user needing to move the scrubber and unencumbered by any scroll positions or scroll pauses.
 In contrast, for the use case of scrolling through a website, few users would enjoy auto-scrolling through a container as it would be startling. In addition to that, a container can have layers to manipulate and content to manipulate from a developer stand-point. From a developer stand-point, in contrast, video content is created and generated by someone else and the video-player is then just placed on the page by the developer.
