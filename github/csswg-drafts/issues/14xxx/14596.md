Using CSS instead of the SVG `<use>` element to display icons on web pages offers numerous advantages, as @LeaVerou's explains in detail in her [article: The best way to use icons in Web UIs](https://lea.verou.me/blog/2026/icons/).

However, for compatibility reasons, the article recommends using the `mask` property. `border-shape` definitely has more potential and advantages in this regard.

But currently, `border-shape: path()` cannot adapt to the container’s size (see the example below), so a solution needs to be explored.

## Why Not Use `shape()`?

Whether it’s vector design software or mainstream icon libraries, SVG is used by default, and converting to `shape()` requires more effort. In a sense, this hinders the widespread adoption of `border-shape`. Furthermore, in scenarios where animation isn’t needed, `path()` is sufficient.

@noamr also said at https://github.com/w3c/csswg-drafts/issues/10647#issuecomment-2618126311:
> btw I think what would make path useful is not overloading it to be like shape, but to give it a viewBox argument and allow it to scale to the reference box. I find that having non-scalable SVG is not the most useful, but it's less about the fact that it's an unmodified SVG string, which is useful for SVG interop.

## Proposal

Extend the `path()` function to allow authors to explicitly specify the scaling method and alignment, and to provide the viewBox of the SVG source canvas when necessary. Properties such as `border-shape` and `clip-path` can all take advantage of this capability.

### Scope and Design Principles

1. **Explicitly enabled.** Does not change the behavior of existing `path(“…”)` and `path(evenodd, “…”)`.
2. **Shared across properties.** Defined at the CSS Shapes layer; the consuming property continues to determine the reference box and geometric usage.
3. **Keep it simple for straightforward scenarios.** Providing `contain`, `cover`, or `fill` individually is sufficient for adaptation.
4. **The original SVG `viewBox` can be preserved.** Through the optional `view-box()` function, paths can retain the white space from the original design (icon design scenarios require consistent bleed areas), ensuring a unified design style.

### Syntax

`<‘fill-rule’>`, `<position>`, `<string>`, and `<number>` retain their existing CSS types. `<path-view-box()>` is a new sub-function type; in the first release, it is used only with `path()` and is not included in `<basic-shape>`.

```
<path()> = path(
  [ <path-view-box()> , ]?
  [ <path-fitting> , ]?
  [ <'fill-rule'> , ]?
  <string>
)

<path-view-box()> = view-box(
  <number>{2}
  <number [0,∞]>{2}
)

<path-fitting> = <path-fit> [ at <position> ]?

<path-fit> = fill | contain | cover
```

- **`fill`: Scale horizontally and vertically separately.** Adjusts the width and height of the source rectangle to match the width and height of the reference box, respectively. This is equivalent to adding `preserveAspectRatio=“none”` to the original SVG. When the aspect ratios differ, the path undergoes non-proportional distortion. This option is suitable for decorative outlines and border shapes that can be stretched, but is not suitable for icons that require aspect ratio preservation.

- **`contain`: Preserves the aspect ratio and fully contains the source rectangle.** Uses a uniform scaling factor to enlarge the source rectangle as much as possible, provided neither its width nor height exceeds the reference box. When the aspect ratios differ, extra space will appear within the reference box, and its placement is determined by `at <position>`. This is typically suitable for displaying icons in their entirety. Corresponds to `mask-size: contain`.

- **`cover`: Preserves aspect ratio and ensures the source rectangle covers the reference box.** It uses a uniform scaling factor to shrink the source rectangle as much as possible, provided that neither its width nor height is less than the reference box. When the aspect ratios differ, the adapted source rectangle will extend beyond the reference box in one direction, with the position still controlled by `at <position>`. This is suitable for scenarios where you want to cover the target area while allowing part of the source canvas to extend beyond it. Corresponds to `mask-size: cover`.

### Valid Examples

```css

path(contain, "M4 4H20V20H4Z")
path(fill, "M4 4H20V20H4Z")
path(cover at right bottom, "M4 4H20V20H4Z")

/* Specify `view-box`; if `fitting` is omitted, the default is `contain at center`. */
path(view-box(0 0 24 24), "M4 4H20V20H4Z")

/* Use with other keywords */
path(contain, evenodd, "M0 0H24V24H0Z M4 4H20V20H4Z")
path(view-box(0 0 16 16), evenodd, "M0 0H24V24H0Z M4 4H20V20H4Z")
path(view-box(0 0 1024 1024), fill, evenodd, "M0 0H24V24H0Z M4 4H20V20H4Z")
```
