### Context

The `rule-visibility-items` properties control whether gap decoration segments are painted next to empty areas.

Grid lanes containers can have empty tracks, but their behavior is not currently defined.

### Proposal

Have `rule-visibility-items` affect  gap decorations in grid lanes in cases with empty tracks. 

- `rule-visibility-items` applies only to grid-axis decorations.
- Each adjacent grid track is treated as one adjacent area.
- A track is occupied if it contains at least one item, including an item that spans that track.
- All segments in a grid-axis gutter use the same adjacent-track rule
- The property has no effect on stacking-axis decorations.
- `normal` behaves as `all`, matching grid containers.


This follows precedent of rule-visibility-items in multicol discussed in https://github.com/w3c/csswg-drafts/issues/13477 where we state that "Column rules are only drawn between two columns that both have content.".

## @jav099 — 2026-10-12

We resolved that `rule-visibility-items` applies per segment in grid lanes. However, I think we still need to define what counts as empty space next to a segment. This is pretty simple in Grid/Multicol, but not as clear in Grid lanes.

In grid lanes, self-alignment can move an item within the empty space in its track. This poses a question of whether segments that happen to be in that space are affected by the seeming emptiness next to it, even though an item _could_ move there with alignment.

<img width="921" height="499" alt="Image" src="https://github.com/user-attachments/assets/068d42d7-76e8-41cd-aff2-9ee4b2400725" />

In this example, item 2 spans both lanes and item 3 in lane 1 is short. With `rule-visibility-items: between`:

- `align-self: start`: segment B is hidden.
- `align-self: end`: segment A is hidden.

**Proposal:** For grid lanes specifically, we consider space as empty only if no item can align into it. Examples of this could be:
1. empty track
2. empty space below or above a spanner

## @alisonmaher — 2026-10-12

> For grid lanes specifically, we consider space as empty only if no item can align into it

I agree with this proposal - I don't think in the second case we can say that 2 is empty on one side because the alignment candidate can be considered as taking up that entire space. And because of this, I don't think we can consider any opening with an alignment candidate as being empty (even if they are start aligned) because we consider that full space as available to that alignment candidate.

So +1, although I'd rephrase to something like "For grid lanes specifically, we consider space as empty only if that opening is not occupied by an alignment candidate".
