The color-mix() serialization rules (https://drafts.csswg.org/css-color-5/#serial-color-mix) specify that percentages should only be omitted when all "effective percentages" are known and equal to 100% / number of components:

> If all [effective percentage](https://drafts.csswg.org/css-color-5/#effective-percentage)s are known and equal to 100% / N, no percentages are serialized..."

This covers test cases like:

```
test_valid_value(`color`, `color-mix(in srgb, red 50%, blue 50%)`, `color-mix(in srgb, red, blue)`) // both 50%
test_valid_value(`color`, `color-mix(in srgb, red 50%, blue)`, `color-mix(in srgb, red, blue)`) // only p1 specified, is 50%
```

While omitting percentages when balanced and the effective percentages sum to less than 100 (e.g. `color-mix(in srgb, red 20%, blue 20%)`) would not be valid (as it would mean the "leftover" component was lost), but I think if they are balanced and they sum to greater than 100 (e.g. `color-mix(in srgb, red 75%, blue 75%)`) I think should be fine to omit.

Proposal:

Change the above the quoted text to something like:

> If all [effective percentage](https://drafts.csswg.org/css-color-5/#effective-percentage)s are known, equal to each other, and greater than or equal to  100% / N, no percentages are serialized..."
