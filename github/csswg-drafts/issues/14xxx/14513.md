https://drafts.csswg.org/css-position-4/#paint-a-stacking-context lets UAs paint outlines either in-band or out-of-band:

- In-band: painted along each box during step 8, so later in-flow content in that same step can cover them.
- Out-of-band: painted at step 11, at the end of the stacking context, so nothing in that stacking context can cover them.

Gecko, Blink, and WebKit do neither. They collect outlines separately, then paint them after in-flow content and negative z-index descendants, but before positioned descendants with `z-index: auto` or higher.

Gecko's display-list merge calls this "7.5: outlines", between content and non-negative z-index children:
https://searchfox.org/mozilla-central/rev/b2433a832c250c55255e0ee37d05192d04f20427/layout/painting/nsDisplayList.cpp#1334

Blink paints `kSelfOutlineOnly` after the foreground phases and before `kNormalFlowAndPositiveZOrderChildren`.

Two testcases:

```html
<!DOCTYPE html>
<style>
.box {
  width: 100px;
  height: 100px;
  outline: 20px solid red;
  outline-offset: -30px;
}
.child {
  position: absolute;
  top: 0;
  left: 0;
  width: 200px;
  height: 200px;
  background: blue;
}
</style>
<div class="box"><div class="child"></div></div>
```

Spec out-of-band would paint the outline on top of the abspos child. Engines paint the child on top.

```html
<!DOCTYPE html>
<style>
.parent {
  position: relative;
  z-index: 0;
  width: 100px;
  height: 40px;
  outline: 15px solid red;
}
.text {
  margin-top: -20px;
  font: 40px/1 sans-serif;
  color: blue;
}
</style>
<div class="parent"><div class="text">X</div></div>
```

Spec in-band would paint the parent's outline during step 8 before the child's line boxes, so the X would cover the outline. Engines paint the outline on top of the X.

Should the spec describe this third order instead of (or in addition to) in-band / out-of-band?
