As it currently stands, an author needs to set `overscroll-container-type` on the [overscroll container](https://drafts.csswg.org/css-overscroll-2/#overscroll-containers).

```
overscroll-container-type: auto | push | overlay | none;
```

This does not allow mixing `push` and `overlay` [overscroll areas](https://drafts.csswg.org/css-overscroll-2/#overscroll-areas) in one single container. For example, I can imagine a situation where one has an `#app` with both a `push` `#navbar` and also an `overlay` `#bottomsheet`. The current way to solve this is for the author to nest multiple overscrollcontainers, which seems unfortunate.

I think that if we were to split out `overscroll-container-type: none | auto` (to go on the overscroll container) and `overscroll-area-behavior: push | overlay | none` (to go on the overscroll area), then the example I gave could work using just 1 overscrollcontainer.

```
overscroll-container-type: none | auto;
overscroll-area-behavior: push | overlay | none;
```

Applied to the example I mentioned:

```css
#app {
  overscroll-container: auto; /* Already set by the UA stylesheet on `[overscrollcontainer]` */
}

#app #navbar {
  overscroll-area-behavior: push;
}

#app #bottomsheet {
  overscroll-area-behavior: overlay;
}
```

The `none` for `overscroll-area-behavior` is added to selectively disable the `#navbar` being an overscroll area while keeping the `#bottomsheet` as an `overlay` overscroll area on larger screen layouts:

```css
@media (min-width: 900px) {
  #app {
    display: grid;
    grid-template-columns: 250px auto;
  }
  #app #navbar {
    overscroll-area-behavior: none;
  }
}
```
