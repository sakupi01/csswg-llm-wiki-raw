We recently [resolved](https://github.com/w3c/csswg-drafts/issues/14192#issuecomment-5202877510) that `accent-color: AccentColor` resolves at compute time to parent's `accent-color`. What should `accent-color: AccentColor` compute to, if the parent's `accent-color` is `auto`?

One way is to compute `accent-color: AccentColor` to `accent-color: auto`, which means the element will use the system accent color. But what about when `AccentColor` is used in a relative color, say `accent-color: rgb(from AccentColor 200 g b / alpha)`? Computing it to `accent-color: rgb(from auto 200 g b / alpha)` wouldn't make sense.

Another solution would be: if resolving `accent-color: AccentColor`, and parent's `accent-color` is `auto`, treat the parent's accent color as  `AccentColor`, which SHOULD be a fixed color (ignoring its special behavior of taking `accent-color`) ([discussion](https://github.com/w3c/csswg-drafts/issues/10372#issuecomment-5202692386)). But in WebKit at least, `accent-color: auto` directs an element to use WebKit's system accent color, which _could_ be different from `AccentColor`. So there's a behavioral mismatch where in one context, `accent-color: auto` means the system accent color, and in other context, `accent-color: auto` means `AccentColor`.

## @tuankiet65 — 2026-08-17

> the system AccentColor value computes to a value at computed-value time right

Yes, but we [resolved here](https://github.com/w3c/csswg-drafts/issues/10372#issuecomment-5202692386) that system `AccentColor` returns a fixed color, which isn't dependent on the actual system accent color. While `accent-color: auto` will use the system accent color.

For example: WebKit resolves system `AccentColor` to `#007aff`, but the system accent color can be changed by the user. Let's say the user changes it to `#ff0000`, then `accent-color: auto` will use `#ff0000`, but system `AccentColor` still resolves to `#007aff`

I disagree, that is a bug :)

> For example: WebKit resolves system `AccentColor` to `#007aff`, but the system accent color can be changed by the user. Let's say the user changes it to `#ff0000`, then `accent-color: auto` will use `#ff0000`, but system `AccentColor` still resolves to `#007aff`

If you want to resolve to a fixed `AccentColor`, you presumably also should style your forms with that same `AccentColor`. We did resolve earlier on those two things being consistent.

E.g., on Windows Firefox spoofs the accent color to blue. We also paint our form controls blue, not with the system accent color.
