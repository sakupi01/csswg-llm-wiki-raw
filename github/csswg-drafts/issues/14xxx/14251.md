Disabled controls should indicate that they are unusable. Proposed to add:

```
:is(input, textarea, select, button):disabled { cursor: not-allowed; }
```

Also `<select>` and `<button>` should indicate they are clickable as a unit, not selectable as text. Proposed to add:

```
select, button { cursor: default; }
```

This might be worth doing for `auto` appearance as well.

## @stubbornella — 2026-09-09

In a design system code analysis I completed, 27 of the 33 systems that specify a cursor use pointer — 82%. The UA baseline is the minority position, and design systems disagree with it. 

I thought perhaps it would relate to using a native vs js select element, but it doesn't seem to. Bootstrap and Salesforce style a native <select> and keep default. Twilio Paste, Zendesk Garden, and USWDS style a native <select> and explicitly override to pointer. Paste's source even names the choice — cursor: "pointer" set deliberately on the native element. Atlassian overrides the other direction, forcing pointer over react-select's default. But either way, most systems choose pointer.

The trigger on option rows always matches the overall select in the data I pulled, but I have data on only 9 systems for that, so it is a weaker claim. That said, I can't really see an obvious reason for making them different.
