### Background
When a document experiences overscroll on the viewport (like on macOS) and when using `scrollbar-color: <color> transparent` (transparent scrollbar track color). The exposed background is the color of the viewport (html/body background). However in case of iframes, the exact behavior is unspecified and inconsistent.

### Current behavior
In Blink and Webkit, the exposed background is determined by the parent document <iframe> background-color.

While in Gecko, the exposed background is determined by the child iframe document viewport/html background-color.

This can be tested with the following demo: https://jeurissen.co/lab/iframe-overscroll-scrollbar-track-background/
<details>
<summary>Click to view the HTML source-code</summary>

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>iframe-overscroll-scrollbar-track-background</title>
  <style>
    body {
      margin: 0;
      background: blue;
    }

    iframe {
      position: absolute;
      left: 0;
      bottom: 0;
      right: 0;
      top: 0;
      height: calc(100vh - 100px);
      width: calc(100vw - 100px);
      box-sizing: border-box;
      margin: auto;
      background: cyan;
    }
  </style>
</head>
<body>
  <iframe srcdoc="
    <!DOCTYPE html>
      <html>
      <head>
      <meta charset='utf-8'>
      <meta name='viewport' content='width=device-width, initial-scale=1.0'>
      <style>
        html {
            background-color: orange;
            scrollbar-color: purple transparent;
            font-family: sans-serif;
        }

        div {
            min-height: 200vh;
            background: linear-gradient(rgba(255,255,255,0.2), rgba(0,0,0,0.3));
        }
      </style>
      </head>
      <body>
        <div>If the track color is cyan, it uses the host document background color of the iframe element (Chrome and Safari). If the track is Orange, it uses the html background of the child document (Firefox).</div>
      </body>
    </html>
  "></iframe>
</body>
</html>
```

</details>

### Ways forward
As end-user being able to control the overscroll and scrollbar track colors from the iframe seems highly preferred (current Firefox behavior).
