I'd like people to consider new value for CSS `position` property - parent :
```
child { 
  position:  parent;
  bottom: 0;
  right: 0;
} 
```
It works as if these two rules are applied:

```
parent { position: relative; }
parent > child { 
  position:  absolute;
  bottom: 0;
  right: 0;
} 
```
But 

1. it is just only one rule;
2. without side effects of position: relative; on parent ;

One of examples where this would be beneficial - `span.badge { position: parent; }` :
```
<button>
     <img src=icon> 
     Some text
     <span class=badge>42</span>
</button>
```
Real life [example](https://www.beercss.com/#badges)

```html
<div class="anchoringparent">

    <div class="outsideelement">Positioned based on &lt;body&gt;</div>

```

```css
.anchoringparent {
    width: 250px;
    height: 200px;
    background: red;
    anchor-scope: --parent;
    anchor-name: --parent;

.anchoredelement {
    background-color: blue;
    width: 50px;
    height: 50px;
    position: absolute;
    position-anchor: --parent;

    height: 50px;
    position: absolute;
    left: 275px;
    top: 50px;
}
```

## @c-smile — 2026-07-26

> It's not clear what exactly you are trying to avoid.

`position: relative` creates a new [stacking context](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Positioned_layout/Stacking_context) on the parent which may not be desirable if other children of the parent need to use other forms of positioning with e.g. offset from grand-parent or the like.
