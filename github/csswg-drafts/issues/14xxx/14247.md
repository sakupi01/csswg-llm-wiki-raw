```html
<img src="icon.svg#:~:param(--color,green)">
<img src="icon.svg#:~:param(--color,blue)">
```
Should these be two independent instances of the resource, or one instance shared by both references?

<!-- comment id=5164520381 author=tabatkins created=2026-08-03T09:19:58Z url=https://github.com/w3c/csswg-drafts/issues/14247#issuecomment-5164520381 -->

## @nullhook — 2026-08-22

Seems like both engines (WebKit and Blink) treat one resource (`icon.svg`) as a single instance shared by all references (img tags). I think treating each reference as its own instance would change existing observable behavior.

I'd also like to bring up the `env()` resolution here. The spec says link parameters establish "global custom environment variables for the resource." Under a shared instance, what does "global" mean here? How should the `env` resolution work in this scenario?

## @dholbert — 2026-09-09

My intuition here is that they should **not** be different instances (or at least, we shouldn't require them at a spec level to be different instances).

The value can already change dynamically, and the browser has to account for that, presumably without restarting animations on each change.  So if two images happen to start out with different param values (as in the original comment here), that's not really any different from starting out with the same param value (where they'd presumably share the same "instance") and then one of them changing its param value on hover or something.

I'm thinking about the following (untested, might have bugs)

```html
<img src="icon.svg">
<img src="icon.svg">
```
```css
img {
  link-parameters: param(--color, green);
}
img:hover {
  link-parameters: param(--color, red);
}
```

Those images presumably would share the same "instance" (which from a user-facing perspective means their animations are synchronized).  When the user hovers one of them, the link parameter will change *just for that one*, and the browser will have to account for that in whatever way makes sense (whether by "sharding" the image in some way, or just dynamically modifying it when it's time to paint the image).

That's not really any different from the scenario in the original comment here.
