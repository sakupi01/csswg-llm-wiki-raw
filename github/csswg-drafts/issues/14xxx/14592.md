The Serialization section's table of token pairs that need a comment between them does not cover two sequences:

1. An `<ident-token>` with the value `--` followed by a `<delim-token>` `>`. Serialized as `-->`, this tokenizes as a `<CDC-token>`, because "consume a token" checks for `->` before it checks whether the input starts an ident sequence.
2. `<delim-token>` `<`, `<delim-token>` `!`, followed by a token that starts with `--` (an ident or a CDC). Serialized as `<!--…`, this tokenizes as a `<CDO-token>`.

Both sequences come from the tokenizer itself (`--/**/>` and `<!/**/--x`), so serializing by the table alone does not round-trip. #6874 fixed the cases where a CDC *follows* a token; these are the cases where tokens join *into* a CDC or CDO.

Chrome 152 and 155 (and Edge 155) show both with the method of `css/css-syntax/serialize-consecutive-tokens.html`: `--t1: --; --t2: >; --r: var(--t1)var(--t2)` computes to `-->`, and `--a: <; --c: --x; --r: [var(--a)!var(--c)]` computes to `[<!--x]`, while `foo` and `-->` correctly give `foo/**/-->`. css-tree 3.1.0's generator writes `-->` and `<!--x` for the same token lists, and its tokenizer reads them back as CDC, and as CDO followed by `x`. Servo's `cssparser` classifies `>`, `<` and `!` as needing no separator, so Firefox likely does the same (not run).

Possible fix: mark (ident, `>`) and (`<`, `!`) in the table, and add both to the test.

Found while proving the round trip for a token writer in Lean.
