Is the URL fragment use-case designed for specific contexts?

Consider the following, the hardcoded value makes sense as the value lives in a URL.

`<img src="icon.svg#:~:param(--color, green)"></div>`

What if we replace it with `var()`, is this valid?

`<img src="icon.svg#:~:param(--color,var(--brand))">`

Here's another usage:

`<div style="--brand: blue"> <img src="icon.svg#:~:param(--color,var(--brand))"></div>`

<!-- comment id=5127962949 author=Crissov created=2026-07-30T07:32:45Z url=https://github.com/w3c/csswg-drafts/issues/14238#issuecomment-5127962949 -->
## @Crissov — 2026-07-30

Would you expect `<img src="var(--foo)" style="--foo: icon.svg">` to work? CSS is not evaluated in random attribute values. 
You would need to use the `style` attribute and the [property parameter assignment](https://drafts.csswg.org/css-link-params/#link-param-prop) for that:

~~~~ html
<div style="--brand: blue">
 <img src="icon.svg" style="link-parameters: param(--color, var(--brand))">
</div>
~~~~

By the way, I’m not convinced it is really a wise design choice to let this property apply to resources embedded by both, the host language and CSS itself. 

<!-- comment id=5133587704 author=tabatkins created=2026-07-30T16:32:48Z url=https://github.com/w3c/csswg-drafts/issues/14238#issuecomment-5133587704 -->
## @tabatkins — 2026-07-30

@Crissov is right - the URL does not parse any part of itself as CSS (just as a url param) and definitely doesn't do any CSS processing. It'll pass the `var()` tokens directly into the img and resolve it *over there*, with the custom env() resolution rules. (Which, uh, aren't well-defined right now.)
