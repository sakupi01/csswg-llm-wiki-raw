Having followed cross-reference from HTML to https://drafts.csswg.org/css-position-4/#process-top-layer-removals, I've ended up feeling confused, I think due to lack of introductory material.

https://drafts.csswg.org/css-position-4/#top-layer jumps straight into defining what "top layer" is — but I think it would benefit from some introductory text explaining more of the _why_.

The existing note, after the definition, says:

> This ensures that things like popovers can be displayed reliably, regardless of what their ancestor elements might be doing.

However, it seems to originate in (the still open?) https://github.com/w3c/csswg-drafts/issues/4998 which is about fullscreen in origin. I think directly mentioning fullscreen might be an even more apparent case — where _only_ the fullscreen content is shown, even if that is only a single element — and spelling that out directly would be clearer still.

Mentioning "popover" makes me assume it's meant to be used for cases where the other layers _are_ still rendered, but are just greyed out or similar in the background; I would presume that is a very different case to fullscreen?

I'd also favour putting something in way of an introduction _before_ the first normative statement, because defining "top layer" doesn't really help explain what this is or why it is where it is.

The `overlay` property almost feels more surprising/confusing, where the spec says in a note:

> overlay is a somewhat unusual property, as it is only set by the user agent, and can’t be set by authors at all.

But it never explains _why_ that is the case, which seems very notable given it is, as far as I know, without precedent.

## @tabatkins — 2026-07-16

The existing spec has additional text before the bit you quoted, which explains the motivation:

> This special rendering behavior ensures that elements in the top layer cannot be clipped by anything in the document, or obscured by anything except elements later in the top layer.

That's precisely the reasoning you seem to be looking for, right? You want to display something, but an ancestor might be scrollable or have a clip or transform or what-have-you, and promoting to the top layer ensures you escape all of that and are *definitely* visible.

> The overlay property almost feels more surprising/confusing, where the spec says in a note:

The explanation is just a synthesis of the *next* several notes, about *what you use overlay for* (transitioning it, similar to 'visibility'), why you can't set it (it's a UA !important rule), and why the UA can cancel transitions for it (to prevent abuse keeping things in the top layer).

I assume that your issue is that the three notes don't synthesize together sufficiently to provide an understandable explanation?
