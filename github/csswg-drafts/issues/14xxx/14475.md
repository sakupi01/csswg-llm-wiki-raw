`@keyframes` forbids empty string name, but it seems that in  Chrome/Firefox/Safari, I can set them to empty. This is an example in Firefox:

```
> css = document.styleSheets[0].cssRules[0]
< CSSKeyframesRule { 0: CSSKeyframeRule, 1: CSSKeyframeRule, 2: CSSKeyframeRule, name: "foo", cssRules: CSSRuleList(3), length: 3, type: 7, cssText: "@keyframes foo {\n0% { top: 0px; }\n50% { top: 100px; }\n0% { top: 50px; }\n}", parentRule: null, parentStyleSheet: CSSStyleSheet  }

> css.name = ""
< ""

> css
< CSSKeyframesRule { 0: CSSKeyframeRule, 1: CSSKeyframeRule, 2: CSSKeyframeRule, name: "", cssRules: CSSRuleList(3), length: 3, type: 7, cssText: "@keyframes none {\n0% { top: 0px; }\n50% { top: 100px; }\n0% { top: 50px; }\n}", parentRule: null, parentStyleSheet: CSSStyleSheet  }
```

The spec does say that `@keyframes` forbids empty string name, but doesn't say what should happen if `CSSKeyframesRule.name` is set to empty string. Maybe we should throw on that?

On a sidenote, the spec also doesn't specify how the string being set to `CSSKeyframesRule.name` should be handled. From [this WPT test](https://wpt.fyi/results/css/cssom/CSSKeyframesRule.html?label=master&label=experimental&aligned), it seems that when a string is set, the string is first treated as an identifier, and if it's not an allowed identifier, then it's treated as string. This is important for serialization, as identifier name is serialized without `"`, but string name is.
