Using scroll-driven animations in conjunction with a `sticky` positioned layout is quite common, especially in "scrolltelling". It's often desired to tie the start of a range to the scroll position when an element becomes "stuck", and tie the end of the range to the position when it becomes "unstuck".

This is why we specifically added a note in the spec:

> Note: For [sticky-positioned boxes](https://drafts.csswg.org/css-position-3/#sticky-position) the 0% and 100% progress conditions can sometimes be satisfied by a range of scroll positions rather than just one. Each range therefore indicates whether to use the earliest or latest qualifying position.

While this currently work fine, it still requires authors to manage tying layout and range offsets together.
It would be a significant improvement to the interface if authors could simply write:

```css
.animated {
  animation-range: stuck;
}
```

And have that range automatically watch the scroll range during which the timeline subject is "stuck", exactly [like we exposed for container queries scroll-state](https://drafts.csswg.org/css-conditional-5/#stuck).

This should make a lot of cases both less error-prone + allowing much better ergonomics.

## @flackr — 2026-08-04

Reading the minutes there's two things I'm not clear on.

What is the behavior is if the element has `top: 0; bottom: 0;`. Such an element could stick to the top in 0-100, and to the bottom in 900-1000. The container state stuck is only active when it is actually stuck at the bottom or the top (e.g. 0-100 or 900-1000) but not the middle segment where it is not stuck (100-900). Presumably this new range is active from when the element is first stuck to when it is last stuck, i.e. 0-1000? Then I suppose we could introduce additional ranges like stuck-start and stuck-end to target these separately?

What happens if the element isn't sticky or doesn't have sticky constraints in the observed axis? Presumably we would want the animation to not be active but I'm not sure if we have a way to do this from the range.

Yes, I mentioned this when presenting, maybe it was dropped from the scribing.

> What happens if the element isn't sticky or doesn't have sticky constraints in the observed axis? Presumably we would want the animation to not be active but I'm not sure if we have a way to do this from the range.

Right, so not activating based on range isn't something we currently have, only from the timeline. Or, would it be possible to put the animation in the "before" phase? It's like being outside of `contain` before you entered it. Of course, if you have a `fill: backwards/both` that will apply the effect.
