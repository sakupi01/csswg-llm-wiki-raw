In https://github.com/w3c/csswg-drafts/issues/5675 we resolved to add new grid-lanes values to `reading-flow` for improved a11y support when navigating items in the track-axis order, as well as reading items in the flow-axis order.

However, we didn't land on names for these new values. Opening this issue to bikeshed naming.

Below are some initial ideas, but I would love to gather ideas from a broader audience:

1. Lane axis name ideas

`reading-flow: grid-lanes-direction`
`reading-flow: grid-lanes-track-direction`
`reading-flow: grid-lanes`
`reading-flow: grid-lanes-per-track`
`reading-flow: grid-lanes-along-track`
`reading-flow: grid-lanes-track-axis`

2. Flow axis name ideas

`reading-flow: grid-lanes-cross-direction`
`reading-flow: grid-lanes-flow-direction`
`reading-flow: grid-lanes-flow`
`reading-flow: grid-lanes-across-track`
`reading-flow: grid-lanes-flow-axis`

I assume we want to prefix these values with `grid-lanes-*` based on precedence with other display types already supported, but we could consider shorter forms if desireable like `reading-flow: per-lane` and `reading-flow: cross-lane`.

## @celestepan — 2026-10-05

For the case of reading down each individual track in the stacking-axis (at the moment, using `grid-column` when tracks are in the column direction), if reversed placement is present, we may want to have the option to read in the opposite direction, so from the last column and reading up that column.

<!-- comment id=6518625468 author=rachelandrew created=2026-10-30T08:36:48Z url=https://github.com/w3c/csswg-drafts/issues/14290#issuecomment-6518625468 -->
## @rachelandrew — 2026-10-30

I think I prefer something like `grid-lanes-flow-direction` and `grid-lanes-track-direction`. In the typical "masonry/pintrest" type layout the former would follow the layout of items left to right then move to the next row(ish) of items. The latter would move top to bottom (as if the items were laid out with multicol. People seem to get confused with axis and cross-axis type terminology when the axes can change, and I think when people consider this type of layout they are thinking about how their items flow into the layout.

<!-- comment id=6518905131 author=rachelandrew created=2026-10-30T08:54:19Z url=https://github.com/w3c/csswg-drafts/issues/14290#issuecomment-6518905131 -->
## @rachelandrew — 2026-10-30

For flexbox we use a flow value:

- `flex-visual`: Only takes effect on flex containers. Follows the visual reading order of flex items, taking the writing mode into account. Therefore, a document in English, with [flex-direction: row-reverse](https://drafts.csswg.org/css-flexbox-2/#propdef-flex-direction) and [reading-flow: flex-visual](https://drafts.csswg.org/css-display-4/#propdef-reading-flow) would have a reading order of left to right.
- `flex-flow`: Only takes effect on flex containers. Follows the [flex-flow](https://drafts.csswg.org/css-flexbox-2/#propdef-flex-flow) direction.

Perhaps we could drop the `-direction` and just have `grid-lanes-flow` and `grid-lanes-track`:

- `grid-lanes-flow`: Only takes effect on items inside a [grid lanes container](https://drafts.csswg.org/css-grid-3/#grid-lanes-container). Follows the visual order in which items are laid out on the grid axis, taking writing mode into account. Therefore, a document in English using `grid-template-columns` would have a reading order of left to right.
- `grid-lanes-track`: Only takes effect on items inside a [grid lanes container](https://drafts.csswg.org/css-grid-3/#grid-lanes-container). Follows the visual order in which items are laid out on the stacking axis, taking writing mode into account. Therefore, a document in English using `grid-template-columns` would have a reading order of top to bottom, starting with the column on the left.
