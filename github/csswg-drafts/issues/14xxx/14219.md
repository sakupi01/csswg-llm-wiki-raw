https://drafts.csswg.org/css-animations-2/#animation-delay

  > Specifying a single value [for `animation-delay`] will set the `animation-delay-start` to that value, **and will not affect the value of `animation-delay-end`**, for backward compatibility with the `animation-delay` previous longhand behavior.

A strict interpretation is that a single value should not reset `animation-delay-end`. But since it did not exist, I do not see how this would not be backward-compatible. Is it an oversight?

## @cdoublev — 2026-07-24

Thanks for the clarification. I missed that scenario (setting `animation.endDelay` via WAAPI, then `animation-delay` via CSS).

My understanding of this [comment](https://github.com/w3c/csswg-drafts/pull/14167#discussion_r3572630533) was that `animation-delay-end` simply does not default to `animation-delay-start`.

This behavior makes `animation-delay` the first shorthand to not declare all of its sub-properties, if I am not mistaken. 

I am not sure [CSS Cascade](https://drafts.csswg.org/css-cascade-5/#shorthand) prevents it:

  > When values are omitted from a shorthand form, unless otherwise defined, each “missing” sub-property is assigned its initial value.
  >
  > > Note: This means that a shorthand property declaration always sets all of its sub-properties, even those that are not explicitly set. [...]

I think it generally means that a shorthand can be defined to set omitted sub-property to a non-initial value.

In [serialize a CSS value](https://drafts.csswg.org/cssom-1/#serialize-a-css-value):

  > 2. If there is no such shorthand or `shorthand` cannot exactly represent the values of all the properties in list, return the empty string.

For all shorthands, this requires checking that each property in the list has a declaration. However, this would be inappropriate for `animation-delay`.
