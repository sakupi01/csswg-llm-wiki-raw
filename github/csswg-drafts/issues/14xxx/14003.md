See sibling issue https://github.com/whatwg/html/issues/12516. HTML defines base-select as using `content: counter(fake-counter-name, disclosure-open)` seemingly to get around wanting `disclosure-open` but not really wanting to use a counter.

Maybe it's worth us allowing `content: <list-style-type>`, with something akin to a "guaranteed invalid counter name"? This would allow HTML spec to then use `content: disclosure-open`.

This would have the fridge benefit of allowing e.g. `content: circle` as a more descriptive alternative to `content: \25E6` and so on.

/cc @emilio 

<!-- comment id=5285817349 author=fantasai created=2026-08-13T20:08:11Z url=https://github.com/w3c/csswg-drafts/issues/14003#issuecomment-5285817349 -->
## @fantasai — 2026-08-13

I think we should restrict this list to just the [built-in symbolic types](https://www.w3.org/TR/css-counter-styles-3/#simple-symbolic) (disc, circle, square, disclosure-open, etc.). Allowing any counter style opens up the syntax space too much, and also the rest of them need a counter index anyway.

<!-- comment id=5287790062 author=tabatkins created=2026-08-14T00:05:22Z url=https://github.com/w3c/csswg-drafts/issues/14003#issuecomment-5287790062 -->
## @tabatkins — 2026-08-14

Yes, just the predefined symbolic types. The non-symbolic types don't really make sense (it'll expose the counter value used), and any custom counter-styles you can just copy the string you used when defining the `@counter-style`.
