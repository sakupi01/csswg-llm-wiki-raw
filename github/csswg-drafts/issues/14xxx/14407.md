https://drafts.csswg.org/css-mixins-1/#private

The spec doesn't currently explain or give examples for using the same name in the same style rule.

For example:

```css
.foo {
	--alpha: public;

	@private {
		--alpha: private;
	}

	--beta: var(--alpha);
}
```

```css
.foo {
	@private {
		--alpha: private;
	}

	--alpha: public;

	--beta: var(--alpha);
}
```

> and any reference to a custom property of that name (for example, with a `var()`) is a reference to the private property.

From that I understand that the non-private property becomes essentially invisible in that style rule.
So `--beta` always has a value of `private`.

----

But `--alpha: public;` would still be present and work perfectly fine.
And any other style rule matching the same element (or descendants) would have a value of `public`.

```css
.foo {
	@private {
		--alpha: private;
	}

	--alpha: public;

	--beta: var(--alpha);
}

.foo {
  --delta: var(--alpha); // `public`
}

.foo * {
  --delta: var(--alpha); // `public`
}
```

Is this correct?

The value of `--alpha` in another rule without that name in it's private names is the public version of `--alpha` which is not set in your examples.

## @kbabbitt — 2026-09-03

Here's a more complex example based on my understanding:

```css
.foo {
  --alpha: banana;         /* sets public --alpha */
}
.foo {
  --alpha: grape;          /* sets private --alpha but gets overridden by later declaration */
  @private {
    --alpha: apple;        /* sets private --alpha but gets overridden by later declaration */
  }
  --alpha: orange;         /* sets private --alpha */

  --beta: var(--alpha);    /* refers to private --alpha */
  & .bar {
    --delta: var(--alpha); /* refers to private --alpha defined by parent rule */
  }
}
.foo .bar {
  --gamma: var(--alpha);   /* refers to public --alpha */
}
```
```js
let b = getComputedStyle(document.querySelector('.foo .bar'));
b.getPropertyValue("--alpha"); /* banana */
b.getPropertyValue("--beta");  /* orange */
b.getPropertyValue("--delta"); /* orange */
b.getPropertyValue("--gamma"); /* banana */
```

## @tabatkins — 2026-09-04

I do need to add an example, but the behavior *is* well-defined currently; having a "private property" lexically in scope causes it to shadow any global custom (or higher private) properties of the same name. This is identical to how variable shadowing works in practically every programming language in existence:

```js
let foo = 1;
function test(foo = 2) {
  let foo=3;
  if(true) {
    let foo=4;
    console.log(foo); // 4, no way to access 1, 2, or 3 in this block
  }
}
```

I understand what you mean and I somewhat agree but `@private` makes things lexically scoped to the nearest style rule, not to itself.

So the syntax and shadowing isn't actually the same at all.

```js
let foo = 1;
function test(foo = 2) {
  let foo=3;

  }

```

But that isn't how JS works.

It is exactly this disconnect that worries me about `@private`.
It makes things lexically scoped, but not to the rule where you actually define it.
