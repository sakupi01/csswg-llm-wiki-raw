CSS Grid 2 §8.5 step 2 describes placing row-locked items at the “earliest (smallest positive index) column index”. Step 4 explicitly starts at the start-most row and column of the implicit grid. Could step 2 clarify the index origin when definite column placements require tracks before explicit line 1?

Minimal original example:
```html
<style>
.grid {
  display: grid;
  width: max-content;
  grid-template-columns: 20px 20px;
  grid-template-rows: 10px;
  grid-auto-columns: 10px;
  grid-auto-rows: 10px;
  column-gap: 2px;
  row-gap: 1px;
}
.a { grid-column-start: -5; }
.c { grid-row-start: 1; }
</style>
<div class="grid"><div class="a"></div><div class="b"></div><div class="c"></div></div>
```

A has a definite column two tracks before the explicit grid, but its row is auto. C is row-locked and therefore placed by step 2, before A and B in step 4.

Interpreting step-2 indices over the whole implicit grid puts C at its start-most column, not explicit line 1. Relative border-box rectangles then are:

| Item | x | y | width | height |
|---|---:|---:|---:|---:|
| A | 0 | 11 | 10 | 10 |
| B | 12 | 11 | 10 | 10 |
| C | 0 | 0 | 10 | 10 |

The container is 66×21. This is the result observed locally in Chrome 155.0.8059.85; I have not checked other browsers. A literal reading of “positive” as authored explicit-grid line numbers would instead put C at x=24, leaving A and B on the first row.

Is the implicit-grid-origin interpretation intended? If so, could step 2 say so explicitly, including that definite minor-axis positions of items not yet fully placed determine that origin? Step 3 currently describes determining the implicit-grid column extent only after step 2.

Normative references: [§8.5](https://drafts.csswg.org/css-grid-2/#auto-placement-algo), [§7.5](https://drafts.csswg.org/css-grid-2/#implicit-grids).

## Related step-2 sparse-history wording

The same step requires the item to be past items “previously placed in this row by this step”. Please also clarify that “this row” is the definite row-start position, rather than every row intersected by a previous spanning item.

For a 3×3 grid of 20px columns and 10px rows, consider these items in source order:

1. A: row 3, column 1 (fully definite).
2. B: row 1 / span 3, automatic column.
3. C: row 2, automatic column.
4. D: row 1, automatic column.

B must use column 2 to avoid A. A cursor keyed by row-start places C in column 1 and D in column 3. Advancing history for every row B covers would instead put C in column 3. The row-start interpretation matches the independently executed Chrome and Taffy results for a reduced case. Occupancy, separately, still covers every spanned row.
