[§2.3 Content-Type of CSS Style Sheets](https://drafts.csswg.org/css-cascade-5/#content-type) says:

> If the host document is in quirks mode, and the host document's origin is [same origin](https://html.spec.whatwg.org/multipage/browsers.html#same-origin) with the linked resource [response](https://fetch.spec.whatwg.org/#concept-response)'s [URL](https://fetch.spec.whatwg.org/#concept-response-url)'s origin, the type is treated as `text/css`.

A response's URL can be same origin with the document while the response is still opaque, e.g. a cross-origin `@import` that redirects back to the document's origin. Treating that as `text/css` lets the page infer the contents of a resource it isn't allowed to read (CVE-2010-0654).

whatwg/html#12468 adds a CORS-same-origin condition to the same quirk for `<link rel=stylesheet>`, and css-cascade seems to need it too.

Firefox Nightly 158.0a1 and Chrome Canary 155 appear to block such an `@import`; Safari 26.6.2 applies the quirk. Tests in web-platform-tests/wpt#62516 (`css/css-cascade/import-mime-type-quirks.html`).
