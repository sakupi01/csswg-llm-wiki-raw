For example:

[`color-mix(in hsl, hsl(30deg 40% 80% / 25%), hsl(90deg 0 80% / 25%))`](https://preset-env.cssdb.org/color/computed/#JTdCJTIyY2klMjIlM0ElMjJjb2xvci1taXgoaW4lMjBoc2wlMkMlMjBoc2woMzBkZWclMjA0MCUyNSUyMDgwJTI1JTIwJTJGJTIwMjUlMjUpJTJDJTIwaHNsKDkwZGVnJTIwMCUyMDgwJTI1JTIwJTJGJTIwMjUlMjUpKSUyMiU3RA==)
[`color-mix(in hsl, hsl(30deg 40% 80% / 25%), hsl(90deg none 80% / 25%))`](https://preset-env.cssdb.org/color/computed/#JTdCJTIyY2klMjIlM0ElMjJjb2xvci1taXgoaW4lMjBoc2wlMkMlMjBoc2woMzBkZWclMjA0MCUyNSUyMDgwJTI1JTIwJTJGJTIwMjUlMjUpJTJDJTIwaHNsKDkwZGVnJTIwbm9uZSUyMDgwJTI1JTIwJTJGJTIwMjUlMjUpKSUyMiU3RA==)

In both cases browsers do a linear interpolation between `30deg` and `90deg` while in my implementation the `90deg` is powerless and becomes missing. This missing hue is then filled in with the `30deg` from the other color.

I suggest rewriting section 13 to make it clearer what all the steps are.

-----

> 2. changing any [powerless](https://drafts.csswg.org/css-color-4/#powerless-color-component) components to [missing](https://drafts.csswg.org/css-color-4/#missing-color-component) values

This step seems redundant as it is already included in https://drafts.csswg.org/css-color-4/#color-conversion

-----

Add a step between what is now 4. and 5. for ["the missing component is treated as having the other color’s component value"](https://drafts.csswg.org/css-color-4/#interpolation:~:text=If%20a%20color%20with%20a%20carried%20forward%20missing%20component%20is%20interpolated%20with%20another%20color%20which%20is%20not%20missing%20that%20component%2C%20the%20missing%20component%20is%20treated%20as%20having%20the%20other%20color%E2%80%99s%20component%20value.)

_or maybe at another position in the sequence?_

-----

With those suggestions the spec text would be become:

> 1. checking the two colors for [analogous components](https://drafts.csswg.org/css-color-4/#analogous-components) and [analogous sets](https://drafts.csswg.org/css-color-4/#analogous-set) which will be carried forward
> 2. converting them both to a given color space which will be referred to as the interpolation color space below.
> 3. (if required) re-inserting [carried forward](https://drafts.csswg.org/css-color-4/#carried-forward) values in the converted colors
> 4. fill in missing components with the other color's component values
> 5. (if required) fixing up the hues, depending on the selected [&lt;hue-interpolation-method>](https://drafts.csswg.org/css-color-4/#typedef-hue-interpolation-method)
> 6. changing the color components to [premultiplied](https://drafts.csswg.org/css-color-4/#premultiplied) form
> 7. linearly interpolating each component of the computed value of the color separately
> 8. undoing [premultiplication](https://drafts.csswg.org/css-color-4/#premultiplied)

-----

If color space conversion (and there for powerless to missing) is actually intended to be a conditional step, then step 2. should explicitly state this.

For example:

> 2. (if required) converting them both to a given color space which will be referred to as the interpolation color space below.

With this last change I think the spec would match browser behavior.
No idea if we actually want to change the spec to match :)
