I've resolved #14447 (how to easily pass currentcolor or accentcolor to an SVG) by defining `param(color)` and `param(accent-color)`, but there are a few other values we might want to pass into SVG, most notably fonts. (This was also discussed as part of #9872)

This seems a lot more complex, tho, so I think it's worth pulling out separately. How, exactly, do we want this to work?

We could use effectively the same behavior I defined for `param(color)`, so `param(font-family)` would grab the value of 'font-family' on the element and use that as the initial value of 'font-family' on the linked resource, etc. Presumably we'd want to allow `param(font)` to carry all the bits over, too.

How does this work with `@font` and related rules, tho? Do we effectively copy over all of the `@font`/etc rules affecting any listed 'font-family' to the linked resource? Is that something reasonable for implementations to do?

I think it's not unusual for SVGs to specifically set a particular generic family on their text, like monospace or sans-serif, rather than relying on the initial value (serif). Do we want to allow overriding a particular generic family with a specified font?

Are there other details I'm missing?

## @svgeesus — 2026-09-11

> We could use effectively the same behavior I defined for `param(color)`, so `param(font-family)` would grab the value of 'font-family' on the element and use that as the initial value of 'font-family' on the linked resource, etc

Yeah that only gets you so far: generics, and local fonts. As you say:

> How does this work with `@font` and related rules, tho? Do we effectively copy over all of the `@font`/etc rules affecting any listed 'font-family' to the linked resource? Is that something reasonable for implementations to do?

That is the core of the problem. By "copy over" do you mean injecting the `@font-face`, which the SVG then separately downloads and uses (currently would not work with SVG on `img`, only works on `object`) or do you mean treating the SVG same as inline, meaning it has access to the already downloaded font from the parent document?

CSS Fonts 4 [says](https://drafts.csswg.org/css-fonts-4/#font-face-rule)

> Downloaded fonts are only available to documents that reference them. The process of activating these fonts must not make them available to other applications or to documents that don’t directly link to the same font. User agent implementers might consider it convenient to use downloaded fonts when rendering characters in other documents for which no other available font exists as part of the installed font fallback procedure. However, this would cause a security leak since the contents of one page would be able to affect other pages, something an attacker could use as an attack vector. These restrictions do not affect caching behavior, fonts are cached the same way other web resources are cached.

## @tabatkins — 2026-09-15

Okay, that seems pretty clear then - we *should not* make the fonts themselves available to the linked resource. 

In that case, just passing the actual property values seems like the extent of what we should do, just making it easy to control fonts in a linked resource.
