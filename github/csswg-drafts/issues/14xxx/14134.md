> https://drafts.csswg.org/css-color-4/#interpolation-missing

> If a color with a carried forward missing component is interpolated with another color which is not missing that component, the missing component is treated as having the other color’s component value.
> 
> Therefore, the carrying-forward step must be performed before any powerless component handling.

This is followed by example 37:

> For example, if these two colors are interpolated, the second of which has a missing hue ...

But example 37 doesn't have any powerless components.
Neither is there any color space conversion.

------

For example by the current spec:

`color-mix(in lch, oklch(78.3% 0 326.5), oklch(39.2% 0.4 none))` should result in `lch(49.61684142 61.33679401 none)` where the outcome doesn't have any `hue`!

------

I am unsure what the intention was behind the statements or example 37.
It predates a lot of edits, but maybe the aspect it tries to explain is still relevant and just needs to be updated?

## @svgeesus — 2026-07-06

[Example 37](https://drafts.csswg.org/css-color-4/#ex-oklch-missing-hue) is intended to illustrate the first of those sentences, not the second. In terms of the [8 stage sequence of steps](https://drafts.csswg.org/css-color-4/#interpolation) the initial colors to be interpolated are ` oklch(78.3% 0.108 326.5)` and  `oklch(39.2% 0.4 none)`.

At step 1, hue is identified as an analogous component.
At step 2, nothing happens
At step 3, nothing happens
At step 4, the carried-forward component is re-inserted, giving us `oklch(78.3% 0.108 326.5)` and `oklch(39.2% 0.4 326.5)` which is the point of the example.
(The example does not continue on to the other four steps)

Perhaps it would be clearer if the example was moved up, ahead of 

> Therefore, the carrying-forward step must be performed before any powerless component handling.

although that splits up the flow of reading somewhat. Also, 'carrying forward' is used in two places: step 1 (where the things to be carried forward are identified and the values saved) and step 4 (where they are re-inserted). So perhaps that would be clearer as 

> Therefore, the identification of carried-forward components must be performed before any powerless component handling.

in other words, before things get converted to zero.

## @romainmenke — 2026-07-06

> At step 4, the carried-forward component is re-inserted, giving us oklch(78.3% 0.108 326.5) and oklch(39.2% 0.4 326.5) which is the point of the example.

🤔 If that is correct then I have misunderstood carry-forward.

As I understood it:
When an analogous component is missing and the color is converted to another color space the missing component would become `0`, because a numeric value is needed for the conversion math. After conversion the analogous component is set to missing. This "setting to missing if it was missing originally" is the carry forward step.

So I thought that "carry-forward" only describes the effect of preserving missing components during conversion.

This is based on (emphasis mine):

> Thus, the first stage in interpolating two colors is to classify any missing components in the input colors, and compare them to the components of the interpolation color space. If any **analogous components which are missing components** are found, they will be carried forward and re-inserted in the converted color before premultiplication, and before linear interpolation takes place.

https://drafts.csswg.org/css-color-4/#interpolation-missing

------

My confusion wasn't about carry-forward, but rather about the mention of powerless component handling. As the example doesn't have any powerless hue. So I don't understand how the example is supposed to illustrate the effects of the order.

> the missing component is treated as having the other color’s component value

For reference in my implementation this step happens after all color space conversions.
Always possible that I have bugs :)

https://github.com/csstools/postcss-plugins/blob/28d00d2d3dd978c99e8b9bbcf42970bba71cd374/packages/css-color-parser/src/functions/color-mix.ts#L372-L382

```
// convert both colors to the interpolation space
const a_channels = colorDataTo(a_color, colorNotation).channels;
const b_channels = colorDataTo(b_color, colorNotation).channels;

// fill in missing components with components from the other colors
a_channels[0] = fillInMissingComponent(a_channels[0], b_channels[0]);
b_channels[0] = fillInMissingComponent(b_channels[0], a_channels[0]);

a_channels[1] = fillInMissingComponent(a_channels[1], b_channels[1]);
b_channels[1] = fillInMissingComponent(b_channels[1], a_channels[1]);

a_channels[2] = fillInMissingComponent(a_channels[2], b_channels[2]);
b_channels[2] = fillInMissingComponent(b_channels[2], a_channels[2]);
```

## @romainmenke — 2026-07-06

Maybe the intention was to clarify the order between these steps:

> checking the two colors for [analogous components](https://drafts.csswg.org/css-color-4/#analogous-components) and [analogous sets](https://drafts.csswg.org/css-color-4/#analogous-set) which will be carried forward

> For all other purposes, a missing component behaves as a zero value, in the appropriate unit for that component: 0, 0%, or 0deg. This includes rendering the color directly, converting it to another color space, performing computations on the color component values, etc.

https://drafts.csswg.org/css-color-4/#missing

Converting missing/none to `0` isn't mentioned explicitly here: https://drafts.csswg.org/css-color-4/#interpolation

----


> > Therefore, the identification of carried-forward components must be performed before any powerless component handling.
> 
> in other words, before things get converted to zero.

Maybe:

> Therefore, the identification of carried-forward components must be performed before any missing components are converted to zero for color space conversion.

(I understand `powerless component handling` as the step where chroma/saturation is checked and hue might become missing.)
