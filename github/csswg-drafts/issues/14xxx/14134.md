## @svgeesus — 2026-07-06

[Example 37](https://drafts.csswg.org/css-color-4/#ex-oklch-missing-hue) is intended to illustrate the first of those sentences, not the second. In terms of the [8 stage sequence of steps](https://drafts.csswg.org/css-color-4/#interpolation) the initial colors to be interpolated are ` oklch(78.3% 0.108 326.5)` and  `oklch(39.2% 0.4 none)`.

At step 1, hue is identified as an analogous component.
At step 2, nothing happens
At step 3, nothing happens
At step 4, the carried-forward component is re-inserted, giving us `oklch(78.3% 0.108 326.5)` and `oklch(39.2% 0.4 326.5)` which is the point of the example.
(The example does not continue on to the other four steps)

Perhaps it would be clearer if the example was moved up, ahead of 

> Therefore, the carrying-forward step must be performed before any powerless component handling.

although that splits up the flow of reading somewhat. Also, 'carrying forward' is used in two places: step 1 (where the things to be carried forward are identified and the values saved) and step 4 (where they are re-inserted). So perhaps that would be clearer as 

> Therefore, the identification of carried-forward components must be performed before any powerless component handling.

in other words, before things get converted to zero.

## @svgeesus — 2026-07-09

> 🤔 If that is correct then I have misunderstood carry-forward.
> 
> As I understood it: When an analogous component is missing and the color is converted to another color space the missing component would become `0`, because a numeric value is needed for the conversion math. After conversion the analogous component is set to missing. This "setting to missing if it was missing originally" is the carry forward step.

I agree that you seem to have misunderstood.

Firstly, this is about carry-forward when interpolating colors. (Interpolation may or may not call colorspace conversion, depending on the colorspace of the colors to be interpolated, and the interpolation colorspace)

> When an analogous component is missing and the color is converted to another color space the missing component would become `0`, because a numeric value is needed for the conversion math. 

It would, yes. And that often produces undesirable results  with interpolation.

> After conversion the analogous component is set to missing. This "setting to missing if it was missing originally" is the carry forward step.

No. After conversion, during interpolation, the analogous component is set to **the value from the other color**.

Here is an example. The colors to be interpolated are `gray` and `cyan`. The interpolation colorspace is `Oklch`.

`gray` -> `oklch(59.99% 0 none)`
`cyan` -> `oklch(90.54% 0.1546 194.8)`

Hue is the analogous component, because one color has `none` and the other has a value which is not `none`.

Without carry forward, the none would be zero which is a reddish-magenta hue. If the interpolation was for a gradient, [we would have undesirable reddish and purplish hues](https://apps.colorjs.io/gradients/?color1=oklch(59.987%25%200%200)&color2=cyan).

_With_ carry forward, the actual colors interpolated both have the _same_ hue

`oklch(59.99% 0 194.8)`
`oklch(90.54% 0.1546 194.8)`

and so we [come smoothly from a neutral gray to a cyan](https://apps.colorjs.io/gradients/?color1=gray&color2=cyan), as the chroma increases and the actual hue stops being powerless.
