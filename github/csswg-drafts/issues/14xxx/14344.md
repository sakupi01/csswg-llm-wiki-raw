The `progress()` function takes a value, and a min/max, and returns a number indicating what progress the "value" represents between the min/max. (Or before/after the min/max, if unclamped.) That is, `progress(50px, 0px, 200px)` return `0.25`.

The inverse operation can also be useful - given a progress value, and a min/max representing the 0/1 progress value, return the corresponding value. 

This actually *already exists* in the spec, just accidentally: `random(fixed 0.25, 0px, 200px)` will return `50px`. It's pretty weird to (mis)use `random()` for this, though!

Would it be worth adding the functionality directly to the spec? This isn't *just* a trivial linear transform, as `random()` also has useful *step* behavior that is either complicated or impossible to reproduce manually (I haven't worked at it yet to tell for sure whether you can actually do it with full fidelity, given the end-clamping behavior). That is, `calc-range(N, 0px, 200px, 50px)` would only return 5 possible values - 0px, 50px, 100px, 150px, and 200px, each taking 20% of the 0-1 argument range.

----------

Little side feature discussion - the current `random()` behavior for steps is pretty specialized to the "clamped to 0-1" requirement that random() imposes. If you allowed values <0 or >1, it's no longer perfectly symmetrical, as the first/last values would be overrepresented; in the previous example, `200px` would be returned for the range `[.8, 1)`, and *also* for `[1, 1.2)`.

Possibly, for both this function and for random(), we could allow optionally specifying [one of the `jump-*` keywords from `steps()`](https://drafts.csswg.org/css-easing-2/#valdef-step-position-jump-start), defaulting to `jump-none` when unspecified.

```css
width: calc-interpolate(0.25, 0: 0px, steps(5, jump-none), 1: 200px);
```

## @tabatkins — 2026-09-04

Whoops, I totally forgot about `calc-interpolate()`. Yup, that works! (It's not *quite* the same as `random()` if you use a step and start+N*step doesn't hit the end exactly, but I'm more okay with that precise behavior being `random()`-specific.) 

The only unfortunate bit is that you do have to calculate the number of steps yourself, as `steps(calc((end - start)/step + 1, jump-none)`, but eh. We can address that more directly if someone actually asks for it.
