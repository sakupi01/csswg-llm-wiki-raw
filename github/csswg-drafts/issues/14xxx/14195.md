Proposal by @yaomingliu 

This is a proposal to introduce a mode configuration for the scrollbar length. 

###  Challenge: 

When padding is applied, the size of the content box no longer matches the size of the container. 

Currently, the scrollbar's length still aligns with the padding edge, which leads to a poor user experience, as shown in the following picture. The blue rectangle (2) represents the content box, (1) the container, and (3) the scrollbar.

<img width="485" height="559" alt="Screenshots showing container, content box with padding, and the scrollbar track reaching the top and bottom of the main container" src="https://github.com/user-attachments/assets/554abe89-ffdf-4b95-b22d-e0b2d3c1dcca" />

### Proposal

This is a proposal to introduce a mode configuration for the scrollbar length. 

<img width="489" height="554" alt="Screenshots showing container, content box with padding, and the scrollbar track aligned with the top and bottom of the content  box" src="https://github.com/user-attachments/assets/f28ea426-8daa-4120-b36b-f4655815bee6" />

By default, it would still align with the padding edge, but developers should also have the option to align it with the content edge.

### Explainer

https://github.com/ArkWebCore/ArkWeb-explainers/blob/main/ScrollbarLength/explainer.md

Please, share your feedback.

## @tabatkins — 2026-07-17

Previous discussion on this issue was in #12385, where we recommended separating the two ideas being presented (shortening the scrollbar, and offsetting it into the content) into separate proposals.

As I said during the call where this was presented (and several other people thought similar), this is a reasonable idea. I like the proposal to let you use keywords to automatically shorten it to an appropriate box.

Did you find no use-cases for an explicit length? I would assume that would still be useful; for example, a box with border-radius might have enough horizontal padding to keep the content from being obscured, so there is no need for vertical padding, but the scrollbar would intersect with the corner more, and could use some inset. I think it would be useful to allow specifying both a keyword and a length, with the length *further* insetting the scrollbar from where the keyword starts it.

(Related: I assume we don't want to allow the scrollbar to get *longer* than normal, but being able to set a smaller box via keyword and then get a little longer than that seems reasonable, so I suppose the length is *allowed* to be negative, but with the overall inset clamped at used-value time to not make an end extend further than normal.)

This proposal also switches to a '-length' naming, implying that it can only do matched insets on both ends of the scrollbar. I'd also assume that, while this is *common*, it might not be all the use-cases, and it would be simple to instead use side naming (`-top`, etc) to allow individual control over each end of the scrollbar. Authors can still use a directional shorthand (`-y`, `-block`, etc) to shorten both sides the same amount in the common case.

If we do go for side-based naming, then 'length' isn't the right word to use. A few people proposed in the telcon to use 'inset' as the term, as that's used elsewhere in CSS to indicate shrinking some length in from the various sides. So, 'scrollbar-inset' as the highest shorthand, then 'scrollbar-inset-y/x/block/inline` as middle shorthands to set just one side, and 'scrollbar-inset-top//block-start/etc` as the longhands to set an individual side.

----------

So, some nits on the proposal, but I support this overall.

## @yaomingliu — 2026-10-07

## Proposal Summary: `scrollbar-inset`

Here is a quick recap and structuring of the proposed property for controlling scrollbar positioning relative to element boundaries:

### 1. Property Hierarchy & Naming

* **Primary Shorthand:** `scrollbar-inset`
* **Axis Shorthands:** `scrollbar-inset-x`, `scrollbar-inset-y`
* **Longhands:**
* `scrollbar-inset-top`
* `scrollbar-inset-bottom`
* `scrollbar-inset-left`
* `scrollbar-inset-right`



---

### 2. Value Syntax & Definitions

```css
scrollbar-inset: [ padding-edge | content-edge ] <length>?;

```

* **`padding-edge`**: The scrollbar is aligned with the **padding edge** of the element.
* **`content-edge`**: The scrollbar is aligned with the **content edge** of the element.
* **`<length>`** *(optional)*: Provides a fine-tuned numeric adjustment to the baseline layout boundary (supporting positive/negative values for precise offsetting).

---

### Example Usage

```css
/* Align with the content edge and add a fine-tuned numeric adjustment */
.scroll-container {
  scrollbar-inset: content-edge 4px;
}

```
