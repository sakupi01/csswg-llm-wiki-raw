Spec: https://drafts.csswg.org/css-text-decor-4/#text-decoration-thickness-property

When a decoration propagates from its [decorating box](https://drafts.csswg.org/css-text-decor-4/#decorating-box) to descendant text with a different `font-size`, the spec doesn't say whose `font-size` a percentage `text-decoration-thickness` resolves against. Browsers disagree.

### Testcase

```html
<!DOCTYPE html>
<style>
.big { font: 80px/1 monospace; }
.small { font: 20px/1 monospace; }
.decorated {
  text-decoration: overline solid blue;
  text-decoration-thickness: 25%; /* 20px of 80px, or 5px of 20px */
}
</style>
<!-- 1. Inline descendant -->
<p><span class="big decorated"><span class="small">text</span></span></p>
<!-- 2. Ruby base -->
<p><span class="big decorated"><ruby class="small">base<rt>anno</rt></ruby></span></p>
```

In both cases the only decorated text is 20px. The 80px decorating box contributes no glyphs of its own.

### Results

| | Case 1 | Case 2 |
|---|---|---|
| Blink | 20px | 20px |
| WebKit | 20px? | 20px |
| Gecko | 5px | 5px |

### Question

When the decorating box's `font-size` differs from that of the decorated text, should a percentage `text-decoration-thickness` (and `text-underline-offset`) resolve against:

1. the decorating box's used `font-size`, giving one value per decorating box (Chrome and Safari today, and the #3121 example), or
2. the `font-size` of the decorated text (the considered text), reduced to one value per line as § Text Decoration Line Uniformity requires (consistent with Firefox's result)?

Whichever is chosen, the percentage definitions and the note should say it explicitly.

### Why it matters

Beyond how the line itself renders, layout sometimes has to make room for the line. css-ruby places a base's decoration between the base and its annotation, so the ruby layout has to know the thickness to position the annotation. An engine whose layout and paint answer this question differently overlaps the annotation.

### Related Spec text and Tickets

**For the decorating box's `font-size` (20px):**

* The definition says "A percentage value specifies the thickness of text decoration lines as a percentage of the used 'font-size'", without saying whose. The property "sets the stroke thickness of underlines, overlines, and line-throughs specified on the element ... and affects all decorations originating from this element even if descendant boxes specify a different thickness". That reads as the originating element's font-size.
* #3121, which led to the percentage values, gave this example for `text-underline-offset`:
  ```html
  <div id="outer" style="font-size: 32px; text-underline-offset: 12.5%; text-decoration: underline;">
      <div id="inner" style="font-size: 16px;"> ... </div>
  </div>
  ```
  > The observed offset on the inner element should be 4px because of the decorating box.

  That is 12.5% of the decorating box's 32px. The issue was closed in favor of #2165 without ruling on this example.

**For the decorated text's `font-size` (5px):**

* [§ Determining the Position and Thickness of Line Decorations](https://drafts.csswg.org/css-text-decor-4/#line-position) computes the line "per line, from all text decorated by the decorating box on that line, the considered text", and says "user agents may consider the font sizes, faces, and weights of descendants to provide an appropriately averaged thickness". But the section carries: "Issue: ... It is still under review, and needs integration with 'text-underline-offset' and 'text-decoration-thickness'."
