  > Specifications that define operations on the `CSS` namespace and want to store some state should store the state on the current global object’s associated `Document`.

https://drafts.csswg.org/cssom-1/#the-css.escape()-method

  > To **register a custom property** [...]:
  >
  > 1. Let `property` set be the value of the current global object’s associated Document’s `[[registeredPropertySet]]` slot.

https://drafts.css-houdini.org/css-properties-values-api/#register-a-custom-property

In Chromium/Gecko browsers (I cannot test WebKit), the `<p>` is green in `b.html`, not in `a.html`:

```html
<title>a.html</title>
<p style="color: var(--custom)">color?</p>  <!-- black -->
<script>
  function registerProperty() {
    frames[0].CSS.registerProperty.call(CSS, {
      name: '--custom',
      syntax: '<color>',
      initialValue: 'green',
      inherits: false,
    })
  }
</script>
<iframe src="b.html" onload="registerProperty()"></iframe>
```

```html
<title>b.html</title>
<p style="color: var(--custom)">color?</p> <!-- green -->
```

So my understanding is that `--custom` is registered in the relevant global object's associated document.

See https://html.spec.whatwg.org/multipage/webappapis.html#current-global-object:~:text=One%20reason%20why%20the%20relevant%20concept%20is%20generally%20a%20better.
