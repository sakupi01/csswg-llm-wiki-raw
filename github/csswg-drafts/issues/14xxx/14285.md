There has been a host of issues around the concept of powerless and missing components. I think the use cases are served perfectly fine via `none` alone. We just specify that certain conversions produce `none` in certain places, we make sure `none` is preserved as much as possible, and if you explicitly set components to non-`none` values in ways that produce no discernible difference, I think that's **fine**.

The idea being, if you explicitly _want_ to create a e.g. red saturated white, knock yourself out. You just shouldn't get these by accident.

That would simplify a host of issues, without actually losing much (if anything).

## @romainmenke — 2026-08-06

Can we define what we are trying to achieve?
With specific examples and how they produce unexpected results based on the current spec.

-----

The main purpose for the effect that is currently named "powerless components" is to prevent having a `0deg` hue when converting from a rectangular color space to a polar color space.

i.e. `hsl(from rgb(128 128 128) h s l)` is `hsl(none 0% 50%)`.

Unfortunately all polar to polar conversions also go through a rectangular color space (either d50 or d65 xyz).

So `lch(from oklch(0.5 0 70deg) l c h)` is `lch(42 0 none)`.
And `hwb(from hsl(70deg 0 50%) h w b)` is `hwb(none 50% 50%)`.

This effect will not go away by describing it differently :)

So can we first describe what we are trying to solve and then see how we can get there?
