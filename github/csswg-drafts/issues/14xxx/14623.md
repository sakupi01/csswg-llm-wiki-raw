The [`polygon()` grammar](https://drafts.csswg.org/css-shapes-1/#funcdef-polygon) currently accepts `round <length>` without a nonnegative range. Chromium, Firefox, and WebKit reject a negative literal rounding radius, as required by the existing WPT assertions in [`clip-path-invalid.html`](https://github.com/web-platform-tests/wpt/blob/master/css/css-masking/parsing/clip-path-invalid.html) and [`offset-path-parsing-invalid.html`](https://github.com/web-platform-tests/wpt/blob/master/css/motion/parsing/offset-path-parsing-invalid.html):

```js
CSS.supports("clip-path", "polygon(round -1px, 1px 2px)"); // false
CSS.supports("offset-path", "polygon(round -1px, 1px 2px)"); // false
```

Probably we should change `round <length>` to `round <length [0,∞]>` to express the interoperable restriction.
