**Where:** CSS Cascading and Inheritance Level 5, Editor's Draft 13 April 2026, §7.3.6 Rolling Back Rules: the revert-rule keyword (#revert-rule-keyword), read with §6.1 Cascade Sorting Order (#cascade-sort), "Element-Attached Styles".

**Text.** §7.3.6:

> If the cascaded value of a property is the revert-rule keyword, the cascaded value is rolled back such that the specified value is calculated as if the current style rule had not been present at all.

§6.1 separates element-attached declarations from style rules:

> Separately for normal and important declarations, declarations that are attached directly to an element (such as the contents of a style attribute) rather than indirectly mapped by means of a style rule selector take precedence over declarations the same importance that are mapped via style rule.

**Example.**

```html
<style> div { border-radius: 5px; } </style>
<div style="border-radius: 2px; border-radius: revert-rule"></div>
```

Both attribute declarations are normal author declarations in the same tree context. The Element-Attached Styles step ranks them above `div { … }`, and inside the attribute the later declaration wins by order of appearance. So the cascaded value is `revert-rule`, and the rollback has to be applied.

A `style` attribute is not a style rule, so "as if the current style rule had not been present" does not say what to remove:

- Reading 1: the whole attribute block counts as the current rule. Both attribute declarations are gone and `div { border-radius: 5px }` applies: `5px`.
- Reading 2: only the declaration with `revert-rule` is removed. The earlier `border-radius: 2px` in the same attribute stays and wins: `2px`.

**Why it is unclear.** The same question was asked for revert-layer in #6743 (closed, accepted by resolution), and Level 5 answers it in §7.3.5 with a dedicated sentence:

> If the cascaded value of a property is the revert-layer keyword, the cascaded value is rolled back to the earlier layer, so that the specified value is calculated as if no rules were specified in the current cascade layer —​or between its normal and important levels in the cascade —​for this property on this element. For revert-layer in important element-attached styles, however, it only reverts the element-attached styles and the intervening animation origin, and not any of the intervening author-origin important rules.

The changes list records it:

> Clarified the behavior of revert-layer keyword when used in the style attribute or @keyframes at-rule. (Issue 6743)

§7.3.6 has a sentence for the other special origin:

> The revert-rule keyword behaves like revert-layer in the animation origin.

but no sentence for element-attached styles. #10443 (open, where revert-rule was defined) and #13916 (open, a possible loop) do not discuss the style attribute in their first messages.

Found during an AI-assisted review of the cascade specs.

**Request:** could §7.3.6 say what counts as the "current style rule" for element-attached declarations, for example: "For revert-rule in element-attached styles, the element-attached declarations of the same importance are treated as the current style rule."?

## @rifmj — 2026-10-31

Thanks, I hadn't checked browsers before filing. Browsers do what you expect.

WPT already covers this pattern: [`css/css-cascade/revert-rule-basic.html`](https://github.com/web-platform-tests/wpt/blob/master/css/css-cascade/revert-rule-basic.html), subtest "Reverting from style attribute reverts to regular rules":

```html
<div id=test3 style="color:red; color:revert-rule"></div>
```

with `#test3 { color: green }` in a style rule. It expects green: the earlier inline `color:red` is rolled back too, and the style rule applies. If only the `revert-rule` declaration were dropped, the result would be red. On the stable wpt.fyi runs of 31 October, Chrome 156, Edge 156, Firefox 159 and Safari 27.2 all pass it. That is reading 1 from the issue (`5px` in my example).

So for normal declarations this looks editorial: §7.3.6 does not say what the test encodes. The smallest fix may be to extend the sentence that is already there, "The revert-rule keyword behaves like revert-layer in the animation origin", to "...in the animation origin and in element-attached styles". That would also bring in the §7.3.5 rule for `!important` element-attached styles. I couldn't find a WPT test for that case (`revert-rule-important.html` has no style attribute), so it may be the one point that needs a decision.
