https://drafts.csswg.org/css-scroll-snap-2/#initial-scroll-target computes the initial scroll position with CSSOM View's [determine the scroll-into-view position](https://drafts.csswg.org/cssom-view-1/#determine-the-scroll-into-view-position). From that, https://drafts.csswg.org/css-scroll-snap-1/#intro implies that the result is snapped, so a snap area of a different element can win over the initial scroll target, and that `scroll-padding` and `scroll-margin` apply:

> Also, to offer better control over paging and scroll positioning even when snapping is off, this module defines the 'scroll-padding' property for use on all scroll containers, to adjust the scroll container’s optimal viewing region for the purpose of paging and scroll-into-view operations. Similarly the 'scroll-margin' property can be used on any box to adjust its visual area for the purpose of scroll-into-view operations.

Neither spec says this outright; it only follows from Scroll Snap 2 using determine the scroll-into-view position. Maybe add a note? `css/css-scroll-snap/scroll-initial-target/scroll-initial-target-with-scroll-snap.tentative.html` already expects snapping to win; I didn't find a test for `scroll-padding` or `scroll-margin`.
