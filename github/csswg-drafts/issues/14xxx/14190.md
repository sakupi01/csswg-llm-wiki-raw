https://drafts.csswg.org/css-align-3/#propdef-align-content
https://html.spec.whatwg.org/multipage/rendering.html#button-layout

```html
<!DOCTYPE html>
<button style="align-content: start; height: 100px">Text</button>
```

<img width="49" height="111" alt="Image" src="https://github.com/user-attachments/assets/07739635-ad62-49e0-a886-5b806bedb04e" />

Browsers agree that the text is still vertically centered, because the [anonymous button content box](https://html.spec.whatwg.org/multipage/rendering.html#anonymous-button-content-box) gets centered regardless. In order to avoid this, the author needs to use `display: flex` or such.

But I wonder whether HTML could just drop

> If the box does not overflow in the vertical axis, then it is centered vertically.

in favor of `button { align-content: safe center }` in the UA sheet, which authors could then override.

## @emilio — 2026-07-16

So FWIW, I realized that it doesn't affect flex by default because `align-content` only works with `flex-wrap`.

So tweaking the UA sheet would only change behavior with explicit `align-content` (as intended), or `display: grid`, or `display: flex` + `flex-wrap: wrap`, which may not be that bad?

I'd be willing to try that change if Blink or WebKit follow suit as well.

## @emilio — 2026-07-16

Cool, concrete proposal then:

```css
/* Almost like the rule from https://html.spec.whatwg.org/#form-controls */
input:not([type="file" i], [type="range" i], [type="checkbox" i], [type="radio" i]) {
  align-content: unsafe center;
}

select:not(:listbox), /* All engines have a :listbox equivalent */
button,
::file-selector-button,
input:is([type="color"], [type="reset"], [type="button"], [type="submit"]) {
  align-content: center;
}
```

Does that look good to you, @bfgeek?
