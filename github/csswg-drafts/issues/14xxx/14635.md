Per the CSSOM spec, when serializing a CSS value, "if component values can be omitted or replaced with a shorter representation without changing the meaning of the value, omit/replace them". However, for the `line-clamp` shorthand I think this can result in a serialization that's less readable than the alternative.

When `line-clamp` is not `none`, a value needs to be specified for either the `max-lines` shorthand, the `block-ellipsis` shorthand, or both. When only `max-lines` is provided, `block-ellipsis` defaults to the `ellipsis` value, which pedagogically is the default behavior of the ellipsis in `line-clamp`. However, when only `block-ellipsis` is provided, `max-lines` defaults to `auto` (meaning clamp to whatever fits in the current `max-height`), which doesn't seem like such a default behavior.

Therefore, serializing `line-clamp: auto no-ellipsis` to `line-clamp: no-ellipsis` seems less than ideal. We should probably explicitly specify that the `auto` keyword should not be omitted.
