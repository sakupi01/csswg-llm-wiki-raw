The [Images 4 serialization rules](https://drafts.csswg.org/css-images-4/#serialization) require “omitting components when possible without changing the meaning”. Since an omitted `image-set()` resolution defaults to `1dppx`, this appears to require omitting that resolution when serializing.

However, Chromium, Firefox, and WebKit all include it, even when the author omitted it:

```js
const element = document.createElement("div");
element.style.backgroundImage = 'image-set("https://example.test/a.png")';
document.body.append(element);

console.log(getComputedStyle(element).backgroundImage);
// All three engines:
// image-set(url("https://example.test/a.png") 1dppx)

element.remove();
```

This was checked in Chromium 151, Firefox 153, and WebKit 26.5. The existing [image-set computed-value tests](https://github.com/web-platform-tests/wpt/blob/master/css/css-images/image-set/image-set-computed.sub.html) also consistently expect the resolution to be included.

Could we add an explicit exception requiring serialization of each `image-set()` option’s resolution, including its default value? That would bring the prose into agreement with interoperable behavior and existing WPT expectations. The serialization section already has a similar exception requiring percentages to be included for `cross-fade()`.

## @cdoublev — 2026-10-20

`1x` appears to also be added for the declared value, i.e. it is not resolved from the image source metadata in the WPT tests.

  > Since an omitted `image-set()` resolution defaults to `1dppx`

The text actually defines that *"it behaves as `1x` [...] but if some other source of data supplies a natural resolution, that resolution must be honored instead"*. Therefore, adding `1x` would override this natural resolution.

However, this would be consistent with the behavior of the `srcset` attribute in HTML image elements, if I am not mistaken, which might explain why browsers chose to adopt this approach.

I also note that `dppx` is the canonical unit of [`<resolution>`](https://drafts.csswg.org/css-values-4/#resolution-value), therefore `1dppx` should be added, not `1x`.
