Title:
Proposal: Add a Visual-degree (vad) Unit for Perceptual Sizing in CSS.
Proposed by: Waylon Shao, China, 2026-08-24, E-mail: waylon_shao@163.com.
________________________________________
Summary:
CSS provides units for CSS lengths (px, em, rem), physical/reference lengths (mm, in), and viewport-relative lengths (vw, vh).
However, CSS currently lacks a unit that directly expresses perceptual visual size.
I propose introducing a new unit:
vad
where:
1vad = 1 degree of visual angle.

vad means visual angle in degree.
For example:
body {
    font-size: 0.6vad;
}
would indicate that the intended typographic height is approximately 0.5 degrees of visual angle under the applicable viewing model.
The goal is not to replace px or existing CSS units, but to provide a new abstraction specifically for perceptual sizing.
________________________________________
Motivation:
The same physical text size does not produce the same perceived size on different display environments.
For example, consider:
•	a 6.3-inch smartphone viewed at approximately 38 cm; 
•	a 15.6-inch laptop viewed at approximately 45 cm; 
•	a 27-inch desktop display viewed at approximately 55 cm; 
•	a 75-inch television or display screen wildly used in companies’ meeting room viewed at approximately 3 meter. 
Suppose a glyph is physically 4 mm high.
At a viewing distance of 45 cm to laptop, its visual angle is approximately:
5 mm / 450 mm ≈ 0.0111 rad ≈ 0.637°
At a viewing distance of 3 m:
5 mm / 3000 mm ≈ 0.00167 rad ≈ 0.0955° , causing viewers feel the words are only 15% size than they looks in laptop.
Therefore, the same physical font height can appear dramatically smaller on a large display viewed from some farther away, whose distance is regarded most common when watching.
To maintain approximately the same visual angle, the physical size of the text should increase as the viewing distance increases.
For example, maintaining approximately 0.509° would require roughly:
45 cm viewing distance → 5 mm text
300 cm viewing distance → 5*(3000/450) ≈ 33.3 mm text
This is fundamentally different from maintaining the same CSS pixel size, i.e., the same physical millimeter height.
________________________________________
Why Not Just Use px, mm, vh, or vw?:
px, mm
A fixed CSS pixel size does not maintain a consistent visual angle when viewing distance changes.
When in smartphones, words will be too large. If using CSS cods to specially decide the pixels for smartphones, it increase programmer’s codes lines, and sometimes codes do not work, and programmers have to spend much time to find root reasons.
When in large screen like 75 inch TV or screen in companies’ meeting room, px will make the words too small, views feel very difficult to distinguish the words.
vw
Viewport width is not a reliable proxy for viewing distance. If future viewers use ultrawide monitor with desktop, it will make the words too large. But my vad will not.
vh
The vh/vw depends on the viewport, not the display screen pixels/size. When user zoom the viewport window to about half of the screen height, words will shrink to half height. This is not expected nor hoped by user. My new CSS unit vad (visual degrees of angle) can solve this shortcoming, because vad keep words same height after viewport window is zoomed smaller.
Viewport height can be a useful approximation in some situations, but it still describes the viewport rather than perceptual size. For different displaying equipment, same 2% do not have same viewing angles. Thus, it needs programmers to write several and even several tens more codes to suit different equipment situation. If webpage is complex and issues occur, find their CSS root reason cost too much time.
If using my vad unit, only one line of CSS code is needed, it will automatically works perfectly for any types of screen that the future viewers will use.
________________________________________
The Missing Abstraction:
Current CSS units primarily describe one of the following:
px       CSS coordinate size
mm       physical/reference length
em/rem   document-relative size
vh/vw    viewport-relative size
A visual-degree unit would describe:
vad       intended perceptual visual angle in degree.
In other words:
px → "How large is it in the CSS coordinate system?"

vad → "How large is the viewing angles that eyes will proximately receive, no matter what screen type the viewer is using?"
These are different design objectives.
________________________________________
Proposed Syntax:
The basic syntax would be like:
font-size: 0.6vad;
with the conceptual definition:
1vad = 1 degree of visual angle
Examples:
body {
    font-size: 0.6vad;
}

h1 {
    font-size: 1.7vad;
}

small {
    font-size: 0.48vad;
}

Website programmer can decide what vad numbers should be used in the page display.
The exact mapping from vad to a used CSS length would be defined by browser’s calculation when viewing pages.
________________________________________
Mathematical Model:
For a desired visual angle θ in degrees, an object is viewed from distance D, the object physical height H in the screen should be:
H = 2 * D * tan (θ/2)
For small angles, this can be approximated to:
H ≈ D * θ / 180 * π

If first regarding a height H is desired for a distance D, the desired vad number that should be written in CSS line is:

θ=2 * arctan (H / 2 / D) ≈ H / D rad ≈ H / D / π * 180 degrees.

A visual angle degree unit naturally maintains the viewing physical effect of text for most common viewing distance for a screen, no matter the screen type, nor the screen’s pixels size, nor the screen’s physical size.
Thus, when programmer is writing CSS codes in order to letting future viewer feel most satisfied, he do not need know what type the view will use in future.
When a future view watch the words, the words pixels will be decided and shown on screen by the browser with communication with the display equipment at that time.
________________________________________
Reference Viewing Model:
A user agent could initially use a standardized reference viewing model.
Possible approaches include:
1. Fixed default reference distance:
For example:
Default reference viewing distance = 50 cm

If cannot communicate to the display, or the display screen is too old type, it can be adopted by the browser.
2. Device-class reference distance:
The user agent could use empirical reference distances for different device classes, for example:
smartphone       ≈ 38 cm
laptop           ≈ 45 cm
desktop display  ≈ 55 cm
television       ≈ 300 cm
These values are illustrative and would require empirical investigation or impartially voted by public.
3. Future platform information:
Future platforms may provide additional information about:
•	display physical dimensions; 
•	display density; pixels;
•	Suggested viewing distance; 
•	user preferences settings; E.g., browser can regard it as the real viewing distance.
•	Maybe headset/VR viewing geometry. 
The specification could allow such information to improve the conversion while retaining a standardized fallback.
________________________________________
Use Cases:
1. Laptop vs. large television/display screen:
The same CSS:
body {
    font-size: 0.6vad;
}
could theoretically produce physically larger text on a television than on a laptop while maintaining approximately the same intended visual angle.
________________________________________
2. Large displays:
Large displays in:
•	conference rooms; 
•	classrooms; 
•	control rooms; 
•	public information systems; 
are often viewed from substantially much greater distances than desktop monitors.
A perceptual unit would allow typography to be specified in terms of the intended visual scale rather than arbitrary CSS pixels.
________________________________________
3. Digital signage:
Digital signage can involve extremely large displays viewed from several meters away.
A fixed pixel size is poorly suited to describing typography for such environments. 
________________________________________
4. Smartphone:
Most smartphone screen physical height does not differ too much. Even it differs too much, it has no problem.
Because the communication between browser and screen controller, the browser knows the screes all specification like physical height and pixels. This enable browser can calculate how many physical pixels should be used to show the words. In obscure cases, if browser cannot know the screen specification information, default numbers (like supposing its height pixels are 2400, physical height is 155mm) can be used, and will work very well for most cases.

________________________________________
5. Accessibility:
A visual-angle-based text preference could potentially provide a more device-independent way of expressing minimum readable text size.
Browser zoom and operating-system accessibility settings should remain authoritative.
________________________________________
Relationship to Existing CSS Units:
vad would be additive rather than a replacement.
For example:
body {
    font-size: 0.6vad;
}

.logo {
    width: 5rem;
}

.container {
    width: 70vw;
}
Different units would therefore serve different purposes:
px       CSS coordinate sizing
mm       physical/reference sizing
rem/em   document-relative sizing
vw/vh    viewport-relative sizing
vad       perceptual visual sizing
________________________________________
Backward Compatibility:
Existing CSS would remain unchanged.
For example:
font-size: 18px;
would continue to work exactly as before.
A fallback could be written as:
body {
    font-size: 18px;
    font-size: 0.6vad;
}
Browsers that do not support vad can ignore the second declaration and use the fallback.
________________________________________
More thought or questions:
1.	Should vad be limited to typography?:
Could it eventually be useful for:
o	icons; 
o	controls; 
o	focus indicators; 
o	interactive targets; 
o	other perceptual UI dimensions?  
2.	How should the unit behave when a browser window moves between displays?:
Some users use two and even three monitor with the same computer. I think this can be solved and supported by operation system, or by browser, or their negotiating in time and before the vad sizing international standard is published. 
3.	Should user-agent accessibility preferences be able to modify the effective visual angle? :
Viewers often move forwards and backwards from screen. I suppose screen should not react to this movement. Just allowing viewers have the rights to change the screen’s virtual preferable watching distance is enough, then the browser take it to replace the standard viewing distance
4.	Why I propose using vad, not deg, not vd, not vdeg?:
Because vad can be spoken loudly and quickly, this help discuss the words and fonts size among programmers. Deg name has been used in CSS. vdeg is some long causing more typing time, and can not be orally spoken quickly.
________________________________________
Design Principle:
The central principle of this proposal is:
CSS should be able to express not only the geometric size of content, but also its intended perceptual angle size to a human observer. Same vad number will have same viewing angle in any type of displaying screen.
CSS already provides abstractions for:
•	document-relative sizing; 
•	viewport-relative sizing; 
•	CSS coordinate sizing; 
•	physical/reference lengths. 
A visual-degree unit would provide an additional abstraction for human visual perception.
I am proposing this as a discussion topic rather than as a fully specified implementation.

## @Crissov — 2026-08-24

`px` is literally called the *visual angle unit* and the [_reference pixel_](https://drafts.csswg.org/css-values-4/#reference-pixel) is defined as the “visual angle of one pixel on a device with a device pixel density of 96dpi and a distance from the reader of an arm’s length”.

ISO 9241 recommends a viewing distance of 50 cm to 70 cm in a desktop setting. A 265-&mu;m device pixel measures about 1.8&prime; at 50 cm, 1.5&prime; at 60 cm or 1.3&prime; at 70 cm viewing distance.  The proposed `vad` or `vd` unit should therefore correspond to something between `33px` and `46px`. 
However, CSS Values and Units gives “0.0213 degrees”, i.e. 1.278&prime;, for a rather large “arm’s length” viewing distance of 28 inches or 71 cm, which suggests almost `47px` for `1vad`. 

With an arbitrarily chosen 45:1 ratio, a visual arc minute, or `1vam`, would be exactly `0.75px` – while `1px` = `0.75pt`. To justify this nice-ish relationship, the nominal viewing distance for that 96-dpi screen would need to change to about 68.2 cm or a bit less than 27 inches. 

Likewise, to make `1vam` equal `0.2mm` or `0.8q` (and therefore `1vad` equal `12mm`), the nominal distance should be 68.75 cm or roundabout 27 inches.

To make `1vad` even equal `1cm`, <!--37.8 px/vad--> the viewing distance needed to be just 57.3 cm or slightly more than 22.5 inches, which seems like a substantive change.
