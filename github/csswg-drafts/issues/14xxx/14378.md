Proposed by: Waylon Shao, China, 2026-08-24, E-mail: waylon_shao@163.com.

________________________________________
Summary:

CSS provides units for CSS lengths (px, em, rem), physical/reference lengths (mm, in), and viewport-relative lengths (vw, vh).
However, CSS currently lacks a unit that directly expresses perceptual visual size.
I propose introducing a new unit:
vad
where:
1vad = 1 degree of visual angle in reality when the distance between eyes and screen is normative.

vad means visual angle in degrees.
For example:
body {
    font-size: 0.6vad;
}
would indicate that the intended typographic height is approximately 0.6 degrees of visual angle under the applicable viewing model.
The goal is not to replace px nor existing CSS units, but to provide a new more accurate viewing similarity among various types of screen for a same webpage.
________________________________________
Motivation and Mathematical Model:

The same physical text size does not produce the same perceived size on different display environments. The problems of font size on different types of screen, have troubled me about one years. I think huge amount of website programmer have been meeting this kind of problems and trouble. So I decide to think and write to find this way to solve it for the world.

For example, consider:
•	a 15.6-inch laptop viewed at approximately 45 cm; 
•	a 6.6-inch smartphone viewed at approximately 38 cm; 
•	a 75-inch television or display screen wildly used in companies' meeting room viewed at approximately 3 meter. 
Suppose a glyph is physically 5 mm high on a 15.6-inch laptop.
The laptop pixels are 1920x1080. The screen height = 15.6*25.4*sin(arctan(1080/1920))=194.26 mm, px/mm=5.56, px/mm=5.560
The smartphone pixels are 2340x1080 which is very popular. Its screen height=6.6*25.4*cos(arctan(1080/2340))= 151.21 mm, px/mm=15.373
The 75-inch screen pixels are 3840x2160. The screen height = 75*25.4*sin(arctan(2160/3840))=933.95 mm, px/mm=2.313
Thus, 
5 mm glyph occupies 5*5.56=27.8 pixels (of course, it will be displayed with 28 pixels) on laptop.
Suppose the glyph is full high without any space in height.
If wanting it appears accurately 5 mm high on laptop, CSS code must be font-size: 27.8px.
When using smartphone, DPR is 1, browser also uses 27.8px to show it, occupying a height =27.8/15.373=1.8083 mm
When user use big screen to view this webpage, DPR is 2, browser use 2*27.8=55.6 pixels to show it. Its height will be 55.6*2.313=24.04 mm.
Viewing Angle Calculating:
At a viewing distance of 45 cm to laptop, its visual angle is approximately:
5 mm / 450 mm ≈ 0.0111 rad ≈ 0.637°. 
At a viewing distance of 38 cm to smartphone:
1.8083 / 380 mm ≈ 0.004759 rad ≈ 0.2727°, causing viewer feel words too small.
At a viewing distance of 3 m to big screen:
24.04 mm / 3000 mm ≈ 0.00801 rad ≈ 0.459°, causing viewers feel the words are a little smaller than they looks in laptop.

For a desired visual angle θ in degrees (like 0.637°), an object is viewed from distance D, the object physical height H in the screen should be:
H = 2 * D * tan (θ/2)
The needed screen physical pixels is = H * px/mm
The px/mm can be easily calculated by browser after communicated to screen controller and get its pixels number and physical size.

Note: For small angles, this can be approximated to:
H ≈ D * θ / 180 * π
If first regarding a height H is desired for a distance D, the desired vad number that should be written in CSS line is:
θ=2 * arctan (H / 2 / D) ≈ H / D rad ≈ H / D / π * 180 degrees.

Because the browser can know screen's pixels and physical mm through communication link, it can calculating how many physical pixels it should output to screen to keep the same designed visual angle as viewing to a standard 15.6-in laptop.

On the above, we already calculated and known the px/mm for three typical screens.

For the 15.6-inch laptop:
Needed height to show 0.636° certainly equals its original height = 5 mm.
Needed pixels to show this angle=5*5.56=27.8 physical pixels.
The rest thing has no problem, just electronically shows these physical pixels.

For the 6.6-inch smartphone:
Needed height to show 0.637° =2*380*tan(0.637°/2)=4.225 mm.
Physical pixels to accurately show 0.637° = 4.225*15.373=64.95 physical pixels.
For the 75-inch big screen:
Needed height to show 0.637° =2*3000*tan(0.637°/2)=33.354 mm.
Physical pixels to accurately show 0.637° = 33.354*2.313=77.15 physical pixels.
The above formula and sample calculation proves this perfect displaying way to use vad angle unit in CSS can be solved by the browser with communication to screen controller to know its basic specification.
Certainly, final deciding displaying pixels must take account of browser page zoom ratio and operation system zoom ratio.

The root reason for this problem is CSS px does not consider that the viewing distance varys quite different for various types of screen, while users often view 38 cm or 3 m words, and px did not consider smartphone is portrait.
To maintain approximately the same visual angle, the physical size of the text should increase when the viewing distance increases, as well as DPR should continue to be used to take consideration of high density pixels screens.
vad does not have fixed ratio to CSS px, nor to physical pixels. It only keeps fixed visual angle that the object gives eyes. With written vad value like 0.6vad in CSS, browser calculates the needed physical pixels just before webpage needs it to show, as per the specification that browser gets from communication with screen controller at that moment or when screen is connected to browser. The calculating is based on the custom preferrance viewing distance by viewer, or the specification that the screen will have told browser or operation system, or the default international standard distance for a specific screen.
My aim is to adopt vad as a new unit, in order programmers do not need to consider future screen type, nor their pixels, nor their physical mm, nor need to make complex CSS codes in order to suit different type of screen, and user viewers opening the webpage will see the same visual angle whatever the screen types they will use, only if they keep the standard distance from the screen.
When a future viewer open the webpage, the words pixels will be decided and shown on screen by the browser with communication with the display equipment at that time.
For example:
A programmer only write a very simple line with CSS:
body {
    font-size: 0.6vad;
}
There will be perfect viewing angle effect in any types of screen. 
________________________________________
Backward Compatibility:

Existing CSS would remain unchanged.
For example:
font-size: 18px;
would continue to work exactly as before.
A fallback could be written as:
body {
    font-size: 18px;
    font-size: 0.6vad;
}
Browsers that do not support vad can ignore the second declaration and use the fallback.
________________________________________
Why Not Just Use px, mm, vh, or vw?:

px:
A fixed CSS pixel size does not maintain a consistent visual angle when viewing distance changes.
If using CSS cods to specially decide the pixels for smartphones, it increase programmer's codes lines, and sometimes codes do not work, and programmers have to spend much time to find root reasons. The much the CSS codes have the line numbers, the difficult programmer to solve bugs.
When in large screen like 75 inch TV or screen in companies' meeting room, and distance is 3 m and more, px will make the words some small, viewers feel difficult to distinguish the words.
If regarding 1px as 1/96 inches, it seems having no relationship to distance. 16px = 16 / 96 * 25.4 = 4.233 mm. The same 4.233 mm fonts on a smartphone, or on a laptop, or on a desktop, or on a very big size meeting room screen and even huge screen in airport and railway station, has quite different visual effect.
mm:
Fixed mm cannot suit various sizes and types of screen. E.g., displaying same 5 mm on smartphone and 75-inch big screen, the visual effect differs too much. If adjusting height on different types of screen, this looses mm original meaning.
vh:
The vh/vw depends on the viewport, not the display screen pixels/size. When user zoom the viewport window to about half of the screen height, words will shrink to half height. This is not expected nor hoped by user. My new CSS unit vad can solve this shortcoming, because vad keep words same height after viewport window is zoomed smaller. Viewport height % vh can be a useful approximation in some situations, but it still describes the viewport rather than perceptual size when viewing distance vary in different screen type. For different displaying equipment type, and for different screen physical size with same resolution pixels, same vh like 2% do not have the same viewing angle and effect.
vw:
Viewport width is not a reliable proxy for viewing distance. If future viewers use ultrawide monitor with desktop, it will make the words too large. But my vad will not.

If wanting good viewing effects for a same webpage on various types of screen, all the above existing units require webpage programmers to write several or even several tens of more codes. If webpages are complex and issues and bugs in them occur, finding their CSS root reasons costs too much time, most programmer including me do not like this work.

If using my vad unit, only one line of CSS code is needed, it will automatically works perfectly for any types of screen that the future viewers will use.

________________________________________
Proposed Syntax:

The basic syntax would be like:
font-size: 0.6vad;
with the conceptual definition:
1vad = 1 degree of visual angle
Examples:
body {
    font-size: 0.6vad;
}

h1 {
    font-size: 1.7vad;
}

small {
    font-size: 0.48vad;
}

Website programmer can decide what vad numbers should be used in the page display.
The exact mapping from vad to a used CSS length would be defined by browser's calculation when viewing pages.
________________________________________
Reference Viewing Model:

A user agent could initially use a standardized reference viewing model.
Possible approaches include:
1. Fixed default reference distance:
For example:
Default reference viewing distance = 50 cm

If cannot communicating to the display, or the display screen type is too old, it can be adopted by the browser.
2. Device-class reference distance:
The user agent could use empirical reference distances for different device classes, for example:
smartphone       ≈ 38 cm
laptop           ≈ 45 cm
desktop display  ≈ 55 cm
television       ≈ 300 cm
These values are illustrative and would require empirical investigation or impartially voted by public.
3. Future platform information:
Future platforms may provide additional information about:
•	Suggested viewing distance; 
•	user preferences settings; E.g., browser can regard it as the real viewing distance.
The specification could allow such information to improve the conversion while retaining a standardized fallback.
________________________________________
Relationship to Existing CSS Units:

vad would be additive rather than a replacement.
For example:
body {
    font-size: 0.6vad;
}

.logo {
    width: 5rem;
}

.container {
    width: 70vw;
}
Different units would therefore serve different purposes:
px       CSS coordinate sizing
mm       physical/reference sizing
rem/em   document-relative sizing
vw/vh    viewport-relative sizing
vad       perceptual visual sizing

More Thought or Questions:

1.	Should vad be limited to typography?:
Could it eventually be useful for:
o	icons; 
o	controls; 
o	focus indicators; 
o	interactive targets; 
o	other perceptual UI dimensions?  
2.	How should the unit behave when a browser window moves between displays?:
In companies' meeting room, there are often 75 and even 100 inches big screen for webpage showing, as well as some laptops that the attendees own showing the same webpage as the big screen. And one laptop or desktop output two displaying links, one to computer or laptop screen, another to the big screen.
Some users use two and even three monitor with the same computer.
I think this can be solved and supported by operation system, or by browser, or graphics card, or their negotiating when just needing to display the page. And their corporations and CSSWG can discuss and make a new vad sizing international standard to thoroughly solve this questions, and current displaying shortcomings listed above.
3.	Should user-agent accessibility preferences be able to modify the effective visual angle? :
Viewers often move forwards and backwards from screen. I suppose screen should not react to this movement. Just allowing viewers have the rights to change the screen's virtual preferable watching distance is enough, then the browser take it to replace the standard viewing distance
4.	Why I propose using vad, not deg, not vd, not vdeg?:
Because vad can be spoken loudly and quickly, this help discuss the words and fonts size among programmers, better than vd. The deg name has been used in CSS. vdeg is some long causing more typing time, and cannot be orally spoken quickly.
5.	Some people maybe think same angle is a little big for smartphone because of its width is narrow, this can be bettered by browser company from the above caculation formulas.
E.g., for the formula H = 2 * D * tan (θ/2), browser can change it to be: H = F * 2 * D * tan (θ/2) with F to be 0.8, when it find the screen is smartphone. With F set to be 0.8 in smartphone's setting and in browser's setting as default, F number can be changed by user. Browser take user's setting as preferance to adopt. This mean user can adjust the general sizing level to all webpages. Thus, the calculated H value becomes smaller, causing subsequent needed physical pixels becomes less and the words on smartphone becomes smaller. However, I do not hope that programmers have to make different special CSS codes lines or Javascript lines in many webpages specially for various types of screen.
6. Crissov in GitHub studied my last post, he propsed a unit of vam (visual angle of minutes), 1vad = 60vam, thus no need to write and say point for small fonts.
________________________________________
Design Principle:

The central principle of this proposal is:
CSS should be able to express not only the geometric size of content, but also its intended perceptual angle size to a human observer. Same vad number will have same viewing angle in any type of displaying screen.
CSS already provides abstractions for:
•	document-relative sizing; 
•	viewport-relative sizing; 
•	CSS coordinate sizing; 
•	physical/reference lengths. 
A visual-degree unit would provide an additional abstraction for human visual perception.
I am proposing this as a discussion topic rather than as a fully specified implementation.

## @Crissov — 2026-08-24

`px` is literally called the *visual angle unit* and the [_reference pixel_](https://drafts.csswg.org/css-values-4/#reference-pixel) is defined as the “visual angle of one pixel on a device with a device pixel density of 96dpi and a distance from the reader of an arm’s length”.

ISO 9241 recommends a viewing distance of 50 cm to 70 cm in a desktop setting. A 265-&mu;m device pixel measures about 1.8&prime; at 50 cm, 1.5&prime; at 60 cm or 1.3&prime; at 70 cm viewing distance.  The proposed `vad` or `vd` unit should therefore correspond to something between `33px` and `46px`. 
However, CSS Values and Units gives “0.0213 degrees”, i.e. 1.278&prime;, for a rather large “arm’s length” viewing distance of 28 inches or 71 cm, which suggests almost `47px` for `1vad`. 

With an arbitrarily chosen 45:1 ratio, a visual arc minute, or `1vam`, would be exactly `0.75px` – while `1px` = `0.75pt`. To justify this nice-ish relationship, the nominal viewing distance for that 96-dpi screen would need to change to about 68.2 cm or a bit less than 27 inches. 

Likewise, to make `1vam` equal `0.2mm` or `0.8q` (and therefore `1vad` equal `12mm`), the nominal distance should be 68.75 cm or roundabout 27 inches.

To make `1vad` even equal `1cm`, <!--37.8 px/vad--> the viewing distance needed to be just 57.3 cm or slightly more than 22.5 inches, which seems like a substantive change.
