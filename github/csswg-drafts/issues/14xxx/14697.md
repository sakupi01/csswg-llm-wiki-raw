Currently, per CSS cascade, transition rules override all levels of the cascade, including user-agent `!important` rules.

That usually wouldn't be very problematic because those rules are (usually) not changing and thus not triggering transitions (though there are exceptions!).

But there's the issue that via web animations you can:

 * Retarget a transition from one element to another (via `KeyframeEffect.target`).
 * Override the keyframes of a random transition to transition another property.

This causes rules that are supposed to be invariant to break. Here's a test-case that shows a red backdrop incorrectly in Blink, because we force `overlay: auto` on a random element. Note that the element doesn't have to be a `popover`, but that just proves that it overrides the `overlay: none !important`:

<details>

```html
<!doctype html>
<style>
  #target {
    transition: all 0.5s allow-discrete;
    background: green;
    font-size: 0px;
    width: 100px;
    height: 100px;
    position: absolute;
    top: 0;
    left: 0;

    &.tweak {
      /* Trigger a random transition */
      font-size: 20px;
    }
  }
  #target::backdrop {
    position: fixed;
    background: red;
    inset: 0;
  }
</style>
<div id="target"></div>
<script>
  target.getBoundingClientRect();
  target.classList.add("tweak");
  let anim = target.getAnimations()[0];
  anim.effect.setKeyframes([{ overlay: "auto" }, { overlay: "auto" }]);
  anim.pause();
</script>
```
</details>

(Note that `getComputedStyle()` in blink lies here: https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/css/properties/longhands/longhands_custom.cc;l=12487-12502;drc=cd1353540baa7888b33d30c7d00c5afb15c247db).

I propose that we should swap the transitions cascade order with the UA `!important` origin. I've implemented this in Firefox (https://bugzilla.mozilla.org/show_bug.cgi?id=2081760) (though I just realized that the WPT I added passes in Blink / WebKit because the implement that with C++ magic, so I'll write another one that shows the issue in Blink / WebKit).

## @tabatkins — 2026-11-11

> I feel like this is surprising even for authors that transitions override their own !important rules.

Well, note that before the Web Anim API, transitions could *only* be kicked off by CSS changes, and so they *had* to be above author !important rules *precisely so* they'd actually do something when the ending style was !important. Otherwise the !important value would win and the transition would kick off but do absolutely nothing visible! Remember that there's no phase where *just* the transition applies; it's always operating *on top of* the ending style.
