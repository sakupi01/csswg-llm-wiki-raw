While reviewing [a CL](https://crrev.com/c/8398770) from @johannesodland to update Chromium's behavior to the current spec for `::first-letter`, I noticed that the [exact definition](https://drafts.csswg.org/css-pseudo-4/#first-letter-pattern) of what text is allowed in the `::first-letter`depends on the term "intervening typographic space".  The formal definition has a note following, with a regex and a railroad diagram explaining that regex that I think is intended to clarify what "intervening" means.  However, I think there are two issues here:

1. It should be clear enough from the normative prose what is meant without having to read the note; I don't currently think this is the case.  For example, for what is allowed before the "letter" character, it seems that "intervening" means that spaces are allowed *after* the first punctuation character but not before it.
2. I think the regex and railroad diagram are likely wrong.  In particular, for the characters *following* the `::first-letter`, the note allows spaces *after* the last punctuation character, but not *before* the first following punctuation character.  I think the intent of "intervening" in the normative text seems like it means (and probably ought to mean) that the whitespace characters have to be between other non-whitespace characters that are included in the first letter, which makes me think the note describing what is meant has the after-the-letter part backwards.
