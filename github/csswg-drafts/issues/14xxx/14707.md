Spec: https://drafts.csswg.org/css-values-5/#boolean

The production block that spells out `<boolean-expr[]>` defines two types:

```
<boolean-expr[ <test> ]> = not <boolean-expr-group> | <boolean-expr-group>
                                            [ [ and <boolean-expr-group> ]*
                                            | [ or <boolean-expr-group> ]* ]

<boolean-expr-group> = <test> | ( <boolean-expr[ <test> ]> ) | <general-enclosed>
```

Only `<boolean-expr>` is a definition (`<dfn type><<boolean-expr>></dfn>` in the prose above the block, `#typedef-boolean-expr` in the draft). `<boolean-expr-group>` has no `<dfn>`, so the draft has no `#typedef-boolean-expr-group`, its uses in the block link nowhere, and tools that read the spec's definitions, webref's extract and `@webref/css` among them, get a `<boolean-expr>` whose syntax names a type that does not exist.

### Steps to reproduce

1. Open https://drafts.csswg.org/css-values-5/#boolean and hover or click any `<boolean-expr-group>` in the production block.
2. Open https://drafts.csswg.org/css-values-5/#typedef-boolean-expr-group.
3. Run the checker in https://gist.github.com/YevheniiKotyrlo/37e27e9c5a82563ee8db8a12779f098c (Node 18 or later), which reads the Editor's Draft, webref's `ed/css/css-values-5.json` on `main` and the newest `@webref/css`, and exits 1 while the draft has no `#typedef-boolean-expr-group`:

```sh
git clone https://gist.github.com/37e27e9c5a82563ee8db8a12779f098c.git boolean-expr-group
cd boolean-expr-group
node check-boolean-expr-group.mjs
```

**Expected:** `<boolean-expr-group>` is a definition like `<boolean-expr>`: its uses link to `#typedef-boolean-expr-group`, and the extracts carry it beside `<boolean-expr>`, whose definition stays as it is.

**Actual:** it is plain text in the block, the anchor does not exist, and neither extract has it:

```
node v26.12.1; csswg-drafts main at cb8227b68d1b67b905744e24c31d6633de52511a; webref main at 451d8bd646abc4186eb859aaccb358dc7a0959a8
Editor's Draft defines #typedef-boolean-expr: true
Editor's Draft defines #typedef-boolean-expr-group: false
Editor's Draft writes <boolean-expr-group>: 5 times
webref main ed/css/css-values-5.json has <boolean-expr>: true
webref main ed/css/css-values-5.json has <boolean-expr-group>: false
@webref/css@8.7.8 <boolean-expr> syntax: not <boolean-expr-group> | <boolean-expr-group> [ [ and <boolean-expr-group> ]* | [ or <boolean-expr-group> ]* ]
@webref/css@8.7.8 has boolean-expr-group: false
SUMMARY: the Editor's Draft writes <boolean-expr-group> 5 times and defines it nowhere: #typedef-boolean-expr-group does not exist
```

A `<dfn>` cannot go inside the `<xmp class=prod>` itself, so the second production's type could be defined in the prose, as the first one's is.
