This issue is a follow-up to https://github.com/w3c/csswg-drafts/issues/13609 which is about adopting the design principle that `appearance: base` controls should be polished enough to be acceptable in production out of the box. This reduces the load on the web developer--potentially to zero--while also (paradoxically perhaps) making it easier for them to customize `appearance: base` controls.

What would it mean for us to implement that principle in the UA style sheet? Maybe if we answer this concrete question first, we can better understand and phrase the principle.

Apple has been prototyping some possible improvements to the UA style sheet along these lines, and would like to show how that concretely makes `appearance: base` form controls more usable for both authors and users.

**Update: See [Jen's slides](https://github.com/user-attachments/files/30839445/proposal.for.customizable.select.UA.styles.pdf) for a walk-through and explanation.**

Issue breakdown of the proposed changes:

* [Adopt box-sizing on all form control parts](https://github.com/w3c/csswg-drafts/issues/14249)
* [Inherit all typography, but not into icons](https://github.com/w3c/csswg-drafts/issues/14250)
* [Improve the picker icon](https://github.com/w3c/csswg-drafts/issues/14317)
* [Use empty alt for ::picker-icon and ::checkmark](https://github.com/w3c/csswg-drafts/issues/14316)
* [Vertically center form control contents](https://github.com/w3c/csswg-drafts/issues/14319)
* [Apply overflow and wrapping control to select button contents](https://github.com/w3c/csswg-drafts/issues/14255) (see also [#14323](https://github.com/w3c/csswg-drafts/issues/14323))
* [Apply flex:1 to button contents instead of auto margin to ::picker-icon](https://github.com/w3c/csswg-drafts/issues/14395)
* [Refine base appearance colors by using reduced border-color](https://github.com/w3c/csswg-drafts/issues/14254)
* [Refine internal spacing for all base appearance controls](https://github.com/w3c/csswg-drafts/issues/14321)
* [Apply border-radius to all base appearance controls](https://github.com/w3c/csswg-drafts/issues/14308)
* Improvements to ::picker() sizing: see [#14172](https://github.com/w3c/csswg-drafts/issues/14172) and [#14273](https://github.com/w3c/csswg-drafts/issues/14273)
* [Add 4px margin between select picker and button](https://github.com/w3c/csswg-drafts/issues/14324)
* [Use system colors for (prefers-contrast) and (forced-colors) defaults](https://github.com/w3c/csswg-drafts/issues/14318)
* [Inherit color into picker](https://github.com/w3c/csswg-drafts/issues/14322)
* [Adopt box-shadow on ::picker()](https://github.com/w3c/csswg-drafts/issues/14252)
* [Specify appropriate cursors](https://github.com/w3c/csswg-drafts/issues/14251)
* [Animate picker between open and closed states](https://github.com/w3c/csswg-drafts/issues/14325)

* [Specify appropriate cursors](https://github.com/w3c/csswg-drafts/issues/14251)
* [Animate picker between open and closed states](https://github.com/w3c/csswg-drafts/issues/14325)

Let's keep this issue for discussion on the overall direction, and tackle specifics in the individual issues.

One thing to keep in mind when reviewing the changes: specificity doesn't matter. **A declaration of any specificity in the author cascade origin (even zero) will override *every* declaration of that same property in the UA stylesheet.** For example, if we do something clever with `border-color` to represent state changes (like focus or disabled), a mere `select { border-color: ...; }` declaration by the author will blow all of that away. So don't worry about specificity. Worry about if this is a good default that the author will most likely appreciate and otherwise find easy to identify the property to change.
