Given we have syntax for specifying a [color image](https://drafts.csswg.org/css-images-4/#image-notation), `image(<color>)`, I think we should consider removing support for special syntax in [cross-fade()](https://drafts.csswg.org/css-images-4/#cross-fade-function) components to specify a color (e.g. `<cf-image> = [ <image> | <color> ] && <percentage [0,100]>?`).

It comes down to whether:

```css
background-image: cross-fade(url(foo.png) 50%, red);
```

is sufficiently better than:

```css
background-image: cross-fade(url(foo.png) 50%, image(red));
```

An alternative simplification, would canonicalizing a `<color>` to `image(<color>)` (or vice-versa) for computed values.

WebKit has not shipped support for `<color>` on its own in `cross-fade()`, so I don't think there is a huge compatibility risk, but I could be wrong.
