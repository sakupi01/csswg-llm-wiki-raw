[`3.2 Styling Highlights`](https://drafts.csswg.org/css-pseudo-4/#highlight-styling) enumerates the list of allowed properties as:

- `color`
- `background-color`
- `text-decoration`
- `text-shadow`
- `stroke-color`
- `fill-color`
- `stroke-width`
- custom properties

One of the big reasons to avoid all properties is that these highlight elements should not effect layout, however there are some non-layout effecting declarations which would be very useful:

- `caret-color` (& `caret-shape`, `caret-animation`)
- `cursor`
- `outline` (& `outline-width`,`outline-style`,`outline-color`)
- `opacity`

These predominantly are useful around interactivity, such as changing the caret color to match the hue of the highlight type while keying through the highlight, or changing the cursor from the caret selection to the hand icon to cue the user that there is interactivity behind the highlight.

It's not just due to the "affect layout" constraint, fwiw. `opacity` needs to introduce a stacking context and it seems like it'd be complicated to define what the stacking order is there, specially if the highlight isn't contained to the same stacking context.

The others look ok to support I think.
