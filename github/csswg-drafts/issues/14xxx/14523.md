[A recently-added WPT test](http://wpt.live/css/css-fonts/synthetic-bold-does-not-widen-advances.html) asserts that:

> `<title>Synthetic bold must not change a run's measured advance width</title>`

with a link to the Fonts spec:

> `<link rel="help" href="https://drafts.csswg.org/css-fonts-4/#font-synthesis-weight">`

However, AFAICS the spec here says nothing about the impact (or not) of synthetic bold on advance widths.

Given that for most font families, a bold face tends to be somewhat wider than a regular one, it seems only natural that when a browser synthesizes a bold face (in the absence of a true bold face), it may also adjust advance widths to avoid overcrowding the emboldened glyphs.

Should we have a note in the spec to explicitly mention that synthetic emboldening _may_ affect glyph advances and therefore text measurement, to make it clear that this test expectation is flawed?

Or do we want to mandate that synthetic-bold _must not_ affect glyph advances, as this new test wants to assert? That would be a new constraint on how browsers are allowed to implement the effect. Is it desirable?

> Should we have a note in the spec to explicitly mention that synthetic emboldening _may_ affect glyph advances and therefore text measurement, to make it clear that this test expectation is flawed?

That would be consistent with existing practice.

> Or do we want to mandate that synthetic-bold must not affect glyph advances, as this new test wants to assert? That would be a new constraint on how browsers are allowed to implement the effect. Is it desirable?

That would likely reduce legibility, and does not seem desirable in general.  (If it *was* seen as desirable, it should be an opt-in with a new value for `font-synthesis-weight`, such as `grade`).

Instead, the WPT should be corrected.
