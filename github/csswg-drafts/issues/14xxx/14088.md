- renders as black
- computed `color(display-p3 0 0 0)`

## @weinig — 2026-06-27

I think the underlying question here is actually how should color conversions work in the face of maximum-finite-value component values.

For example, in your example above:

```
color(from color(srgb calc(Infinity) 0.2 0.3) display-p3 r g b)
```

to resolve this, the origin color, `color(srgb calc(Infinity) 0.2 0.3)`, must be converted to `display-p3` so it can be used by the relative color syntax.

But, is that color conversion well defined?

The first step seems well defined, and its evaluating the calc expression, turning `color(srgb calc(Infinity) 0.2 0.3)` into `color(srgb {max-finite-value} 0.2 0.3)` ("[Infinities](https://drafts.csswg.org/css-values-4/#css-infinity) do not escape a [top-level calculation](https://drafts.csswg.org/css-values-4/#top-level-calculation); they’re clamped to the minimum or maximum value allowed in the context, as defined in [§ 10.12 Range Checking](https://drafts.csswg.org/css-values-4/#calc-range)." - https://drafts.csswg.org/css-values-4/#css-infinity)

The second step would be converting `color(srgb {max-finite-value} 0.2 0.3)` to linear-srgb by applying the inverse gamma function on each component. In WebKit, that function looks something like:

```
float toLinearSRGB(float c)
{
        auto sign = std::signbit(c) ? -1.0f : 1.0f;
        c = std::abs(c);

        if (c <= 0.04045f)
            return c / 12.92f * sign;
        return std::pow((c + 0.055f) / 1.055f, 2.4f) * sign;
}
```

For that first component that started as `calc(Infinity)` and is now `{max-finite-value}` (or FLT_MAX in WebKit), the call to toLinearSRGB will return INFINITY.

So, the question becomes, does that INFINITY also get clamped to `{max-finite-value}`? Or should the rest of the color conversion math continue with the infinity in place?

@romainmenke I am curious how your implementation deals with this? How do you avoid saturating to +infinity during conversion to display-p3?

## @tabatkins — 2026-06-29

It is indeed up to the implementation (in general, intentionally undefined, because we don't specify exactly what supported value ranges are) how precisely to treat infinity. The spec only mandates that math functions clamp to the allowed range, whatever that is in the given calculation context. There is intentionally zero difference between `calc(infinity)` and `1e1000`; both are too large to actually be stored, and will instead be treated as some maximum value.

(We keep getting these sort of questions about `calc(infinity)` in various contexts. What needs to be fixed in the spec to make it clearer that it's exactly identical to just using an incredibly large value, and thus already has well-defined behavior?)
