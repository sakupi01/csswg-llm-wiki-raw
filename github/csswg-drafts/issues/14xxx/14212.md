https://drafts.csswg.org/css-mixins-1/#function-rule specifies that:
- the default value of a parameter is `<declaration-value>` which does not accept `!important`
- the function body is `<declaration-rule-list>` which *could* accept `!important` on declarations

`!important` doesn't seem particularly useful to me in the context of a function or mixin local or parameter, but I wanted to raise the issue to clarify.
Blink's implementation of functions currently drops declarations with it: https://codepen.io/kevinbcmu/pen/bNgjLxM

<!-- comment id=5040244897 author=tabatkins created=2026-07-21T23:51:27Z url=https://github.com/w3c/csswg-drafts/issues/14212#issuecomment-5040244897 -->
## @tabatkins — 2026-07-21

In parameters (function or mixin), no, invalid. They're not declarations.

In mixin body, yes, it should be valid. The body of a mixin is just a style rule.

In function body, it doesn't seem necessary to support; the locals don't have anything else to cascade against except each other. I don't have an opinion on whether it's valid or invalid to have `!important`, and am happy to match Blink's behavior of making it invalid.

## @kbabbitt — 2026-07-22

> In mixin body, yes, it should be valid. The body of a mixin is just a style rule.

Oh right, that makes sense for mixin results. Not sure it does for mixin locals, or `@locals` block contents if we end up adopting that - they also don't have anything to cascade against except each other, right?

Though now I find myself wondering if we should just accept `!important` and drop it, so that a declaration cut-and-pasted from elsewhere still works.
