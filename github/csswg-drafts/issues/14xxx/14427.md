## @kbabbitt — 2026-09-15

Oh, I see [the current spec draft](https://drafts.csswg.org/css-mixins-1/#private) has:
> It is not exposed to the page via any CSSOM APIs. (For example, [CSSStyleDeclaration](https://drafts.csswg.org/cssom-1/#cssstyledeclaration).[getPropertyValue()](https://drafts.csswg.org/cssom-1/#dom-cssstyledeclaration-getpropertyvalue) can’t get its value, the [CSSStyleDeclaration](https://drafts.csswg.org/cssom-1/#cssstyledeclaration) enumeration won’t contain them, etc.) It is only accessible to styles in the same [style rule](https://drafts.csswg.org/css-syntax-3/#style-rule) that defined them, or its nested rules.

I *think* the intent was that private properties are not exposed on the CSSOM for computed style declarations, or for the containing style rule. But if you have a CSSOM object for the `@private` rule itself, it seems to me you should be able to read and write the properties in it, even though they're private. So the text probably needs to be tweaked a bit to account for that.
