Browsers create `CSSImportRule.styleSheet` synchronously (except if its import conditions evaluate to false), because it was not nullable before b6a233e. If backward-compatibility does not allow for a change (`null` until loaded), my suggestion is to clarify this, as well as the expected behavior when you try to insert a rule in a loading style sheet:

```html
<style></style>
<div></div>
<script>

  const sheet = document.styleSheets[0]
  sheet.insertRule('@import "data:text/css,div::after { content: %221%22 }"')
  const loadingSheet = sheet.cssRules[0].styleSheet

  loadingSheet.insertRule('div::after { content: "2" }')
  new Promise(resolve => setTimeout
    () => {
      loadingSheet.insertRule('div::after { content: "3" }')
      resolve()
    },
    2500))

</script>
```

Chrome blocks DOM loading until the promise is fullfilled. The rules are inserted after the style sheet contents is loaded.

Firefox disallows access to the loading style sheet and throws an exception.
