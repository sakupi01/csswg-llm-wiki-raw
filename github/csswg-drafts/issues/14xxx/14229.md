TypedOM currently extends the `CSS` namespace like [this](https://drafts.css-houdini.org/css-typed-om-1/#:~:text=clamp%22%2C%20%7D%3B-,partial%20namespace%20CSS):

```webidl
partial namespace CSS {
    CSSUnitValue number(double value);
    // ...
}
```

However, per spec the `CSS` namespace is only exposed on `Window` (via `[Exposed=Window]` in [here](https://drafts.csswg.org/cssom-1/#namespacedef-css)).

~It seems Blink at least exposes `CSS.number` and co in workers.~

When testing more aspects of the TypedOM API in workers, it seems no engine exports the CSS factory functions in workers. I think doing that would be ok since those interfaces are exposed in workers. Maybe `CSS.escape` and a couple others could work in there as well, they're useful for things like `FontFace`.

But my understanding is that it shouldn't work per spec right now. I have some ideas of how to fix this like:

 * Make the CSS namespace definition a plain `[Exposed=(Window, Worker, ...)] namespace CSS {}`
 * Make the existing CSS partials _except the TypedOM one_ `[Exposed=Window]`.

Is there a cleaner alternative @tabatkins? I worry a bit about future specs just doing `partial namespace CSS` and they not realizing by default it's exposing stuff to workers.
