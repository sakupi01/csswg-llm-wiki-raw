When using `grid-lanes-direction: column/row fill-reverse`, should we adjust our definitions of "start" and "end" for content alignment?

In the case of regular stacking axis alignment, if an item has `align-self: end`, it aligns to the bottom of the container:

<img width="539" height="365" alt="Image" src="https://github.com/user-attachments/assets/ef2fb6c1-a0cf-45ab-9977-e28efaa84a27" />

In the case that we have fill-reverse enabled, items would fill up the container starting from the bottom.  If we were to specify `align-self: end` to an item, should it still align to the bottom of the container:

<img width="534" height="373" alt="Image" src="https://github.com/user-attachments/assets/d6dc913e-2ed6-469b-a9fa-bd1071c2e0ab" />

Or align to the top of the container, which is technically near the "end" of where items are placed:

<img width="528" height="357" alt="Image" src="https://github.com/user-attachments/assets/456d3b76-578f-4012-8ef1-47ac28956b34" />

In CSS Flex, if we try to align items along the main axis where things are placed in reverse:
```
<div style="display: flex; gap: 10px; width: min-content; height: 250px; border: 2px solid; flex-direction: column-reverse; justify-content: flex-end;">
   <div style="width: 30px; height: 30px; background: pink;"></div>
   <div style="width: 30px; height: 30px; background: pink;"></div>
   <div style="width: 30px; height: 30px; background: pink;"></div>
   <div style="width: 30px; height: 30px; background: lightgreen;"></div>
</div>
```
Using `justify-content: flex-end` moves items along the main axis to the TOP of the container:
<img width="51" height="266" alt="Image" src="https://github.com/user-attachments/assets/d777f7af-d784-49d5-b20a-e3a03ec2fe8f" />

I do think that `fill-reverse` should only be changing the behavior of auto-placed items, and `align-self/items: start` in columns should still align items to the original start of the container.  It would be confusing if  `align-content: start` moved all (fill-reversed) items to the bottom of the container in the column direction, and it would be confusing if `align-items` didn't have the same direction as `align-content`.

The same question applies to `track-reverse` -- when that's enabled, do we change where alignment for the grid-axis should be as well? ie, if we have `track-reverse` on a column container, would `justify-items` center items to the left or to the right?

## @Loirooriol — 2026-06-16

Flex layout has `flex-start` and `flex-end`. It would seem inconsistent to redefine `start` and `end` for masonry. But adding new keywords for each reversable layout doesn't seem great either.

I think I would like to come up with a name that is not layout-specific, alias `flex-*` to that, and keep `start`/`end`/`self-start`/`self-end` purely based on writing mode.

<!-- comment id=4727657524 author=Loirooriol created=2026-06-17T08:25:09Z url=https://github.com/w3c/csswg-drafts/issues/14052#issuecomment-4727657524 -->
## @Loirooriol — 2026-06-17

I was thinking that e.g. `align-self: something-start` would:
 - In flex layout with `flex-wrap: wrap-reverse`, behave like `end`
 - In waterfall grid lanes layout with `fill-reverse`, behave like `end`
 - I'm not sure if we resolved to add a reversal mechanism for plain grids, if so, analogous
 - Otherwise, behave like `start`

And `flex-start` would become an alias of `something-start`.

<!-- comment id=4744762188 author=alisonmaher created=2026-06-18T18:00:44Z url=https://github.com/w3c/csswg-drafts/issues/14052#issuecomment-4744762188 -->
## @alisonmaher — 2026-06-18

Per spec, `flex-start` is supposed to work like `start` in everything but flex (see https://drafts.csswg.org/css-align-3/#positional-values) so I think whatever we decide should happen for `start` in grid lanes with `fill-reverse`, `flex-start` should match that (regardless of what `flex-start` does with reversals in flexbox).
