We currently inherit font and all its longhands explicitly, however there are other typesetting properties that we do not inherit because they are currently blocked by the HTML UA default stylesheet, see https://html.spec.whatwg.org/multipage/rendering.html#form-controls which currently says:

```
input, button, textarea {
  letter-spacing: initial;
  word-spacing: initial;
  line-height: initial;
}

input, select, button, textarea {
  text-transform: initial;
  text-indent: initial;
  text-shadow: initial;
  appearance: auto;
}
```

Proposal:

1. Merge these two selector lists in the HTML UA stylesheet (for `auto` and `base`) so that the rules apply consistently including to `select`.
2. Keep the `text-transform`, `text-indent`, and `line-height` resets for `base` appearance (no change).
3. Switch `letter-spacing`, `word-spacing`, and `text-shadow` to all `inherit` for base appearance.
4. Assign `system-ui` to `::picker-icon` and `::checkmark` so it doesn’t inherit random symbol glyphs from random fonts; and make sure it doesn’t get obliqued.

```
input, select, button, textarea {
  letter-spacing: inherit;
  word-spacing: inherit;
  text-shadow: inherit;
}

::picker-icon, ::checkmark {
  font-family: system-ui;
  font-style: normal;
}
```

Note that (all?) engines currently override the line-height for select elements in native code: https://github.com/whatwg/html/issues/4481

So effectively, there is something akin to `select { line-height: initial !important; }` going on already (although not specified anywhere).
