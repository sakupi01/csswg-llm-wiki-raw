There was a related issue at https://github.com/w3c/csswg-drafts/issues/11038 but I couldn't quite identift whether this specific question about `text-box-trim` was resolved.

[CSS Inline 3](https://drafts.csswg.org/css-inline-3/#text-box-trim) says the below regarding `text-box-trim`, which doesn't seem to include specific behavior for independent BFCs. I don't see anything else about propagation in this property definition (other than column containers).

> Note: Like ::first-line, this property does not apply to, or propagate through, flex, grid, or table formatting contexts.

[CSS Pseudo 4](https://drafts.csswg.org/css-pseudo-4/#first-formatted-line) _does_ say the following about the first formatted line, though.

> Note: The first line of a block container that does not itself participate in a block formatting context cannot be the first formatted line of an ancestor element.

I'm not 100% sure, but I think the "does not itself participate in a block formatting context" is synonymous with "establishes an independent block formatting context"? Does this definition mean that `text-box-trim` does not propagate through independent BFCs?

That's my interpretation, but there's an existing WPT that asserts the opposite - [new-fc-001.html](https://wpt.fyi/results/css/css-inline/text-box-trim/new-fc-001.html?label=experimental&label=master&aligned) passes if `text-box-trim` _does_ propagate to an independent BFC (a `display: flow-root` in this case). Blink passes that, Gecko and WebKit do not. I was going to add additional tests to assert that propagation doesn't happen with other BFC-establishing children, but this existing WPT has me a bit perplexed.

(Tracking this on the Gecko side at https://bugzilla.mozilla.org/show_bug.cgi?id=2049484)

## @kbhomes — 2026-09-09

Related, does `text-box-trim` propagate into the independent formatted context of a scroll container? 

Question was just raised on the Gecko side in [Bug 2049484](https://bugzilla.mozilla.org/show_bug.cgi?id=2049484):
- Gecko _doesn't_ trim the scroll container because, it blocks propagation through independent BFCs. 
- WebKit _does_ trim the scroll container. 
- Blink is strange and doesn't trim but _does_ scroll the container down so that it _looks_ like it's trimmed (but you can scroll to see the untrimmed space on the top and bottom).
