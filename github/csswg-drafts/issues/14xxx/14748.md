https://drafts.csswg.org/css-scroll-snap-2/#scroll-initial-target-fragment-navigation says:

> While the document is being updated, a scroll container's initial scroll target might arrive after that scroll container has been laid out. If this happens, user agents should still scroll to the initial scroll target unless the user agent has reason to believe the user is no longer interested in scrolling to the initial scroll position.

It doesn't say what happens when HTML's [restore scroll position data](https://html.spec.whatwg.org/multipage/browsing-the-web.html#restore-scroll-position-data) also applies, e.g. on reload or history traversal to a document with an initial scroll target. I'd expect the restored scroll position to win.

`css/css-scroll-snap/scroll-initial-target/scroll-initial-target-with-anchor-navigation.tentative.html` tests that `history.back()` after a same-document fragment navigation restores the previous position, but nothing covers reload or cross-document traversal.

(Raised by @hiikezoe in https://github.com/mozilla/standards-positions/issues/1107#issuecomment-2620523525.)
