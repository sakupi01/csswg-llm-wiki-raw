We could've used `@macro` with `@extend` like so

```css
@macro --reset {
  appearance: none;
}

.button {
  @extend --reset;
  background-color: rebeccapurple;
  color: white;
}
```

would output to:

```css
.button {
  appearance: none;
  background-color: rebeccapurple;
  color: white;
}
```

we also could've renamed it to `@placeholder`

```css
@placeholder --reset {
  appearance: none;
}

.button {
  @extend --reset;
  background-color: rebeccapurple;
  color: white;
}
```

`@macro` is just block of rules like `%<ident>` was just block of rules for SASS plus it makes it more clear if you use `@extend` not `@apply` with `@macro` like this:

```css
@macro --reset { /* or @placeholder */
  appearance: none;
  background: none;
  border: none;
  color: inherit;
  font-family: inherit;
  font-size: 1em;
  margin: 0;
  padding: 0;
}

.a {
  @extend --reset;
}

.b {
  @extend .a;
  font-weight: 700;
}

.c {
  @extend .a;
  color: purple;
}
```

```css
@mixin --reset() {

  margin: 0;
  padding: 0;
```

## @tabatkins — 2026-08-26

```
@macro --reset {
  appearance: none;
}

.button {
  @extend --reset;
  background-color: rebeccapurple;
  color: white;
}

/* desugars to */
.button {
  appearance: none;
  background-color: rebeccapurple;
  color: white;
}
```

That's how `@mixin` already works per spec:

```
@mixin --reset {
  appearance: none;
}

.button {
  @apply --reset;
  background-color: rebeccapurple;
  color: white;
}
```

However, we never had Sass's `@extend` feature in the spec, and it's not currently planned to add it. However, you can get similar functionality by nesting mixins, instead.
