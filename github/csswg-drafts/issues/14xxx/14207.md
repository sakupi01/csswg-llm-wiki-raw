Delta E is a class of algorithms to measure the actual perceived difference between two colors.

ΔEOK2 is a slightly modified version of the existing ΔEOK which scales the `a` and `b` axes by a factor of 2
as [recommended by Björn Ottosson](https://github.com/w3c/csswg-drafts/issues/6642#issuecomment-945096257), inventor of Oklab:

> Adjust the scaling of a&b to more accurately predict color distances

He [also said](https://github.com/w3c/csswg-drafts/issues/6642#issuecomment-945714988)

> I unfortunately didn't spend that much time calculating and validating that scaling factor when I first derived Oklab since I was mostly focused on the orthogonality between L, C and h (and I didn't expect it to become so widespread so quickly), and it seems like it is off by quite a bit.
> I've recently done some tests with color distance datasets as implemented in Colorio and on both the Combvd dataset and the OSA-UCS dataset a scale factor of slightly more than 2 for a and b would give the best results (2.016 works best for Combvd and 2.045 for the OSA-UCS dataset).

So instead of changing the definition of Oklab, which is now widely adopted, the proposal is to make another distance metric, ΔEOK2, if it is demonstrably better then ΔEOK.

## Experimental verification

I [generated a synthetic dataset](https://github.com/svgeesus/deltaE-OK2/tree/main) of normally distributed base colors (so, favoring more common low-chroma colors but including wide-gamut colors). Colors outside `rec2020` were eliminated. I then produced, for each color in the dataset, a group of similar colors by perturbing the lightness, chroma and hue (again, normally distributed).

To avoid any dependence on `Oklab` itself, the base colors were generated in CAM16 JMh as were the derived colors. Here is a plot of the base colors, converted to `Oklab`

## Conclusion

`ΔEOK2`, which is `ΔEOK` with the `Oklab` `a` and `b` axes scaled by 2, agrees with the highly-regarded but computationally complex `ΔE2000` noticeably better than `ΔEOK` does (correlation coefficient r² **0.722** vs  **0.642** on 5000 BT.2020 color
pairs). Scaling the `a/b` axes by 2 is a measurable improvement, supporting Ottosson's recommendation. It remains computationally simple and fast.

Proposed resolution: add ΔEOK2 to CSS Color 4 and recommend it over ΔEOK.

I would note that when using MINDE chroma reduction, which specifically relies on color distancing, at most lightness ranges, hue shift is lessened when using OK2 vs OK, which is a good thing.

This doesn't affect GMA approaches that do not rely on distancing: Ray Trace, Edge Seeker, Cubic solvers (Halley, Cardano, etc.).

It seems from the bit I've looked into ∆E OK2 that it does seem to be a better approach.

I guess that doesn't surprise me. I'm sure the lightness helps "on average". The distance of every color doesn't necessarily correlate better with ∆E2000, but on average it does, but only when values aren't so skewed away from ∆E2000. So requiring both adjustments kind of makes sense to me.

In this [experiment](https://facelessuser.github.io/coloraide/playground/?notebook=https%3A%2F%2Fgist.githubusercontent.com%2Ffacelessuser%2F0235cb0fecc35c4e06a8195d5e18947b%2Fraw%2F735d97fa895a0f9f1610189a31028b7bb1bbc2bb%2Fexploring-tonal-palettes.md), I was tweaking the toe function to better match LCh lightness across the board for tonal palettes. Nothing fancy, just adjusting the coefficients.

When I applied the tweaked `toe` function values after the doubling of the ∆a and ∆b, it improved a little more. Nothing drastic, but just a little more. But of course, this only applies with ∆a and ∆b correction as well.

```
K1 = 0.173
K2 = 0.004
K3 = (1.0 + K_1) / (1.0 + K_2)
```

I haven't looked any further than noting that the `r^2` value improves. So, it seems, as long as the ∆a and ∆b are skewed more favorably with ∆E2000, adjusting ∆L to look more like LCh also improves the `r^2` (on average).
