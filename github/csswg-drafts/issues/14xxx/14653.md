A while ago we resolved to trim whitespace from the start/end of property values, which is observable via custom properties. In #14370 I'm, among other things, recommending that we do the same thing to custom function/mixin arguments. In [a comment on that issues](https://github.com/w3c/csswg-drafts/issues/14370#issuecomment-6331807193), @domenic asks if we can also do it for `if()` values.

I think this is pointing toward a more general behavior - we should probably just automatically trim leading/trailing whitespace from [`<declaration-value>`/etc](https://drafts.csswg.org/css-syntax-3/#any-value) in general.

Any arguments against? Otherwise, Agenda+ to resolve on this. (Technically a breaking change; there's even [a WPT for `if()`](https://github.com/web-platform-tests/wpt/blob/0ed321dcab3b3943d281b56ddc71c9f1a5feecab/css/css-values/if-conditionals.html#L113) that depends on the current behavior and will need tweaking.)
