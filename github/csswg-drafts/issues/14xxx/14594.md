Following https://github.com/w3c/svgwg/issues/1171

The SVG WG resolved on 2026-10-06 to add `referrerpolicy` to SVG `image` and `script` (https://www.w3.org/2026/10/06-svg-minutes.html, PR https://github.com/w3c/svgwg/pull/1188). The issue also asked about `feImage`, but `feImage` is defined in Filter Effects 1, so it comes here.

**1. `referrerpolicy` on `feImage`**

`feImage` fetches an image the same way SVG `image` does, and it already has `crossorigin`, defined by pointing to HTML's `img`. `referrerpolicy` would be defined the same way.

Let's check what browsers do today with `<feImage href="…" referrerpolicy="…">`, using a server that echoes back the `Referer` header:

| `referrerpolicy` | Safari 27.0 | Firefox 159 | Chrome 156 |
|---|---|---|---|
| absent | origin (default) | origin (default) | origin (default) |
| `no-referrer` | origin, **ignored** | origin, **ignored** | origin, **ignored** |
| `unsafe-url` | origin, **ignored** | origin, **ignored** | origin, **ignored** |

Measured 2026-09-29. No browser supports it today, so adding it does not risk breaking anything.

**2. The `crossOrigin` IDL type contradicts its own definition**

https://drafts.csswg.org/filter-effects-1/#InterfaceSVGFEImageElement

```webidl
interface SVGFEImageElement : SVGElement {
  readonly attribute SVGAnimatedPreserveAspectRatio preserveAspectRatio;
  readonly attribute SVGAnimatedString crossOrigin;
};
```

> The crossOrigin IDL attribute must reflect the crossorigin content attribute, limited to only known values.

A `readonly SVGAnimatedString` cannot reflect a content attribute limited to known values. Gecko, the only engine with the member, ships `attribute DOMString? crossOrigin;`, which is also the type in HTML for `img` and in SVG 2 for `SVGImageElement`. WebKit and Blink have neither the `crossorigin` attribute on `feImage` nor the IDL member.

`interfaces/filter-effects.idl` in WPT copies the spec version, so the IDL test checks something that  no browsers are currently shipping.

## @karlcow — 2026-10-13

1. Change the IDL to `attribute DOMString? crossOrigin;`, as in HTML `img`, SVG 2 `SVGImageElement` and Gecko.
2. Add a `referrerpolicy` content attribute to `feImage`, defined as HTML's [referrer policy attribute](https://html.spec.whatwg.org/multipage/urls-and-fetching.html#referrer-policy-attribute), and `attribute DOMString referrerPolicy;` reflecting it, limited to only known values. Same wording as https://github.com/w3c/svgwg/pull/1188 for `image`.
