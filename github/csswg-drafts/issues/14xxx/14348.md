`match-parent` says:

> Uses the same default anchor element as the parent—or originating element, if this is a pseudo-element—if any, and if that would be an acceptable anchor element.

"the parent" isn't linked to a definition, and the spec doesn't say which tree it's resolved in. For an element in a shadow tree that's the host vs. the shadow root, and for slotted content it's the slot vs. the host, so the two readings disagree in both directions.

I assume the flat tree is intended, given css-shadow-1 uses it "for all purposes after Selectors (including inheritance and box construction)", and that acceptable anchor element is already defined in terms of flat tree order. Worth saying explicitly?

This WPT PR already includes shadow DOM tests that assume flat tree https://github.com/web-platform-tests/wpt/pull/62042
