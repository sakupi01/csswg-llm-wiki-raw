Despite my best efforts:

```html
<pre class='ignored-specs'>
spec:css-color-3
spec:css3-color
</pre>

<pre class=link-defaults>
spec:css-color-4; type:dfn; text:color
spec:css-color-4; type:value; text:color
spec:css-color-4; type:value; text:currentcolor
spec:css-color-4; type:property; text:color
</pre>
```

(the above being [insufficient to stop Color 5 linking to Color 3](https://drafts.csswg.org/css-color-5/#index-defined-elsewhere)) CSS specs will link to CSS Color 4 for the `currentColor` value and the `color` property **BUT stubbornly assert that `<color>` is defined in CSS Color 3**. This is a significant problem because the syntax for the `<color>` type is significantly expanded in CSS Color 4. Plus, CSS Color 4 defines resolving color values, and serializing color values (moved here from CSSOM).

I notice that some specs attempt to clarify this in prose. For example [css-ui-4 definition of `outline-color`](https://drafts.csswg.org/css-ui-4/#propdef-outline-color):

> 
<html><body>
<!--StartFragment-->

Computed value: | The computed value for invert is invert. For <color> values, see [[!CSS-COLOR-4#resolving-color-values]] in [CSS-COLOR-4].
-- | --


<!--EndFragment-->
</body>
</html>

and yes ... `<color>` links to CSS Color 3.

Is there some magical link-defaults incantation that I am missing, or

## @tabatkins — 2021-07-09

This is happening because Color 3 is defined as the preferred default for `<color>` in the link-defaults file <https://github.com/tabatkins/bikeshed/blob/main/bikeshed/spec-data/readonly/link-defaults.infotree#L43>

And *that* is because it was specified in [the earlier version of this file](https://raw.githubusercontent.com/w3c/csswg-drafts/5367c02618505b290956838b480562ff0a5eaa70/autolinker-config.md), which I switched away from seven years ago. Specifically, `<color>` was added about eight years ago <https://github.com/w3c/csswg-drafts/commit/771e11471f8e393accf4355793f58b4f5f40ba08>, back when Color 4 was only an ED ([FPWD was in 2016](https://www.w3.org/TR/2016/WD-css-color-4-20160705/)), so linking to Color 4 was a problem for anything publishing to /TR.

I think I can remove a chunk of these defaults ^_^
