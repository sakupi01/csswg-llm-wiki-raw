Normal kerning for CJK fonts that support the ‘kern’ feature should only apply the feature on proportional glyphs. By default this means excluding the fullwidth CJK glyphs and only kerning the proportional Latin glyphs. 
If kerning the CJK fullwidth glyphs you must also apply ‘palt’ (‘vpal’ in vertical) or the kerning amounts will be incorrect. This kerning should be optional and not the default.

## @fantasai — 2023-02-01

Discussing with @MurakamiShinyu, we outlined 5 possible things that an author might want to do:

1. no kerning
2. kern non-CJK† only
3. apply palt/vpal and kern everything
4. apply palt/vpal and kern non-CJK
5. apply palt/vpal and kern nothing

Of these 5, the first 3 seem to be clearly needed; the last two, we're not sure. Either way, the spec should clarify that kerning CJK requires applying palt/vpal as well.

A question raised was whether palt/vpal should be applied via `font-variant-east-asian` where we already have the somewhat-related `proportional-width` keyword. But `font-variant` is fundamentally about alternate glyphs whereas palt/vpal is about spacing, so `font-kerning` is probably a better place to control it.

Possible syntax for these options:
1. `font-kerning: none`
2. `font-kerning: normal`
3. `font-kerning: all` (new keyword)
4. Unclear if we need this (not easy to work around if needed)
5. Unclear if we need this (can use `font-feature-settings` if needed‡)

It might be useful to hear from @macnmm and others if options 4 or 5 are needed.

† The appropriate division here is probably East Asian Wide vs others.
‡ The naive way to do this would be `font-kerning: none; font-feature-settings: "palt"`, but this doesn't handle writing modes correctly, so the correct way to do it would be `font-kerning: all; font-feature-settings: "kern" off, "vkrn" off`.

## @kidayasuo — 2026-09-01

## Input from the JLReq Task Force

At its meeting on 2026-09-01 the JLReq TF resolved to state the following position. This issue is understood to be blocked partly on the view that Japanese typography experts are divided; this is our view. The background — what has changed on the OpenType side, in implementations, and in WPT since the 2022–23 public-i18n-japanese thread — is collected in w3c/jlreq#492.

**Scope.** Horizontal writing, Japanese text. Vertical (`vpal` / `vkrn` / `vapk`) is structurally identical and we would expect it to follow, but we have kept it out of this statement so that the horizontal case can be settled first.

### 1. Kerning should not be applied to Japanese characters by default

Japanese type is designed to be readable when set solid — one em per character, no adjustment. Tightened setting (*tsume*) is not a readability improvement; it is a deliberate design choice that suits headings, display sizes and particular editorial settings. It should not be what happens when the author has asked for nothing.

Beyond that, what Chrome and Safari do today is not tsume either. As recorded in w3c/jlreq#492, both apply `kern` by default while leaving `palt` inactive. The `kern` values in these fonts are authored against `palt`-adjusted advance widths; applying them to glyphs that are still full width produces spacing that no one designed — neither solid setting nor correct tsume. This is not a matter of competing aesthetics. The current default is simply incorrect, and it is also contrary to the registry text cited in 2 below.

It also removes the author's control over line length. Japanese layout is built on the em grid: line length is normally an integer multiple of the character size, and characters-per-line is a value the author sets and relies on. Unpredictable per-pair adjustment of full-width characters breaks that relationship, and with it the alignment of text across lines and columns.

### 2. The dependency on `palt` should be stated normatively in CSS

Kerning presupposes the adjusted advance widths, so neither `kern` nor `apkn` may be applied to these glyphs unless `palt` is also active. The OpenType feature registry states this in its current edition (1.9.1, incorporated into ISO/IEC 14496-22:2026). Under `kern`, CJK text is given as an exception to default activation: in a font implementing `palt`, the feature "should not be activated by default to glyphs covered by 'palt' lookups" unless `palt` itself has been activated. The `palt` entry states the same from its own side, and `apkn` is made conditional on `palt` in the same way. The converse does not hold: `palt` on its own is a legitimate setting, with kerning left to default or user preference.

Implementations arrive at this behaviour through CSS, and CSS says nothing. We would like css-fonts to state the dependency explicitly rather than leave it as an OpenType-side requirement that implementers may or may not read. Issue #7958 asks for this and has been open since 2022; it predates `apkn`, so the `apkn` half would need to be added, either there or here.

### 3. What we are asking for

We take no position on the `font-kerning` keywords — that is the CSSWG's to decide, not a question of Japanese typography. What we are asking for is the behaviour:

- Japanese characters are **not** kerned by default.
- Japanese characters are kerned **only** when the author explicitly asks for it.

**By default, `kern` has to be applied selectively.** This is the harder half of the request and worth stating plainly: the default is not "kerning off". Glyphs that are proportional by default — Latin, and anything else the font spaces proportionally — should continue to be kerned exactly as they are today. Only the full-width glyphs are to be left alone. An implementation therefore has to condition the application of `kern` rather than switch it off. The registry describes ways to do this: scanning the coverage tables of the `palt` lookups, or using the East Asian Width property to identify characters likely to be full width by default. Firefox has done this since Fx 108, and arriving at a workable division was one of the difficulties that blocked agreement in 2022–23.

**When kerning is explicitly requested:**

- font implementing `palt` + `kern`, without `apkn`: activate `palt` and `kern` together.
- font implementing `apkn`: activate `palt` and `apkn` together. `kern` remains active as usual, since in such a font it carries only pairs for glyphs that are proportional by default.

`apkn` is not a separate mechanism requiring separate rules: `palt` + `apkn` is the current, registry-recommended way of expressing what `palt` + `kern` fonts express, with the `palt`-dependent pairs moved out of `kern` and into `apkn`. The registry draws the consequence itself: in a font implementing both, `kern` can be applied by default to all horizontal text, and `apkn` can be left inactive on any run without `palt` without scanning lookup tables to decide which glyphs to exclude. The conditioning remains necessary for the `palt` + `kern` fonts already in circulation, but for fonts adopting `apkn` the question does not arise.

**Separately:** @MurakamiShinyu withdraws the `font-kerning: all` keyword he proposed in https://github.com/w3c/csswg-drafts/issues/6723#issuecomment-1411487571.

Firefox has applied this behaviour since Fx 108 (December 2022) — no kerning of CJK at `font-kerning: auto`, `palt` activated together with `kern` at `font-kerning: normal` — and the behaviour is exercised by [css/css-fonts/cjk-kerning.html](https://wpt.fyi/results/css/css-fonts/cjk-kerning.html). Per w3c/jlreq#492, a Chromium CL doing the same was written in February 2026 and withdrawn in March, the stated reason being the absence of CSSWG consensus. As far as we can tell, a WG decision is the only thing missing.

## @taroyamamoto-451 — 2026-09-02

As has already been recognized and noted above, the `kern` feature must **_not_** be applied by default to Japanese text, regardless of whether the font implements `palt`. Only when the user explicitly requests `kern` may the requested feature be applied to Japanese text. In either case, `palt` must also be applied so that the full-width CJK glyphs covered by `palt` are given their alternate proportional widths and side bearings.

However, this does **_not_** mean that the `kern` feature cannot contain kerning data for full-width Japanese glyphs not covered by the font’s `palt` feature. Some Japanese glyphs do not require alternate proportional widths and should retain their default full-width metrics even when Japanese text is set in “kana-tsume” (alternate proportional metrics) mode. Nevertheless, such glyphs may still need to be kerned with other Japanese glyphs, whether or not those other glyphs are covered by `palt`.

This “contradiction,” which existed in earlier versions of the OpenType specification, was eliminated in OpenType 1.9.1.

The current specification explicitly makes an exception to the default activation of `kern` for CJK glyphs covered by `palt`. Such glyphs normally have fixed-width metrics, so `kern` should not be activated for them unless `palt` has first made their metrics proportional.

Moreover, OpenType 1.9.1 introduced the `apkn` feature specifically for kerning glyphs that are fixed-width by default but have been given proportional metrics through `palt`. 
Thus, the scopes of the features are no longer contradictory:

- `kern` is intended primarily for glyphs that have proportional metrics by default.
- `palt` changes fixed-width glyphs to proportional metrics and remains off by default.

In addition, for new fonts, the specification recommends that such kerning be implemented in `apkn`, while `kern` should continue to be used for glyphs that are proportional by default.

It is true that the rationale behind the feature interaction in earlier versions of the specification was difficult to understand, But the specification has been substantially clarified and improved in OpenType 1.9.1.
