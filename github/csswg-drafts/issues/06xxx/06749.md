If there's a `revert-layer` in a keyframe, which layer does it revert to? Should it be the layer below where the keyframe is defined?

For example:
```css
@layer first {
  #target { font-size: 200px; }
}

@layer second {
  @keyframes anim {
    from { font-size: 100px }
    to { font-size: revert-layer }
  }
}

#target { animation: anim 5s; }
```

Since the keyframes are defined in layer `second`, should keyframe `to` revert to layer `first`, and therefore animates `font-size` from `100px` to `200px`?

This looks like the most reasonable behavior to me, but I'd like to make sure it's the correct one. And we probably need a note in the spec since this isn't completely trivial.

## @xiaochengh — 2021-10-21

The issue seem more complicated when we take tree scopes into consideration. For example:

```html
<style>
@keyframes anim {
  from { font-size: 100px }
  to { font-size: revert-layer }
}
#target { animation: anim 5s; }
</style>
<div id="target">
  <template shadowroot="open">
    <style>
    :host { font-size: 200px; }
    </style>
  </template>
</div>
```

Which layer does it revert to? If we strictly follow the cascade sorting order, since there are no more layers in the outer tree scope, the layer below is the shadow DOM style, which is `:host { font-size: 200px; }`. Is this behavior what we want?

I don't have a strong opinion on this, but just feel it's quite unintuitive, so it's better to make sure we agree on what to do.

---

And what if there's a `revert-layer` in an animation created by JS? For example:

```javascript
elem.animate({ fontSize: revert-layer }, 1000);
```

Do we revert to the top author layer, including the inline `style` attribute (treating it as a special layer)?

<!-- comment id=948980790 author=tabatkins created=2021-10-21T20:31:21Z url=https://github.com/w3c/csswg-drafts/issues/6749#issuecomment-948980790 -->
## @tabatkins — 2021-10-21

Just like #6743, there's no way to create cascade layers in the animation origin, so all the styles there just sit in the single default layer. So `revert-layer` acts identically to `revert`, just like in a style attribute.

<!-- comment id=949041186 author=xiaochengh created=2021-10-21T22:11:40Z url=https://github.com/w3c/csswg-drafts/issues/6749#issuecomment-949041186 -->
## @xiaochengh — 2021-10-21

@tabatkins `revert` in keyframes actually reverts to the user origin, or at least that's what Blink is doing and [this WPT](https://wpt.fyi/results/css/css-cascade/revert-val-006.html?label=master&label=experimental&aligned&q=css%2Fcss-cascade) is asserting.

Are you suggesting `revert-layer` in keyframes should directly revert to the user origin?

<!-- comment id=951178656 author=fantasai created=2021-10-25T18:12:53Z url=https://github.com/w3c/csswg-drafts/issues/6749#issuecomment-951178656 -->
## @fantasai — 2021-10-25

Good point, this is specced in https://www.w3.org/TR/css-cascade-5/#default which defines the animation origin as part of the author origin for the purposes of `revert`.

Probably `revert-layer` should revert only the animations origin. Agenda+ for discussion
