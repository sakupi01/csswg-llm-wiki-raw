#3280 marked `contain: style` as at-risk, and dropped it from the `strict` and `content` shortcuts.

But since #6272 it's no longer at-risk.

Do we need a new shortcut like `strict` but including style containment? Like `contain: stricter`?

I guess this could be useful for container queries, instead of having to specify `contain: layout size style`, just `contain: stricter` would do the trick.

Or maybe just change `strict` to include `style`? But it may be too late for compat.

<!-- comment id=840014834 author=mirisuzanne created=2021-05-12T18:44:27Z url=https://github.com/w3c/csswg-drafts/issues/6287#issuecomment-840014834 -->
## @mirisuzanne — 2021-05-12

This seems related to #6174 – creating an explicit syntax for query-containers.

If the purpose of style containment is currently only for container queries, I'm not sure that a variant of `strict` is either the most clear, or the most flexible for specifying 1d or 2d size containment variants.

> Or maybe just change strict to include style? But it may be too late for compat.

Is someone able to run a query on sites that use `contain: strict` to determine how many would render differently if they were switched to `contain: layout style paint size`. In theory, it's different, so it could break things, but whether or not this actually causes problems in the wild is less certain, given than the effects of style containment are quite limited.
