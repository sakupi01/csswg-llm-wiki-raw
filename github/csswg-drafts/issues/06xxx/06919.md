Similar to https://github.com/w3c/csswg-drafts/issues/5167 I suggest we clarify what happens with `@font-palette-value` at-rules in shadow-trees, i.e. similar to that issue clarifying 

"A `@font-palette-values` rule is invalid if it occurs in a stylesheet inside of a [shadow tree](https://dom.spec.whatwg.org/#concept-shadow-tree), and must be ignored."

I guess this is fine for the time being. Will this include a "will likely change in the future" issue, though, similar to #5167? <!-- comment id=1034206291 author=tabatkins created=2022-02-09T21:24:58Z url=https://github.com/w3c/csswg-drafts/issues/6919#issuecomment-1034206291 -->
## @tabatkins — 2022-02-09

[My answer from 2020](https://github.com/w3c/csswg-drafts/issues/5167#issuecomment-639129614) stands - we only disallow insofar as impls are not yet following [the rules in Scoping](https://drafts.csswg.org/css-scoping/#shadow-names). Once an implementation supports those, then they must support these at-rules in shadow trees, following these rules.

## @litherum — 2022-02-10

I don't know why font-palette-values should deserve any special treatment - it should follow whatever the behavior is for other at rules.
