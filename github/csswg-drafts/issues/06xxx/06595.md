2 problems:

1. Fingerprinting. We might not want to add yet another place that is sensitive to system locale
2. Currently it's not possible to ask for a different localization than the one the system is in. For comparison, the JS Intl APIs allow authors to specify their own locale, and the functionality depends on that. We may want the same kind of thing here. (I'm not sure of use cases though.)
