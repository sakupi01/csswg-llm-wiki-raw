<!-- comment id=945026774 author=MatsPalmgren created=2021-10-17T00:27:13Z url=https://github.com/w3c/csswg-drafts/issues/6729#issuecomment-945026774 -->
## @MatsPalmgren — 2021-10-17

Apple has still not submitted the `env()` features that they are [shipping](https://github.com/WebKit/WebKit/blob/75f779ef02785f296dc4c6d68541066097fe9ec7/Source/WebCore/dom/ConstantPropertyMap.cpp#L57-L61) to the csswg for standardization (as they are *required* to do per the resolution in #2820).

AIUI, if css-env is published it would make Safari and all other webkit-based browsers _non-compliant_ CSS UAs.

Also, given the vast number of open issues on this spec, I don't think it's anywhere near ready.

<!-- comment id=945200494 author=svgeesus created=2021-10-17T21:48:48Z url=https://github.com/w3c/csswg-drafts/issues/6729#issuecomment-945200494 -->
## @svgeesus — 2021-10-17

A vast number of open issues does not preclude FPWD.

However, lack of consensus on general direction or major features *could* preclude FPWD, on the grounds that the patent exclusion opportunity would thereby be wasted until CR.

## @bramus — 2025-05-14

AFAIK these `fullscreen-*` envvars are something that got added (and shipped) in WebKit/Safari without WG-consensus, so I don’t think Tab would be the one that needs to file a PR here.

Also, I see that there was a discussion about this in https://github.com/w3c/csswg-drafts/issues/2871, but that there was no resolution to adopt these. Which makes me wonder: if there is no resolution, should we even be adding them to the spec? Especially because the spec includes this paragraph:

> The following UA-defined [environment variables](https://drafts.csswg.org/css-env-1/#css-environment-variable) are officially defined and must be supported. Additional UA-defined environment variables must not be supported unless/until they are added to this list.
