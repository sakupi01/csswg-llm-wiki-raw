In [CSSOM](https://drafts.csswg.org/cssom/#parsing-selectors):

> ## 5.1. Parsing Selectors
>
> To **parse a group of selectors** means to parse the value using the `selectors_group` production defined in the Selectors specification and return either a group of selectors if parsing did not fail or null if parsing did fail.

I can not find `selectors_group` in Selectors. Does it correspond to `<selector-list>`? When does [**parse a selector**](https://drafts.csswg.org/selectors/#parse-selector) should be used?

**EDIT:** 

I think it should use [**parse a selector**](https://drafts.csswg.org/selectors/#parse-selector), as well as the definition for parsing the prelude of a [style rule in Syntax](https://drafts.csswg.org/css-syntax-3/#style-rules), which is currently:

> The prelude of the qualified rule is [parsed](https://drafts.csswg.org/css-syntax-3/#css-parse-something-according-to-a-css-grammar) as a [`<selector-list>`](https://drafts.csswg.org/selectors-4/#typedef-selector-list). If this returns failure, the entire style rule is [invalid](https://drafts.csswg.org/css-syntax-3/#css-invalid).*

And it should be completed with a validation for nest-containing selector for `@nest`, as explained in my comment below.

## @cdoublev — 2022-02-02

Partially related: neither *parse a group of selectors* and its underlying procedures nor the procedure to set `CSSStyleRule.selectorText` when it represents a **nested** style rule, seems to handle a selector starting with `&`, which I think should be required for a nested style rule's selector to be valid.

**EDIT:**

A *nesting selector* (starting with `&`) is handled at the syntax level in *consume a style block’s contents*, but it is still required to define define something (syntax rule or value definition) to parse a *nest-containing selector*, which is currently only defined in prose.

Related: #5745.
