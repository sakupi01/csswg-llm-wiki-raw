The most recent definition of how to actually read the propdef blocks is still in 2.1. There's no other more appropriate CSS module for this, as it's meta knowledge, not any particular feature.  The snapshot seems like the best place to have it live.  (I can then redirect the newly-added propdef `th` links to those sections.)

Relatedly, we copy the conformance boilerplate in every single module. Much of it used to be in snapshot, but was moved out when the snapshot was made non-normative.  Can we do something about that?

## @frivoal — 2018-09-26

Actually, I'd like to revisit this. the part about propdef blocks is being solved in #1139.

So the only thing left here is removing the #conformance section from every spec, and adding to the snapshot instead. Do we actually want to do that? Even if you say it's doable with the process, it seems quite weird to me that every spec would have a normative dependency on something that only ever is either a WD or a Note. So whenever something goes to REC, wait a bit, and the conformance section which it incorporates by reference to a snapshot becomes non normative as the latest WD snapshot is retired into a note to make room for the following years snapshop…

That doesn't make very much sense to me.
