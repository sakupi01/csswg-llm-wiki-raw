From [CSS Text Decoration](https://drafts.csswg.org/css-text-decor-3/#line-decoration),

>  the decorations are propagated to all in-flow children.

From [CSS Display](https://drafts.csswg.org/css-display/#valdef-display-contents), `display: contents` means

> The element itself does not generate any boxes, but its children and pseudo-elements still generate boxes as normal.

Then, if a decoration is specified in an element which does not generate boxes, does the decoration propagate to the descendants which generate boxes?

`display: contents` does not affect inheritance, but text decorations are special because they propagate using a mechanism different than inheritance. I'm not sure if it is an element-tree thing, and thus the decoration should still propagate, or if it's a box-tree thing, and thus it shouldn't.

Example: https://jsfiddle.net/203oz4jr/

```html
<div>Foo</div>
```
```css
div {
  display: contents;
  text-decoration: underline;
}
```

Should Foo be underlined? It's underlined on Chrome, but not on Firefox.

## @tabatkins — 2017-05-15

I'm not sure I agree with @rune-opera; why should this propagate thru the box tree specifically?  I can easily see it doing so thru the element tree instead. That is, I can see it going either way, and I want to make sure we're making the decision deliberately.

@fantasai makes the argument (in person) that a run-in merging into a paragraph should pick up the paragraph's text-decoration. That would imply that it propagates thru the box-tree.  Any counter-arguments to this?

## @Loirooriol — 2017-05-15

I think I have a counter-argument which suggests that it propagates thru the element-tree.

When an inline element contains a block-level element, the block splits the inline. So the block box ends up outside the two inline box fragments. But decoration in the inline is propagated to the block.

From https://drafts.csswg.org/css-text-decor-3/#line-decoration,

> The decoration is then further propagated to any in-flow block-level boxes that split the inline (see [CSS2.1 section 9.2.1.1](https://www.w3.org/TR/CSS21/visuren.html#anonymous-block-level))

<!-- comment id=301938274 author=tabatkins created=2017-05-16T22:56:00Z url=https://github.com/w3c/csswg-drafts/issues/1136#issuecomment-301938274 -->
## @tabatkins — 2017-05-16

While that is a reasonable tick in the "element tree" column, there's so many aspects of the propagation that only work in the box tree that I think it's best served by just being an explicit call-out exception in how it box-tree propagates.

@rune-opera Yup, that bug makes it pretty clear that propagation needs to be a box-tree concept, so that fixup can interrupt propagation properly.

Okay, so I think we can close this issue with the conclusion that decorations definitely propagate thru the box tree, and thus the interaction of decorations and display:contents is already well-defined. (In particular, in the OP's example, no decoration should be applied - the `div` doesn't generate a box, so no decoration is ever established on a box.)

This work for everyone?

(Separately, @fantasai and I are now looking more closely at the propagation text, and realizing that the "applied to" paragraph is woefully underspecified.)
