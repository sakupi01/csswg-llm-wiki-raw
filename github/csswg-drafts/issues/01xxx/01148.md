image(): https://drafts.csswg.org/css-images-3/#image-notation

Quick test: http://dabblet.com/gist/33ac15e3d6372b2d97b17061783eb40f
The above tests basic functionality for `image()`, `image-set()`, `cross-fade()`, and parsing for `image-resolution`, `image-orientation`, `image-rendering`.

**Results**
`image()`: None
`image-set()`: WebKit, Blink
`cross-fade()`: WebKit, Blink
`image-resolution`: None
`image-orientation`: Gecko
`image-rendering`: Blink, Gecko, WebKit

Since `image()` has not been implemented in any browser, I think it should be deferred to Images 4, so that Images 3 can move forward. It has been sitting in CR for 5 years, and many of its other features seem to have excellent interoperability (even though they still need tests...).

## @LeaVerou — 2017-04-01

Excellent, thanks for agenda+ing @fantasai!
In the call, I plan to suggest deferring a few other features with 0-1 implementations:

- `image-set()` and `cross-fade()` seem to have some degree of implementation on Blink & Webkit, though they are not yet considered independent implementations (but should be). Perhaps they can stay.
- `image-orientation` is only recognized by Gecko (and no idea how good their implementation is), so I think it should be deferred.
- `image-resolution` is not even recognized by any UAs I tried, so I think it should be deferred.
- Gradient interpolation is also not implemented anywhere, so I think it should be deferred.

Unless of course any implementers are just about to work on these features, in which case speak up now! :)
