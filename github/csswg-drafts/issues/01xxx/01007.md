The indices in Snapshot 2017 have several issues:

1. The Selector Index is [empty](https://www.w3.org/TR/2017/NOTE-css-2017-20170131/#selectors).

2. `@font-face` and `@import` do not appear in the [At-Rule Index](https://www.w3.org/TR/2017/NOTE-css-2017-20170131/#at-rules), although `css-fonts-3` and `css-cascade-3` are [present](https://github.com/w3c/csswg-drafts/blob/0010e3a556ebe27cca78c9d87b78985e0c416d94/css-2017/Overview.bs#L732-L765) in `Overview.bs`.

3. There are two index sections:

* https://www.w3.org/TR/2017/NOTE-css-2017-20170131/#indices
* https://www.w3.org/TR/2017/NOTE-css-2017-20170131/#index

Should the two sections above be put together? If so, is it technically feasible (with the current Bikeshed)?

Can't the combination of `status="TR"` for the `<index>` element and the new URLs of the modules in the `specs` attribute be part of the problem? For example, that lists have `css-images-3` among other values, but the TR-published version of CSS Images Level 3 hasn't undergone the Great Renaming yet, so its URL is still [css3-images](https://www.w3.org/TR/css3-images/).

Maybe other TR specs published with the old template (somewhere in 2013-2014) have also other problems that prevent their terms and definitions from being parsed correctly?

In the Indexes document, the `<index>` elements have no `status` and `specs` attributes, so they might be not affected by this problem.
