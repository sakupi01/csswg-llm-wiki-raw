Currently if you don't have a 0% or 100% keyframe, a keyframe is synthesized using the un-animated / underlying animated style (see #1841). It's odd, however, that this behavior only ever applies at the endpoints and you can never, for example, have a 50% keyframe where the property value is taken from the underlying style.

<!-- comment id=333432511 author=AmeliaBR created=2017-10-02T03:19:00Z url=https://github.com/w3c/csswg-drafts/issues/1842#issuecomment-333432511 -->
## @AmeliaBR — 2017-10-02

Could we overload [the `revert` keyword](https://drafts.csswg.org/css-cascade-4/#valdef-all-revert) just a little bit more, to give it special behavior in keyframes?  It already has different behavior depending on the origin of the rule it's in, and animations are [treated as a separate origin for the cascade](https://drafts.csswg.org/css-cascade-4/#cascading-origins).

<!-- comment id=333442175 author=birtles created=2017-10-02T05:10:22Z url=https://github.com/w3c/csswg-drafts/issues/1842#issuecomment-333442175 -->
## @birtles — 2017-10-02

I think `revert` might make sense for the un-animated style, but in #1841 I'm proposing that we use the underlying animation's style in which case I don't think `revert` makes sense (since we'd be applying other styles from the same origin).
