Currently, the CSS Paged Media spec uses inner at-rules inside an outer `@page` at-rules to style [page-margin boxes](https://drafts.csswg.org/css-page/#margin-boxes).

I feel like using pseudo-elements to do such is much more consistent with the rest of the CSS syntax.

```CSS
@page :first::top-center
{
	content: "Document Title";
}
```

To avoid repetition, [nesting](https://tabatkins.github.io/specs/css-nesting/) could be allowed inside `@page` rules.

Nesting, beyond being useful for styling page-margin boxes, would help to avoid repetition more generally.

-----

Reusing other features of CSS leads to a more consistent experience for those trying to style page-margin boxes than trying to come up with a different approach to do what is already solved by other parts of the CSS spec and proposals.

## @g12n — 2017-12-22

This seems to have implications for the this #499 as well.

In practice there isn't a difference between styling a [grid-template-area](https://www.w3.org/TR/css-grid-1/#grid-template-areas-property) as a pseudo-element or styling a [magrin-box](https://www.w3.org/TR/css3-page/#margin-boxes). 

So whatever solution is picked for  to style grid-cells should be considered to be adopted to `@page` or for all [fragmentation contexts](https://www.w3.org/TR/css-break-3/#fragmentation-model) in general. 

# Otherwise we end up with two syntaxes doing the same thing:

## @page margin-boxes width nested at-rules in paged media:

When Applying `margin` to an `@page` the designer gets access to **16** quite arbitarily named [magin-boxes](https://www.w3.org/TR/css3-page/#margin-boxes) via at-rules. 

````css
@page {
    margin: 15mm;
    size:  140mm 90mm;
    @left {
         background: yellow;
    }
}
````

`@left` is not in the Spec but in the implemetation by [PrineXML](https://www.princexml.com/doc/7.1/page-headers-footers/)

## suggetion: pseudo-elements to style grid-cells (compare #499)

This would be the version with the pseudo-element by @tabatkins

````css
#grid-container {
  width: 140mm; 
  height: 90mm;
  grid: 15mm repeat(3, 1fr) 15mm / 15mm repeat(3, 1fr) 15mm; 
}

#grid-container::grid-area(2/1/-2/2) {
  background: yellow;
}
````

# @page treated like a flex-box

Harmonizing the syntax of [CSS Paged Media Module](https://www.w3.org/TR/css3-page/) and [CSS Grid Layout Module](https://www.w3.org/TR/css-grid-1/) could actually boost their adoption. Regular Browsers who mostly ignore the paged media module could easily implement it by treating a page like a grid-container with fixed dimension. ([Example](https://codepen.io/g12n/pen/eydyzJ))

Specialized tools like [princeXML ](https://www.princexml.com/) and [PDF-Reactor
](http://www.pdfreactor.com/) who have to adapt the css grids as a new feature would benefit by this approach as well.

## @faceless2 — 2021-01-31

Strongly agree with @frivoal, `@page::top-center` might be slightly more consistent but it doesn't seem to fix a problem or add anything new. There are an existing body of users, tools and documentation describing the current syntax, introducing a rival syntax will confuse things. It's not like we're creating hundreds of page styles per document.

Strongly against the make-like-a-grid suggestion - for the same reasons as above, and also because `@page::grid-area(2/1/-2/2)` is a big leap backwards in legibility. I'm all for boosting adoption, but it's not the syntax or layout model that's preventing it.
