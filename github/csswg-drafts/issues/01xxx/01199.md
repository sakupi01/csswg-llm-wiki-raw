The resolution of https://www.w3.org/Bugs/Public/show_bug.cgi?id=17521 introduced a rule in the CSS Transforms spec that:

> For all [non-root] elements that are affected by a transform (i.e. have a transform applied to them, or to any of their ancestor elements), a value of fixed for the background-attachment property is treated as if it had a value of scroll

It's not clear whether an element with `transform-style: preserve3d` but without an actual transform counts as "affected by a transform". Based on their behaviour on [this test case](https://codepen.io/anon/pen/vxPeXW), Edge seems to think it does not, while Firefox seems to think it does.

Could we clarify the intention here?

<!-- comment id=532052890 author=smfr created=2019-09-17T04:24:48Z url=https://github.com/w3c/csswg-drafts/issues/1199#issuecomment-532052890 -->
## @smfr — 2019-09-17

I think "affected by transform" does not include elements with transform-style: preserve-3d or their descendants, only those with or affected by an ancestor with a non-default transform property.

Do we think this needs a spec edit?

<!-- comment id=532057319 author=mattwoodrow created=2019-09-17T04:49:39Z url=https://github.com/w3c/csswg-drafts/issues/1199#issuecomment-532057319 -->
## @mattwoodrow — 2019-09-17

I think this is a Gecko bug, where we're incorrectly treating transform-style:preserve-3d as 'transformed'.

We could change the wording here to refer to 'transformed element' (which is an explicitly defined term) to be a bit clearer.
