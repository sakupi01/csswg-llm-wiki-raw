Imagine you have a series of paragraphs, wrapped in an article element. 
Each paragraph has a 1em margin above and below, `p {margin: 1em 0;}`. 
You also apply `article {columns: 4;}` to create four columns of the paragraph text. 
Here's a demo: https://codepen.io/jensimmons/pen/OOXXvW

The problem: in the first column, the paragraph does not have a collapsing top margin, so the paragraph is pushed down 1em. In the other columns, the margin does collapse. Plus, we don't really have interop across browsers for this behavior.

(In the demo, I've applied `break-inside: avoid;` as well to get the paragraphs to start at the beginning of a column. Feel free to remove it to see how things behave differently without it.)

It would make much more sense for margins to collapse in all columns, imo. If we decide we must have margins not collapsing in the first column, then we should at least make that consistent across all columns.

## @fantasai — 2017-11-06

Note that margins are preserved at forced breaks also. It's only at unforced breaks that they disappear. There was some discussion about a property to control this, e.g. `margin-break: auto | discard | keep`. See https://lists.w3.org/Archives/Public/www-style/2009Mar/0065.html

## @jensimmons — 2017-11-06

The other place margin collapsing is mentioned is this, from https://drafts.csswg.org/css-multicol/#the-multi-column-model:

> A multi-column element establishes a new block formatting context, as per CSS 2.1 section 9.4.1.
> 
> A top margin set on the first child element of a multicol element will not collapse with the margins of the multicol element.
