The [spec](https://drafts.csswg.org/css-text-3/#letter-spacing-property) says that the computed value should be an absolute length, but at least Safari and Firefox preserve the keyword `normal` in computed values.

<!-- comment id=371432237 author=fantasai created=2018-03-08T09:33:18Z url=https://github.com/w3c/csswg-drafts/issues/1484#issuecomment-371432237 -->
## @fantasai — 2018-03-08

CSS2 used to treat `normal` different than `0`, so computing differently was a requirement. Now that the spec treats them the same, it's possible to compute through. I'll ask the WG if they want to change the implementations or the spec in this case.

<!-- comment id=374465072 author=FremyCompany created=2018-03-20T03:53:41Z url=https://github.com/w3c/csswg-drafts/issues/1484#issuecomment-374465072 -->
