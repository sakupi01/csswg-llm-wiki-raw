"disc" is the initial value of `list-style-type`, and making it overridable may add some unnecessary complexity to implementation. I hope we can make it not overridable like `decimal`.

So my proposal is:
> Additionally, in the context of the prelude of an @counter-style rule, an ASCII case-insensitive match for "decimal" **or "disc"** is also an invalid <counter-style-name> and makes the @counter-style rule invalid.

<!-- comment id=307854848 author=tabatkins created=2017-06-12T17:12:49Z url=https://github.com/w3c/csswg-drafts/issues/1521#issuecomment-307854848 -->
## @tabatkins — 2017-06-12

The only reason I made 'decimal' not overrideable is so I had some dependable fallback that didn't lose information.

I don't have a problem with making 'disc' non-overrideable as well, but it would be beyond the original justification for it.

<!-- comment id=307959965 author=upsuper created=2017-06-12T23:06:53Z url=https://github.com/w3c/csswg-drafts/issues/1521#issuecomment-307959965 -->
## @upsuper — 2017-06-12

I totally understand the reason why 'decimal' needs to be non-overridable, and yeah, 'disc' doesn't need to be non-overridable theoretically. I just find it annoying when working on our new style system, and I don't think it is really something important worth the complexity to preserve.
