We currently define some URL modifier functions: https://drafts.csswg.org/css-values-5/#request-url-modifiers

They don't have hyphens. Should they? CC @annevk @SebastianZ @tabatkins @cdoublev 

<!-- comment id=3075618822 author=SebastianZ created=2025-07-15T20:57:58Z url=https://github.com/w3c/csswg-drafts/issues/12483#issuecomment-3075618822 -->
## @SebastianZ — 2025-07-15

Strong yes, they should have hyphens, from my side. We generally use hyphens in names and consider multi-word names missing them like `currentColor` and `nowrap` as [mistakes](https://wiki.csswg.org/ideas/mistakes).

Also, the keywords they take already do use hyphens. And we also have other function names like `linear-gradient()` etc. that have hyphens in their names. Plus, the header names like [`Referrer-Policy`](https://w3c.github.io/webappsec-referrer-policy/#referrer-policy-header) _also_ use hyphens.

So I don't see any reason to write them without hyphens.

Sebastian
