Several of the arithmetic methods are referring to this's `unit` internal slot.
However, `this` might be an instance of some other class than `CSSUnitValue`.
As a result it won't have a `unit` internal slot.

Example from step 2 of [`add(...values)`](https://drafts.css-houdini.org/css-typed-om-1/#dom-cssnumericvalue-add):
> return a new CSSUnitValue whose unit  internal slot is set to this’s unit internal slot 

This affects the following methods:
- [add(...values) method](https://drafts.css-houdini.org/css-typed-om-1/#dom-cssnumericvalue-add): `this` might be a `CSSMathSum` object
- [min(...values)](https://drafts.css-houdini.org/css-typed-om-1/#dom-cssnumericvalue-min): `this` might be a `CSSMathMin` object
- [max(...values)](https://drafts.css-houdini.org/css-typed-om-1/#dom-cssnumericvalue-max): `this` might be a `CSSMathMax` object

The issue can be fixed by defining unit in the steps:
> If all of the [items](https://infra.spec.whatwg.org/#list-item) in values are [CSSUnitValue](https://drafts.css-houdini.org/css-typed-om-1/#cssunitvalue)s and have the same [unit](https://drafts.css-houdini.org/css-typed-om-1/#dom-cssunitvalue-unit) _unit_, return a new [CSSUnitValue](https://drafts.css-houdini.org/css-typed-om-1/#cssunitvalue) whose [unit](https://drafts.css-houdini.org/css-typed-om-1/#dom-cssunitvalue-unit) internal slot is set to _unit_
