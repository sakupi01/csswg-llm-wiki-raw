See: https://drafts.csswg.org/css-color-5/#color-mix-result


> 4. If items is length 1, set color to the color of that sole item.

Since converting to the interpolation space only happens in `4.2` and `4.2` only applies when there is more than 1 item, a single color is never converted when following the spec text.

So `color-mix(in oklch, red)` yields `red` and not `oklch(0.628 0.258 29.234)`

While `color-mix(in oklch, red, red)` would yield `oklch(0.628 0.258 29.234)`.

I suggest we always convert to the interpolation space:

> If items is length 1, set color to the color of that sole item, converted to the specified interpolation `<color-space>`

------

Even when `red` and `oklch(0.628 0.258 29.234)` are equivalent, differences do surface when the input color has `none` (or missing components) and the interpolation color space is such that those components go away.

For example: `color-mix(in srgb, hsl(none 50% 50%))`
There is no way to expressing "missing hue" in `rgb` notation and the rgb result would be `rgb(191.25 63.75 63.75)`
