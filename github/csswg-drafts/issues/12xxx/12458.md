[`<whole-value>`](https://drafts.csswg.org/css-values-5/#whole-value) is unusually defined in a [heading element](https://github.com/w3c/csswg-drafts/blob/e2903b127e6af374279a884588c882aa27a53869/css-values-5/Overview.bs#L1493) with a `type` attribute, instead of with a `<dfn>` element, so `w3c/reffy` misses it and [drafts.csswg.org/css-values-5/#typedef-whole-value](https://drafts.csswg.org/css-values-5/#typedef-whole-value) does not work.

Is it intentional, or you would it be possible to add a proper type definition?

@tidoust

## @tabatkins — 2025-07-18

Reffy shouldn't be missing that - the [definitions data model](https://speced.github.io/bikeshed/#dfn-contract) allows headings to be defining elements, if they have the right attributes.

(I'd be fine with moving it out, too, but if it's missing this definition, it's probably missing a *number* of definitions.)

<!-- comment id=3090517022 author=cdoublev created=2025-07-18T19:32:23Z url=https://github.com/w3c/csswg-drafts/issues/12458#issuecomment-3090517022 -->
## @cdoublev — 2025-07-18

I only find `<whole-value>` as a CSS value defined in a heading. I do not know how `w3c/reffy` extracts definitions from other specs than CSS specs. But I am inclined to say it should support this.

FWIW, I confirm the pattern was supported in definitions extracts. It wasn't supported in the logic that produces more specific CSS extracts. It now is!
