In the discussion about [adding typographic pseudo-elements to the Safe to Release Exceptions](https://github.com/w3c/csswg-drafts/issues/12773#issuecomment-3286010681), @fantasai asked for the `::marker` element to be added to the Safe to Release Exceptions, as well. (This was not minuted, though.)
As `::marker` wasn't part of that issue, here's a new one, so we can discuss it separately.

So here are the facts and stats regarding this pseudo-element:

* [implemented in all major browsers since 2020, though limited support for properties](https://developer.mozilla.org/en-US/docs/Web/CSS/::marker#browser_compatibility)
* WPT [pseudo](https://wpt.fyi/results/css/css-pseudo?label=experimental&aligned&q=marker) + [lists](https://wpt.fyi/results/css/css-lists?label=experimental&label=master&aligned&q=marker): passing tests: Chrome: 348, Edge: 348, Firefox: 316, Safari: 300; interop [pseudo](https://wpt.fyi/results/css/css-pseudo?label=master&label=experimental&aligned&q=marker+all(status%3Apass)) + [lists](https://wpt.fyi/results/css/css-lists?label=master&label=experimental&aligned&q=marker+all(status%3Apass)): 266 / 359 (74.1%)
* Open issues: on GitHub [pseudo](https://github.com/w3c/csswg-drafts/issues?q=is%3Aissue+state%3Aopen+label%3Acss-pseudo-4+"%3Amarker"+in%3Atitle) + [lists](https://github.com/w3c/csswg-drafts/issues?q=is%3Aissue%20state%3Aopen%20label%3Acss-lists-3%20%22%3Amarker%22%20in%3Atitle): ~9, [in spec.](https://drafts.csswg.org/css-pseudo-4/#issues-index): 2

> WebKit supports parsing `content`

Yeah, I added both parsing tests and behavior tests. I guess they wanted to raise their WPT pass rate so they just enabled parsing without adding any real support for lots of properties, which would require a huge refactoring.

On the other hand, Gecko has real support for all properties, it's just gated by a pref. So they only need to relax it a bit and allow more properties without the pref.
