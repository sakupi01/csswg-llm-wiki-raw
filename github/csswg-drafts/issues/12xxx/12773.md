Splitting the discussion from #10687 for adding typographic pseudo-elements from [CSS Pseudo-Elements 4](https://drafts.csswg.org/css-pseudo-4/) (basically all from CSS 2 with double-colon syntax plus `::prefix` and `::postfix`) to the Safe to Release pre-CR Exceptions section of the CSS Snapshot 2025.

Data to consider:

* Spec. status: WD (last published: 27 June 2025)
* Implemented in all major browsers for many years
* [WPT](https://wpt.fyi/results/css/css-pseudo?label=master&label=experimental&aligned&q=before-after): passing tests: Chrome: 3, Edge: 3, Firefox: 3, Safari: 3; [interop](https://wpt.fyi/results/css/css-pseudo?label=master&label=experimental&aligned&q=before-after%20all(status%3Apass)): 3 / 3 (100.0%)
* Open issues: [on GitHub](https://github.com/w3c/csswg-drafts/labels/css-pseudo-4): ~14, [in spec.](https://drafts.csswg.org/css-page-3/#issues-index): 0

Summary: Very high interoperability, only minimal number of WPTs, many open issues

As it was pointed out in the call, `::first-line`, `::first-letter`, `::before`, and `::after` are already in Selectors 3, which is already part of the official definition.
And `::prefix` and `::suffix` are actually implemented nowhere yet, it seems.

Therefore, I'm closing this.
