See https://github.com/whatwg/html/issues/10616 and [explainer](https://github.com/w3c/csswg-drafts/blob/main/css-view-transitions-2/two-phase-transition-explainer.md).

Currently a cross-document view-transition has to wait twice:
- Wait until the navigation is committed before snapshotting the old state
- Wait until the new document is ready to present a frame before activating the view transition

These delays, in cases where the navigation is not instant, can create a jarring experience.

To overcome this, a common pattern is to start some animation/view-transition instantly, and then transition from that to the next page when it is ready to render.

See some demo here: https://noamr.github.io/two-phase-vt/api-explorer/

The issue with this pattern is that the author has no control over the timing of the cross-document view transition, and it can abruptly interrupt the transition to the preview.

The proposal in the explainer is as follows:
```css
@view-transition {
  navigation: auto;
  /* A future value can be `auto` */
  preview: always | none;
}
```

When preview is `always`, the UA would start an instant view transition when the navigation is initiated, into a phase called preview.
The preview phase would be a navigation phase:
```css
@navigation (phase: preview) {
  .skeleton { display: block }
}
```

In addition, there would be two new UA view transition types, to control the view-transition that leads to the preview, and from the preview to the final state:

```css
:active-view-transition-types(-ua-to-preview) {
  .real-element-in-old-page { view-transion-name: foo; }

  @navigation (phase: preview) {
    .real-element-in-old-page { view-transion-name: none; }
      .skeleton .element-placeholder { view-transition-name: foo; }
   }
}

@navigation (phase: preview) {
  .skeleton .element-placeholder { view-transition-name: foo; }
}

:active-view-transition-types(-ua-from-preview) {
      .skeleton .some-other-element { view-transition-name: bar; }
}
```

See the above demo for a more elaborate/real use case.
