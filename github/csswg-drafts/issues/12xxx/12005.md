```
@sheet foo {}
@sheet "foo" {}
```

The former feels natural, but this issue is whether we should *also* support the latter. 
 
For precedent, `@layer` *only* supports the former:

```
<layer-name> = <ident> [ '.' <ident> ]*
```

https://www.w3.org/TR/css-cascade-5/#layer-names

...while `@keyframes` allows both (as equivalent values):

```
<keyframes-name> = <custom-ident> | <string>
```

https://drafts.csswg.org/css-animations-1/#keyframes

## @tabatkins — 2025-03-26

Keyframes are the odd one out here, one of many oddities resulting from the spec being implemented by Apple well before WG review. We *very rarely* allow strings to name things.

The clear precedent is that it should be ident only.

## @tabatkins — 2025-03-26

The benefit of `<custom-ident>` over `<ident>` is that (a) if the value ever shows up in a property, it'll automatically work reasonably without having to do some weird engineering, and (b) it's just more consistent in general where we don't allow inherit/initial/etc as keywords.
