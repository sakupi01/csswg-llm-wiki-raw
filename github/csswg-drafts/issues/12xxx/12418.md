@LeaVerou [raised this question](https://github.com/w3c/csswg-drafts/issues/11756#issuecomment-2689332711) in a discussion about scoped imports:

> why aren't they valid? We resolved a while ago that outside of nesting, `:scope` and `&` resolve to `:root`. If `> h2` is essentially equivalent to `& > h2`, why wouldn't that be valid in the root scope?

## @tabatkins — 2025-06-30

My arguments against top-level relative selectors only apply to actual top-level selectors, unscoped by anything. If you have a scoped stylesheet, they don't apply, and I think top-level relative selectors are fine. (Notably, *non*-relative selectors work as expected in that case, identical to non-relative selectors inside a `@scope` block.)

<!-- comment id=3020500608 author=mirisuzanne created=2025-06-30T19:50:39Z url=https://github.com/w3c/csswg-drafts/issues/12418#issuecomment-3020500608 -->
## @mirisuzanne — 2025-06-30

If we don't allow them generally, I think it would be strange to allow them when the same file is imported with a scope modifier. That would make the syntax conditionally valid depending how the file is imported. My preference would be to have the same rules in both cases. 

Notably, if we disallow, authors can still achieve the same impact explicitly:

```css
:scope > h2 { … }
```

As you noted in the other issue, when `:scope` is the root `html` element, both child and sibling combinators become basically useless. So this might only match when the stylesheet is scoped – but it would be valid and clear about the intent of the selector in both cases. 

<!-- comment id=3020630807 author=tabatkins created=2025-06-30T20:43:47Z url=https://github.com/w3c/csswg-drafts/issues/12418#issuecomment-3020630807 -->
## @tabatkins — 2025-06-30

> That would make the syntax conditionally valid depending how the file is imported. My preference would be to have the same rules in both cases.

Yeah, that's a reasonable argument to keep them banned here, and I agree that writing `:scope > ...` is reasonable and readable when it's necessary.

<!-- comment id=3021285584 author=LeaVerou created=2025-07-01T00:38:57Z url=https://github.com/w3c/csswg-drafts/issues/12418#issuecomment-3021285584 -->
## @LeaVerou — 2025-07-01

I think it's pretty confusing if `&` behaves like `:scope` in some contexts and not others. What's the downside of letting it be valid regardless?

<!-- comment id=3024600197 author=mirisuzanne created=2025-07-01T15:51:11Z url=https://github.com/w3c/csswg-drafts/issues/12418#issuecomment-3024600197 -->
## @mirisuzanne — 2025-07-01

I don't think `&` ever behaves quite like `:scope`? `&` always refers to the parent selector (which might be the scoping selector, but could match multiple elements) while `:scope` refers to the scoping root element (always a single element).
