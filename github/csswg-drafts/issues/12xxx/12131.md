`anchor()` allows specifying percentage values, which [interpolates between `start` and `end`](https://drafts.csswg.org/css-anchor-position-1/#valdef-anchor-percentage).

This seems like something that can be simplified, since I think the basis of that will always be positive, since it depends on the anchor element's size in that axis. OTOH, WPT test `anchor-parse-valid.html` expect the `min(50%, 100%)` value to round trip.

```js

div.style.display = "none"; // Get the computed, not resolved, value
```

Yeah , re-reading this, anchor() actually isn't an example of the question here - the % in anchor() *doesn't* resolve against any basis, it's left as-is, so it can be resolved immediately regardless.

<!-- comment id=5604794412 author=tabatkins created=2026-09-09T15:56:04Z url=https://github.com/w3c/csswg-drafts/issues/12131#issuecomment-5604794412 -->
## @tabatkins — 2026-09-09

Just to make things clear here, since it's been a while since this was discussed: back in 2020 [we resolved that min()/max() will simplify values that we know the relative sizes of](https://github.com/w3c/csswg-drafts/issues/4550#issuecomment-594970559) - that is, `min(10px, 20px)` will just immediately resolve to `10px`.

This issue is specifically about whether or not we do so for percentages, *when we know via context* that the % is resolved against a non-negative number. (In general, such as in background-size, you can't tell whether `10%`	is bigger or smaller than `20%`, as whether the basis is positive or negative inverts the answer.)
