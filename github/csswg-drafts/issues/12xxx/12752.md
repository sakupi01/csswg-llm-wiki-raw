Anchor positioning is great for positioning things relative to other elements. Sometimes, I want to position things next to the [insertion caret ](https://drafts.csswg.org/css-ui-3/#insertion-caret) though, for things like autocomplete suggestions in a large contenteditable element.

I'm not sure if this has been proposed before, but I think this might be a good fit for anchor positioning.

## @flackr — 2025-09-08

This seems like it would be cleanest to do with a pseudo-element, e.g.

```
.my-editable-element::caret {
  anchor-name: --caret;
}
```

Though this idea of having a pseudo-element came up previously in https://github.com/w3c/csswg-drafts/issues/9707#issuecomment-1933199902 and was resolved to stick to adding more `caret-` properties.
