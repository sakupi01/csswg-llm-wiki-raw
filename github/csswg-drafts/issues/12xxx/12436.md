@LeaVerou [raised the idea](https://github.com/w3c/csswg-drafts/issues/12154#issuecomment-3028591124) of adding a combinator that allows an author to select an element that is the target of an interest invoker. So:

```html
<button id=invoker interestfor=target>Interest invoker</button>
<div popover id=target>Target of interest invoker</div>

<style>
  #invoker --> #target {
    /* Styles for the target popover that only apply when
      #invoker points to #target, as above. */
  }
</style>
```

Here, I made up the combinator as `-->` just as a placeholder. Though it's not bad, maybe?

If this combinator is a good idea, it might alleviate some of the questions in https://github.com/w3c/csswg-drafts/issues/12154#issuecomment-3028591124, e.g. by obviating the need for two separate pseudo classes for the invoker and the target. If there was simply a pseudo class on the invoker, then "target with interest" could be selected with `:interest-invoker --> [popover]`. 

<!-- comment id=3028984370 author=LeaVerou created=2025-07-02T18:47:36Z url=https://github.com/w3c/csswg-drafts/issues/12436#issuecomment-3028984370 -->
## @LeaVerou — 2025-07-02

Please note that future combinators will follow the `/name/` syntax, not ASCII art. So this might be something like `/invokes/` or `/interestfor/`, e.g. `#invoker /interestfor/ #target`. In which case, indeed `#invoker:interest-target /interestfor/ #target` gets you the popover.

You could even have a combinator for "invoker invoked another element", e.g. `/invoked/`.
Then, you could even do `#invoker:has(/invoked/ *)` and `* /invoked/ #target` and you're pretty much done with most (all?) of the pseudo-class use cases 😁 

That said, https://github.com/w3c/csswg-drafts/issues/12154 seems to be missing a solid list of use cases around styling, which makes it hard to propose good syntax.

## @LeaVerou — 2025-07-03

> Wouldn’t `:root:has(#invoker:has-interest) #target` get you there?

No, because the invoker-target relationship is not 1-1. Also, that means there is no generic way to target invoker targets, which can be useful for design systems, libraries, etc.

## @wimbarelds — 2026-03-17

> > Note that with a combinator to go from target to invoker, we get that for free, via :has().
> 
> I don't doubt it's possible using all the magic of modern CSS but off the top of my head I can't quite picture it. Can you show an example CSS snippet to do it?

I think he means that, given

```
<label for="something">Text</label>
<input id="something">
```

If you can go from label to associated input using:

```css
label /idref(for)/
// or
label /interestfor/
```

Then you can probably find the label that has a referenced input

```css
label:has(/idref(for)/)
// or
label:has(/interestfor/)
```

Or perhaps a more useful example might be

```css
label:has(/ifref(for)/:invalid) {
  color: red;
}
// or
label:has(/interestfor/:invalid) {
  color: red;
}
```

To select labels with an invalid associated input
