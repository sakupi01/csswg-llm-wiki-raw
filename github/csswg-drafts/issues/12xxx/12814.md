Hi Team,

Just wanted to start discussion thread whether ::first-letter [1] and ::first-line [2] should have animations and scroll animations allowed similar to ::marker.

As of right now, they are not allowed and Chrome and Firefox implementations are as such.

[1] https://drafts.csswg.org/css-pseudo/#first-line-styling
[2] https://drafts.csswg.org/css-pseudo/#first-letter-styling

Just want to get clarity and if needed to get explicitly state on this on what needs to be done.

Thanks!

<!-- comment id=3915475294 author=dbaron created=2026-02-17T15:45:55Z url=https://github.com/w3c/csswg-drafts/issues/12814#issuecomment-3915475294 -->
## @dbaron — 2026-02-17

There's a whole bunch of complexity here.

To take just one example, a `::first-letter` pseudo-element on a particular element doesn't have a unique value for each of the properties that it supports.  For example, if you have:

```html
<style>
  p { color: black }
  p::first-letter { transition: color 300ms; }
  p.interesting::first-letter { color: blue; }
  p.first-word { color: gray }
</style>
<p>"<span class="first-word">This</span> is the paragraph.</p>
<script>
  setTimeout(() => { 
    document.getElementsByTagName("p")[0].className = "interesting";
  }, 100);
</script>
```

then it seems like the `"` part of the `p::first-letter` should transition from black to blue, and the `T` part of the `p::first-letter` should transition from gray to blue.

Or is this specifically about CSS Animations *excluding* Transitions?

<!-- comment id=3919361870 author=lilles created=2026-02-18T08:20:22Z url=https://github.com/w3c/csswg-drafts/issues/12814#issuecomment-3919361870 -->
## @lilles — 2026-02-18

None of the major engines implement the [fictional tags](https://www.w3.org/TR/css-pseudo-4/#example-7499991d) for nesting per spec, but style based on the innermost container which has `::first-line` styles only:

```html
<!DOCTYPE html>
<style>
  #outer::first-line { color: lime; }
  #inner::first-line { background-color: green; }
</style>
<div id="outer">
  <div id="inner">First line</div>
</div>
```

I think fixing that would be a prerequisite for supporting this in Chrome in a sensible and predictable way.

<!-- comment id=3922951426 author=flackr created=2026-02-18T20:13:08Z url=https://github.com/w3c/csswg-drafts/issues/12814#issuecomment-3922951426 -->
## @flackr — 2026-02-18

I think there's nothing technically preventing animating all pseudo-elements. Authors can for example create an animation on a custom variable on some ancestor element and use that custom variable in these non-tree-abiding pseudo-elements ([demo](https://jsbin.com/qeyeweg/edit?html,css,output)). That said, I think support in chromium could take significant effort and so we may not be able to support this for some time.
