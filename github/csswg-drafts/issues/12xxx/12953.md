Currently transitions can only be started on an element/document.
Starting a transition on the element as the scope, would only include same-tree descendants of that element when finding participants.
Considering adding `shadowRoot.startViewTransition`, which would pick elements and create pseudo elements inside the shadow scope.


> How does this work with Shadow DOM? If I'm manipulating multiple elements that are directly the children of a shadow root, what do I call `startViewTransition()` on? 

 _Originally posted by @EisenbergEffect in [#9890](https://github.com/w3c/csswg-drafts/issues/9890#issuecomment-3399387164)_

## @skobes-chromium — 2025-10-15

This seems good from an ergonomic perspective, but it does raise the question of which element serves as the "originating element" for the `::view-transition*` pseudos. Document transitions hang them on the `<html>` element but the shadow root has no equivalent of that. If we put it on the shadow host then it interferes with calling `shadowHost.startViewTransition()`.

## @noamr — 2026-07-01

I was thinking about this further, and a cleaner and more flexible approach would be to pass in a list of shadow roots to the `startViewTransition` options:

```js
documentOrElement.startViewTransition({
  async update() { ... },
  shadowRoots: [thisElement.shadowRoot, someOtherElement.shadowRoot]
});
```

So the transition is still on an element and everything is dandy, but it can collect names from any descendant shadow root.

## @emilio — 2026-07-04

I think the transition should probably still be in the host, yeah, or otherwise should behave the same rendering-wise as if you called it on the host... But at that point having it on the shadow tree seems a bit overkill and prevents from transitioning slotted content along with the shadow contents, right?

I guess another option would be to collect names in the flat tree but keep their scoped-ness right? so view-transition-name: foo inside and outside the shadow tree could be two different names? But I think that could be a bit awkward / be undesired in some cases.

So the "give me a set of shadow trees which are ok to pull names from" seems possibly fine, yeah.
