Petition to update the name of the "active" pseudo class to "pressed" to better indicate intent and to also add a "selected" pseudo class to account for elements that incur that behavior AND carries that intent.

What would constitute an element being "selected"? A text selection within it? Around it? Would the selected option in a `<select>` dropdown be `:selected`? What about a ticked checkbox/radio button or a text field that is currently being edited?

Also, what would it be used for?

<!-- comment id=3276661152 author=shaolinkitty created=2025-09-10T21:51:54Z url=https://github.com/w3c/csswg-drafts/issues/12769#issuecomment-3276661152 -->
## @shaolinkitty — 2025-09-10

Yes, the selected option would be :selected and I believe the checkbox and radio button get the ["checked" pseudo-class](https://developer.mozilla.org/en-US/docs/Web/CSS/:checked). The confusion really is around the word "active" itself. Changing the nomenclature to "pressed" further intimates the [intended use](https://developer.mozilla.org/en-US/docs/Web/CSS/:active) for the class and clarifies where it should be used especially when it comes to stacked states. And also considering that folks often conflate the two (active and selected) in terms of how it might be designed and implemented.

## @fantasai — 2025-09-11

I have to agree with @Loirooriol, it's too late (by a couple decades) to make this change.

I'll note that in the early Internet era, `:active` in some implementations continued to match while the link was loading or while its targetted element (for #fragment links) was still the targetted fragment. It's a bit disappointing that it's degenerated to "while mouse down" on any element at this point.
