Gutters are typically defined by the `row-gap`/`column-gap` css properties. However, there could be a "gutter" (space between tracks) as a result of content-distribution properties. 

The [CSS Grid Layout](https://drafts.csswg.org/css-grid/) and [CSS Box Alignment spec](https://www.w3.org/TR/css-align-3/) suggest that the space as a result of alignment properties is a part of the gutter:

[CSS Grid Level 2 ](https://drafts.csswg.org/css-grid-2/#gutters)

> Additional spacing may be added between tracks due to [justify-content](https://www.w3.org/TR/css-align-3/#propdef-justify-content)/[align-content](https://www.w3.org/TR/css-align-3/#propdef-align-content). See [§ 12.1 Grid Sizing Algorithm](https://drafts.csswg.org/css-grid/#algo-grid-sizing). This space effectively increases the size of the [gutters](https://www.w3.org/TR/css-align-3/#gutter).

[CSS Align Level 3](https://www.w3.org/TR/css-align-3/#gutter)
>Gutters effect a minimum spacing between items: additional spacing may be added by [justify-content](https://www.w3.org/TR/css-align-3/#propdef-justify-content)/[align-content](https://www.w3.org/TR/css-align-3/#propdef-align-content). Such additional space effectively increases the size of these [gutters](https://www.w3.org/TR/css-align-3/#gutter).

The phrase **"...effectively increases the size of the gutters."** implies this space should be treated as a gutter for all purposes (including painting decorations).

### Example:
Consider the following grid container where the gap is explicitly set to 0px, but `align-content: space-between` creates visible space between row tracks:

```
<style>
.wrapper {
  display: grid;
  grid-template-rows: repeat(3, 100px);
  height: 500px;
  width: 500px;
  gap: 0px;
  align-content: space-between;
  row-rule: solid;
}
</style>
<div class="wrapper">
  <div class="item1">Item 1</div>
  <div class="item2">Item 2</div>
  <div class="item3">Item 3</div>
</div>
```

Based on the specs, it seems like this is an accurate representation of what the rendered result should be with the `row-rule` property:

### Precedent in Multi-Column Layout:
A little tangential but somewhat related: Today, there is existing precedent for separting the concept of gap's size from the drawing of a rule. As @kbabbitt noted in a meeting offline, in multi-col layout a column rule is drawn even when column gap is set to 0px. This might also hint that a rule can be drawn in the "conceptual" space between tracks, independent of spacing value.

Just to make sure I understand, the idea would be that the "gutter" for gap decoration purposes is not the width defined by the corresponding `*-gap` property, but rather that width plus any additional space introduced by `justify-content`/`align-content`, correct?

That seems reasonable to me, with one comment and one question:

1. The current definition of [crossing gap width](https://drafts.csswg.org/css-gaps-1/#crossing-gap-width) is probably wrong and needs to be updated, as it does not account for that additional space.
2. While drafting up Gaps 1 I had assumed all of the gutters in a given direction (row or column) have the same width. Is it possible to construct a case using `justify-content`/`align-content` where that's not the case? If so, we might need an editing pass to account for it.

## @kbabbitt — 2025-11-10

Had an offline discussion at TPAC with @alisonmaher and @tabatkins and we came to the conclusion that, yes, space from content distribution properties counts as part of the gutter. This is important in particular so that percentages based on crossing gap widths work consistently.

Re: my point 2 question - it is not possible to construct a case where the gutters in a given direction have differing widths over a given container.

## @kbabbitt — 2025-11-11

We chatted about the above case today. The varying gap sizes are definitely an issue for determining percentage basis, but the only case where having percentage basis resolve against crossing gap width is achieving 'join' behavior. In an earlier draft of Gap Decorations, I had a `join` keyword for that purpose. If we reintroduced that and made it magic so that it knows how to join decorations in the above case as well as for T intersections in Grid, that would remove the need to have percentages based on crossing gap width, which would remove the ambiguity that arises from differing gap widths.

This is kind of intertwined with the changes we're discussing in #12784, so I think I'd like to bake these ideas some more before resolving on this issue.

## @kbabbitt — 2026-01-22

Coming back to this, some thoughts:
- The main value of percentages resolving to crossing gap widths is to have `-50%` cause adjacent segments to draw into each other.
- Someone, I think @emilio, correctly pointed out in one of our discussions that it was ambiguous whether such cases were actually drawn as a single continuous decoration or as two decorations touching each other, which could cause issues in colors with alpha, or in the future where we have decorations painted with images, gradients, etc.
- I had assumed that all crossing gaps have the same width, but the example in [this comment above](https://github.com/w3c/csswg-drafts/issues/12922#issuecomment-3514431608) demonstrates there are cases where that's not true.

So my proposal is:
- Space from content distribution properties counts as part of the gutter width.
- Remove percentages as valid values for `*-rule-inset`, without prejudice toward reintroducing them in the future, perhaps with some other basis.
- Add a keyword to `*-rule-inset` that unambiguously causes segments to join across intersections rather than just touch. I'll propose `join` for now, though I don't love the way `rule-inset: join` reads at a surface level. Open to bikeshedding something better.

## @tabatkins — 2026-01-28

Reiterating what I said at the end for visibility:

The question of what 'intersection' breaks looks like for the rules between flex-lines (or masonry tracks) is *in general* still undecided; all of the options seem confusing. (Creating intersection based only on the gutters on one side or the other, or making it for both and somehow dealing with overlaps, or not creating intersections *at all*.)

This is the only case where this issue can actually cause gutters to be different sizes, so until the rendering is resolved *in general*, it's not really useful to do anything about %s *in specific* yet.

## @kbabbitt — 2026-02-19

First resolution already had normative text in css-align-3; I guess we overlooked it. Added a Note to Gaps to call attention to it.
https://www.w3.org/TR/css-align-3/#column-row-gap:
> Gutters effect a minimum spacing between items: additional spacing may be added by [justify-content](https://www.w3.org/TR/css-align-3/#propdef-justify-content)/[align-content](https://www.w3.org/TR/css-align-3/#propdef-align-content). Such additional space effectively increases the size of these [gutters](https://www.w3.org/TR/css-align-3/#gutter).

Second resolution was already captured by previous edits.
https://drafts.csswg.org/css-gaps-1/#segment-endpoints:
> Entering a [gap junction](https://drafts.csswg.org/css-gaps-1/#gap-junction): At the point where a cross gap appears on at least one side of G, create an [end segment endpoint](https://drafts.csswg.org/css-gaps-1/#end-segment-endpoint).
> Exiting a [gap junction](https://drafts.csswg.org/css-gaps-1/#gap-junction): At the point where no cross gap exists on either side of G, create a [start segment endpoint](https://drafts.csswg.org/css-gaps-1/#start-segment-endpoint).
