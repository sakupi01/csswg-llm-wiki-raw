In #7972 we resolved to preserve invalid selectors that contain an `&` as-is. It seems it'd be more consistent to do that for _all_ invalid `:is()` / `:where()` branches like `:is(:unknown)`. That's how `@media` and `@supports` behave.

## @byung-woo — 2026-07-22

IMHO, we should preserve the invalid selector text exactly as-is, regardless of why it is invalid (e.g., a pure parsing error, an unallowed complex selector in :host(), or nested :has() restrictions).

We can then apply the existing serialization rule of adding a space after each comma in the list.

Here is how this approach would handle the questions above:
- `:is(,,,)`: The selector list contains four empty strings which are invalid selectors (`:is(<empty>,<empty>,<empty>,<empty>)`). Following the rule, this serializes to `:is(, , , )`.
- `:host(:is(.a, .b+.c, .d))`: The complex selector `.b+.c` is invalid inside `:host()`. By preserving the invalid token as-is, the whole block serializes back to `:host(:is(.a, .b+.c, .d))`.
- `:has(:is(:has(.x)))`: Nested `:has()` selectors are invalid. Preserving the inner invalid selector as-is means this serializes to `:has(:is(:has(.x)))`.

I think this approach provides predictable results for authors and seems to match the Safari and Firefox behavior.

What are your thoughts on this, @sesse?

## @byung-woo — 2026-07-30

Chrome landed a fix that supports this behind an experimental flag. It also added the following cases to the WPT tests to clarify certain behaviors:

* Preserve empty items, with a whitespace after each comma:
  - `:is(,,,)` -> `:is(, , , )`
* Trim trailing whitespace from an invalid selector:
  - `:is(::before:HOVER  )` -> `:is(::before:HOVER)`
* Serialize an invalid complex/compound selector as-is, even when the selector is valid outside of a forgiving selector list:
  - `:host(:is(.a, .b+.c, .d))`: unchanged after serialization. (No whitespace is added around the `+` combinator, since complex selectors are invalid inside `:host()`).
  - `:is(::before:HOVER, .a)`: unchanged after serialization. (`:HOVER` is not lowercased, since the compound `::before:HOVER` is invalid. `::before` is not allowed inside `:is()`)
  - `:has(:is(:has(.a+.b)))`: unchanged after serialization. (Nested `:has()` is invalid)
