In the first version of the spec, we skip fragmented elements (e.g. inline text with several box fragments).
We should see if there is a need to have those elements participate in the transition.

## @Psychpsyo — 2026-05-27

I'm a bit confused by this.
The spec links to this issue from [capture the old state](https://drafts.csswg.org/css-view-transitions-2/#capture-the-old-state), where elements that have "more than one [box fragment](https://drafts.csswg.org/css-break-4/#box-fragment)" are being ignored.
It then says this:
> [box fragment](https://drafts.csswg.org/css-break-4/#box-fragment) here does not refer to fragmentation of [inline boxes](https://www.w3.org/TR/CSS2/visuren.html#inline-boxes) across [line boxes](https://www.w3.org/TR/CSS2/visuren.html#line-box). Such inlines can participate in a transition.

This was added, with no further elaboration, in https://github.com/w3c/csswg-drafts/pull/9581

Multiple questions:
1. Can fragmented inlines transition?
2. What if the inline is fragmented due to bidi reordering instead of a break between line boxes? Can it transition then?
3. If so, why? If not, why not?
