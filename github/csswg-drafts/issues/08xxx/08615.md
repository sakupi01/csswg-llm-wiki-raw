- [anchor positioning spec](https://drafts.csswg.org/css-anchor-position-1/)
- [pseudo-elements spec](https://drafts.csswg.org/css-pseudo/)

Did a few more experiments just to see what is available: https://codepen.io/kizu/pen/MWqBRPw

There I tried to use `anchor-name` on pseudo-elements like `::first-letter`, `::first-line` and `::marker`. It doesn't work for any of those, probably with the main reason in `anchor-name` not being present in the list of allowed styles (it works for `::placeholder` though, which can be fun).

However! Given that the anchored elements do not impact their target — should we allow this?

Potential use-cases: ability to add various decorations to those pseudo-elements that are not available for them otherwise — like interesting borders, complex backgrounds, and so on. Using anchored elements for this seems like it could be a nice workaround.

## @tabatkins — 2023-03-24

I might need to do some minor wording fix to make it work, but in theory anchoring to a tree-abiding pseudo should be fine (so ::before, ::marker, etc). The non-tree-abiding ones (::first-letter, ::first-line, etc) aren't as reasonable - we purposely extremely limit their possible properties to avoid exposing their exact box structure.

## @tabatkins — 2024-02-26

Added an additional clarification to "acceptable anchor element" that it has be an element, or a pseudo-element that is equivalent to an element. (We don't yet actually have a term for this; Pseudo manually tags ::before/after in this way but misses ::backdrop.) This intentionally excludes ::marker and other pseudos which we do not expose the layout of.
