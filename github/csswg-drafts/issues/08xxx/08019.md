```css
/* 1.a */
:scope {
  @scope (.foo) {
    color: pink;
  }
}

/* 1.b */
& {
  @scope (.foo) {
    color: pink;
  }
}

/* 2.a */
@scope (.foo) {
  :scope {
    color: pink;
  }
}

/* 2.b */
@scope (.foo) {
  & {
    color: pink;
  }
}
```

I find these cases really tricky to reason about.
Are these all equivalent or not?

see : https://github.com/w3c/csswg-drafts/issues/5745

The `1.x` examples:
- nested `@scope` rule
- parent selector is `:scope` or `&`, but this is just `:root` in this context
- they don't have a rule with a selector inside `@scope`

The `2.x` examples:
- normal `@scope` rule
- selector is `:scope` or `&`, but `&` is `:scope` in this context

If we change the nesting of rules for `1.x` we get `2.x` but doing this naively changes the meaning of `:scope`. It is no longer equivalent to `:root`.

## @tabatkins — 2022-12-21

& represents the elements matched by the parent rule; it is *not* a textual substitution of the parent rule's selector. The "desugaring" to flat rules using :is() is informative only; the feature doesn't actually work quite like that.

So in your most recent example, the `:scope` is at the top level and resolves to the root. So the nested `&` represents the root element, and is unaffected by the `@scope` rule.
