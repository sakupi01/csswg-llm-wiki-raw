Should it serialize as specified by the author like a `var()`-containing value, or like other specified values with `<declaration-value`s replaced by the result from parsing against the grammar of the property?

---

*(some context)*

I think this issue may be a duplicate of #6484, whose substantive question is *how to serialize `<declaration-value>` as a component of a specified value?*

Looking at other "abstract" types, the serialization of `<declaration>` and `<any-value>` seems also unspecified (reported in #8735).

To my knowledge, they only appear in the prelude of `@container` (`style()` query), `@media`, `@supports`. The matched value is evaluated into a boolean so it seems less complex to preserve and serialize a string representation.

`<declaration-value>` always has a subsequent "use" that requires the parsed value, therefore I would favor (preserving and) serializing the result from parsing instead of the raw string input representation.
