`list-style-type: circle; list-style-position: inside; list-style-image: initial;`

Should that serialize to `list-style: inside circle;` or `list-style-type: circle; list-style-position: inside; list-style-image: initial;`?

It's obvious that `list-style-type: circle; list-style-position: inside; list-style-image: none;` can serialize to `list-style: inside circle;`, but less obvious for the `initial` case.

Given `initial` and `none` have different meanings when it comes to author intent, I'm tempted to think that `list-style-type: circle; list-style-position: inside; list-style-image: initial;` is the more valid option.

## @emilio — 2022-11-29

> Should that serialize to `list-style: inside circle;` or `list-style-type: circle; list-style-position: inside; list-style-image: initial;`?

The later. Otherwise it doesn't round-trip, because `list-style: inside circle` should expand to `none`, not `initial`. They are different values (even though in this case they compute to the same thing).

<!-- comment id=1331140822 author=Loirooriol created=2022-11-29T18:55:47Z url=https://github.com/w3c/csswg-drafts/issues/8150#issuecomment-1331140822 -->
## @Loirooriol — 2022-11-29

Yes, it's not explicitly stated for `list-style`, but shorthands reset omitted longhands to their initial value (not literally `initial`). The initial value for `list-style-image` is `none`.

<!-- comment id=1332135776 author=darinadler created=2022-11-30T13:12:16Z url=https://github.com/w3c/csswg-drafts/issues/8150#issuecomment-1332135776 -->
## @darinadler — 2022-11-30

Does that mean that setting `list-style` to an image URL resets `list-style-type` to `disc` rather than resetting it to `none`?

<!-- comment id=1332154503 author=Loirooriol created=2022-11-30T13:28:56Z url=https://github.com/w3c/csswg-drafts/issues/8150#issuecomment-1332154503 -->
## @Loirooriol — 2022-11-30

That's the case in Firefox:

```js
var {style} = document.createElement("div");
style.listStyle = "url()";
style.listStyleType; // Firefox: "disc". Blink/WebKit: "initial"
```

If the image is valid it doesn't matter since `list-style-type` will be ignored. If the image is invalid, falling back to `disc` doesn't sound bad. But only Blink seems to fall back to `list-style-type` for invalid images.

<!-- comment id=1332575216 author=darinadler created=2022-11-30T18:33:06Z url=https://github.com/w3c/csswg-drafts/issues/8150#issuecomment-1332575216 -->
## @darinadler — 2022-11-30

Sure, I am not talking about practical considerations as much as I am trying to make sure there are no unnecessary differences between browsers for people to trip up on. For example:
```
var {style} = document.createElement("div");
style.listStyle = "url()";
style.listStyleType = "disc";
style.listStyle; // Should be "url()"?
style.listStyleType = "none";
style.listStyle; // Should be ""?
```

<!-- comment id=1332586087 author=Loirooriol created=2022-11-30T18:43:56Z url=https://github.com/w3c/csswg-drafts/issues/8150#issuecomment-1332586087 -->
## @Loirooriol — 2022-11-30

Assuming omitted longhands are reset to their initial values as usual,

```js
var {style} = document.createElement("div");
style.listStyle = "url()";
style.listStyleType = "disc";
style.listStyle; // 'url("")'
style.listStyleType = "none";
style.listStyle; // 'url("") none'
```
