I describe  N'Ko counter styles at https://r12a.github.io/scripts/nkoo/nqo.html#lists and show some examples.

The cardinal style is straightforward, but I'm not clear how to write a pattern for the ordinal style, and I wonder whether someone can help (@tabatkins), or whether it needs to be described in the spec, like Ethiopic, etc.

The issue has to do with combining marks that are attached only to the last digit (N'Ko digits run RTL, unlike Arabic). Different combining marks, in different locations relative to the base, are used if that digit is 1 vs anything else.

## @tabatkins — 2026-10-26

The "cardinal" numeric style is indeed trivial; just a numeric counter-style:

```css
@counter-style nko-cardinal {
	system: numeric;
	symbols: "\7c0" "\7c1" "\7c2" "\7c3" "\7c4" "\7c5" "\7c6" "\7c7" "\7c8" "\7c9";
	         /* "߀" "߁" "߂" "߃" "߄" "߅" "߆" "߇" "߈" "߉" */
}
```

(Using the existing definition style from the spec of using escapes to define rtl styles to avoid ordering confusion.)

Edit: Ignore the below, I was misreading the numbers. Since the upper/lower dot is based on if the *final* digit is a 1, it's not realistically possible to use ranges for that. It'll have to be a "Predefined Complex Style".

-----------------

The ordinal style *is* technically possible, at least to a specified range. It would be easy if the dot was on the same side all the time; we'd just use a `suffix` descriptor on the cardinal style. But since we need to switch it up, we have to combine two, with ranges defined by hand:

```css
@counter-style nko-ordinal {
	system: numeric;
	symbols: "\7c0" "\7c1" "\7c2" "\7c3" "\7c4" "\7c5" "\7c6" "\7c7" "\7c8" "\7c9";
	suffix: "\307"; /* combining dot above */
	range: 1-1, 10-19, 100-199, 1000-1999, 10000-19999 /* as far as we want to define */;
	fallback: nko-ordinal-rest;
}
@counter-style nko-ordinal-rest {
	system: numeric;
	symbols: "\7c0" "\7c1" "\7c2" "\7c3" "\7c4" "\7c5" "\7c6" "\7c7" "\7c8" "\7c9";
	suffix: "\323"; /* combining dot below */
}
```

Do the ordinal styles allow for negatives?

But if we do want ordinary to support arbitrarily high values, it needs to be custom-defined (but at least is trivial to do so).
