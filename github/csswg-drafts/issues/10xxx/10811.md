https://drafts.csswg.org/css-color-6/#colorcontrast

```
<contrast-color()> = contrast-color(
  [ [ <color> && [ tbd-fg | tbd-bg ] && <target-contrast>? ] |
    [ <color> && [ tbd-fg | tbd-bg ] && <target-contrast>, <color># ] ] )
<target-contrast> = <wcag2>
```

https://drafts.csswg.org/css-color-5/#funcdef-contrast-color

```
contrast-color() = contrast-color( <color> )
```

------

In `css-color-5` there is already a minimal version of this function.
The definition in `css-color-6` should allow passing only a single color argument.

## @svgeesus — 2026-07-18

From [Computing a Contrasting Color: the `contrast-color()` function](https://drafts.csswg.org/css-color-6/#colorcontrast):

> The only mandatory argument is the base color against which the contrast is computed. This is typically (but not necessarily) a background color.

and

> The `<target-contrast.` argument specifies the contrast algorithm(s) to use. If no color candidates have been provided, `<target-contrast.` may be omitted, in which case a UA-chosen algorithm is used.

That seems to be exactly the syntax in Color 5: one color, no candidates, no target contrast.

## @romainmenke — 2026-07-18

https://drafts.csswg.org/css-values-4/#comb-all

> A double ampersand (&&) separates two or more components, all of which must occur, in any order.

The issue is `&& [ tbd-fg | tbd-bg ]` which is mandatory in the syntax definition.

So `contrast-color(red tbd-fg)` is considered valid, while `contrast-color(red)` isn't.
