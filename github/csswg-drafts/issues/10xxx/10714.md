Writing Modes currently says that if a block has a different `writing-mode` value than its parent, then it forms a new block formatting context.

This was quite appropriate for Writing Modes L3, but in L4 we introduced the `sideways-*` variants that are just like their `vertical-*` variants except the line orientation is different. This probably doesn't need a new block formatting context.

Should we loosen this restriction so that `sideways-*` and `vertical-*` blocks can share a block formatting context?

## @dbaron — 2024-11-07

Not necessarily a blocking issue, but it's worth noting that according to [the mappings](https://drafts.csswg.org/css-writing-modes-4/#logical-to-physical), the `inline-start` and `inline-end` mappings swap between `vertical-lr` and `sideways-lr`.  This seems like it might be at least a little awkward for the [logical values of `float` and `clear`](https://drafts.csswg.org/css-logical-1/#float-clear) and would at least require that the definitions be carefully written to handle the case that those mappings can change within a single BFC.

## @dbaron — 2025-10-07

FYI, my thought that this would be simple to do in Chromium turned out to be wrong.  The underlying problem is that coordinates of floats during layout are stored in logical coordinates, which [differ](https://www.w3.org/TR/css-writing-modes-4/#logical-to-physical) between `vertical-lr` and `sideways-lr`, which causes floats in a BFC that mixes those two writing modes to get swapped top/bottom.
