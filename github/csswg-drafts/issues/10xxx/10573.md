In CSS Values 5 I was [astonished to read 5.3. Interpolated Color Values: the `color-mix()` notation](https://drafts.csswg.org/css-values-5/#color-mix)

<blockquote>

This specification extends the color-mix() functional notation as a mix notation accepting the following syntaxes:

```
<color-mix()> =
  color-mix( <progress> && <color-interpolation-method>?, <color>, <color> ) |
  color-mix( <color-interpolation-method>, [<color> && <percentage [0,100]>?]#{2} )
```
 
The used value of the first mix notation variant is equivalent to assigning the &lt;progress> value, as a &lt;percentage>, to the of the second &lt;color> argument in the second variant. That is, color-mix(progress, color1, color2) is equivalent to color-mix(color1, color2 progress). See CSS Color 5 § 3 Mixing Colors: the color-mix() Function for the normative definition of the second variant.
</blockquote>

Why is there a second "variant" of `color-mix()` defined, with **zero discussion** that I can recall, which is merely a permutation of the parameter order, and  has [**zero** tests in WPT](https://wpt.fyi/results/css/css-values?label=master&label=experimental&aligned&q=color-mix), unlike the other "variant" which is **widely** implemented, with [1510 tests in WPT](https://wpt.fyi/results/css/css-color?label=master&label=experimental&aligned&q=color-mix) and part of Interop 2023?
