In https://github.com/w3c/csswg-drafts/issues/9972 we resolved to rename `active-view-transition(params)` to `active-view-transition-type(params)` and add a no-params `active-view-transition`. 

Previously the specificity of `active-view-transition(params)` was 1 class-like if params was `*` and 2 class-like otherwise. For `active-view-transition-type(params)` params can't be `*`. So should it be 2 class-like specificity always? Or should it be 1 class-like?

## @noamr — 2024-03-13

> I'm tempted to follow `:has()` or `:is()` here. So I guess it would equal a type selector.

I'd say that if you have an active view transition it's more equivalent to a `:hover`, which gets 1-class specificity, it says something about the current state of the element, while `:has` and `:is` are only about the DOM structure.

<!-- comment id=1995773795 author=noamr created=2024-03-13T20:52:59Z url=https://github.com/w3c/csswg-drafts/issues/10071#issuecomment-1995773795 -->
## @noamr — 2024-03-13

Another way to look at this is that:
```css
html:active-view-transition {}
/* is equivalent to */
html.active-view-transition {}

/* and */
html:active-view-transition-type(slide) {}
/* is equivalent to */
html[active-view-transition-type="slide"] {}
```

So if we agree with this analogy, both pseudo-class should have a 1-class specificity.
