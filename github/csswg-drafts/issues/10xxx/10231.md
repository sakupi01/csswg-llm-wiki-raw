The `masonry-auto-flow` property does something similar to `grid-auto-flow`; should we merge these two properties?

- https://drafts.csswg.org/css-grid-3/#masonry-auto-flow
- https://www.w3.org/TR/css-grid-2/#grid-auto-flow-property

<!-- comment id=2070918251 author=SelenIT created=2024-04-22T20:42:33Z url=https://github.com/w3c/csswg-drafts/issues/10231#issuecomment-2070918251 -->
## @SelenIT — 2024-04-22

There was once an idea to use the special `grid-auto-flow` value [as the only masonry switch](https://github.com/w3c/csswg-drafts/issues/4650#issuecomment-713221727), with no extra values to `grid-*-template` and no extra properties at all. Maybe it could be worth reconsidering?

<!-- comment id=2099022608 author=fantasai created=2024-05-07T18:09:58Z url=https://github.com/w3c/csswg-drafts/issues/10231#issuecomment-2099022608 -->
## @fantasai — 2024-05-07

If we drop `definite-first` (https://github.com/w3c/csswg-drafts/issues/10260) and we drop `next` (https://github.com/w3c/csswg-drafts/issues/10232) then we can just drop the property entirely.

<!-- comment id=2189979119 author=tabatkins created=2024-06-25T21:12:36Z url=https://github.com/w3c/csswg-drafts/issues/10231#issuecomment-2189979119 -->
## @tabatkins — 2024-06-25

These shouldn't be merged, imo. They're doing the same things, conceptually, but have a totally different set of controls for those things. We'd just have two divergent syntax branches, with one useful only for Grid and the other useful only for Masonry; we'd have to define default behavior for if you used the wrong set of keywords. That doesn't suggest they're actually useful to be in the same property.

(This is ignoring the larger issue about Masonry being a different display type in the first place; regardless of that, I think they're still best as separate properties. But if it is a separate display type, they're clearly best as separate properties imo.)

(But also, as you say, we can just drop the property entirely if we switch over to `masonry-threshold`, since we *have* already dropped the `definite-first` switch.)
