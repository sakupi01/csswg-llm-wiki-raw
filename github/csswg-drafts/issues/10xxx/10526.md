When an `anchor-scope` is specified with a `<dashed-ident>`, it scopes the name to that subtree when the anchor name is ["matching"](https://drafts.csswg.org/css-anchor-position-1/#anchor-scope). The problem is that this matching can be interpreted in at least three ways:

(Assuming that `anchor-scope` is a [tree-scoped reference](https://drafts.csswg.org/css-scoping-1/#css-tree-scoped-reference), which is also not clear in the spec):

 1. It matches by the ident part of the name only, ignoring any tree-scope that would be associated with the name, or
 2. It matches by _exact match_ of the ident part _and_ the associated tree-scope, or
 3. It matches by some mechanism similar to dereferencing of tree-scoped references, where it's a match when the tree-scope of the anchor-scope-name is an inclusive ancestor of the tree-scope of the anchor query.

So we need to define exactly what "matching" means. For now I've implemented (2), but it's not obvious that gives the best behavior.

<!-- comment id=2322168730 author=tabatkins created=2024-08-30T19:01:37Z url=https://github.com/w3c/csswg-drafts/issues/10526#issuecomment-2322168730 -->
## @tabatkins — 2024-08-30

I think (2) is correct? We already have the requirement (per ["target anchor element"](https://drafts.csswg.org/css-anchor-position/#target-anchor-element)) that the anchor name and the anchor reference have to have matching tree scopes.

I think the only effect of doing (1) would be that a positioned element slotted into a shadow could get scoped by an 'anchor-scope' inside the shadow, preventing it from seeing the anchor that's in the light tree elsewhere on the page. Right? That seems pretty unexpected.

## @andruud — 2024-08-30

Agenda+ to clarify that "anchor-scope matching a name" means an exact match of both the name part and the tree-scope part. (Aligned with [target anchor element, step 3](https://drafts.csswg.org/css-anchor-position/#target-anchor-element).)

The CSS Working Group just discussed `[css-anchor-position] When does anchor-scope "match" a name?`, and agreed to the following:

* `RESOLVED: whenever you are comparing names, and at least one is tree scoped, then both are tree scoped, and the scoping has to be exact (not subtree)`
