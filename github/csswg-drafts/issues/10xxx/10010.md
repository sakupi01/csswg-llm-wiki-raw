## @svgeesus — 2024-02-28

The [implementation report](https://test.csswg.org/harness/results/css-backgrounds-3_dev/grouped/) linked from the current spec points to the old, unmaintained, manually-run Shepherd testsuite, not to WPT. **128** tests are listed.

There are no WPT annotations. There are **763** tests (**5556** subtests) in WPT, although these cover all levels.

I feel that the modern, maintained, automatically-run WPT tests are better in general to determine whether to advance to Proposed Rec. I understand that adding WPT annotations to a Bikeshed spec is a bunch of work, but it would be an improvement.

## @AtkinsSJ — 2025-11-06

> FWIW, [wpt.fyi/results/css/css-backgrounds?label=master&label=experimental&aligned&q=border-image](https://wpt.fyi/results/css/css-backgrounds?label=master&label=experimental&aligned&q=border-image) shows the full test coverage for `border-image-*`. If there are tests missing, they should be added.

The issue isn't missing tests, it's that the serialization tests allow several options for the output. That means different browsers can have different serializations and still all pass the tests, even though they don't do the same thing. For authors to be able to use that output, it needs to be consistent. (Also for my own selfish reasons, I'd like to know which one we should be doing in Ladybird. 😅 )
