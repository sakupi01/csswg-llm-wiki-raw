https://crbug.com/40287940 tracks this missing constructor in Chromium. However, it's not clear what a developer could do with a constructed `FontFaceSet`.

According to MDN only Safari has the constructor:
https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet#browser_compatibility

The only tests for `new FontFaceSet` in WPT only checks that a `FontFace` object can be added, but nothing else:

https://github.com/web-platform-tests/wpt/blob/master/css/css-font-loading/fontfaceset-add-css-connected.html

Removing it would be a matter of removing this line and anything connected to it:

https://github.com/w3c/csswg-drafts/blob/3a7db3e637ee1c2ddeb91134872ea9872ec46cce/css-font-loading-3/Overview.bs#L510

## @tabatkins — 2024-07-10

I'm fine with removing it. At the time I wrote this, I was pretty strong on the "we shouldn't have magic objects that can't be constructed" train, and I assume I expected there might be a use for it. But hey, it's years later and no such use materialized, and only one browser even implemented it, so yeah, let's just kill it.

(Like, in theory you could load up a FontFaceSet and call .check() on it, so there's not *zero* utility in theory, but I don't see any particularly good reason to do that rather than just calling .check() on the document's set.)

## @smfr — 2025-12-19

Closed issue I know, but how do you use FontFace in a worker without the constructor? [The spec](https://drafts.csswg.org/css-font-loading/#fontfacesource-workers) says, in a note:

> [FontFace](https://drafts.csswg.org/css-font-loading/#fontface) objects can be constructed and added to it as normal, which affects CSS font-matching within the worker (such as, for example, drawing text into a [OffscreenCanvas](https://html.spec.whatwg.org/multipage/canvas.html#offscreencanvas)).

Lots of offscreen canvas tests (e.g. http://wpt.live/html/canvas/offscreen/text/2d.text.draw.align.center.html) use this, but oddly don't fail in Chrome/Firefox.
