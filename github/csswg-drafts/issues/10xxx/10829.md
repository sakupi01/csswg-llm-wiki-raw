Given that the Working Group resolved on adding a `named-feature()` function that can be used inside `@supports` in https://github.com/w3c/csswg-drafts/issues/3559#issuecomment-1885332213 and https://github.com/w3c/csswg-drafts/issues/9875#issuecomment-2233725405, I would propose adding a `style-queries` named feature. Style queries are currently only supported in Chromium browsers and Safari TP.

## @bramus — 2026-08-24

I marked #13975 as a duplicate. It has some good chatter about this.

One could use a custom supports condition for this, as suggested by @kbabbitt:

```css
@supports-condition --style-query {
  @container style(--theme-color: blue) {}
}
```

But to me that seems like authors would need to drag this from stylesheet to stylesheet, whereas a named-feature would be built-in.

But also OTOH: `named-feature()` is reserved for detecting those things that you can’t detect by just parsing code, so adding `style-queries` would go against that.

And also: A lot of time has passed since Chrome first shipped it in March 2023 and Safari in Sept 2024, so any check would yield a lot of false negatives.
