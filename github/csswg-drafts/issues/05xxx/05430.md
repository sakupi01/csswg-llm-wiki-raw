The title is self-explanatory. Consider adding SVG [stroke-linejoin](url=https://developer.mozilla.org/en-US/docs/Web/SVG/Attribute/stroke-linejoin) options (arcs | bevel |miter | miter-clip | round) to render borders in-text. This thing would be nice to lighten up kanji fonts, especially handwritten ones.

## @fantasai — 2020-08-19

@ninep9up I'm a little confused as to what exactly you're referring to. Glyph outlines are controlled by the font, CSS has no say over how those curves are defined or interpreted. If the font designer wanted different joins, they would have to encode that into the font data.

If you're referring to the `stroke` property as applied to glyph outlines, there already exists a `stroke-linejoin` property that (in theory) could control this.

<!-- comment id=676752137 author=jfkthame created=2020-08-19T22:10:26Z url=https://github.com/w3c/csswg-drafts/issues/5430#issuecomment-676752137 -->
## @jfkthame — 2020-08-19

As I understand it, this is about what happens when a glyph outline (with sharp corners) is stroked rather than filled: in that case, there are different options regarding how the corners are treated, and OpenType fonts don't provide any control over this; it'd be up to whatever graphics system is stroking the path, just like an SVG path (and in principle similar controls could be applied).

<!-- comment id=681857147 author=svgeesus created=2020-08-27T10:12:09Z url=https://github.com/w3c/csswg-drafts/issues/5430#issuecomment-681857147 -->
## @svgeesus — 2020-08-27

Using outlines to bolden or lighten a font is something of a hack (and in the absence of set-geometric operations like the ill-fated [vector effects](https://www.w3.org/TR/2004/WD-SVG12-20041027/vectoreffects.html) which would actually subtract the stroke geometry from the fill geometry, relies on the fill color and the background color being solid colors, to hide the deception.

Now that we have variable fonts with a `wght` axis, "lightening" a glyph is more easily accomplished, produced the result expected by the font designer (which is less obvious with the unmodulated stroke of the fonts used to illustrate this, but is very visible on glyphs with a higher contrast between thick and thin portions) and also, propagates correctly to any children (of a different weight, or a different size).

Having said which, stroking fonts to produce a *visible* outline is totally a thing, and the `stroke-linejoin` is a useful way to control that effect.
