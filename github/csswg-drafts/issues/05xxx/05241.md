https://drafts.csswg.org/css-sizing-4/#intrinsic-size-override

If this property is specified on a replaced element, should that change the aspect-ratio of that element? E.g. should `img { contain: size; contain-intrinsic-size: 100px 200px; }` imply `aspect-ratio: 100/200;`?

(And if yes, should that only for replaced elements that have an intrinsic aspect-ratio or also for others, e.g. iframe?)

ref https://crbug.com/1091331

## @cbiesinger — 2020-07-09

In thinking about it as I wrote an email, I realized that whether the image is loaded can not affect the behavior, since contain:size is defined to be unaffected by the contents. Even today, I think (but didn't verify) we don't use the aspect ratio for an img with contain:size (the only time where contain-intrinsic-size is used).

This does leave the question of whether `<img src=foo style="contain: size; contain-intrinsic-size: 100px 100px; width: 50px;">` should use the ratio from c-i-s.

<!-- comment id=661449597 author=fantasai created=2020-07-20T23:43:36Z url=https://github.com/w3c/csswg-drafts/issues/5241#issuecomment-661449597 -->
## @fantasai — 2020-07-20

We wouldn't derive an aspect-ratio from c-i-s on an IFRAME, so I don't think we should be doing so for IMG either. Also consider OBJECT, which is more ambiguous about whether it should typically have an intrinsic aspect ratio.

Bitmap images intrinsically have an aspect ratio. The IMG element doesn't.

And c-i-s shouldn't introduce an aspect-ratio or not depending magically on what HTML element it's specified on.

<!-- comment id=661464364 author=tabatkins created=2020-07-21T00:01:40Z url=https://github.com/w3c/csswg-drafts/issues/5241#issuecomment-661464364 -->
## @tabatkins — 2020-07-21

Hm, I *feel* like we should differentiate between "having two intrinsic dimensions implies the third" elements like `img` and "each intrinsic dimension is independent and implies nothing about the others" elements like `iframe`; an `img` with c-i-s should implicitly override its intrinsic aspect ratio as well, I think?

<!-- comment id=662002817 author=cbiesinger created=2020-07-21T17:34:29Z url=https://github.com/w3c/csswg-drafts/issues/5241#issuecomment-662002817 -->
## @cbiesinger — 2020-07-21

So I basically want to withdraw my suggestion since with `contain: size`, everything should basically act as if there is no intrinsic aspect ratio. And since that's the only time when `contain-intrinsic-size` is used, it probably doesn't make sense for that to now add an aspect ratio.
