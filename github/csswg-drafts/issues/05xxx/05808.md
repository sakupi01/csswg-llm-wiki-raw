## @frivoal — 2020-12-20

* We cannot.  As [6.2.9](https://www.w3.org/2020/Process-20200915/#transition-pr) of the Process says:
  > A Proposed Recommendation may identify itself as intending to allow new features (class 4 changes) after its initial publication as a Recommendation, as described in § 6.2.11.4 Revising a Recommendation: New Features. Such an allowance cannot be added to a technical report previously published as a Recommendation that did not allow such changes.

   css-contain-1 has already been a REC before, and didn't carry this text, so it cannot be added now.

   (this is intentional: RECs that predate Process 2020 could not gain new features, and may be normatively referenced by things that count on this property to be maintained. So as not to change the existing meaning of REC, only things that declare the intention of gaining new features **prior to becoming a REC** can do so)

* We don't need to, since css-contain has a level 2, which deals with the new features.
