It seems like we should probably add `accent-color` to the list of properties that are [adjusted in Forced Colors Mode](https://drafts.csswg.org/css-color-adjust-1/#forced-colors-properties).

Forcing this to `auto` seems like the obvious choice, similar to `scrollbar-color`. However, what should happen if `forced-color-adjust` is set to `none` or `accent-color` is set to a system color? Should we ignore those and force `accent-color` to `auto` no matter what, or should we honor the adjust rules to allow author customization?

## @FremyCompany — 2021-02-28

If adjust is set to none, I don't think accent color should be reset.

But, more generally, it probably isn't necessary to do anything with this property btw because, in forced colors mode, browsers can just decide not to use the accent color in their firm control design, right ?

<!-- comment id=788247515 author=alisonmaher created=2021-03-01T20:24:54Z url=https://github.com/w3c/csswg-drafts/issues/5987#issuecomment-788247515 -->

@FremyCompany yeah, honoring `forced-color-adjust` and leaving it up to the UA in terms of how to handle `accent-color` in their form control design makes sense to me.
