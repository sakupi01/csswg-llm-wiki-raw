In <https://github.com/whatwg/html/pull/6032>, I'm fixing HTML to define that `<img width height>` constitutes an 'aspect-ratio' presentational hint (setting 'aspect-ratio' at the presentation-hint layer, lower specificity than any rule). (Previously, this was defined as width/height attributes actually giving the element an intrinsic aspect ratio.)

The text I'm replacing only defined this mapping for `img` elements, but it seems reasonable that this should apply to all element that currently process 'width' and 'height' attributes as presentational hints: `embed`, `iframe`, `img`, `object`, and `video`. Does this sound reasonable to other people?

<!-- comment id=707297046 author=fantasai created=2020-10-12T19:10:01Z url=https://github.com/w3c/csswg-drafts/issues/5608#issuecomment-707297046 -->
## @fantasai — 2020-10-12

No, it should apply to video, but embed/object/iframe often represent elements that have a width and a height but no aspect ratio. So it should not map to those.

I feel like there's existing discussion about this over in the WHATWG space...

<!-- comment id=707580923 author=zcorpan created=2020-10-13T08:27:21Z url=https://github.com/w3c/csswg-drafts/issues/5608#issuecomment-707580923 -->
## @zcorpan — 2020-10-13

What @fantasai said.

Although `embed` and `object` *can* be an image (and so have an intrinsic aspect ratio), they can also be a nested browsing context (no intrinsic aspect ratio).

There is however `input type=image` which could map width/height to 'aspect-ratio'.

For `canvas`, the spec currently says 

> The intrinsic dimensions of the canvas element when it represents embedded content are equal to the dimensions of the element's bitmap.

https://html.spec.whatwg.org/multipage/canvas.html#the-canvas-element:intrinsic-dimensions

<!-- comment id=707879128 author=fantasai created=2020-10-13T16:58:31Z url=https://github.com/w3c/csswg-drafts/issues/5608#issuecomment-707879128 -->
## @fantasai — 2020-10-13

So basically `img`, `input type=image`, `video`, and `canvas` should have an aspect-ratio mapping, but none of the others should.
