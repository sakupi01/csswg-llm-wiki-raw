8.1. Hyphens: the hyphenate-character property
https://drafts.csswg.org/css-text-4/#hyphenate-character

`hyphenate-character` has two values: `auto` and string.

it will be great to have this property. But, in cases where hyphenation occurs with no visual mark should content authors supply an empty string or should we have a `none` value?

This is the case for Tamil and Malayalam, eg. 

![hyphenation_ml](https://user-images.githubusercontent.com/4839211/107147576-b88fef80-6946-11eb-9518-741a2f027f71.png)

If there's nothing special about the *mechanics* of it, it just happens with no indicating mark, I'd assume `hyphenate-character: "";` is indeed the right way to go about it.

## @frivoal — 2022-12-28

@r12a 
If you need to hyphenate with no delineating character, empty string is indeed the way to go, and we can call this out in the spec. Just before we do though, I'd like to ask a clarifying question: in what sense is this hyphenation?
* Does this respect morpheme boundaries (therefore making it different from simply `word-break: break-all`)?
* Are such breaks de-prioritized compared to spaces (as hyphenation usually is), or are they usually handled at the same priority (similar to line-breaking in Thai, which also uses a dictionary)?
* Is this something that gets turned on or off depending on context?

I'm trying to understand how this is different from e.g. Thai line breaking or Japanese line-breaking, neither of which are considered hyphenation.
