## @Loirooriol — 2020-07-31

Too many sites rely on `nowrap`, it can't be changed. Adding `no-wrap` as an alias would be possible, but was already rejected in #1537. Do you have new arguments to reconsider that resolution?

<!-- comment id=667411564 author=ExE-Boss created=2020-07-31T22:25:27Z url=https://github.com/w3c/csswg-drafts/issues/5376#issuecomment-667411564 -->
## @ExE-Boss — 2020-07-31

This isn’t about `white‑space`, this is about the new **CSS Text 4** [`text‑wrap`][text-wrap] property, which no engines are shipping yet.

[text-wrap]: https://drafts.csswg.org/css-text-4/#text-wrap

<!-- comment id=667487831 author=frivoal created=2020-08-01T07:24:21Z url=https://github.com/w3c/csswg-drafts/issues/5376#issuecomment-667487831 -->
## @frivoal — 2020-08-01

`text-wrap` is a longhand of `white-space` though, so `nowrap` is the same keyword with the same meaning. Shorthand/longhand relationships are flexible enough that we could map `nowrap` in one to `no-wrap` in the other, but that seems very confusing to me.

<!-- comment id=667536761 author=ExE-Boss created=2020-08-01T14:01:41Z url=https://github.com/w3c/csswg-drafts/issues/5376#issuecomment-667536761 -->
## @ExE-Boss — 2020-08-01

@frivoal Well, if <https://github.com/w3c/csswg-drafts/issues/5382> is accepted, then it will make distinguishing the <code>[&lt;white‑space‑legacy&gt;]</code> `nowrap` value from the <code>[&lt;'text‑wrap'&gt;]</code> `no‑wrap` value much easier.

<!-- comment id=1477344280 author=fantasai created=2023-03-21T06:33:43Z url=https://github.com/w3c/csswg-drafts/issues/5376#issuecomment-1477344280 -->
## @fantasai — 2023-03-21

I'm very certain that we are not going to rename `nowrap` to `no-wrap`, simply for consistency with `white-space` and `flex-wrap`. At most we would add an alias--for all instances of `nowrap`.

<!-- comment id=1483325269 author=tabatkins created=2023-03-24T19:44:09Z url=https://github.com/w3c/csswg-drafts/issues/5376#issuecomment-1483325269 -->
## @tabatkins — 2023-03-24

Yes, we're currently consistently bad with `nowrap`, which sucks, but it's better than some properties having `nowrap` and others having `no-wrap`. Accepting both would be ideal.

<!-- comment id=3897465891 author=Crissov created=2026-02-13T14:16:18Z url=https://github.com/w3c/csswg-drafts/issues/5376#issuecomment-3897465891 -->
## @Crissov — 2026-02-13

For a property called `text-wrap`, the frequently used keyword `none` would have felt more systematic to go with `wrap`, which could have been `auto` just as well. It only makes sense when considering the history and other properties.
