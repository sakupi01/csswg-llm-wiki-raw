As discussed in https://github.com/w3c/csswg-drafts/issues/5697#issuecomment-736914928, "`@import` rules must precede all other valid at-rules and style rules in a ***style sheet***" ([[css-cascade]](https://drafts.csswg.org/css-cascade-5/#at-import)), but that's not the same "style sheet" as is spelled "`<stylesheet>`" and appears inside things like the [conditional at-rules](https://drafts.csswg.org/css-conditional-3/#at-supports). This isn't a terrible problem, but it's also a bit confusing.

@fantasai [suggested](https://github.com/w3c/csswg-drafts/issues/5697#issuecomment-741884022) the right fix is to rename [`<stylesheet>`](https://drafts.csswg.org/css-syntax-3/#typedef-stylesheet). The telecon discussion suggested to explicitly ask @tabatkins if they object.

<!-- comment id=741946180 author=tabatkins created=2020-12-09T17:56:45Z url=https://github.com/w3c/csswg-drafts/issues/5774#issuecomment-741946180 -->
## @tabatkins — 2020-12-09

I don't object, just not sure what new name to use, since `<stylesheet>` means "anything allowed in a stylesheet (except those are only allowed in a top-level context, like `@import`)".

<!-- comment id=741948535 author=svgeesus created=2020-12-09T18:01:00Z url=https://github.com/w3c/csswg-drafts/issues/5774#issuecomment-741948535 -->
## @svgeesus — 2020-12-09

`<stylesheet-body>` perhaps, and the part where `@import` etc live could be `<stylesheet-head>` and thus, a stylesheet is  `<stylesheet-head>` `<stylesheet-body>` 

<!-- comment id=742043009 author=fantasai created=2020-12-09T20:54:02Z url=https://github.com/w3c/csswg-drafts/issues/5774#issuecomment-742043009 -->
## @fantasai — 2020-12-09

I was going to suggest `<styleset>` but @svgeesus’s suggestion is a nice idea. Do we allow @font-face and @keyframes inside conditional rules yet, though? Because if not then there's a top-level vs. encased distinction rather than a header vs. body distinction.

<!-- comment id=996279160 author=tabatkins created=2021-12-16T23:42:41Z url=https://github.com/w3c/csswg-drafts/issues/5774#issuecomment-996279160 -->
## @tabatkins — 2021-12-16

After discussing with @fantasai we decided that `<stylesheet-body>` makes the most sense, even if we don't use any sort of *-head production. (I'm just personally not a fan of "styleset".)

We'll defer actually making the change until January, since virtually all of the specs currently using it are pending publication currently, and will go up before a new Syntax /TR will. We'll just do some editorial repubs for all of them later once Syntax gets republished.

<!-- comment id=1546326060 author=tabatkins created=2023-05-12T21:32:49Z url=https://github.com/w3c/csswg-drafts/issues/5774#issuecomment-1546326060 -->
## @tabatkins — 2023-05-12

I ended up making this moot with the new Syntax text, since I changed all the productions anyway. Nothing is named `<stylesheet>` anymore. (Things that previously used it now just use `<rule-list>`.)
