I just wanted to check if we still want to keep `style()` at its current level in the grammar now that `size()` is removed. It is not consistent with previous choices (`@supports / selector()`), which places the function at or near the "leaf nodes". We should probably do the same for this case, i.e. `style( <style-feature> )`.

## @mirisuzanne — 2022-02-28

To clarify the difference here, the two options look like…

A **feature-level** syntax might be a bit simpler from the spec/implementation side:

```css
@container card-component (style(--card: feature) and style(--mode: dark)) or style(background: maroon) { … }
```

But the current **higher-level** syntax provides a bit more sugar for authors, since the function is only required once, and can contain multiple `style()` conditions:

```css
@container card-component style(((--card: feature) and (--mode: dark)) or (background: maroon)) { … }
```

My thoughts:

- My preference is for the higher-level syntax sugar, but it's not a big difference, and there's no functionality at stake
- This decision would likely apply to any new non-size features added in the future (eg 'state queries')
