What happens to video elements during the locked phase of the transition? (when rendering is prevented by the `prepare` promise)

If a screenshot is made and it takes a couple of frames before the transition starts, this could result in issues. But I can imagine that if the video is a livestream, stopping the video is not great either. This could potentially be left to the authors to solve, but I was wondering if there is some reasonable default here.

Some videos are also rendered fully on the compositor thread, is this an issue?

<!-- comment id=1295369209 author=khushalsagar created=2022-10-28T19:22:35Z url=https://github.com/w3c/csswg-drafts/issues/7555#issuecomment-1295369209 -->
## @khushalsagar — 2022-10-28

@FremyCompany this was discussed as a part of #7784. The video element in particular came up during the discussion (captured in the meeting notes). The conclusion was to pause the video, just like other animations on the page. Otherwise there is an odd jump from the last rendered video frame to the last snapshotted frame when the transition starts.

Can we close this issue given the resolution on #7784?
