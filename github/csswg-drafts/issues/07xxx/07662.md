https://drafts.csswg.org/css-images-4/#image-set-notation

```
image-set() = image-set( <image-set-option># )
<image-set-option> = [ <image> | <string> ]
                     [ <resolution> || type(<string>) ]

<image> = <url> | <image()> | <image-set()> | <cross-fade()> | <element()> | <gradient>
```

Here it is allowed to nest image-set() within image-set(), I don't know what the actual scenario of this is, do we need such a complex image adaptation?

This behavior is currently implemented in [Firefox 88](https://bugzilla.mozilla.org/show_bug.cgi?id=1698133):

cc @emilio 

```css
body {
  background-image: image-set(
    image-set(
      image-set(
        image-set(
          linear-gradient(green, green) 1x
        )
      )
    )

    , linear-gradient(red, red) 1x
  );
}
```

## @Loirooriol — 2022-08-30

https://drafts.csswg.org/css-images-4/#image-set-notation says

> The [`image-set()`](https://drafts.csswg.org/css-images-4/#funcdef-image-set) function can not be nested inside of itself, either directly or indirectly (as an argument to another [`<image>`](https://drafts.csswg.org/css-images-4/#typedef-image) type).

<!-- comment id=1231619086 author=yisibl created=2022-08-30T12:46:56Z url=https://github.com/w3c/csswg-drafts/issues/7662#issuecomment-1231619086 -->
## @yisibl — 2022-08-30

@Loirooriol Yes, I think the grammar would be better changed to this:

```
<image-set-option> = [ <url> | <image()> | <cross-fade()> | <element()> | <gradient> | <string> ]
                     [ <resolution> || type(<string>) ]
```

Or define a new `<image-set-image> = [<url> | <image()> | <cross-fade()> | <element()> | <gradient>]` 

<!-- comment id=1239951455 author=tabatkins created=2022-09-07T22:03:23Z url=https://github.com/w3c/csswg-drafts/issues/7662#issuecomment-1239951455 -->
## @tabatkins — 2022-09-07

I think it would be strictly worse to manually list all the `<image>` variants excluding `<image-set()>` specifically; we'd have to keep that list up to date over time. Such a grammar wouldn't actually reproduce the behavior currently stated in the spec prose, anyway - I'd have to define variants of some of the other functions, like `<image-set-cross-fade>`, that had a similar explicit list. All in all it would be a horrendous mess.

Do you have a specific reason to want this restriction expressed in the grammar rather than in prose?

## @SebastianZ — 2022-09-08

For what it's worth, I've [created a bug report](https://bugzilla.mozilla.org/show_bug.cgi?id=1789918) to fix that in Gecko.

> I think it would be strictly worse to manually list all the `<image>` variants excluding `<image-set()>` specifically;

I agree with Tab that manually keeping the syntaxes in sync would cause headaches. Though reading that, I immediately thought that "<image> except <image-set()>" _could_ be expressed in grammar. So this would avoid having to maintain them manually.

Use cases for being able to express this in grammar are authoring tools, syntax information on MDN and similar outputs and also custom property syntax definitions.

Contrived but valid example for a custom property: Imagine you have a custom property that takes an `<image>` value but you explicitly want to exclude `<url>`. At the moment, this wouldn't be possible.

Sebastian
