Please correct me if I'm wrong, but a CSS descriptor should only occur within the body of a CSS at-rule and exist in the format of `name: value`.  In the CSS Contain specification (and Media Queries), the `<size-feature>` CSS type is described using the `descdef` class which should be reserved for descriptors.  This breaks machine reading of the spec (i.e. [webref](https://github.com/w3c/webref/blob/main/ed/css/css-contain-3.json#L59).  I'd recommend that the `size-feature` definitions are formatted similar to any other CSS type syntax.

## @dbaron — 2022-07-18

I think the formatting of  [mediaqueries-4's `width`](https://drafts.csswg.org/mediaqueries-4/#width) and of  [css-contain-3's `width`](https://drafts.csswg.org/css-contain-3/#width) is useful.  It's not clear to me that we need a class separate from `descdef` for this, but if we do, it seems useful to retain the current formatting.

Being a descriptor definition, on its own, isn't that useful, because you need to know what that descriptor is for.  We probably ought to mark that up.  And if we're doing that, it seems like that markup could express whether it's for the body of an @-rule or for the prelude of a grouping @-rule.

## @pyoor — 2022-07-18

My only argument for a new format, or to modify the existing format, would be to match that of other specifications.  For instance, the [@page](https://www.w3.org/TR/css-page-3/#syntax-page-selector) and [@import](https://drafts.csswg.org/css-cascade-5/#at-ruledef-import) rules both include the prelude in the same manner that general CSS syntax is defined with additional information defined in the prose.
