Originally [raised by @jfkthame ](https://github.com/w3c/csswg-drafts/issues/7633#issue-1346860734):

> (3) A really minor issue, but I have found myself repeatedly writing things like `@supports font-tech(features-opentype)`, and not getting the expected result because the correct keyword is `feature-opentype` (singular). To my mind, the `feature-*` keywords would read more naturally in the plural form (similarly to `font-tech(variations))`. Should we change them to plural, here and in CSS Fonts, before this is widely implemented and webcompat becomes a constraint?

Ok I am going to call this, because in [11.1. Font tech](https://drafts.csswg.org/css-fonts-4/#font-tech-definitions) it says _(note the plural)_

> The features-opentype, features-aat and features-graphite techs refer to support for font features, commonly implemented in [[OPENTYPE]](https://drafts.csswg.org/css-fonts-4/#biblio-opentype) with the [GSUB](https://docs.microsoft.com/en-us/typography/opentype/spec/gsub) and the [GPOS](https://docs.microsoft.com/en-us/typography/opentype/spec/gpos) tables, as well as in [[AAT-FEATURES]](https://drafts.csswg.org/css-fonts-4/#biblio-aat-features) using the [morx](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6morx.html) and [kerx](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM06/Chap6kerx.html) tables and [[GRAPHITE]](https://drafts.csswg.org/css-fonts-4/#biblio-graphite) with the Silf, Glat , Gloc , Feat and Sill tables as documented in the [Graphite Table Format](https://scripts.sil.org/cms/scripts/render_download.php?site_id=nrsi&format=file&media_id=GraphiteBinaryFormat_3_0&filename=GraphiteBinaryFormat_3_0.pdf).
