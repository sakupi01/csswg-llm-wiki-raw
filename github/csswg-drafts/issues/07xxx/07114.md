> Within a [relative color](https://drafts.csswg.org/css-color-5/#relative-color) syntax [oklch()](https://drafts.csswg.org/css-color-5/#funcdef-oklch) function, the allowed [channel keywords](https://drafts.csswg.org/css-color-5/#channel-keyword)[](https://drafts.csswg.org/css-color-5/#valdef-oklch-l) are:
> l is a [<percentage>](https://drafts.csswg.org/css-values-4/#percentage-value) that corresponds to the [origin color’s](https://drafts.csswg.org/css-color-5/#origin-color)[](https://drafts.csswg.org/css-color-5/#valdef-oklch-c) OKLab Lightness
> c is a [<number>](https://drafts.csswg.org/css-values-4/#number-value) that corresponds to the [origin color’s](https://drafts.csswg.org/css-color-5/#origin-color)[](https://drafts.csswg.org/css-color-5/#valdef-oklch-h) OKLCH chroma
> h is an [<angle>](https://drafts.csswg.org/css-values-4/#angle-value) that corresponds to the [origin color’s](https://drafts.csswg.org/css-color-5/#origin-color) OKLCH hue, normalized to a [0deg, 360deg) range.

Previous discussion for `css-color-5` allowing percentages in more color components : https://github.com/w3c/csswg-drafts/issues/7064

From that discussion : 

> lab.L: [0, 100]
lab.a: [-125, 125]
lab.b: [-125, 125] (a and b have the same range, for simplicity)
lch.c: [0, 150]
oklab.L: [0, 1.0]
oklab.a: [-0.4, 0.4]
oklab.b: [-0.4, 0.4] (see above re: a and b)
oklch.c: [0, 0.4]
xyz, xyz-d50, xyz-d65: [0, 1.0]
predefined RGB: [0, 1.0] (not a change, but a clarification)

--------

works today in Safari as `l` is a percentage :

```css
oklch(from var(--color) 50% c h)
```

doesn't work  as `c` is a number :

```css
oklch(from var(--color) l 50% h)
```

css-color-4 only very recently changed and I do not expect it in Safari already, but it isn't clear from the current css-color-5 specification if this should work.

It's tricky to know exactly when to use percentages or numbers. 
If it's a number you also need to lookup which value might work.

Allowing percentages could make this feature easier to use for stylesheet authors.

Overall, I don't really understand this comment.

Oops though, the grammar for RCS OKLCH was updated for #7064 but the channel keyword descriptions were not. All non-hue components now take either a `<number>` or a `<percent>`.

> c doesn't have a known maximum value in the specification, but maybe this can be known for a device?

C is unbounded.

There is a [percent reference range for OKLCH C](https://drafts.csswg.org/css-color-4/#specifying-oklab-oklch) but that isn't a limit, you can go beyond 100%.
