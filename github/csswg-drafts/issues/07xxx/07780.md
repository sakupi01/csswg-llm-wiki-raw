## @drott — 2022-09-23

@emilio Are you thinking about this case from an CSSOM perspective or so? (Is there a CSSOM representation of `@font-palette-values`? FWIW, the 0-indexed palette in a font is the default palette. To render COLRv0 or COLRv1 glyphs, you can't render without a palette, unless the glyphs only contain the color index `0xFFFF` which represents the foreground color. I haven't tested whether our font stack handles fonts without a CPAL table or without a default palette correctly - so in that sense, I am not sure it would be desirable to reset this state to: "Don't refer to any base palette.". What should be the behaviour if @font-palette-values then sparsely defines a new palette, but some indices are missing - should the corresponding parts of the glyphs be rendered with transparent color?
