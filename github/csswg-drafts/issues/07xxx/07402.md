Since we decided elements with `container-type: none` still have style containment, should we rename `none` to `normal`?

I want to point out again, though, that we still have the issue with the other keywords not reflecting that they do not overwrite style containment. But that's probably worth it's own issue.

## @lilles — 2022-06-28

If so, we also need to consider:

- Should 'none' still not be a valid container-name and reserved for later?
- Should 'none' be kept as a way to turn off all container-types including 'style'?
- Make 'normal' an invalid as a custom-ident

<!-- comment id=1168439882 author=anttijk created=2022-06-28T09:01:32Z url=https://github.com/w3c/csswg-drafts/issues/7402#issuecomment-1168439882 -->
## @anttijk — 2022-06-28

I'm opposed to this change. If every element is is a style container (not "have style containment" which would be a web breaking change) then the concept of "style container" has no meaning and value 'none' remains the correct one.
