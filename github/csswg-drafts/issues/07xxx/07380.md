Can you please tell me what are the module interactions between CSS Box Sizing and CSS Grid? Does [CSS Box Sizing](https://drafts.csswg.org/css-sizing-3/#valdef-width-fit-content-length-percentage) has authority over [CSS Grid](https://drafts.csswg.org/css-grid-2/#valdef-grid-template-columns-fit-content) for the definition of `<fit-content()>`?

If CSS Sizing has authority over CSS Grid and if the link to the definition of `<fit-content()>` in CSS Grid were pointing at the definition in CSS Sizing, this would prevent extracting duplicate definitions of `<fit-content()>` by `w3c/reffy`.

Note that the same problem exists for `<url>` in [CSS Values](https://drafts.csswg.org/css-values-4/#url-value), [CSS Filter Effects](https://drafts.fxtf.org/filter-effects-1/#typedef-filter-url), and [CSS Masking](https://drafts.fxtf.org/css-masking-1/#valdef-mask-image-url). See https://github.com/w3c/webref/issues/127#issuecomment-1157732048 for other workarounds that can fix this problem.

FYI, @tidoust.

<!-- comment id=1159125937 author=tabatkins created=2022-06-17T18:17:54Z url=https://github.com/w3c/csswg-drafts/issues/7380#issuecomment-1159125937 -->
## @tabatkins — 2022-06-17

They are completely separate and distinct functions, yes. This is indicated in the actual definition data - the Grid function has `data-dfn-for="grid-template-columns, grid-template-rows"` while Sizing has `data-dfn-for="width, min-width, max-width, height, min-height, max-height"`.

While our functions are *often* uniquely named, they should in fact be treated the same as keywords - potentially context-sensitive.
