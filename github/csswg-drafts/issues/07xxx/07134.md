An iframe can cause its parent window to scroll to another position, for example using `document.body.scrollIntoView();`

There seems to be no way to override (prohibit) this behaviour under the present w3c specification.  StackOverflow user Kaiido has [suggested](https://stackoverflow.com/a/71434176/3438001) a solution that exploits a [bug](https://bugs.chromium.org/p/chromium/issues/detail?id=1019427#c_ts1598605695) in Chrome, which raises the question as to whether a CSS solution to prevent cross-source scrolling would be possible.

Further details at the [StackOverflow answer](https://stackoverflow.com/a/71434176/3438001).

## @e-oz — 2024-12-07

Workaround for cases where you know when iframe will try to scroll parent:

1. Right before this event:
```ts
this.preScrollTop = window.scrollY;
const doc = window.document.documentElement;
this.prevPositionStyle = doc.style.position ?? undefined;
doc.style.position = 'fixed';
doc.style.top = (this.preScrollTop * -1) + 'px';
```

2. After the event:
```ts
window.document.body.style.position = this.prevPositionStyle ?? 'static';
window.scroll({ top: this.preScrollTop });
```
