Currently, [Element.checkVisibility](https://drafts.csswg.org/cssom-view/#dom-element-checkvisibility) (specifically in checkOpacity section) is not checking for `filter:opacity(0)`.

Is this a deliberate choice or could it be reconsidered?

## @vmpstr — 2022-10-03

Sounds reasonable to consider this. FWIW, the choice was not deliberate

<!-- comment id=1351865482 author=fantasai created=2022-12-14T17:59:16Z url=https://github.com/w3c/csswg-drafts/issues/7795#issuecomment-1351865482 -->
## @fantasai — 2022-12-14

Supposing at some point we had custom filters that were capable of making something transparent, having `opacity()` and its custom equivalent behave differently, even though they're both filters in the `filter` property, seems odd. So I think I'd lean towards not treating it specially.

<!-- comment id=1432646788 author=karip created=2023-02-16T07:36:00Z url=https://github.com/w3c/csswg-drafts/issues/7795#issuecomment-1432646788 -->
## @karip — 2023-02-16

It's possible to make an element visible even if it uses `filter: opacity(0)`, like this:

HTML:

    <svg>
      <filter id="flood">
        <feFlood flood-color="green" flood-opacity="0.5"/>
      </filter>
    </svg>
    <div>Hello</div>

CSS:

    div {
      filter: opacity(0) url(#flood);
    }

Here's [jsfiddle](https://jsfiddle.net/qwt2645k/). For these cases, browsers would have to investigate the resulting pixels, which can be expensive.
