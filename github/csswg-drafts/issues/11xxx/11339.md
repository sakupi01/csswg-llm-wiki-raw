Currently, [CSS Masking](https://drafts.fxtf.org/css-masking/#the-mask) says nothing about whether masks impact hit-testing (i.e. if clicks on the masked-out part of the content are treated as a click on the element).

Chrome and Firefox do consult the mask for hit-testing; WebKit does not. Test:
https://codepen.io/therealpaulplay/pen/wBwGdXX

This was [reported as a bug](https://bugs.webkit.org/show_bug.cgi?id=284227) in WebKit.

CSS has historically shied away from specifying hit-testing, but I think this one is important. Also of note is that the spec does talk about the [impact of clip-path on hit-testing](https://drafts.fxtf.org/css-masking/#clipping-paths).

## @schenney-chromium — 2024-12-10

There is this in the [rendering section](https://drafts.fxtf.org/css-masking/#the-mask-image-rendering-model):

* The [mask-image](https://drafts.fxtf.org/css-masking/#propdef-mask-image) property has no effect on the geometry or hit-testing of any element’s CSS boxes.

It seems that Chrome and Firefox are wrong, though as a user I would expect their behavior.
