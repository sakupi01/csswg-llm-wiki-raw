Moving this [from www-style](https://lists.w3.org/Archives/Public/www-style/2024Nov/0009.html) (didn’t look issue-worthy at first):

> [“CSS Cascading and Inheritance” levels 4–6](https://www.google.com/search?q=site%3Aw3.org+%22encapsulation+context%22) speak of an encapsulation context, alas the definition is vague.
>
> The example given, “such as nested tree contexts of shadow trees,” suggests there are other contexts that make for an encapsulation context, but it does not clarify what the determining factor is. In consequence, it seems open, too, whether a declaration would always be part of an encapsulation context, or if it would not.
> 
> (I understand an encapsulation context to be “implied,” but how it’s defined and scoped exactly isn’t clear when reviewing.)
>
> Is there another section, not showing up in search, that would clarify, or is (or could) this be clarified in another draft?

## @fantasai — 2025-03-27

The CSS specs are written so that they could be applied to document trees other than the DOM. So, the vocabulary in the CSS specs hook into the shadow DOM indirectly. In theory there could be other encapsulation contexts, and maybe someday someone will define one; in practice, I'm not aware of other element trees that have such a concept, so the shadow DOM is the only real example.
