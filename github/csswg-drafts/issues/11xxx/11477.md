The [`inset`](https://drafts.csswg.org/scroll-animations-1/#dom-viewtimelineoptions-inset) property of the [`ViewTimelineOptions`](https://drafts.csswg.org/scroll-animations-1/#dictdef-viewtimelineoptions) is currently defined as `(DOMString or sequence<(CSSNumericValue or CSSKeywordValue)>) inset = "auto";`. This means that setting that value to `"auto"` is valid but not setting it to `["auto", "auto"]`.

I suggest we use [`CSSKeywordish`](https://drafts.css-houdini.org/css-typed-om-1/#typedefdef-csskeywordish) instead of [`CSSKeywordValue`](https://drafts.css-houdini.org/css-typed-om-1/#csskeywordvalue) so that strings can be used as well as `CSSKeywordValue`. As it turns out, this is already what is being tested in [scroll-animations/view-timelines/view-timeline-inset.html](https://github.com/web-platform-tests/wpt/blob/038c19b8529b374bb40b6b01cf062577f0dc39dc/scroll-animations/view-timelines/view-timeline-inset.html#L112) and what Chromes implements.

## @flackr — 2025-01-31

I remember from the discussion when we added support for strings the main reason was to allow passing CSS style strings directly for which I imagine you'd pass multiple values space separated: "auto auto". See https://github.com/w3c/csswg-drafts/issues/7748#issuecomment-1325424372

However, I don't think there's much additional complexity to supporting parsing a string for each argument, so I think making this change is reasonable.

## @BorisChiou — 2026-07-17

Just one question for this. Should we accept the `auto` string case-sensitively? It seems [WebKit](https://searchfox.org/wubkat/rev/d221d71a6a560cb45bb3e9b23e526b6bcfa9e4b3/Source/WebCore/animation/ViewTimeline.cpp#133) and [Blink](https://source.chromium.org/chromium/chromium/src/+/main:third_party/blink/renderer/core/animation/view_timeline.cc;l=89;drc=d4bd1c71d3633abd5d6a21cea92055eabdfefd32) compare the string case-sensitively for an individual inset (or I may misread the code).

However, if the author provides a string for the inset, like this "Auto 10px", the spec expects us to parse it as `<view-timeline-inset>` value, and the CSS parser is case-insensitive, IIRC. So this may cause inconsistency. In Gecko, I intend to support the `CSSKeywordish` and check the string case-insensitively to match the CSS parser.
