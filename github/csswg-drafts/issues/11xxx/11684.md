`animation-timeline` is a [`<dashed-ident>`](https://drafts.csswg.org/css-values-4/#typedef-dashed-ident), which is a [`<custom-ident>`](https://drafts.csswg.org/css-values-4/#identifier-value) starting with `--`, which excludes `default` and *any valid CSS identifier that would not be misinterpreted as a pre-defined keyword in that property’s value definition*.

`<dashed-ident>` could have been defined as a case-sensitive `<ident>` starting with two dashes. Since that is not the case, I would expect `--initial`, `--default`, `--auto`, `--none`, etc., to be invalid in `animation-timeline`.

However, Chrome and FF (non-exhaustive) interpret `animation-timeline: --initial` as a valid declaration.

Is this an implementation or specification issue?

<!-- comment id=2649150964 author=Loirooriol created=2025-02-10T20:22:41Z url=https://github.com/w3c/csswg-drafts/issues/11684#issuecomment-2649150964 -->
## @Loirooriol — 2025-02-10

`initial` and `--initial` are different identifiers. The latter is a valid `<custom-ident>` and `<dashed-ident>` (unless a property gives it a special meaning, but that shouldn't happen)

## @tabatkins — 2025-02-11

Right, it's not that a dashed-ident is two dashes + a custom-ident, it's just a custom-ident that starts with two dashes. Thus, by definition, it doesn't run afoul of the custom-ident restrictions, since none of the restricted values start with two dashes.
