https://drafts.csswg.org/css-easing/#funcdef-linear specifies:

“If an argument lacks a [`<percentage>`](https://drafts.csswg.org/css-values-4/#percentage-value), its [input progress value](https://drafts.csswg.org/css-easing/#easing-function-input-progress-value) is initially empty, but that is immediately corrected by [linear() canonicalization](https://drafts.csswg.org/css-easing/#linear-canonicalization) after parsing.”

However, it is not always possible to canonicalize at parse time. For instance, if any of the stops' x values is `calc(0.5 + 0.2 * sign(1em - 1px))`, we may need to wait until the style is computed before we know if it needs to be clamped to the previous point or not. How do we handle this? What if _some_ of the stops may be resolvable but not all of them?
