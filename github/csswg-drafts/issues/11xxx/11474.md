In [CSS Multicolumn, column-span](https://www.w3.org/TR/css-multicol-2/#column-span) it would be useful to have the ability to create content that spans a specified number of columns using an <integer>. It is common to have images span two or three text columns in print.

I would expect this to work where the vertical and starting position coincides with where the `block` element falls in the column, then clears subsequent adjacent columns at that position of content to expand into like a float. This would likely be commonly used with `break-before: column; height: 100%;` styles to create a full height block.

Example of a print layout with images spanning two columns:

[![print layout example showing images spanning two text columns](https://i0.wp.com/tirsogamboa.com/wp-content/uploads/2020/12/TIRSO_magazinedesign_2A.jpg?fit=1200%2C858&ssl=1)](https://tirsogamboa.com/how-to-design-a-magazine-layout-like-a-true-editorial-designer/)

It is possible to hack this functionality into some browsers (Chrome) by using `<figure>` and `::before` and `::after` pseudo elements alongside `break-before` and `break-after`, thus clearing columns for the figure to expand into. https://codepen.io/scottkellum/pen/qBQYyGO?editors=1100

## @claell — 2026-07-19

I have a paged-media use case that may help clarify the intended behavior. It is similar to the print example in the issue, but involves a leading partial spanner and automatic flow through columns with different available heights.

Consider a three-column newspaper, magazine, or folded-brochure page:

* A masthead or section introduction spans the first two logical columns at the block start.
* The third column remains available from the block start instead of being pushed below the masthead.
* All following articles remain in one semantic content stream. If their lengths change, content automatically reflows through the shortened first and second columns and then through the full-height third column.

The important part is the single automatic flow. CSS Grid can place the masthead across two tracks, but it generally requires content to be assigned to particular grid areas rather than flowing automatically through these irregular column areas. `column-span: all` also cannot express the layout because it shortens every column.

A more general version is a photograph, pull quote, or advertisement encountered later in a four-column article that spans the current and next column while surrounding text continues in document order. The existing example already points towards this float-like case.

These examples expose some of the questions already noted in the draft:

* Should an integer spanner start in the column where it is encountered and cover the next logical columns, or are leading partial spanners handled differently?
* Should adjacent covered columns be cleared only over the spanner's block range, producing irregular flow areas?
* In the leading example, should sequential flow fill the shortened covered columns before the full-height uncovered column, even though this means the visual block position moves back towards the top when entering that column?
* How should balancing, fragmentation, writing modes, and insufficient remaining columns affect this placement?

Is `column-span: <integer>` still an actively pursued direction for Multicol Level 2, and is the float-like model described here broadly the intended direction? Would a set of reduced paged-media examples and proposed Web Platform Tests be useful before implementations experiment further?
