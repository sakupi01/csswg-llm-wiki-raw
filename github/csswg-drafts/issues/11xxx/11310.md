This is more-so related to the associated event for `content-visibility: auto` (i.e. `contentvisibilityautostatechange`). I noticed that in Chrome (131) this bubbles, while in Safari (18.1) and Firefox (133) it does not. I was planning on making a WPT for this, but I don’t really know what the behaviour should be, so I figured I’d ask here. [The relevant section in the spec](https://drafts.csswg.org/css-contain/#content-visibility-auto-state-change) mentions nothing about bubbling.

I made [a demo highlighting the bubbling problem](https://knowler.dev/demos/WA2d_f9).

I was discussing this with @AmeliaBR on Mastodon and [she pointed out](https://front-end.social/@AmeliaBR/113584190196184251) that the parent event likely specifies this (i.e. in this case `Event` and its init `EventInit` interface — which doesn’t bubble by default). It seems like if bubbling was intended, then it was missed in the spec.

To be consistent with things like toggle event, it should not bubble. That way nestedly dispatched events don't disturb event listeners in ancestors. And one can always use capturing listener, if one explicitly needs to handle nested stuff
