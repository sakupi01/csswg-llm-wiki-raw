It can take both [`<supports-condition>`](https://drafts.csswg.org/css-conditional-3/#typedef-supports-condition) and `<ident> : <declaration-value>`. The former represents a wider set of values that includes the set from the latter, which does not accept declarations prefixed with `!important`.

Can you please clarify if this is it intentional?

Sorry if I missed something from the various related issues present in the message of the commit adding this function. I only searched briefly.

## @cdoublev — 2024-11-08

I see: `<supports-condition>` allows combining queries but does not allow a naked `<declaration>`. 

But I think `<ident> : <declaration-value>` should be `<declaration>` instead, as in [`<import-conditions>`](https://drafts.csswg.org/css-cascade-5/#typedef-import-conditions):

  > `<import-conditions> = [ supports( [ <supports-condition> | <declaration> ] ) ]? <media-query-list>?`

## @tabatkins — 2024-11-08

Note that `<supports-condition>` is wrapped in parens (or is a boolean expression of paren-wrapped things). We didn't want to force you to include parens for the simplest case in `supports()`, where you're just testing one property. That is, we wanted to allow `supports(foo: bar)`, rather than requiring it to be spelled `supports((foo: bar))`.

<!-- comment id=2465693379 author=tabatkins created=2024-11-08T20:24:41Z url=https://github.com/w3c/csswg-drafts/issues/11155#issuecomment-2465693379 -->
## @tabatkins — 2024-11-08

But yes, it should use `<declaration>` like the @import version of the function does.
