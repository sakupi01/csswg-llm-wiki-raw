`::file-selector-button` isn't dependent on any CSS for its continued existence so it seems a good candidate to be made a [`:has-allowed pseudo element`](https://drafts.csswg.org/selectors/#has-allowed-pseudo-element)?

Is there a reason it wasn't made one initially?

I think this is a good testcase for having a has-allowed pseudo-element.

But I think https://github.com/w3c/csswg-drafts/issues/12630#issuecomment-3819888972 applies here too.  (We could also make `:has(::pseudo)` have a different default behavior from `:has(tag)` and test for pseudo-attachment rather than descendant combinator.)

## @lukewarlow — 2026-04-02

I agree that :has(::file-selector-button) matching the input's parent seems completely wrong. A new combinator feels the wrong approach, we should just make it match the originating element in this case.

<!-- comment id=4179394011 author=dshin-moz created=2026-04-02T17:36:35Z url=https://github.com/w3c/csswg-drafts/issues/11856#issuecomment-4179394011 -->
## @dshin-moz — 2026-04-02

`:has` cannot be nested, so something like `.form:has(.sub-form input:has(::file-selector-button))` wouldn't work, which is maybe unfortunate?

<!-- comment id=4179442306 author=dbaron created=2026-04-02T17:45:03Z url=https://github.com/w3c/csswg-drafts/issues/11856#issuecomment-4179442306 -->
## @dbaron — 2026-04-02

Maybe we want `:has-pseudo()` or `:attached()` or something similar that accepts pseudo-elements, and is allowed inside of `:has()`, and represents only the "this element has one of these pseudo-elements".  (And then we wouldn't allow pseudo-elements in `:has()` at all, but would allow them inside of `:has-pseudo()` inside of `:has()`.

## @dbaron — 2026-04-02

Yeah, I think that's an issue, although there are two ways we could take it:

1. we do need to make this work with `:has()` in some way, or
2. `:has-pseudo-element()` isn't actually different from `:has()` except for the combinator rules at the start -- it's just `:has()` where the implied combinator at the start is pseudo-element-of (and the first thing better be a pseudo-element) but otherwise it's just like `:has()`.

(If we go with (2) we need to decide whether the `:has-pseudo-element(not-a-pseudo)` is a parse error or just fails to match.)
