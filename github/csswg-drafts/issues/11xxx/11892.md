## @lukewarlow — 2025-03-10

They also *sometimes* have a search icon as a prefix icon. I don't personally think we need to standardise that *but* we perhaps want to mention that they're a thing and are omitted deliberately (to pre-empty any questions around them).

Regarding clear icon I think it would be good to add them provided they considered good from an a11y perspective (not sure if there are or aren't concerns). Though perhaps they're useful for any textual input not just search? Could probably be defined to just have a `content: "X"/"Clear Input"` or something like that (maybe a background-image?)

Regarding custom buttons like with the file input button case perhaps that's addressed by current JS capabilities (+ maybe a command="clear"?) as a fallback for those more detailed cases? I think CSS already gives the capabilities needed for that sort of positioning? Again not saying we should rely on this sort of thing, but it comes back to your question of what percentage of use cases we need to solve and how seamless it needs to be for each of them.
