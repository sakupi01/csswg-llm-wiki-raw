Discovered while working on https://github.com/whatwg/html/pull/4695.

## @tabatkins — 2019-06-13

Hm, that's because Bikeshed only sees that definition.

Looking in the HTML spec, it looks like all of the "legacy" elements are marked up as plain `dfn`, with no additional markup. Those'll all need `data-dfn-type=element` to expose them to Bikeshed properly.

<!-- comment id=501810402 author=plinss created=2019-06-13T17:48:56Z url=https://github.com/w3c/csswg-drafts/issues/4030#issuecomment-501810402 -->
## @plinss — 2019-06-13

Shepherd's spec parser has a heuristic to mark all the element `dfn`s in the HTML as elements without the `data-dfn-type` (they all have anchors matching the pattern 'the-&lt;name&gt;-element'). I think the issue here is that HTML doesn't define the `font` element any more...

<!-- comment id=501872406 author=tabatkins created=2019-06-13T20:46:21Z url=https://github.com/w3c/csswg-drafts/issues/4030#issuecomment-501872406 -->
## @tabatkins — 2019-06-13

It does (<https://html.spec.whatwg.org/multipage/obsolete.html#font>), it's just off in a different section and doesn't have any of the indicators of being an element dfn.
