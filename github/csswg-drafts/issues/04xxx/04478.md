It’s this bit in the list of legacy CSS mistakes, and `::placeholder` is still a relatively new pseudo‑class, so stuff like #1537 feels less likely to happen here.

> - `::placeholder` should be `::placeholder-text` and `:placeholder-shown` should be `:placeholder`

I also understand that aliasing `:placeholder-shown` to `:placeholder` might get a bit confusing with the fact that `::before` and `::after` have the legacy **CSS2** aliases `:before` and `:after`, which is why doing the latter is optional, even though engines don’t actually consider `:placeholder` valid at this time.

## @fantasai — 2020-12-30

@ExE-Boss We generally try to avoid aliases unless the original name was particularly problematic/confusing, because it creates a greater amount of incompatibility among browsers/versions and is more stuff for authors to know about. So usually on balance it's better not to alias. I think in this case it's not that severe of a problem, just a nice to have if someone invents a time machine. :) Lmk if you feel differently and I'll raise it with the CSSWG.
