https://bugs.chromium.org/p/chromium/issues/detail?id=1018465#c3

Just my opinion: ::selection should not select hard wrap line break. If a `<br>` is nothing more than a carriage return (CR: 0x0D) and a line feed (LF: 0x0A) (both non-printable characters), then I do not see why a `<br>` should be painted.

Either way, I think the current specification should be explicit on this issue since Chrome and Firefox disagree.

## @fantasai — 2019-10-28

Hi @TalbotG, I think the test is correct, because the selection background should be inherited into `<br>` anyway. But also, it's OK if `<br>` is rendered as taking up space: the question of whether it should or not is outside the scope of css-pseudo-4, so not particularly important to consider for this test. (It should definitely not affect whether the text fits within its container, or at what size its container shrink-wraps, but if it's rendered during selection, it's not much of a problem I think.)
