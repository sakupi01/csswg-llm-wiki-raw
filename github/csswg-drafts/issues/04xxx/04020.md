So let's say I have a user stylesheet:
```
color: red !important;
```
In forced colors mode, what applies? The spec says `revert !important` is added to the cascade at the user level (when?), which may or may not win over my `red !important`.

I don't think it's enough to state that the value is added at the user level. Clearly we need `revert !very important`.

<!-- comment id=515896258 author=andruud created=2019-07-29T08:25:58Z url=https://github.com/w3c/csswg-drafts/issues/4020#issuecomment-515896258 -->
## @andruud — 2019-07-29

If the intent is to revert author styles, then we must `revert` at the author origin, in which case we get the same problem for an author-level declaration `color: red !important`.

<!-- comment id=595587223 author=fantasai created=2020-03-06T03:51:26Z url=https://github.com/w3c/csswg-drafts/issues/4020#issuecomment-595587223 -->
## @fantasai — 2020-03-06

Yeah, you're right, this isn't specified quite correctly. It reverts everything in the author origin as intended, but also reverts everything in the user origin as well. For it to work ideally (preserving user styles), we'd need to have an origin between user and author.

We kindof already have this, in the form of the "non-CSS presentation hints" layer. If we turn that into a real origin and give it a corresponding !important level, then we can inject these rules into that origin and they should work as intended.

Agenda+ to discuss.

<!-- comment id=596442518 author=andruud created=2020-03-09T10:17:54Z url=https://github.com/w3c/csswg-drafts/issues/4020#issuecomment-596442518 -->
## @andruud — 2020-03-09

@fantasai That makes sense. But let's definitely not make the new origin something that can be `revert`-ed _to_ (only from). `revert` is already complicated and expensive enough, so `revert` in the author origin should still revert to the user origin IMO.

<!-- comment id=596593243 author=emilio created=2020-03-09T15:16:29Z url=https://github.com/w3c/csswg-drafts/issues/4020#issuecomment-596593243 -->

FWIW the way Firefox implements this is just treating author-level declarations for those properties as `revert`: https://searchfox.org/mozilla-central/rev/557a0e222dd104c5d805ba344c45d6abc27d3db0/servo/components/style/properties/cascade.rs#406

I think the spec mostly wants to say that any declaration for those properties in the author origin is treated as `revert`, or something of that sort.
