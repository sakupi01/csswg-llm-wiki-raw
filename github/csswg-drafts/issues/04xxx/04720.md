We currently have a rule (which exists due to compat reasons) that if the author sets *either* background-color or color on ::selection, then the UA's rules for *both* background-color and color get dropped. So, for example, if the author sets `color`, then `background-color` becomes `transparent`.

What about if the author sets `fill` or `stroke`? Should they also make the `background-color` become `transparent`, or should the selection continue to use the OS default selection background color?

## @delan — 2023-06-13

This is an interesting issue, and it has some overlap with #6386 (see also @fantasai’s [comment](https://github.com/w3c/csswg-drafts/issues/6386#issuecomment-886111107)).

I think the fact that paired defaults help authors avoid contrast hazards is a nice consequence, but not a good enough reason to extend this behaviour (or for impls to have created it in the first place). Mixing author colors with system colors is always hazardous. Sometimes the hazards are so pervasive in the wild that [we need technical mitigations](https://github.com/w3c/csswg-drafts/issues/3299), but I’m not sure that’s the case for highlight ‘fill’ and ‘stroke’.
