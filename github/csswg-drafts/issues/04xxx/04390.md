As it is difficult to monitor size changes (without observer API), it is difficult to monitor position changes.

there are many things to listen to be able to detect changes in the position of an element:

* window resize event
* element styles change (top, left, margin, transform?, position…)
* previews elements size change(resize observer on each ?)
* …

Under these conditions, the best way to monitor the position of an element is probably through the use of `setInterval` or `requestAnimationFrame`.

It would be better to have an observer API for the movements of an element.

The API could look like this:

```js
const observer = new window.MotionObserver(positionChange);

observer.observe(document.querySelector('.foo'));

function positionChange(change) {
  console.log(
    change.target,
    change.position.x,
    change.position.y,
  );
}
```

As we are probably interested in observing both size and position changes, it would be better to create an API that can handle both.

Here's what it might look like:

```js
const element = document.querySelector('.foo');

const observer = new window.BoundingRectObserver(rectChange);

observer.observe(element, {
  observeResize: true,
  observeMotion: true,
});

function rectChange(change) {
  console.log(
    change.target,
    change.rect.x,
    change.rect.y,
    change.rect.width,
    change.rect.height,
  );
}
```

here, the second parameter of the `observe` function allows you to specify whether to observe changes in size, position or both, which can, I suppose, improve performance.
